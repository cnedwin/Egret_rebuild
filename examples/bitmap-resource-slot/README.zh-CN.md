# Bitmap 资源替换

[English](README.md) | 简体中文

示例组合公共 Engine 资源槽、普通 Bitmap、变换后的矩形裁剪、显式命中区、主鼠标输入和两个独立 BitmapButton。原创资产为红色 A（2×2，裁剪成 1×2）、绿色 B（3×1）、蓝色 C（1×3）及共享灰色按钮图集，无需外部美术。

按仓库正常流程构建并提供本地网页服务，打开本目录 `index.html`，通过链接选择 Canvas 或 WebGPU。点击画布内左按钮请求 B、右按钮请求 C，再使用画布下控件完成、失败或取消；点击上方目标保留选择。provider 刻意忽略取消直到受控结果到达，使过期请求真正经过迟到结果清理。资源槽已销毁或发生冲突时，两颗场景替换按钮均停用，其余控件按可用操作启停。“重建资源槽”显式恢复应用拥有的 A 绑定，并创建借用该绑定的新槽。

替换等待、失败或取消时保留旧绑定，只有最新已接受请求可以提交。新尺寸重置资源裁剪，变换、显式 hitArea 和选择仍由应用维护。初始租约归应用，槽仅拥有自己获取的替换租约。手工独立重绑导致冲突；此后销毁槽保留手工字段及独立拥有的租约。按钮内部 Bitmap 不作为替换目标。

专用验证器分别检查 Canvas/WebGPU 原生点击，以及 14 个检查点中每处的六个字面 RGBA 采样点，颜色容差为零。每帧 WebGPU 都先申请读回再提交，首帧读回成功后才就绪。每后端使用一个全新完整普通上下文，以及另一个全新完整错误颜色对照上下文。对照在完整流程结束后仅修改启动检查点中的一个预期颜色，不计入主用例。

示例局部 `window.bitmapResourceExample` 接口控制原创 provider 屏障并提供检查数据。其 `readback()` 返回最近一次 Host 实际读回的宽、高、RGBA 字节及标签副本。验证器在比较前保留健康启动屏障和全部 14 个检查点的完整原始 RGBA 字节，使用不同文件名，记录尺寸、字节数和 SHA256。Node 从每份已保存字节中独立读取六个采样点。健康启动屏障与名为 startup 的检查点分别记录，前者不增加普通检查点验收计数。保留完整帧供复核，验收范围仍是声明的六个采样点、生命周期和原生输入流程；截图仅作辅助。

该接口不增加 SDK 诊断导出，也不增加读回请求。关闭时完成所有原创 provider 工作、退役 Scope/Engine，并记录剩余计时器、读回与宿主资源。本示例不代表完整 UI、Spine/3D 动画、手机性能、全画面逐像素正确或物理显示保证。

验证器先解析并验证示例原有的有限 import map，再投影路由；仅接受声明的准确相对目标，不接受 scopes 或额外字段。应用仅导入四个公共 Engine 入口，SDK 内部别名另行准入。基础库通过 Engine 声明的 `packages/engine/node_modules/robust-predicates` 别名解析到实际物理所有者，并核对包名与版本。共享文件身份辅助模块在导入前核实物理所有者、准确大小写、URL 和原始字节。服务器仅提供已捕获的有限模块路由。

原生执行前，先以 `node tools/verify-bitmap-resource-slot.mjs --repository <仓库绝对路径> --application-root <应用根绝对路径> --snapshot <全新仓库外JSON绝对路径> --snapshot-only` 生成并审查独立闭包快照；此模式只读源码/构建产物，不启动浏览器。随后用同一验证器，指定已审查 `--snapshot`、准确的 `--playwright <已安装1.62.1目录>`、`--channel msedge` 和全新仓库外 `--output` 目录。原生模式在启动 Edge 前拒绝所有输入漂移，采用普通启动默认值，不添加额外 flags。
