# Bitmap resource replacement

English | [简体中文](README.zh-CN.md)

The example composes the public Engine resource slot, one ordinary Bitmap, transformed rectangular clipping, explicit hit areas, primary mouse input and two independent BitmapButtons. The original assets are red A (2×2, cropped to 1×2), green B (3×1), blue C (1×3) and a shared gray Button atlas. No external artwork is required.

Serve the repository after its normal build. Open this directory's `index.html`; the backend links select Canvas or WebGPU. Click the left in-scene Button for B or the right for C, then complete, fail or cancel using the controls below the canvas. Click the upper target to retain its selection. The provider deliberately ignores cancellation until a controlled result arrives, so a superseded request can exercise genuine late-result retirement. Disposed or conflicted slots disable both in-scene replacement Buttons; the remaining controls reflect the available operations. Recreate slot explicitly restores the A binding owned by the application and creates a new slot that borrows it.

The old binding remains while a replacement is pending, fails or is cancelled. Only the latest accepted request commits. New dimensions reset the resource crop; authored transforms, hitArea and selection remain. The application owns its initial lease. The slot owns only its acquired replacement leases. Manual independent rebinding conflicts with the slot; disposing after a manual binding leaves those manual fields and independently owned lease intact. Button internals are not replacement targets.

The dedicated collector checks native clicks and six literal RGBA points at each of 14 checkpoints separately on Canvas and WebGPU, with zero color tolerance. GPU readback is armed before each frame and the first readback must settle successfully before readiness. Each backend receives a fresh complete ordinary context and a separate fresh complete wrong-color control context. The control changes only one expected startup-checkpoint color after the complete schedule; it provides no ordinary-case credit.

The example-local `window.bitmapResourceExample` interface controls authored provider barriers and inspection. Its `readback()` returns a copy of the exact last Host readback width, height, RGBA bytes and label. Before comparisons, the collector retains the unaltered complete RGBA bytes for the healthy startup barrier and all 14 checkpoints, with distinct filenames and recorded dimensions, byte length and SHA256. Node independently reads the six points from each saved byte array. The healthy startup barrier is separate from the checkpoint named startup and adds no ordinary checkpoint credit. Retained full frames support replay; acceptance remains limited to the declared six points, lifecycle and native input schedule. Screenshots are ancillary.

The interface adds no SDK diagnostic export or readback request. Closing settles every authored provider job, retires scopes/Engine and records remaining timers/readbacks/host resources. This example establishes no complete UI, Spine/3D animation, target-phone performance, all-pixel correctness or physical-display guarantee.

The collector parses and validates the original finite import map before projecting any routes. Only its exact declared relative targets are admitted, without scopes or extra fields. The application imports only four public Engine entries; internal SDK aliases have separate admission. The foundational package resolves through the Engine-declared `packages/engine/node_modules/robust-predicates` alias to its physical owner, with package name and version checks. The shared file-identity helper's physical owner, exact spelling, URL and raw bytes are authenticated before import. The server serves only the captured finite module routes.

Before native execution, create and review a standalone closure snapshot with `node tools/verify-bitmap-resource-slot.mjs --repository <absolute-repository> --application-root <absolute-application-root> --snapshot <new-absolute-external-json> --snapshot-only`. This reads sources/emissions without starting a browser. Then invoke the same collector with the reviewed `--snapshot`, exact `--playwright <installed-1.62.1-directory>`, `--channel msedge` and a new external `--output` directory. Native mode refuses any changed input before launching Edge. Use ordinary browser launch defaults, with no extra flags.
