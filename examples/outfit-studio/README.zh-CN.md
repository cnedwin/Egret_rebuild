# 白鹭换装工作室

[English](README.md) | 简体中文

换装工作室的默认精简配置在同一个 Engine 中组合了可编辑角色列表、两个 Spine 实例、序列帧效果、两层背景板和原生重命名弹窗。两个角色起初共享相同图集，各自保留装扮和播放状态。

在仓库根目录运行 `pnpm setup:dev`，然后运行 `node examples/outfit-studio/serve.mjs`。打开输出的本地地址，选择 WebGPU 或 WebGL2。桌面场景使用 960 × 520 的逻辑尺寸和像素比 1。用鼠标或 Tab 与 Enter 选择角色并应用装扮。在详情里选择重命名，再选中字段进行编辑。保存时先用场景字体检查名称，检查通过后提交到工程。名称被拒绝时可在弹窗内重新编辑。取消会丢弃草稿。鼠标操作需在按下的行内释放才会执行。

切换配色通过共享场景 Host 准备新的 Spine 资源。加载期间保留原画面。加载或准备失败时，当前角色与工程仍可使用，同一行可以重试。切换成功后，所选角色沿用既有 RESET 策略重新开始动画。关闭时释放界面、播放、字体、资源组和 Host。重新载入会打开创作数据。

修改 `project.json` 后重启服务即可看到变化。两个稳定实体 ID 标识角色及各自的 `name`、`outfit`、`palette` 字段。「导出工程」会下载当前已提交的快照。可以在运行中的页面打开该文件，或运行 `node examples/outfit-studio/serve.mjs --project <快照路径>`，在启动时使用它。播放时间、选择和草稿属于本次会话。示例复用现有工程存储和共享资源管理器。[示例工程](project.json)

「打开工程」在正在运行的工作室里打开已导出的快照。文件先在当前工程的副本上准入，并作为一次编辑事务写入。随后加载每个新配色，由 Host 接收，期间保留原画面。暂存完成后，工作室一起应用工程、角色和列表的变更。「打开工程」按钮此时显示「正在呈现工程…」，并保持禁用，直到首帧绘制结束。

- **角色必须相同。**文件须包含当前工程的角色，稳定 ID 相同、顺序相同，版本固定值也相同。各角色的 `name`、`outfit`、`palette` 以及工程名称取自文件。固定场景会为两个角色的导出文件补上六个参考角色，与服务启动时一致。
- **发布前可取消。**工作室准备文件期间可以点击「取消打开」。准备期间取消或遭到拒绝时，当前工程、角色和播放保持原样，同一文件可以再次选择。发布后若首帧绘制失败，工程已打开，工作室会提示刷新预览。
- **配色改变的角色会重新开始动画**，沿用与切换配色相同的 RESET 策略。其他角色继续原来的播放。一套配色的初始 Spine 资源组会保留到最后一个使用它的初始角色完成替换，随后释放该组的租约。加载器沿用既有上限。
- **文件最大 64 KiB。**更长的文件在读取之前即被拒绝。

工作室沿用 `animation-outfits` 的原创程序化 Spine 和序列帧素材。第二套配色交换现有两张图集页的颜色，并构建新的清单身份。工作室代码及原创场景几何采用 Apache-2.0。[换装素材出处](../animation-outfits/PROVENANCE.zh-CN.md) · [CanvasKit 和 Noto 素材](../paragraph-panel/vendor/README.zh-CN.md) · [Spine 运行时条款](../../third-party/spine-core-4.3.13.LICENSE) · [JSONC 解析器署名](../../third-party/jsonc-parser-3.3.1.LICENSE)

使用 Playwright 1.62.1 和已安装的 Edge，运行 `node examples/outfit-studio/verify.mjs <Playwright 包绝对路径> <新的绝对输出目录>`。同批验证覆盖两个真实浏览器后端、鼠标与键盘、名称拒绝、拖出原行再释放、配色失败与重试、导出重开和退出清理。每个后端采集三次冷 HTTP 启动，截止到首帧完成并允许交互。记录的传输是本地回环未压缩 HTTP。[验证摘要](verification-summary.json)

打开工程的验证运行 `node examples/outfit-studio/verify-open.mjs <Playwright 包绝对路径> <新的绝对输出目录>`。每个后端通过页面导出两次，通过页面的文件字段打开导出文件，让一次加载失败，取消一次，再重试，提交七个必须被拒绝的文件，并在固定桌面场景打开一个精简导出。固定桌面场景还会替换八个角色的配色、重新打开原工程，并在故意延迟首帧时检查取消按钮不可用。第三个参数 `software` 改用 Playwright 自带的浏览器和软件渲染，代替已安装的 Edge。2026-11-14 以这种方式在无头 Chromium 153 上通过了 WebGL2 各项：精简场景八项，固定场景一项。后续在搭载 NVIDIA RTX 5090 Laptop GPU 的 Windows 上使用 Edge 157，两后端各通过十项。Galaxy Z Fold7 真机使用 Chrome 157 与 Adreno 830，在 X-MTouch/1 档位下每个后端各通过五项。点按按钮可取消延迟导入，同一文件可重试，八个角色打开原工程后保留稳定 ID。提交后，打开按钮禁用至首帧结束。测试将浏览器文件对象交给页面输入框，Android 系统文件选择器留待单独验证。

## 固定场景配置

沿用同一个服务，选择「固定桌面」或「移动触摸」。默认地址继续打开精简工程。固定配置保留原来两个角色的 ID，并补入六个稳定的参考角色。目录可以选择全部八个角色。命令行验证工具会重新打开固定配置导出的快照，检查 ID 和创作值。浏览器也可打开角色 ID 与版本固定值均符合固定场景的快照。 [#91](https://github.com/cnedwin/Egret_rebuild/issues/91)[固定负载与布局](workload.mjs)

| 配置 | 逻辑尺寸与渲染像素比 | 初始目录 |
| --- | --- | --- |
| X-D60/1，`?profile=x-d60&backend=webgpu` | 1024 × 768，像素比 1 | 32 行可见，最多 48 个容器 |
| X-MTouch/1，`?profile=x-mtouch&backend=webgl2` | 竖屏 360 × 640 或横屏 640 × 360，像素比 2 | 8 行可见，最多 24 个容器 |

移动端切换横竖屏时，场景背景会随画布尺寸重新缩放。

固定场景包含 6,000 个有序创作节点、计入活动行子节点后的 600 个可见 UI 节点、八层嵌套裁剪、一个 Alpha 遮罩、一个半径为 2 的离屏模糊和 50,000 条变高目录记录。八个 Spine 实例各有 120 根骨骼、96 个插槽、2,000 个加权网格顶点和两条活动轨道，初始共享同两张图集页。当前画面还包含 80 个相位独立的序列帧实例和两块平面 2D 背景。表单沿用 CanvasKit 和 Noto 字体集，显示英文、中文、阿拉伯文及已覆盖的 🆕 字形。[原创加权几何](author-x.mjs)

在手机上按住「＋」移动，用第二指点「■」触发动作。场景支持单指拖动和双指平移、缩放、旋转。地图接纳两指，第三个地图触点会被拒绝。目录可滑动或点按已提交的记录，滑到边界后外层抽屉可再移动最多 12 个逻辑像素。模态弹窗会取消已有触点。旋转时重建当前视图并关闭临时草稿，保留创作快照、目录位置和动画状态。键盘改变可用高度时保持当前逻辑方向。CSS 安全区与留边参与坐标映射，渲染像素比单独设置。

## 固定配置验证

安装 Edge 和 Playwright 1.62.1 后，运行 `node examples/outfit-studio/verify-fixed.mjs <Playwright 包绝对路径> <新的输出目录> --check`。计时使用新的输出目录和 `--timing`。每个后端及状态预热 30 秒，记录五个 60 秒窗口。稀疏或全脏状态按固定顺序对前 60 个或全部 6,000 个节点交替施加 0 和 0.25 逻辑像素偏移，再推进 1/60 秒。静态状态保持初始姿态。

### 历史混合场景结果

下表和 Android 结果来自原始的两个深度四边形场景。当前双面板示例仍可运行夹具做开发检查。正式执行 [#92](https://github.com/cnedwin/Egret_rebuild/issues/92) 计时需先恢复等效混合合成或确定经评审的后继档位。

| 后端 | 状态 | 同步阶段耗时 p95（ms） | Host 全段 p95（ms） | 完成帧间隔 p95（ms） | p99（ms） |
| --- | --- | ---: | ---: | ---: | ---: |
| WebGPU | 静态 | 33.9 | 30.1 | 41.1 | 76.8 |
| WebGPU | 稀疏 | 75 | 35.1 | 82.4 | 89 |
| WebGPU | 全脏 | 74 | 34.6 | 82.2 | 88.6 |
| WebGL2 | 静态 | 37.9 | 34.4 | 46.3 | 85.4 |
| WebGL2 | 稀疏 | 80.7 | 40.5 | 87.5 | 91.4 |
| WebGL2 | 全脏 | 87.8 | 38.9 | 96 | 104 |

表中取各窗口百分位的中位数。同步阶段按单帧相加动画、捕获和 Host 同步耗时，Host 全段包含准备、打包与提交。实测经过时间可能包含驱动等待或调度抢占，和 8 毫秒的对照用于定位。完成帧间隔未达到目标，正式全引擎 CPU、准备耗时和 GPU 计时继续开放。原始记录单独保留 UI 耗时和夹具变更耗时。启动记录来自本地未压缩回环传输。

Android Chrome 真机上，两个后端均完成了 100 次受控触摸响应，以及多点、滚动、模态、系统键盘、旋转与 Home 返回用例。WebGPU 和 WebGL2 的响应 p95 分别为 412.4 和 383.6 毫秒，目标为 100 毫秒。测试通过 CDP 注入触点并观察对应完成帧。真人触摸与中文输入法组合、iPhone Safari、压缩启动和持续生命周期验收仍待完成。[实测摘要与源码哈希](fixed-verification-summary.json) · [M4 验收计划](../../knowledge-base/Cns/docs/m4-core-acceptance-plan.md)
