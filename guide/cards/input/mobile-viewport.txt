# Fit the page to a phone screen and its safe areas

`play` and `play3d` fill the window by themselves. For a phone held either way, give them `fit: 'expand'` (no black bars) and a `portrait` size, and hold edge controls with `game.pin(node, { right: 16, top: 16 })`, which places them in `game.safe` again on every turn, or place them from `game.safe` in `arrange(game)`; see `knowledge-base/en/docs/screen-fit.md`. A game that lays out its own page needs the following, all taken from the large games.

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
```

```css
html, body { margin: 0; height: 100%; overflow: hidden; }
#stage { position: fixed; inset: 0; width: 100%; height: 100%; touch-action: none; }
.hud-top { padding-top: max(8px, env(safe-area-inset-top)); }
.touch-left { left: max(12px, env(safe-area-inset-left)); }
.panel { max-height: calc(100dvh - 22px); }
```

Rules:

- An Egret 5 project of `scaleMode` fixedWidth, fixedHeight, fixedNarrow or fixedWide keeps it: they are values of `fit` too, and the stage then follows the window. Pixel art takes `wholeScale: true`, a whole number of device pixels a unit.
- Size the canvas with CSS and let the view follow it. `createWorld3DView` resizes the drawing buffer when the canvas's displayed size changes; its `maxPixelRatio` defaults to 2. All three games pass 1.5, so a 3x phone does not draw nine times the CSS pixels.
- Use `100dvh`, not `100vh`: mobile address bars change the visible height.
- Pad every edge control by `env(safe-area-inset-*)`, which a page has only with `viewport-fit=cover`. Phones in landscape put a notch or a rounded corner under the left or right HUD.
- `touch-action: none` on the play area during play only. Menus and long lists (upgrade cards, settings) keep `touch-action: pan-y` so they still scroll.
- Plan for a short landscape screen. The measured Samsung run in FPS used an 873 × 325 CSS viewport; HUD text, cards and buttons must fit that.
- Start low on weak devices. `createWorld3DApp` with quality `auto` picks `low` for software rendering, a touch screen or a window under 600 px tall, and `medium` for 4 GB of memory or less; `pickWorld3DQuality` gives the same choice to a game with its own renderer.
- Let the player change quality and language on the title screen, and store the choice (in a `try`: private windows may refuse storage).
- Ask for fullscreen and pointer lock only from a press, and show a way back when the browser refuses.
