# Key combinations, mouse chords and shortcuts

Bind actions, not keys, and read a combination as two actions. The kit binds by `KeyboardEvent.code` (the key's place, the same on any layout), ignores auto-repeat, lets every key go when the window loses focus or the page is hidden, and leaves keys alone while the player types in a field:

```js
const input = createInputActions({
  guard: { bindings: ['Key:KeyK', 'Mouse:2'] },
  attack: { bindings: ['Key:KeyJ', 'Mouse:0'] },
});
const page = bindBrowserInputActions(input, { pointerTarget: canvas });
if (input.pressed('guard') && input.justPressed('attack')) riposte();
settingsRow.textContent = describeInputBinding(input.bindingsOf('guard')[0]);   // "K"
```

In `play`, `game.keys.down('shift')` and `game.keys.pressed('space')` read the same way.

**Mouse chords.** A browser sends `pointerdown` for the first button pressed and `pointerup` for the last released. A button pressed or released in between arrives as `pointermove`, with `event.button` set and a new `event.buttons` mask. SnowTemple's right-button guard stuck or never started until it reconciled the mask. At engine ec17a5a22 the kit's binding listens to `pointerdown` and `pointerup` only, so add this when two mouse buttons are bound:

```js
const MASK = [1, 4, 2, 8, 16];   // event.button -> bit of event.buttons (middle is 4, right is 2)
window.addEventListener('pointermove', (event) => {
  if (event.pointerType !== 'mouse' || event.button < 0) return;
  const binding = 'Mouse:' + event.button;
  if (event.buttons & MASK[event.button]) { if (event.target === canvas) input.press(binding); }
  else input.release(binding);
}, true);
```

Rules:

- Listen on the window in the capture phase: a button released over a dialog or toolbar never reaches the canvas.
- Do not bind Ctrl or Cmd with W, T, N, Q, L or Tab; the browser keeps them. Alt alone moves focus to the menu on Windows. On macOS other keys get no `keyup` while Cmd is held, so let everything go when Cmd comes up.
- Many keyboards cannot report some combinations of three or more keys. Need at most two keys plus a direction, and allow rebinding with `input.rebind`.
- A dialog that answers keys (SnowTemple's 1, 2, 3 for a lesson) listens in the capture phase and calls `preventDefault()` and `stopPropagation()`, so the game does not act on the same key. It takes focus, keeps Tab inside and gives focus back on close.
- Test chords in Node with synthetic events, as SnowTemple does in `test/input-quality.test.mjs`: press left, press right by `pointermove`, release right over an overlay; only that hold ends.

Pausing and overlays are in `pause-and-overlays`; touch is in `touch-controls`.
