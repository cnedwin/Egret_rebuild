# HUD and controls on a short landscape screen

A phone held sideways is about 320 to 430 CSS pixels tall (FPS measured 873 × 325 on a Samsung). Five fixes in four games were the page, not the engine: JY's battle commands and its portrait dialogue were pushed below the screen, SnowTemple's lesson cards and goal line ran into the corner buttons, and Lantern Shadows' crowd line sat under the touch buttons. `play` and `play3d` keep their own stage in shape; this card is for HUD drawn as page elements over the canvas.

Write one rule for the short landscape case and keep it apart from the desktop rules:

```css
@media (pointer: coarse) and (orientation: landscape) and (max-height: 500px) {
  .masthead { display: none; }                       /* titles go first */
  .screen { display: grid; grid-template-columns: minmax(0, 1fr) clamp(246px, 38vw, 320px); }
  .controls { grid-column: 2; }                      /* commands beside the picture, not under it */
  .viewport { max-width: calc((100svh - 80px) * 1.7778); }   /* the picture yields height, keeping 16:9 */
}
```

Rules the games converged on:

- Move commands to the side in landscape. Height is the scarce dimension; JY put its full battle command set in a right column instead of shrinking it below.
- Size from the visible height: `svh`/`dvh` and `clamp()`, never fixed pixel heights.
- While a panel such as a dialogue is open, hide the controls it makes useless. JY keeps only the key that advances the dialogue, so the text and the picture share the height.
- Keep every command reachable: lay buttons out again (one column, `repeat(n, minmax(44px, 1fr))`) before hiding any. Hide decoration, titles and keyboard hints first.
- Vertical writing and tall cards do not fit: SnowTemple turns its vertical lesson titles horizontal under `max-height: 420px`.
- Give each corner one owner. When touch buttons take the foot of the screen, move text that lived there (Lantern Shadows writes its line higher on a coarse pointer).
- HUD that fades with a cut scene can drop and rebuild its compositor layers, which shows as flicker; SnowTemple keeps `will-change: opacity` on the desktop HUD.

Check it: open the page at 844 × 390 and 667 × 375 in a phone emulation with touch, in every screen (title, play, dialogue, menus, results), and look for clipped or overlapping controls. That is a layout check, not a phone run; record a real device separately (see `verify-end-to-end`). Safe areas and pixel ratio are in `mobile-viewport`; readable labels in `touch-labels`.
