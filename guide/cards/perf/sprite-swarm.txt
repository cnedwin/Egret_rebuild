# A swarm of moving sprites from pooled rectangles, not shared-texture Bitmaps

In headless Chromium with SwiftShader (no GPU), many `Bitmap`s sharing one small texture cost far more than rectangle sprites. At engine `2e53f45` on a 1280 × 720 play, 800 moving Bitmaps of one 48 × 48 texture from `textureFromCanvas` ran at 66.7 ms p50 and 83.4 ms p95; 800 moving `game.rect` sprites at 16.8 ms p50 and 33.4 ms p95. In the 540 × 960 prototype for Nezha Stirs the Sea at engine `b5628eb`, 100 Bitmaps were already 33.3 ms p95 though they drew in about 2 `drawArrays` a frame, and the profile was led by waiting on the GPU and by `getError`.

So a survivors-like with a hundred soldiers on screen cuts every moving thing from `drawRect` and keeps sprites of a kind in a pool:

```js
const pools = new Map();
const take = (key, make) => {
  const list = pools.get(key) ?? [];
  pools.set(key, list);
  const sprite = list.pop() ?? make();   // reuse before drawing a new one
  sprite.visible = true;
  return sprite;
};
const give = (key, sprite) => { sprite.visible = false; pools.get(key).push(sprite); };
const crab = take('crab', () => game.sprite((g) => g.beginFill(0xc8553d).drawRect(-12, -8, 24, 16).endFill(), layers.soldiers));
```

Rules:

- Measure first, with the same count the game reaches at its busiest; the game kept mid-game waves at 16.8 ms p95 and its cap of 140 soldiers at 33.3 ms.
- Draw a sprite's Graphics once when it is made; per frame, change only `x`, `y`, `rotation`, `alpha` and scale.
- Cap what is on the field in the rules, not the view, so the bot and the page agree.
- Rotated rectangles stay cheap; circles and paths that move do not (see moving-shapes).

Still Bitmaps cost the same: 250 tiles cut from one atlas by `sourceRect`, none moving, ran at 50 ms p50 / 66.7 ms p95 on a 1280 × 720 play. Tiles at rest go on a page canvas under the engine's, painted again only when they change (see still-background).

Learnt from Nezha Stirs the Sea (ENGINE-NOTES 3) and Taiwan Sixteen-Tile Mahjong (ENGINE-NOTES 5).
