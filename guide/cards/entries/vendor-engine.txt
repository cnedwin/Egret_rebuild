# Copy a pinned engine build into a game folder

A game that ships as static files carries the part of the engine it loads. Each game in PortedGamesEgret has a `vendor/` folder and a `vendor/SOURCE.md` naming the exact engine commit.

From a built engine checkout (`pnpm setup:dev` builds it):

```
node tools/vendor-game.mjs ../MyGame @egret/engine @egret/engine/world3d @egret/engine/webgl2/world3d @egret/engine/webgpu/world3d
```

It copies only the JavaScript those entries import, the licences, and writes:

| File | Use |
| --- | --- |
| `vendor/importmap.json` | paste into the page's import map |
| `vendor/importmap.js` | or load it with a plain script tag first |
| `vendor/node-register.mjs` | `node --import ./vendor/node-register.mjs --test` runs rules under the page's names |
| `vendor/SOURCE.md` | commit and entries; keep it, it is the pin |
| `vendor/egret.mjs` | the guide for an agent in the game: `guide <question>`, `card <id>`, `list`, `explain <CODE>`; the cards are under `vendor/egret/` |

Rules:

- Name every entry the game imports, including ones loaded with `import()` at run time, or the page fails on the first missing file.
- Refresh the engine as its own commit: re-run the tool, run the game's tests, play it once on each backend it supports, then update the README or STATUS with the new pin. Mixing a refresh with gameplay changes hides which one broke a run.
- After a refresh, re-read the game's known issues. A limit recorded against an older pin may be gone (FPS records eight point lights a frame; the current engine adds tiled lights, see `world3d-lights-shadows`).
- Do not edit files under `vendor/`. A fix belongs in the engine, then a new copy. `--no-agent-kit` leaves the guide out of a copy that must stay small.
- Record the pin in any public result: a frame time or a device check is evidence for that pin only.
