# Keep the rules of a large game apart from its picture

All three large games (FPS, Rally, Jelly Pandas) use the same layout, and each one can play a whole run in Node:

| File | Holds | Imports the engine? |
| --- | --- | --- |
| `src/sim.mjs` | rules: state, `update(dt, input)`, an `events` list | only DOM-free entries (FPS uses `createPhysicsWorld3D`, `createNavMesh3D`) |
| `src/data.mjs` | numbers and text in both languages | no |
| `src/view.mjs` | scene, lights, effects; reads the sim, never writes it | yes |
| `src/hud.mjs`, `src/input.mjs`, `src/audio.mjs` | page interface, input, sound | page only |
| `src/main.mjs` | makes the engine, runs one frame: input, then sim, then view | yes |

Rules:

- The sim takes a seed and a plain input object, and steps by a fixed `dt` (1/60). It has no `Math.random`, no clock and no DOM. The same seed and inputs give the same run.
- The sim reports what happened through `game.events`. The view and audio read the events and clear them once a frame.
- Write Node tests against the sim only (`node --test`). Use a helper that advances N seconds with a scripted input. None of the three sims calls `Math.random`.
- Add a stand-in player (`createBot`) and a headless script that plays whole runs per seed. It prints times and results, which is how numbers are balanced without opening a page.
- In a vendored game, load the engine's DOM-free entries in Node with `node --import ./vendor/node-register.mjs`.

```js
import { runHeadless } from '@egret/engine/kit';

const runs = runHeadless({
  createGame: seed => createGame({ seed }),
  createPlayer: (game, seed) => createBot(game, { seed }).think,
  done: game => game.state === 'won' || game.state === 'dead',
  seeds: 8,
});
```

Why: Jelly Pandas measured its rules alone (1.59 ms a step before a change, 1.28 ms after) with the headless run. That number is not visible when rules and drawing share one frame.
