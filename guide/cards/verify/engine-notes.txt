# Write the engine's faults into ENGINE-NOTES, and ask which are fixed

When the engine cannot do what a game needs, the game works around it with the engine's own parts and writes the fault down, so that the engine can fix it and the game can drop the workaround later. Each fault is a note in `ENGINE-NOTES.md` at the game's root: a heading `### <n>. <title> — open`, what happens, the workaround and where it is, a suggestion, and one header line under the heading:

```html
<!-- engine-note: {"id": "MyGame#3", "status": "open", "topic": "paragraph-without-webassembly", "workaround": ["src/view/plainText.mjs"]} -->
```

- `id` is the game's folder, `#` and the note's number; a number is never used again.
- `status` is `open`, `partly`, `worked-around`, `documented` or `resolved`.
- `topic` names the fault in words joined by dashes, the same in every game that meets it. The engine says what it fixed by topic, so a game it never named still learns.
- `workaround` lists the game's files that hold the workaround.

After every refresh of the engine copy, run `node vendor/egret.mjs notes` in the game's folder. It lists each note the copy has resolved or documented since, what changed, the files to take the workaround out of and the card to read; `--check` exits 1 while one is still marked open. Take the workaround out, check the game again, then change the note's status and its heading.

Rules:

- One fault, one note. Two games that meet one fault give it one topic.
- Name the engine commit the fault was found at, and keep a reproduction (a test or a page) beside the workaround.
- Do not edit `vendor/`: a fix goes to the engine, then into a fresh copy.

Learnt from The Inquest Scrolls, whose notes led to engine changes in #474 to #478 that the game could not see from its own folder.
