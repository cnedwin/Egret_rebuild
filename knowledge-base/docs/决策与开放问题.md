# 决策与开放问题

[English](决策与开放问题.en.md) | 简体中文

本阶段已经明确“为谁服务、支持什么、最终交付什么”。工程技术选择仍处于候选阶段，不能因为进入知识库就视为批准或实现。[需求登记册](../registry/需求.json)保存已确认的项目要求，[决策登记册](../registry/决策.json)保存十六项技术候选及验证门槛。

## 当前的技术候选

D001 至 D016 依次覆盖增量数据提取、UI/3D 执行列表、小型帧图、移动前向基线、图形后端抽象、跨语言桥接、复杂 UI、动画、资源构建、调度与持续性能、诊断、接口版本。D013为构建分离、D014为模块化原生Runtime、D015为可选GPUAI、D016为工程结构/API与代码规范。全部状态为 proposed，负责人及批准日期为空。

接受技术决策需要说明需求、替代方案、性能与正确性证据、失效条件、迁移代价和回退办法。短期采用的原型方案不自动成为长期选型；D005 尚未指定原生 GPU 实现，D006 尚未确定哪些内核需要 Rust、C++ 或 WASM。

## 按依赖推进的开放问题

| 问题 | 需要的依据 | 影响 |
| --- | --- | --- |
| Q001 轻量 3D 的标杆玩法和规模 | 场景、角色、特效、动画、UI 及交互清单 | 帧时间、内存、渲染功能和资源预算 |
| Q002 首批宿主与最低设备 | 创作者需求、发行场景和能力探测 | 后端、兼容下限、发布顺序 |
| Q003 可接受的效率和质量门槛 | 同质量基线、设备与持续测试 | H001 至 H004 的量化验收 |
| Q004 旧工程支持版本与样本 | 自有或授权工程、外部依赖和历史行为基线 | V006 范围、自动化目标与成本 |
| Q005 创作者的修改路径 | 无开发经验者及已有手游经验者的任务测试 | 编辑器、代码可见度、Agent 工具 |
| Q006 团队、预算和交付日期 | 模块范围、验证结果和人员能力 | 里程碑承诺与职责分配 |
| Q007 公开仓库、授权和治理 | 拟公开资产清单、第三方组件许可、维护职责 | 社区代码入口、许可证与发布方式 |
| Q009 原生SDK设备与VM所有权 | App/SDK宿主、实际VM构建、owned/borrowed设备、D3D11接入是否必要 | 原生图形库、FFI与发布范围 |
| Q010 编译反馈与AI增强预算 | 代表工程、计时阶段、模型/SDK硬件条件、同画质成本 | H008及可选D015取舍 |
| Q008 商业模式与服务边界 | 创作者价值、成本、导出和持续维护需求 | 本地/云端分工、收费与生态服务 |

问题用于安排研究，当前不要求一次性回答全部。前四项优先形成可运行验证边界；项目从第一天按开源方式建设；Q007继续核查具体公开资产的授权、仓库信息、许可证与维护治理。

## 提案与替代

用 [RFC 模板](../templates/RFC提案.md)提出方案，用 [ADR 模板](../templates/ADR决策记录.md)记录接受、拒绝或替代的理由。需求变更与技术选择分开记录。替代旧决策时保留旧记录及适用版本，交付项与回归测试随之更新。
