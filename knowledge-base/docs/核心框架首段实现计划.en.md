# First Core Framework Implementation Slice Plan

English | [简体中文](核心框架首段实现计划.md)

Version: 0.1 · October 8, 2026 · Status: execution plan for the first slice; bounded implementation of the three responsibility-based packages is complete. See the [core framework implementation record](核心框架实现记录.en.md) for actual results. The steps below retain the original plan and do not constitute new execution records.

**Goal:** Implement the already specified cancellation, Scope, display tree, events, and Engine lifecycle contracts as a small independent TS core slice that can be compiled, run, and reviewed.

**Architecture:** Follow the delivered candidate engineering/API specifications and create three actual responsibility-based packages—contracts, runtime, and engine—in an independent artifact directory. Do not yet create other candidate packages without responsibilities. Run through a headless host port that can later connect to graphics executors. Write this first core slice independently to the candidate specifications, retaining origins for reference research and third-party development dependencies.

**Tech Stack:** The project pins TypeScript 7.0.2, ESM, and a pnpm workspace. Node 24's built-in test runner is used only for development verification. There are no third-party runtime dependencies. The compiler version determines only the tools for this prototype verification; it does not constitute full acceptance of the D013 toolchain.

**Spec:** [Engineering structure](工程技术架构与项目结构.en.md), [public APIs](公共API设计与命名规范.en.md), and [code standards](代码规范与质量门禁.en.md). This plan covers their lifecycle and display-tree subset, not completion of the full specifications.

## Global Constraints

- The artifact root is `outputs/白鹭引擎核心框架原型`, development version 0.0.0. See the [core framework implementation record](核心框架实现记录.en.md) for execution reports and failure chains. The project is built as open source from day one. This slice is a local prototype; the public repository and release package have not been published. File hashes track current artifacts.
- The core independently implements Egret specifications and standards. Research sources, third-party code, and development tools have separate attribution records; the third-party compiler has an explicit version and license entry.
- The core uses strict types, noUncheckedIndexedAccess, exactOptionalPropertyTypes, and verbatimModuleSyntax. Its lib is only ES2022, types is empty, and implicit DOM/Node types are prohibited in the core. Node tests/tools use mjs.
- TypeScript class names use PascalCase, members camelCase, and main-class files PascalCase. Retain the language of Event, DisplayObject, DisplayObjectContainer, Stage, Engine, and Scope.
- Do not implement GPU, texture loading, Sprite.graphics, layout, coordinate transforms, skeletal animation, native VMs, Agent services, or migration. List these gaps explicitly; placeholder interfaces must not claim support.
- Synchronous scope cleanup is reverse-order and idempotent, and continues after failures. Different scopes cannot take ownership of the same value. Cancellation first enters closing. During closing, registration of a value already in this scope is rejected without early cleanup; a new unowned value is cleaned up and then rejected; a foreign value is rejected without destruction.
- Objects bind to an Engine on Scope registration or first attachment; detach retains the binding. Cross-Engine operations and display-tree cycles must be rejected before changing parent-child relations. Recursive cleanup carries the initiating root owner and does not change because of an unowned intermediate container; foreign subtrees are detached only, with recursion stopped.
- An entire event dispatch fixes all path/phase candidates. Additions take effect on the next dispatch, removed listeners are skipped, and once listeners are removed before invocation. Capture → target capture → target non-capture → bubble; priority is a finite integer, descending, then registration order. stopPropagation preserves the current node; stopImmediate terminates the current node. Active reentrancy with the same Event is rejected; state recovers after exceptions.
- Engine shutdown returns the same Promise, rejects new scopes/attachments, first closes scopes and stage, stops the host, then waits for host.close within a bound. Only successful close resolution confirms that the host has returned the surface. Ordinary or late rejection retains isolation; this slice has no isolation-release/retry interface. Timeout retains resource/presentation ownership until the host successfully completes and does not wrongly destroy borrowed devices. There is no real GPU in this slice, so it does not establish GPU completion fences.
- A surface defaults to one Engine. Reserved exclusive ownership must cover asynchronous startup; failed startup also attempts cleanup. The primary error and cleanup errors retain cause and cleanupErrors.

## Review Focus

1. Cancellation listeners may throw, remove/add listeners, or reenter; notification still occurs once and subsequent cleanup completes. New listeners after cancellation receive no replay.
2. Duplicate registration during Scope closing and late results cannot change the reverse order of registered resources, leak new results, or destroy foreign resources.
3. Mixed owned/unowned subtrees and failed cross-Engine attachment cannot partially change the original tree or owner.
4. Target-listener changes during capture, nested once listeners, propagation stops, or thrown handlers must follow the entire-dispatch snapshot and restore state.
5. Startup races, shutdown reentrancy, stop/close failures, and late completion after deadlines cannot hand an exclusive surface to another instance too early.

## Task 1: Small core lifecycle and display-tree slice

**Files:** package.json, pnpm-workspace.yaml, pnpm-lock.yaml, and tsconfig baseline at the artifact root; CancellationSignal/Disposable/Diagnostic/HostAdapter in packages/contracts/src; EgretError/CancellationController/Scope/ownership/Event/EventDispatcher/DisplayObject/DisplayObjectContainer/Stage in packages/runtime/src; Engine/createEngine/index in packages/engine/src; tests/*.test.mjs, tests/types, examples/headless.mjs; test/build entry points in tools.

**Interfaces:**
- `CancellationSignal`: readonly aborted/reason, addEventListener("abort", listener, {once?}), removeEventListener; listeners have no DOM Event parameter. `CancellationController.abort(reason?: unknown): void`.
- `Disposable.dispose(): void` and `Releasable.release(): void`; Scope.use takes ownership of either, Scope.dispose is synchronous, state is open/closing/closed, and signal implements the minimal protocol above.
- `EventType<T>` and `createEventType<T>(key, {bubbles?, cancelable?})` bind the payload; `new Event(type, payload)`, `on(type, handler, {signal?, capture?, once?, priority?}) -> unsubscribe`, and `dispatchEvent(event) -> boolean` indicates that the default action was not prevented.
- `DisplayObjectContainer.addChild/removeChild/getChildAt/setChildIndex`; parent and numChildren are readonly. DisplayObject.dispose terminates; removeChild only detaches. Engine creates and binds Stage.
- `HostAdapter` includes surface identity, optional asynchronous start, optional stop, asynchronous close, and a `setTimeout(callback, delayMs) -> cancelTimer` port, without requiring DOM/Node. `createEngine({host, shutdownTimeoutMs?, onDiagnostic?}) -> Promise<Engine>`. The prototype's default shutdown deadline is 1000 milliseconds, a positive finite integer; it is a failure boundary rather than a performance target.
- `Engine.stage`, `Engine.createScope()`, and `Engine.dispose() -> Promise<void>`. Graphics features, asset services, and features are outside this slice.

- [ ] Write failing behavioral tests for cancellation/Scope/events/display trees/Engine, using manually derived order and real objects, rather than generating expectations from internal data structures. First establish loadable unimplemented methods, proving behavioral assertion failures rather than only missing-module errors.
- [ ] Run failing tests and retain failure output and covered behavior; each new behavior fails before implementation. Code goes into the artifact; failing versions remain in work and do not contaminate the final runtime directory.
- [ ] Implement these interfaces and invariants, splitting necessary internal mechanisms into files by responsibility. Do not add generic frameworks without consumers.
- [ ] Install the pinned development compiler with dependency lifecycle scripts disabled and generate a lockfile. Run a full strict build, core dependency checks, and positive/negative compile-time type examples.
- [ ] Run the complete prototype tests and headless example to demonstrate linkage among shutdown, events, Scope, and the display tree. Record commands, actual versions, results, source hashes, known limitations, and implementation origins.
- [ ] Independently review specification coverage and code quality. Fix significant issues and run corresponding regressions; retain initial-review and correction evidence. Without Git, use file hashes and a source-file review package in place of commit diffs.

## Interpretation boundaries

R017 establishes the start of the first core-framework and logic implementation slice, following earlier specifications and limiting this slice's scope. It does not accept all candidate technical tradeoffs. Complete rendering, resource management, cross-platform performance, and one-click migration retain separate delivery gates. Implementation and independent review are recorded separately. Shared code changes must be integrated into the same version; research gaps can be checked in parallel.
