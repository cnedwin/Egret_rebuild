# 工程事务核心合同

[English](工程事务核心合同.en.md) | 简体中文

0.14.0工程预览的规范合同；包版本0.0.0及协议1.0保持不变。历史独立草案PASS仅证明规范闭环，范围实现测试和测量另见[证据](工程事务核心实现证据.md)；最终预览审阅与交付在本段文档编写检查点仍待完成，后续证据另行记录。原冻结规范身份保留于来源记录（仓库根路径 `source-origin.json`）。

## 权威与边界

内部引擎包 DAG 为 project → contracts；经固定版本、归属/许可证审查、fixture 与 headless import 验证的公开 JSON parser/tokenizer/canonicalization 依赖允许使用，jsonc-parser3.3.1已作为私有scanner/visitor依赖准入，实际范围见实现证据；禁止反向依赖和 project → runtime/engine/toolchain/legacy。无 DOM、Node、GPU、文件、网络、时钟、随机数、模型或 MCP；导入期间不访问宿主、不进行 IO/计时器/随机数/调度、不创建或修改工程 store 权威状态；允许纯模块定义及常量/cache 准备。工程是创作事实，运行实例和构建产物不写回工程。文件只登记摘要/长度，不证明资源存在、授权或摘要真实。所有 domain kind/schema 未经语义检查，必须保留原 data 和显式警告。R008/V006 的完整导入→独立新工程→等价运行→可视化/代码/AI 持续编辑→真实目标发布与更新不缩减；本包不完成 V003、编辑器或迁移验收。

## 精确类型与字段

完整公共 TS 签名见本文附录，采用原提案且仅下述精化；所有对象字段必需，除 Diagnostic 中的 ?。所有信封拒绝未知字段；data/details 是开放 JSON 字典。schema/protocol/history 固定为字符串 1.0；role/source actorKind/operation/phase/code/status 枚举均封闭。Partial<ProjectLimits> 只允许所列键，省略采用默认；undefined、非正安全整数和超出下表硬上限拒绝。类型只读同时具有运行时深不可变保证。

ID 长度 3–128 ASCII，分别匹配 ^p_[A-Za-z0-9][A-Za-z0-9_-]*$、e_、f_、t_ 同型模式。身份区分命名空间，不归一化。revision/baseRevision/targetRevision/byteLength 为 0…9007199254740991 整数，拒绝 -0；通用 JSON 数字允许有限双精度数，-0 规范为 0。空 roots/references/entities/files/retired/scope 合法；edit operations 必须 1…上限。name 为 0…256 UTF-8 字节；kind/expectedKind/dataSchemaVersion/version pin/slot/source actorId/toolId/toolVersion 必须 1…128 字节；intent 为 0…1024 字节；mediaType 为 1…128 字节，词法须 ASCII 可打印且不含空格。上述文本均无 U+0000…001F/U+007F；普通 data 字符串允许这些字符并正确转义。sha256 为 64 个小写十六进制字符。

roots 和 references 保留顺序；roots 唯一、引用 slot 在各 entity 内唯一。所有最终目标存在且 expectedKind/expectedRole 精确一致。允许一般图环，不宣称 domain 树有效。entity kind 与 file role 在身份首次创建后不可改变；dataSchemaVersion 可修改但仍未做语义验证。

## 输入与规范字节

要求严格 JSON token 行为，不要求手写 parser：每层重复 key（包括转义后同名）、孤立代理码点、非 JSON 数字、尾部垃圾拒绝，整数专用字段还检查原始数字 token 的数学值精确安全且整数，避免 9007199254740991.1 经浮点舍入冒充整数。-0 或指数表示负零在整数字段拒绝；非整数通用 data 数字遵循 ECMAScript 双精度解析，非有限结果拒绝。

对象输入仅接受 Object.prototype/null 原型普通对象和 Array.prototype 数组。逐 own descriptor 检查，并直接读已检查 data descriptor 的 value，不访问 getter。普通对象禁止非枚举 own key；数组仅豁免 intrinsic own data length，要求恰有 enumerable data index 0…length-1，允许 frozen flags，禁止空洞、额外键/symbol/accessor。拒绝自定义原型、cycle、函数、undefined、BigInt、Date、Map、typed array；live key/string 亦拒绝孤立代理码点。共享无环 alias 可复制，但遍历期间按展开后的逻辑 JSON 检查 depth/size，包括重复 alias，不能先制造巨型 clone。Proxy 反射异常转 PROJECT_INPUT_INVALID，不承诺 trap 无副作用；恶意输入用 JSON 文本。null-prototype clone 中 __proto__/constructor 保持 inert own data。live number 只能检查已经给出的数值，无法恢复舍入前来源，不能检测原写法 9007199254740991.1 已舍入的事实。文本整数用有界 sign/coefficient/fraction/exponent 分析与 MAX_SAFE 十进制长度/值比较，不建立巨大 10**exponent。

规范序列化：own 对象键按 UTF-16 code unit 升序，不用 localeCompare；直接按排序序列输出，避免 JSON.stringify 的整数键重排。entity/file 数组按 ID 排序；retired 集合与 scope ID 集合排序；roots/references/operations 顺序保留。字符串用 JSON.stringify 的转义规则；非 ASCII 保留原码点、不 NFC；数字用 ECMAScript JSON 表示，负零数据为 0；紧凑、无 BOM/空格/换行。这是本协议规范，不声称 RFC8785 认证。同样字节定义用于 snapshot/history/transaction identity/diff 内容比较；scope 输入排列不影响 retry，operation 顺序影响 retry。

## 路径

相对 POSIX 路径 ≤1024 UTF-8 字节；禁止绝对/drive/UNC/backslash、空/. /..组件（点组件按实际字符判断）、控制符、: * ? " < > |、结尾空格/点、设备名 CON/PRN/AUX/NUL/COM1…9/LPT1…9（忽略大小写及扩展名）。碰撞 key 明确为每个完整 path.normalize("NFC").toLowerCase()，ECMAScript locale-independent Unicode lowercasing；不声称完整 Unicode case folding 或完整操作系统等价，完整导出仍须真实目标适配器复查。路径不静默改写，源路径映射以后由 importer 保留。这里不做 symlink、archive、containment 或 IO 验证。

## 提交与生命周期

1. 有界安全拷贝并校验 command/schema/ID/canonical bytes。有效 known transactionId 优先核查 retry identity；同规范命令返回 replayed，当前 head+原 receipt，不改变任何状态；有效但不同命令返回 PROJECT_TRANSACTION_ID_REUSED；语法/结构无效的 altered command 先返回对应 schema 错误。失败命令不占用 transactionId，可修正后重试。有效 retry 在 journal 满额/revision 最大时仍成功。
2. 未知 ID 检查 projectId、baseRevision 严格 CAS，当前 revision 最大拒绝 PROJECT_LIMIT_EXCEEDED；无自动 rebase。验证 scope 集合唯一/正确 namespace，直接 entity/file 操作必须声明 ID；metadata/roots 操作必须有对应 true。scope 可包含未操作 ID，不必声明间接被引用的目标。restore 无 scope，显式表示全工程恢复。
3. entity/file 每个 ID 最多一个操作；metadata/roots 各最多一次。remove 缺失拒绝；put 完整替换或新建；新建不能用 retired ID；现存 kind/role 不变。无级联删除。前向引用依最终候选检查。
4. 全部操作、最终引用、生命周期集合、规范字节、journal 容量均成功后，单个同步发布点更新 head+追加不可变 command+receipt/retry index。任何预期拒绝保留 head 对象、旧快照和 exportHistory 字节。不调用用户回调；运行环境 OOM 不是可恢复产品错误承诺。每次新 commit 即使内容相同也 +1；diff 不含 revision/退休生命周期，ID 数组升序，changed 用完整记录规范内容比较，metadata 比较 name+versions，roots 比较顺序。
5. 删除将 ID 转 retired。restore 可从 retained revision 恢复相同逻辑实体/文件身份；不会将该 ID 分配给新引入的身份，也不承诺 JavaScript 引用相等。restore 后 retired = 当前 active∪retired∪历史 target 的 retired 减 restored active；当前集合已包含全部已知身份，公式冗余项用于审计。恢复的 authored 内容（name/versions/roots/entities/files）精确相同；revision 和 retired 集合不回滚。恢复后再编辑仍保持 kind/role 的原身份含义，不能借 restore 改类别。被新版本引入而恢复目标未含的 ID 退休。
6. createProjectStore 可接受非零 baseline revision；earliestRevision=baseline.revision；只承诺该 checkpoint 后的 history。standalone snapshot 保留退休身份，但不含过去 transaction dedup/restore 权限；用它建新 store 是显式新历史边界，不能宣称持久 exact retry。完整保存/重开必须 exportHistory/openProjectHistory。
7. journal 是 baseline+成功 command 的唯一权威，无 rejected/replayed entry、无另存 head/receipt、无自动 prune。open 必须整本重放验证，transactionId 唯一，CAS 连续，restore target 在 baseline…此前 head 内；journal 中旧 base 的重复 retry 条目拒绝 PROJECT_HISTORY_INVALID，不能通过 commit 的 replay 分支混过。有效 replay 推导出的 receipts/retry index 与原运行一致。无摘要签名时，语法及语义仍合法的恶意篡改不可检测，不宣称防篡改。
8. 保存 baseline+commands+current head+receipt/retry index 和小型派生 prefix-cost 数组 P，不缓存每个完整快照。成本唯一权威见下一节；实际重建用显式 stack/等价迭代遍历，展开前预算检查，用完丢弃 working state，避免深 JS 调用栈。结构共享/memo 不改变 admission；实际内存观察记录于实现证据，真实瞬时峰值仍未确立。

## 默认与硬上限

所有 existing ProjectLimits 字段默认沿用，硬上限等于默认的 16 倍，maxJsonDepth 硬上限 64；新增 maxReplayWorkUnits 默认 10000000、硬上限 160000000。这是初版保护配置，不是完整工程限制或性能保证；扩大需显式调用者配置和测量。

| 字段 | 默认 |
|---|---:|
| maxSnapshotUtf8Bytes |16777216|
| maxHistoryUtf8Bytes |67108864|
| maxTransactionUtf8Bytes |4194304|
| maxJsonDepth |32（root container 为 1）|
| maxStringUtf8Bytes |65536（含对象 key）|
| maxEntities |100000（active+retired）|
| maxFiles |50000（active+retired）|
| maxReferencesPerEntity |4096|
| maxOperationsPerTransaction |10000|
| maxTransactions |1024|
| maxReplayWorkUnits（新增） |10000000|

深度按每个逻辑 snapshot/transaction 独立 root container=1，history.baseline 与每条 command 边界重置；固定 history wrapper 只接受指定 object+transactions array 形状，不计入 payload 深度。公开 snapshot/transaction 文本 parser 的 raw byte bound 包含全部输入 whitespace。open 的整个 raw 文本受 history bound，内嵌 baseline/command raw span 从 { 至匹配 }（不含外围 whitespace）受局部 bound；局部 canonical bound 同时成立。live 输入只有 canonical bound。所有 payload key/value 字符串受 string bound，UTF-8 计数前检查 Unicode。诊断最多首个 error 加 KIND_UNCHECKED/CONTENT_UNVERIFIED 各一个 count summary；message≤1024 UTF-8、details canonical≤4096、jsonPointer≤1024 UTF-8，超长 pointer 截至最长完整 segment 的安全 ancestor，details.pointerTruncated=true。诊断固定 bounds 独立于用户 document/string/depth limits。details 不含原 data/source，只容计数/安全短字段。顺序为信封声明、规范 ID 集合、authored 数组；错误优先 raw size→input/schema→retry→CAS→scope/operations→final references→limits/history。retry diagnostics 描述当前 head，receipt 保持原提交。

## 评审风险

恢复身份不等于复用；checkpoint 不带 dedup 权威；自定义 canonical 排序不能交给 JSON.stringify；数字 token 舍入必须单测；Proxy trap/运行时 OOM 不可承诺隔离；路径 NFC+lowercase 不能代表全平台碰撞；restore 重建预算和实际 memory 需要实现证据；合法 journal 修改无法被结构验证识别。新增 replay bound 的精确计数必须在实现前冻结为可手算 fixtures，不能以实现内部重构改变已接受文档结果。

## 身份、成本与错误的唯一规范

entity/file 活跃 ID 各唯一；对应 retired 集合各唯一且与 active 不相交；roots 必须解析为现存 entity。scope ID 与 roots/slot 的唯一性同样检查。expectedKind 与 kind 同样 1…128 UTF-8、无控制符；baseRevision/targetRevision 与 revision 使用同一安全整数规则。

nodeCount 为每 scalar/container 1 加每 object own key 1，array index 不另计。baseline index=0，command index 从1起；targetIndex=targetRevision-baseline.revision。

- P[0]=nodeCount(baseline)。
- P[j]=P[j-1]+nodeCount(command[j])+nodeCount(snapshot[j])+(restore ? P[targetIndex] : 0)。
- 安全饱和至 maxReplayWorkUnits+1；新 commit 检查 projected P[j]，known retry 不增成本；此保守协议可拒绝实际实现较廉价的短 journal。

createProjectStore 必须检查 baseline 所有局部 bounds、canonical empty history envelope 的 history bytes 与 P[0]，才能返回。每次 commit 检查追加后全部 history bytes 和 P[j]。每个成功创建/提交/export（包括空 journal）在相同 limits 下均必须可 open。P 为小型派生数组，非持久权威；成本计算单次迭代，不递归计算 oracle；实际恢复用显式 stack/迭代展开，memo 不改变 P。没有 former-kind/role tombstone 元数据需求。

| 条件 | 规范 code |
|---|---|
| malformed ID | PROJECT_ID_INVALID |
| duplicate active/retired/root/slot/scope | PROJECT_ID_DUPLICATE（details.reason 区分集合） |
| active-retired overlap、put retired、改变 kind/role | PROJECT_ID_REUSED |
| 有效已知 transaction 内容改变 | PROJECT_TRANSACTION_ID_REUSED |
| project 不匹配、remove absent、无效 limits | PROJECT_INPUT_INVALID |
| missing root/reference target | PROJECT_REFERENCE_MISSING |
| expected kind/role 不一致 | PROJECT_REFERENCE_TYPE_MISMATCH |
| CAS 不一致 | PROJECT_REVISION_CONFLICT |
| scope 越界 / 重复操作 target | PROJECT_SCOPE_VIOLATION / PROJECT_OPERATION_DUPLICATE |
| restore 越出 retained range | PROJECT_RESTORE_UNAVAILABLE |
| 数值/byte/count/work 超限 | PROJECT_LIMIT_EXCEEDED |

open 的 raw syntax/size、history/project/protocol unsupported version 保留直接 parse/limit/PROJECT_FORMAT_UNSUPPORTED code。baseline/entry 的 schema/semantic/lifecycle/admission 失败统一 PROJECT_HISTORY_INVALID，details={causeCode,index}，baseline index=0；不暴露部分 store。非法 integer token 语法→PROJECT_INPUT_INVALID，非整数/负零/不安全值→PROJECT_LIMIT_EXCEEDED。JSON/schema 字段类型、Unicode、未知字段→PROJECT_INPUT_INVALID；未知固定版本→PROJECT_FORMAT_UNSUPPORTED。path lexical/collision→PROJECT_PATH_INVALID/PROJECT_PATH_COLLISION。

declare const projectIdBrand: unique symbol;
declare const entityIdBrand: unique symbol;
declare const fileIdBrand: unique symbol;
declare const transactionIdBrand: unique symbol;

export type ProjectId = string & { readonly [projectIdBrand]: true };
export type EntityId = string & { readonly [entityIdBrand]: true };
export type FileId = string & { readonly [fileIdBrand]: true };
export type TransactionId = string & { readonly [transactionIdBrand]: true };
export type ProjectRevision = number;
export type Sha256 = string;
export type JsonValue = null | boolean | number | string
  | readonly JsonValue[] | { readonly [key: string]: JsonValue };
export type JsonObject = { readonly [key: string]: JsonValue };

export interface ProjectVersionPins {
  readonly engineVersion: string;
  readonly resourceFormatVersion: string;
  readonly toolProtocolVersion: "1.0";
}

export type ProjectReference =
  | { readonly slot: string; readonly target: "entity";
      readonly id: EntityId; readonly expectedKind: string }
  | { readonly slot: string; readonly target: "file";
      readonly id: FileId; readonly expectedRole: ProjectFileRole };

export interface ProjectEntity {
  readonly id: EntityId;
  readonly kind: string;
  readonly dataSchemaVersion: string;
  readonly name: string;
  readonly data: JsonObject;
  readonly references: readonly ProjectReference[];
}

export type ProjectFileRole =
  "source" | "asset" | "configuration" | "legacy-original" | "other";

export interface ProjectFile {
  readonly id: FileId;
  readonly path: string;
  readonly role: ProjectFileRole;
  readonly mediaType: string;
  readonly sha256: Sha256;
  readonly byteLength: number;

export interface ProjectSnapshot {
  readonly projectSchemaVersion: "1.0";
  readonly projectId: ProjectId;
  readonly revision: ProjectRevision;
  readonly name: string;
  readonly versions: ProjectVersionPins;
  readonly roots: readonly EntityId[];
  readonly entities: readonly ProjectEntity[];

  readonly retiredFileIds: readonly FileId[];
}

export interface ProjectTransactionSource {
  readonly actorId: string;
  readonly actorKind: "creator" | "agent" | "legacy-converter" | "tool";
  readonly toolId: string;

  readonly intent: string;
}

  readonly entityIds: readonly EntityId[];
  readonly fileIds: readonly FileId[];

  readonly roots: boolean;

  readonly transactionId: TransactionId;

  readonly source: ProjectTransactionSource;
  readonly targetRevision: ProjectRevision;
}

export type ProjectTransaction = ProjectEditTransaction | ProjectRestoreTransaction;

export interface ProjectDiff {
  readonly addedEntityIds: readonly EntityId[];
  readonly changedEntityIds: readonly EntityId[];
  readonly removedEntityIds: readonly EntityId[];
  readonly addedFileIds: readonly FileId[];
  readonly changedFileIds: readonly FileId[];
  readonly removedFileIds: readonly FileId[];
  readonly metadataChanged: boolean;
  readonly rootsChanged: boolean;

export type ProjectDiagnosticCode =
  | "PROJECT_INPUT_INVALID" | "PROJECT_FORMAT_UNSUPPORTED"
  | "PROJECT_LIMIT_EXCEEDED" | "PROJECT_ID_INVALID"
  | "PROJECT_ID_DUPLICATE" | "PROJECT_ID_REUSED"
  | "PROJECT_REFERENCE_MISSING" | "PROJECT_REFERENCE_TYPE_MISMATCH"

  | "PROJECT_SCOPE_VIOLATION" | "PROJECT_OPERATION_DUPLICATE"

## 被选中非法输入的顺序

普通闭合对象在当前被选中对象指针拒绝未知自有字段，然后遍历声明子节点；开放data字典保留合法任意JSON。Union公共前缀先于依赖分支的闭合/discriminator错误。记录身份遍历中，自有字符串ID直接按UTF-16排序，包括非法字符串；同键按编写索引，缺失/非字符串/非对象候选随后保持编写顺序。退役/scope集合采用相同规则，roots/references/operations保持编写顺序。诊断和精确数字词元查找始终保留原输入索引及转义后的嵌入前缀。

被选中形状/标量检查之后，集合完整性按生成的快照声明顺序执行：roots唯一性、实体ID唯一性先于slots、文件ID唯一性先于路径、各退役集合重复先于活跃重叠，随后最终引用与数量。历史将生成节点与基线及各指令立即顺序准入交错执行；较早错误CAS先于较后不支持协议。固定外壳分类不代表schema接受，也不预查较后头部字段。整数字段非整性/负零/不安全值返回LIMIT_EXCEEDED；普通data非有限值在被选中节点返回INPUT_INVALID。实值Number不能恢复舍入前来源。
