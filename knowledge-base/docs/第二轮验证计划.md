## 问题、方法与边界

| 研究问题 | 实验方法与反证 | 可得结论与限制 |
| --- | --- | --- |
| 图形镜像恢复后如何保持跨界必达事件 | 独立事件流、outbox、水位、ACK丢失/重发/乱序/背压；以仅恢复图形状态的旧策略作为漏事件反例 | 内存模型的接受、顺序、去重与恢复合同；没有持久事务便不保证进程崩溃后的恰好一次副作用 |
| 合批是否真正保留共享状态 | 全量逐命令参考与独立按批header执行比较；故意忽略clip/pipeline形成像素反例；再做实际WebGL几何合批读回 | 本轮有限材质、矩形和混合模式的正确性；不替代任意mask、filter、骨骼附件或所有后端 |
| 嵌套失效能否截断且保持正确 | 固定/内容适应尺寸、插入删除、重挂父节点、隐藏、祖先尺寸与世界坐标；对照独立源树全量计算及命中 | 明示布局语义和操作量；文本测量fixture不代表真实塑形/IME；工作量不是速度提升 |
| CPU数据和GPU驻留如何独立恢复 | 每次获取独立lease、decode/upload分开、设备代次、迟到任务、fence、失败及异步重传；旧owner Set策略作为反例 | 确定性状态机合同；调度的异步完成仍是模拟，不证明GPU驱动、线程竞争或性能 |
| 局部合同能否进入同一图形实验 | 程序生成3D网格，叠加多层UI、矩形裁剪、简单两段骨骼与序列帧；指定帧与像素检查 | 同一本地WebGL2实验的有限表现；不是完整角色/资产导入、复杂动画、编辑器或目标宿主验收 |

## 执行与质量门

1. 保留0.2.0完整知识库及原始证据快照，按旧核验摘要逐项确认。
2. 三个独立状态/布局实验并行，批次与图形实验分别维护实现和结果；集成时核对共用合同与版本。
3. 每组先记录能说明错误策略的失败反例，再执行修正模型；结果记录环境、输入、容差、实际计数、源码SHA256与未覆盖项。
4. 独立审阅者检查反例是否真能发现错误、参考是否独立、恢复是否丢语义、结论是否越界。发现直接破坏合同的问题先修正复验。
5. 集成后重新执行局部实验，核对结果与源码摘要；统一回写三份设计文档、来源和交付登记册，再核验知识库结构。

首批设备与宿主选择仍待确定；本地研究可推进，手机功耗、完整引擎性能和跨小游戏兼容不能由本轮替代。旧工程一键迁移R008继续参与接口与行为设计，完整交付依赖保持不变。
