# Resource core contract: CPU acquisition and leases

English | [简体中文](资源核心合同.md)

Date: 2026-10-08. Status: specification for the next experimental implementation slice, not acceptance of a rendering backend or a complete resource product.

This slice implements `engine.assets`, following the asynchronous acquisition, typed references, and Scope ownership in the [public API contract](公共API设计与命名规范.en.md). It manages CPU values returned by providers; it does not implement download protocols, image/font/model decoding, GPU upload, budgets/LRU, persistent manifests, or device recovery. Providers own their network/decoding work and response to cancellation. They must not hand in-flight GPU handles to this slice for synchronous cleanup.

## Public interfaces

- `createAssetType<T>(name: string, is: (value: unknown) => value is T): AssetType<T>` creates an immutable descriptor matched by object identity; descriptors with the same name do not automatically become aliases. The generic type is invariant.
- `createAssetRef<T>(type: AssetType<T>, id: string): AssetRef<T>` creates an immutable resource reference. A nonempty ID is a stable identity within the manager; the same ID cannot be reused with a different type descriptor. Both descriptors and references must come from the factories; forged structural objects are rejected at runtime.
- `engine.assets.register<T>(type: AssetType<T>, provider: AssetProvider<T>): void` registers each type once. A provider supplies `load(ref, {signal, resourceGeneration, taskId}): Promise<T>` and synchronous `dispose(value): void`; callbacks are fixed at registration. Each successfully returned value has independent cleanup ownership. If a provider shares an underlying object, it must wrap that sharing with its own reference counting rather than return the same destructible object to different tasks.
- `engine.assets.acquire<T>(ref: AssetRef<T>, options?: {signal?: CancellationSignal}): Promise<AssetLease<T>>` infers the type from the reference and validates the returned value at runtime with that type's `is` guard. Closure, missing providers, forged references, type conflicts, and cancellation are all returned as rejected Promises.
- `AssetLease<T>` provides readonly `value`, `leaseId`, `resourceGeneration`, and idempotent `release()`. Accessing `value` after release or manager closure throws `ASSET_LEASE_RELEASED`. A lease is bound to its producing Engine; a Scope from another Engine cannot adopt it.
- `engine.assets.invalidate(ref): void` retires the current generation of that ID from future acquisitions; existing waiters and delivered leases still refer to the original generation. The next acquisition starts a new generation. An old result or old release must not overwrite/delete the new generation.
- `engine.assets.dispose(): void` synchronously terminates the manager: first close its entry points, then cancel all waits, revoke delivered leases, and clean up acquired values. Engine calls it after Scope and Stage cleanup and before `host.stop`. Repeated manager disposal is idempotent; registration/acquisition after closure is prohibited.

Names and IDs must not be empty or entirely whitespace; valid IDs are not implicitly trimmed or rewritten. `leaseId`/`taskId` are increasing positive integers within the manager, and `resourceGeneration` is an increasing positive integer for the same ID. None may exceed the safe-integer range. They are not persistent project IDs, `deviceEpoch`, or cross-thread ACKs.

## Acquisition, cancellation, and cleanup

The same ID/type/current generation shares one provider call; each acquisition has its own wait and independent lease. Register the current entry and first waiter before invoking the provider so synchronous reentry cannot start a duplicate task. When the last waiter cancels and there are no delivered leases, terminate and remove the current entry before notifying the provider of cancellation. Even if the provider ignores cancellation, a late value is cleaned up and never delivered.

A signal only cancels this acquisition before successful delivery. Delivery and cancellation use first-terminal-wins arbitration; successful delivery removes the listener, and a later abort does not release the lease. A Scope first cancels waits, then releases its registered leases in reverse order. A lease arriving after `await` is still cleaned up by the existing `Scope.use` rules.

There is no completed cache without leases: when the last valid lease is released, terminate the entry and clean up its value; the next acquisition creates a new generation. Callers that require a resident resource must retain a lease. Invalidation only changes future acquisition; it does not forcibly replace an old value that is still borrowed.

A synchronous load throw, asynchronous rejection, or failed/throwing type validation fails that generation; all still-waiting calls receive an `EgretError`, and a later explicit acquisition may retry. A returned value that fails validation is also cleaned up. All internal Promise chains observe rejection; callers must still handle the acquisition Promises they receive.

Commit the entry's terminal state, mapping removal, and cleanup-attempt flag before external callbacks such as cancellation, `provider.dispose`, or diagnostics; mapping deletion must check entry identity. Call `dispose` once for each successful load result. Cleanup exceptions produce diagnostics with `phase: "assets"` and enter `cleanupErrors` while Engine is closing, without retries or interruption of other cleanup. One invocation does not mean cleanup succeeded; synchronous closure of this slice cannot prove that physical work stopped when a provider's Promise never settles.

If a signal adapter fails to register/remove a listener, preserve a diagnostic and roll back the local wait without leaving unreachable demand. A throwing diagnostic observer must not change cleanup progress. Synchronous reentry from type validation, cancellation, and disposers must follow the terminal-state rules above.

## Acceptance and provenance

Use first-party provider boundaries and controllable Promises to verify sharing, individual cancellation, last-waiter cancellation, late success/failure after cancellation, reentry during closure, interleaved generations, failure retry, type validation, and Scope/Engine integration. Also run the core with a genuinely asynchronous provider example. Test output only proves this CPU contract, not GPU fences, performance, package size, power use, or migration success.

Design inputs are this project's [public API contract](公共API设计与命名规范.en.md), [engineering plan](工程规划.en.md), and [asynchronous resource research record](../evidence/async-resource-probe-results.json). The latter's 25 cases are manually interleaved research and are not presented as evidence from this execution. Whole-lifecycle cancellation in the reference chain differs from cancellation of a wait in this acquisition API. Code is independently authored without copying research probes or third-party implementations; existing public research retains its provenance and licensing in the original records.
