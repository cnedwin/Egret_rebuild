## 26 项 CPU 见证检查什么

测试检查新鲜且冻结的输出、稳定共享几何身份、空快照、对副本/代理/外来身份不读字段即拒绝、自有字段/索引顺序、忽略额外机制、读取故障的 cause、空洞/继承字段、早期绘制数量及记录形状拒绝，以及不经迭代的跨 realm 数组捕获。

不对称透视/正交字面量样例检查 `projection × modelView`、反向深度端点和列主序。零/负 w 及穿越近裁剪面的几何得到保留。测试覆盖全部 MVP 槽位、正常 float32 端点、次正规/需舍入数值拒绝、未引用坐标/颜色、binary64 模型系数组合为获准最终 MVP，以及 +0 规范化。运算余量见证覆盖准确上限、下一 float32、绝对乘积抵消规则及有限范围拒绝。预期矩阵和费用由字面量编写，不以产品数学输出充当自身判定依据。

身份记账见证区分重复、不同、空及未引用几何。接近预算上限的测试使用真实工厂几何：最多 64 次绘制、64 个身份、`cpuLogicalBytes` 8388608、`sceneBytes` 4194304、`uniformBytes` 4096。这些是逻辑准入限制，不是物理驻留或分配证明。

受控 JavaScript 分配/复制/冻结/身份/数学/登记失败会恢复内建函数，并检查没有发布帧、准确 cause 和登记来源。CPU 数学包装错误及再次抛出的登记错误保留局部错误边界。这些单次故障控制建立所选分支证据；真实 OOM、永久污染内建函数、操作系统资源安全和原生图形仍是独立义务。
