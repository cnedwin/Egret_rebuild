## 目标、人群与确认边界

让创作者把意图变为可玩、可持续修改、可交付和更新的游戏工程。已确认的项目需求是：首阶段主体是依靠 AI 制作游戏的新创作者，同时重视有手游经验者进入 AI 创作；支持复杂 UI 的 2D 与轻量 3D，渲染引擎和运行时是核心，覆盖 3D 场景、角色、特效及 UI、2D 骨骼、序列帧；旧白鹭完整迁移和持续知识库社区属于正式要求。

以下旅程、工作台功能、优先级细分和标杆均为候选设计建议。规模、画质、最低设备、首批宿主顺序、团队、预算、工期、数字性能门槛及商业模式未确认；浏览器、微信、抖音及其他宿主不据此排定首发。D 类候选技术决定不构成产品批准。需求权威为 R001—R017；R017确认启动局部核心实现与缺口核查，不接受整套候选或升级产品范围；R011要求研究验证与自审，R012要求成熟开源原理优先，R015要求核心独立实现与公共依赖明确归属。底层复用服务作品完整性、效率和可维护性；实现与验收分别由产物和证据确认。

新创作者的任务是表达玩法、理解修改、发现问题并完成发布，需验证其是否能理解对象、资源和恢复入口。手游开发者的任务是把已有代码、资源和制作经验带入 AI 流程，需验证代码编辑、调试、资源复用和批量操作需求；不得用熟练开发者代办结果证明新手成功。

## 底层复用对产品的要求

R012使成熟渲染、文字、资源与动画组件成为优先工程起点。创作者继续使用统一工程和编辑流程，无需选择字形图集、理解GPU状态或处理底层库版本。采用组件后仍须验收中文质量、交互、恢复、可继续编辑、目标发布和旧工程对照；组件已有功能不能直接标为白鹭功能完成。采用边界见[开源参考实现与采用方案](开源参考实现与采用方案.md)。

第三轮真实资产参考链已执行3D动画、共享实例、Canvas原文与缓存、渲染交接及恢复边界。它是研发输入，尚不是创作者可以完成制作的工作台。初始化失败、加载中取消或离开、重复启动都应回到可恢复状态；画面恢复须再验证交互才能报告作品可用。生产首包按2D/3D能力配置生成，不能让纯2D作品默认携带全部3D参考模块。当前边界见[第三轮集成记录](第三轮集成记录.md)与[第三轮审计](第三轮审计.md)。

## 工程与创作者控制

“工程”包含可编辑场景与 UI、对象、资源原件与依赖、业务代码、玩法规则、目标配置和版本记录；试玩结果与发布包是工程产生的产物。导出工程后仍能继续制作，不能只留下不可维护的包。

对象与资源有稳定身份：角色改名、按钮移动、资源换路径后，引用、修改记录和问题定位仍指向同一对象。用户按名称、画面和用途选择对象，无需理解内部标识。复制对象形成新身份，并明确引用关系；删除时显示受影响的玩法与资源。

自然语言、可视化与代码编辑操作同一工程。业务代码和源资源可查看、修改、保留及导出；AI 改动不得覆盖用户后续手改。试玩中的临时状态须由用户选择才能写回工程。每次任务展示目标、范围、改动和验收结果；AI 不得为消除报错静默删除玩法、事件、资源、存档或平台功能，降级必须说明影响并获得用户选择。失败停在可恢复版本，取消、重试和撤销不会破坏原有作品。

第二轮研究细化了事件恢复、嵌套布局和异步资源合同，以下据此补充候选用户行为与验收，未新增已实现能力。布局研究使用外部文字尺寸夹具，资源研究手动交错任务，事件研究只涉及存活会话中的内存消费；混合图形程序使用程序网格、简单双段骨骼和图集。真实文字塑形、真实异步 GPU 上传、完整编辑器及迁移仍未完成。实际结果、失败历史和未覆盖项以[第二轮验证记录](第二轮验证记录.md)与[第二轮审计](第二轮审计.md)为准。

## 新作品旅程与核心验收

建议工作台围绕作品、编辑画面、资源、试玩、任务记录和发布入口组织。流程反馈用“正在处理什么、哪里受阻、已有成果、下一步选择”解释，不把模型协议或渲染实现要求塞给创作者。

| 步骤与能力 | 具体验收场景 | 失败状态与用户反馈 |
| --- | --- | --- |
| 首次创作（R001、R006；V003、V005） | 用户描述角色展示与换装玩法，确认玩法摘要，生成可编辑作品；首次试玩能切换装扮并保留选择状态。记录从提交意图至首次可玩的时间及人工帮助。 | 意图矛盾或生成失败时展示需澄清内容、已有可用部分和重试入口，不能声称作品完成。 |
| 混合表现（R002—R005；V002、V004） | 同一画面有 3D 角色、场景特效、复杂 UI、骨骼与序列帧；遮挡、输入、文本、层级和动画事件按约定呈现，连续操作与恢复后仍正确。 | 缺失动画、点击错位或预算超限须定位画面对象、复现步骤和受影响体验；降低画质等选择明示效果差异。 |
| 布局与点击一致（R002、R004；V002、V005） | 文案变长使列表行变高，插入/删除条目、隐藏/恢复或把面板移到另一容器后，相关祖先、兄弟及点击区域同步更新；按画面点击仍选中正确业务对象，裁剪外对象不接收该点击。 | 布局依赖矛盾或修改被拒绝时保留原布局与点击状态，指出相关面板、文案或依赖；不靠丢弃更新掩盖错位。真实字体、输入法和虚拟列表复用另行验收。 |
| 局部多轮修改（R001、R006；V003、V005） | 用户先改按钮布局，再换角色，再手改价格逻辑，最后要求 AI 改特效；应用前可看局部预览、改动差异和影响范围，应用后回放既有换装、价格与状态流程。撤销后恢复对应可用版本，再继续编辑。 | 目标不明确先指出候选；工程已被手改时展示冲突及可选处理，不套用过期结果。回归失败定位本轮改动，允许恢复原版本或继续修复；不能整工程重写、丢失手改或只报“已优化”。 |
| 资源导入与换装（R004、R007；V004） | 导入模型、贴图、字体、骨骼、序列帧与音频，看到预览、依赖和使用位置；换装时先准备并验证新素材可显示，再切换，保留角色选择与交互。取消、再次换装或退出后，迟到的旧任务不覆盖新选择；共享素材仍被其他对象使用时不提前移除。 | 准备或显示失败说明具体素材、阶段与原因，保留原件和仍可用的旧装扮，允许补齐、替换或取消。内存不足导致无法同时保留时，先说明限制与可恢复路径，不能静默显示空白或报切换成功。 |
| 试玩与定位（R003、R005、R006；V002、V003、V005） | 用户复现按钮失效或动画卡顿，能从画面定位对象、关联规则和资源，回看同一输入下的结果；性能提示对应真实测量。 | 不能复现时标明条件差异和证据不足；运行中断显示最后可靠状态、诊断和可恢复入口，不只显示聊天报错。 |
| 中断与恢复（R003—R005、R007；V002、V004、V005） | 试玩中画面设备中断时明确显示“素材准备中”“画面恢复中”“可继续操作”；相关资源重新可显示且关键交互复验后才报告作品可用。恢复后装扮、布局与需保持的玩法状态正确，已完成音效/奖励等不因画面重建再执行；未完成操作可定位。 | 不把“设备可用”报成“作品恢复”。素材准备、显示资源重建或交互复验失败分别列出受影响对象和重试/退出选择；不能误用迟到结果。外部服务、进程重启或不可确认操作须显示待核对状态，不承诺自动补做或绝不重复。 |
| 修复与撤销（R006；V003、V005） | AI 在用户可见的时间/费用限制内修复缺失引用，复验原玩法；用户撤销后工程、资源引用和玩法恢复，随后可继续编辑。 | 达到限制、取消或语义不确定时停止并列出已改/未改和剩余问题，允许接管、撤销或另选方案，失败重试计入成本。 |
| 目标发布与更新（R007；V004、V005） | 用户选定已声明支持的宿主，完成能力检查、打包和真实设备试玩；改玩法后发布新版本，验证启动、前后台、资源更新及需保持的存档。 | 不支持的能力在打包前解释；构建、宿主服务或渠道检查失败分别定位，保留上一可用版本；发布包生成不等于审核或上线成功。 |

## 旧项目旅程与正式交付

R008/V006 与上述创作闭环共用验收边界，目标是尽量少人工干预并移植后完美运行。只可在公布的支持矩阵和完整对照通过后报告迁移成功。矩阵外、未验证或部分通过项必须分别显示；旧 Egret3D、自定义分支和第三方 SDK 不能自动视为支持。

| 步骤 | 具体验收场景 | 失败状态与用户反馈 |
| --- | --- | --- |
| 导入与盘点 | 用户选择原工程，一键建立只读快照；盘点引擎版本、UI、资源、动画、业务代码、扩展和平台依赖，取得旧运行基线，生成范围报告。 | 原工程不可运行、版本未知或依赖缺失时列出阻塞和处理路径；原文件完整保留，不能编造旧行为。 |
| 转换与修复 | 产生独立新工程，显示转换进度、对象对应、差异及 AI 修复记录；按公开的次数、时间和费用限制处理剩余问题。 | 不确定规则、预算用尽或不支持项进入明确待处理状态；不得删掉旧玩法让构建通过，允许接管、回滚和重跑。 |
| 旧新对照 | 同一输入比较关键玩法、事件顺序与次数、计时/暂停恢复、动画事件、布局命中、资源切换/释放、状态存档、宿主与性能。加入画面中断、资源准备失败和迟到完成，核对旧新语义及恢复后的副作用。 | 差异报告定位原/新对象、业务代码或资源，列出复现输入、时间条件、预期/实际顺序与次数、映射规则及影响；重复音效/奖励、漏事件或计时突跳均为未通过项。启动成功只算阶段完成，外部服务替身通过不能替代真实宿主验证。 |
| 继续编辑与发布 | 在迁移结果中修改角色、UI 与业务代码，完成试玩、撤销、目标构建及一次更新；交付工程、构建、日志、差异、未解决项和验收报告。 | 无法继续编辑、缺失源资源、撤销失效或发布受阻均不算完整交付；原工程可恢复，通过样本纳入升级回归。 |

## 非功能验收与测量口径

数值目标必须由 V001 的授权样本、同功能同画质、宿主设备和网络条件建立基线，再共同确定；以下产品指标目前均未实测，局部合同与像素检查不算这些指标的基线。应同时报告分布、失败和样本范围，不能只挑成功案例或平均值。创作任务耗时与玩家首次交互分别统计。

| 指标 | 候选定义与验收方式 |
| --- | --- |
| firstInteractive | 从冷启动请求到约定玩家输入得到有效响应；拆分加载、初始化和等待，固定缓存/网络条件，并检查热启动与恢复。 |
| tailFrame | 持续试玩的帧时间尾部与卡顿分布，记录采样窗口、输入和场景；同时检查输入响应，不以平均 FPS 代替。 |
| memory | 运行峰值、稳定占用及反复进入退出/替换资源后的增长；区分设备条件，检查失败和恢复后的残留。 |
| AI 总成本 | 完成整项创作或迁移的模型费用、调用、缓存、重试与失败修复、工具时间和用户等待；同时报告每个成功任务的总成本。 |
| manualIntervention | 人工接管次数、原因、角色、有效工作时间与等待；必要账号/测试配置另记，专家代修不能隐藏为自动成功。 |
| 体验与可靠性 | 首次可玩时间、需求满足、无关玩法保持、撤销恢复、发布更新成功、底包与资源加载、持续功耗/发热；每项注明基线与测试条件。 |
| 恢复与语义保持 | 记录资源准备完成、当前显示资源上传完成、作品可交互三个时点，以及恢复前后关键状态、事件次数和未完成操作；耗时目标待真实样本确定，不能凭画面出现宣告恢复完整。 |

迁移漏斗报告本批全部纳入支持范围工程的导入、转换、构建、运行、完整对照及继续编辑结果，同时报告总体拒绝率与原因。“零人工成功”要求无人修改代码、配置、资源或专家代修，且完整验收通过。

## 首轮标杆与待验证问题

首轮主标杆仍为候选：复杂 UI 与 3D 角色展示/换装，包含多层面板、滚动列表、文本、骨骼及序列帧特效，用于交叉验证对象选择、资源替换、事件、连续修改和预算；补充小型 3D 动作场景验证场景移动、输入、角色动画与特效，动作规则和规模待定义。迁移另选有授权、可运行的旧工程，覆盖 UI、动画、业务状态和平台接口，不以新样例替代旧项目。

1. 新创作者首先要制作哪类玩法，能否独立完成意图表达到发布？手游开发者在哪些步骤需要不同入口？
2. 首批宿主与设备是什么，哪些服务必须真实验证，离线试玩是否足够满足首轮目的？
3. 主标杆的 UI 复杂度、画质、资产规格及轻量 3D 边界如何固定，如何避免缩减功能换取好成绩？
4. 用户如何选择局部对象，改名、移动、复制后是否仍理解范围与影响？
5. 连续修改中哪些玩法必须保持，预览、冲突、撤销和回归结果是否足以让用户发现并决定有意改变的规则？
6. 新手能否理解资源准备、画面恢复和作品可用的区别；待核对操作何时必须人工接管，是否有隐藏专家劳动？
7. 哪些代码编辑、资源工具和工作习惯是手游开发者的必要入口，能否与 AI 共用工程？
8. 旧工程版本、扩展、动画与 SDK 怎样取样，事件、时钟、资源恢复如何定义等价；旧基线无法取得时如何处理？
9. 同样任务的总成本、等待、人工介入与实际设备表现能否支持效率差异化，失败成本如何影响结论？
10. 社区能否依据公开文档复现实验、提出改动并理解支持边界，哪些私有资产与授权限制妨碍贡献？

V001 研究部分为 in_progress，用于整理样本与基线；V002—V006 分别承担运行、工程接口、资源、创作发布与迁移验收，V002有局部自主核心，其他产品实现未开始；V007 持续维护需求、提案、证据和变更，V008 是本稿与白皮书、工程规划的候选设计包。D001—D016 全部 proposed，H001—H008 全部 untested；各轮实际检查与修复复验保存在对应验证记录，本稿不复述实验通过数。R009 的社区入口应允许贡献者提交可复现问题，反馈接收、需补证据或处理结论；无法复现不伪报已解决。R010 的竞品研究用于比较同任务的代价与选择理由，不据文档宣传认定产品领先。范围变化先回写需求与证据，经确认后更新本稿。

## 编译调试与原生扩展

R013要求降低创作修改等待，预览、类型诊断和发布状态分别可见；错误能回到原始代码、场景与Agent事务，资源变更不重复构建无关内容。历史30秒以内不直接作为新产品数字门槛。R014要求保留原生App/SDK与跨平台扩展空间，Steam/PC及GPUAI尚未成为首发承诺。浏览器2D不带原生VM；原生2D仍需选定VM或已验收宿主VM。创作者无需选择底层Rust/C++或图形库，产品显示可用能力、真实错误与必要效果支持情况。详见[选型设计](图形后端编译与原生Runtime选型.md)。
