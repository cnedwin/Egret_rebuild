# B1 场景主机契约

[English](b1-host-contract.en.md) · [验证证据](b1-host-evidence.zh-CN.md)

白鹭自主实现的 B1 主机把有明确预算的 3D 网格通道与既有 2D 矩形、图片通道接到同一生命周期和提交管理器上。这是内部工程阶段能力。`createB1WebGPUHost`、`renderSceneFrame`、`getSceneStatus` 尚未由包入口集中导出；当前源码签名不代表稳定公开 API。

## 准入与所有权

`packages/engine/web/b1.ts` 接受既有 `WebGPUHostOptions`。B1 模式由私有闭包选择，选项不能安装加载器、协议或渲染回调。`packages/engine/web/WebGPUHost.ts` 在 B1 启动时立即观察字面调用 `import('./b1.js')` 的结果。普通 WebGPU 主机及其原型链没有场景方法。显式导入 B1 入口时，其依赖可能已经求值并进入缓存。

冻结的内置协议包含一个版本字段和七个固定函数引用。协议与场景准入先检查实际模块持有的真实身份，再读取场景字段；冻结副本和代理对象不能取得该身份。这一机制以绑定的模块和依赖为前提，不认证替换加载器或修改后的源码。

每帧对每个不同几何对象的真实身份只打包一次。重复绘制共享其顶点、索引上传；内容相同但身份不同的对象分别计费。每次绘制，包括空绘制，都分配 64 字节列主序 MVP 矩阵常量。当前网格着色器使用位置和编码 RGB，并执行 MVP 变换；光照、材质和蒙皮不在此阶段范围内。

## 帧与资源契约

一个目标视图、一个编码器先记录场景通道：颜色清除并保存，深度格式为 `depth32float`，反向深度清除值为 `0`、比较方式为 `greater`、启用深度写入。随后 UI 通道加载并保存颜色，不附加深度，保持矩形和图片的画家顺序。可选回读在两个通道结束后进行，每帧只完成、提交一次。叠加 UI 必须满足 `clearAlpha === 1`。

完整准入先于场景打包、GPU 修改以及序号、账本提交。场景与 UI 上传共同受配置额度约束。固定 B1 上限如下：

| 项目 | 每帧 | 尚未退休的提交合计 |
| --- | ---: | ---: |
| 绘制数 / 不同几何身份数 | 64 / 64 | — |
| CPU 逻辑几何字节 | 8,388,608 | — |
| 打包后的场景字节 | 4,194,304 | 8,388,608 |
| 场景矩阵常量字节 | 4,096 | 8,192 |
| 逻辑深度字节（`4 × 宽 × 高`） | 16,777,216 | 33,554,432 |

既有配置默认仍为每帧上传 33,554,432 字节、待退休上传合计 67,108,864 字节、最多两个待退休帧。回读按对齐后的暂存区与输出区**合计**计费：1×1 回读占用 260 字节，因此 259 字节额度会拒绝。图片投影预算继续单独计费。这些是逻辑准入额度，不是实际 GPU 物理内存测量。

资源在可重入属性读取前登记到提交管理器。只要尝试了队列写入或提交，就观察其完成栅栏，即使编码失败、尚未提交。无法证明安全结算时，保留账本计费，直到关闭流程尝试退休；清理可返回不安全结果，并隔离由 Engine 持有的画布。借用设备仍归调用者所有。取消启动后继续等待、收束已开始的 B1 加载屏障，再决定是否允许 GPU 工作。

## 验证边界

当前证据覆盖 CPU 准入、描述符、模拟 GPU 调用和固定运行时的模块加载。修正后的默认Node测试路线通过全部十三项Host用例，所选组合源码通过整仓验证：901/901项测试以及编译、边界、类型门禁。配对证据区分这些新结果、此前isolation-none专项运行及默认worker guard失败尝试。原生着色器编译、真实像素、浏览器及设备行为、性能仍未运行／未验证；字体、DragonBones 和完整工程迁移属于另外的开放任务。
