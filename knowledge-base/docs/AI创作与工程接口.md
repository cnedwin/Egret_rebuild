# AI 创作与工程接口

[English](AI创作与工程接口.en.md) | 简体中文

候选目标是让 AI 能理解当前作品、完成局部修改、获得反馈并继续迭代。R006 要求适配 Agent、Skills 和 MCP 生态；具体工程协议和工具尚待实现，不能把接入模型等同于可靠创作。

## 共同工程语义

对象与资源使用稳定 ID；路径、名称与场景位置可变化。工程、资源格式、引擎版本和目标宿主配置分别锁定版本。可视化界面、代码工具和 AI 操作共享同一套引用检查、修改命令、构建与诊断。

运行时场景是权威状态，GPU 或原生镜像可以重建。编辑工程是创作事实，试玩中的临时状态不能未经选择写回工程。开发者生成的业务代码仍然是需要编译、运行和验证的程序，结构化编辑不能代替玩法测试。

## 修改闭环

1. 读取目标对象、引用、版本、能力和性能预算，明确本次意图及完成条件。
2. 生成范围明确的差异，列出资源、规则与交互可能受到的影响。
3. 在版本前提下执行修改；冲突时重新读取，保留修改前快照。
4. 等待资源导入和构建完成，取得可定位到对象、资源、代码及阶段的诊断。
5. 试玩与回放关键输入，检查预期行为、原有玩法、视觉及性能预算。
6. 在限制的修复轮数与成本内修复；报告结果或剩余问题，支持撤销和重新尝试。

工具返回应包括任务 ID、工程版本、状态、差异、诊断、产物和验收结果。异步导入、构建和测试需要查询、取消、超时与恢复语义；重试必须明确幂等性。不要用无定位的聊天文本作为唯一机器反馈。

## 候选能力分组

| 能力 | 典型用途 | 验证重点 |
| --- | --- | --- |
| 工程查询与定位 | 找到某个角色、按钮、玩法规则及资源引用 | 多次重命名、移动后仍定位正确 |
| 结构与代码修改 | 改 UI 布局、角色属性、事件和业务逻辑 | 局部范围、类型/引用、玩法保持 |
| 资源导入与构建 | 导入骨骼、模型、音频，生成目标资源 | 源资产保留、授权、异步完成与错误 |
| 试玩与诊断 | 输入回放、对象状态、截图、帧时间分析 | 可重复结果、对象来源、测量口径 |
| 版本与恢复 | 撤销、比较、继续修复、更新旧工程 | 冲突、取消、失败恢复与数据一致 |

Skills 提供任务知识和操作步骤；MCP 提供工具发现与调用；引擎接口承担工程语义与正确性。应允许接入不同模型与客户端，模型选型、费用和托管形式尚未确定。协议依据见 [MCP 工具规范](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)。

## 验收方式

连续执行同一作品的多轮修改，记录需求满足、无关功能保持、撤销成功、人工接管、等待和成本。新创作者与有手游经验者分别测试。诊断能指导优化但不证明优化有效；AI 改动必须经过行为与视觉复验。H005 与 V003 对应[假设](../registry/假设.json)和[交付](../registry/交付.json)，旧工程进入相同闭环见[迁移要求](旧工程迁移.md)。
