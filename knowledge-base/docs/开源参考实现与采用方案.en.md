## First executed reference chain

Three r186 execution uses commit `9b4a2ac29c63ccb43fd51c5661f2f873ac2c39b8`, separately registered from historical r180 evidence. RiggedSimple is a Cesium 2017 CC-BY-4.0 asset from a pinned Khronos commit: a skinned cylinder with one skin, two joints, and one clip. Precise provenance/licensing is in the [notices](../experiments/asset-reference-probe/THIRD_PARTY_NOTICES.en.md). The actual 17/17 checks, failures, corrections, and limits are in [third-round integration](第三轮集成记录.en.md). GLTFLoader/SkeletonUtils/AnimationMixer/WebGLRenderer and native Canvas text were executed; upstream test suites were not. KTX2/Basis, complete 2D skeletons, complex UI, and production hosts remain unaccepted.

The current untrimmed five JS files plus embedded asset total 2,313,137 bytes; per-file compression values are in the [file estimate](../evidence/asset-reference-file-footprint.json). This is not a release-package/network-transfer measurement. A 2D configuration should exclude 3D modules; 3D trimming and initial-package measurement enter the next work package. Recovery invalidates only old GPU allocations/listeners, retaining the shared CPU bundle; final instance release ends ownership. The correction applies only to the measured chain, not a general claim about upstream defects.

Egret's scene, UI, frame scheduling, resource lifecycle, animation semantics, AI engineering, and migration core are independently written against its own specifications. HostAdapter and BackendCaps express surface, font, network, worker, and device ownership across browsers, mini-games, and native hosts. Hosts without Canvas/DOM use an independent TextProvider. Native GPU providers continue researching mature options under existing D005 candidates, with build, interoperation, and host execution validated separately.

## Concrete design revisions from established facts

**Transparency order and state caches.** Three's WebGLRenderLists sorts opaque and transparent queues separately; WebGLRenderer offers resetState for shared contexts. UI retains display order; 3D distance sorting does not replace UI painter order. One context does not automatically share two libraries' caches: both must invalidate or reset their tracked state at handoff. [Sorting source](https://github.com/mrdoob/three.js/blob/0af9729d0c143a86a1d725d6e2c3ad83301f3f34/src/renderers/webgl/WebGLRenderLists.js), [resetState](https://github.com/mrdoob/three.js/blob/0af9729d0c143a86a1d725d6e2c3ad83301f3f34/src/renderers/WebGLRenderer.js#L3348-L3362).

**Chinese baseline and cache granularity.** Pixi measures/rasterizes through Canvas and manages text-texture references. Its ordinary path without extra letter spacing draws whole strings; some spacing fallbacks split graphemes. Babylon draws whole lines; PlayCanvas builds atlases per symbol, which is not complete line shaping. Separate default paragraph text and highly reused labels, avoiding premature independent font rasterization or forced MSDF for all text. [Pixi drawing](https://github.com/pixijs/pixijs/blob/5b41ee37fd36c61e089113345a8f12cf1c3323cf/src/scene/text/canvas/CanvasTextGenerator.ts#L680-L773), [text UI research](../evidence/reference-text-ui.json).

**Actual cost of adding atlas glyphs.** PlayCanvas updateTextures detects missing glyphs and merges characters, then _renderAtlas remeasures, repacks, clears pages, and uploads. This is neither append-only incremental insertion nor an established LRU eviction mechanism. Egret adaptation adds atlasGeneration and invalidates old UV/advance/layout on rebuild. Batch missing glyphs and prewarm before deciding whether another mature incremental atlas is needed. [CanvasFont](https://github.com/playcanvas/engine/blob/c3eb40348be7e80617164e4f2fea0b139ad42ebb/src/framework/font/canvas-font.js#L169-L206).

**Dirty regions are not partial uploads.** Babylon ADT reduces Canvas redraw area, but the reviewed WebGL dynamicTexture path still sends the entire source to texImage2D. Egret separately counts CPU redraw and GPU upload, rather than equating their optimizations. Actual update frequency and device data determine whether UI textures should be split. [Upload source](https://github.com/BabylonJS/Babylon.js/blob/cbe5bb36998fdde6bd93d76e67813ff571a535db/packages/dev/core/src/Engines/Extensions/engine.dynamicTexture.pure.ts#L43-L75).

**Font readiness and coverage.** A CSS font name cannot distinguish pre-load fallback from the loaded font. Proposed Egret keys include fontAsset/contentHash, fontEpoch, fallback chain, original text, layout/language/direction, and resolutionBucket. This is not a common API already present in all reference engines. Atlas entries and successful loading do not prove actual glyph coverage. Do not normalize business text without authorization; if normalization is needed, retain the original and state the rule. DOM/HTML line breaking applies to corresponding hosts only, not as a requirement for all mini-games. [Cache analysis](../evidence/reference-text-ui.json).

**Text recovery sources.** A merged Pixi PR records pooled Canvas/images reused after upload, causing blank or incorrect recovery text. Current CanvasTextPipe unloads managed text on contextChange and regenerates it on the next draw; HTMLText submits upload before returning temporary objects to pools. Egret retains text/style/font dependencies as generation authority instead of assuming temporary Canvas can always be reuploaded. [PR 12170](https://github.com/pixijs/pixijs/pull/12170), [pinned TextPipe](https://github.com/pixijs/pixijs/blob/5b41ee37fd36c61e089113345a8f12cf1c3323cf/src/scene/text/canvas/CanvasTextPipe.ts#L27-L59).

**Handle reconstruction and dependent caches.** Merged Three PR 31755 addresses old bind-group caches surviving replacement GPU textures. PlayCanvas PR 9397 addresses device creation after application destruction during asynchronous recovery. Egret must invalidate all dependent bindings/views by resource generation, recheck owner/epoch after await, and promptly release obsolete creation results. [Three fix](https://github.com/mrdoob/three.js/pull/31755), [PlayCanvas fix](https://github.com/playcanvas/engine/pull/9397).

**External resources and offscreen pixels.** Rebuilding texture objects does not restore render-to-texture/GPU-only historical content. Owners must declare recovery responsibility for external devices/textures. Text, filters, thumbnails, UI caches, and similar resources register source locations or generators and request redraw after recovery. Render-target destruction must also release stencil/mask bookkeeping. [PlayCanvas device recovery](https://developer.playcanvas.com/user-manual/graphics/advanced-rendering/device-loss/), [Pixi stencil-state fix](https://github.com/pixijs/pixijs/pull/12194).

**Egret import and destruction boundaries.** A glTF loader parsing assets does not mean the product covers every required extension. Egret defines its support matrix before import and rejects unsupported required extensions with a location diagnostic; this is Egret product policy. In Three r180, the default branch over extensionsUsed only warns for names that are also required and lack a plugin. This cannot be generalized to all required errors: required KHR_texture_basisu without KTX2Loader throws, for example. KTX2 loader.dispose and disposal of created textures are separate. A container sharing mesh/material with instances cannot be destroyed while references remain. Egret's independent import policy and resource contract handle these boundaries. Explicit parsing/transcoding dependencies retain attribution; research implementations do not automatically enter the independent core. [glTF extensions](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#specifying-extensions), [resource/animation research](../evidence/reference-assets-animation.json).

**Animation research and scope read.** Mature animation libraries supply mechanism evidence and may be assessed as explicit dependencies for actual uses. Current source evidence checks clip/track import, Mixer actions/binding caches, CPU skeleton preparation, and component entry points only. AnimationAction/PropertyMixer/Interpolant, final GPU skinning shaders, and deep state-control algorithms have not been fully read. Independent animation follows Egret specifications; explicit dependencies retain attribution. Add implementation and asset-golden checks before entering the support matrix. DragonBones Slot research covers 2D display/attachment/order adaptation semantics; Spine constraints/clipping still need their own evidence. Verify actual SDK distribution licensing separately for a Spine route. [Resource/animation evidence and limits](../evidence/reference-assets-animation.json).

## Focused validation work

Existing transparency-order, interpolation, and format principles supply design foundations. The independent core follows Egret specifications; general parsing/transcoding/font libraries are evaluated as explicit dependencies. Retain counterexamples and lessons from upstream fixes; new experiments validate correctness, adaptation differences, Egret contracts, and product benefits.

First advance the real-asset reference chain, TextProvider/SharedDeviceState/ResourceRegistry interfaces, and legacy skeleton semantic samples. Add integration regressions for state handoff between executors, invalidation after font loading, atlas generations, final shared-resource release, destruction/recovery races, required-extension rejection, animation events, and migration comparisons. Lack of current devices need not stop these tasks.

Once target phones/hosts are available, measure Chinese font cold loading/new-glyph bursts, clarity/IME, CPU/GPU frame time, peak memory, upload/overdraw, recovery pauses, thermal stability, and energy. Source explains mechanisms, not how far Egret leads. The previous 71 results were not rerun or broadened here. D001–D012 remain proposed, H001–H007 remain untested; R008 complete migration remains a formal delivery requirement.

## Current attribution and implementation status

Existing vendor files, adapters, and experiment results retain their original versions. Three execution modules belong to a third-party research chain; Egret adapters are separately recorded. The current independent core has three headless packages. Its 44/44 behavior checks and 11 negative type assertions cover only CPU and simulated hosts; GPU, Native, real hosts, and CI await acceptance. See the [core framework record](核心框架实现记录.en.md). Future changes submit [provenance records](../templates/实现来源记录.en.md) so design grounds, implementation attribution, and validation scope remain publicly aligned.
