## 0.12.0 显示与帧候选范围

后续工作包按[显示与帧合同](显示与帧执行合同.md)及[实现计划](显示与帧执行实现计划.md)推进：显示变换、继承可见性/透明度与本地矩形裁剪、Sprite 所属 Graphics 的矩形填充，以及不可变 CPU 帧捕获/提交。首个已实现执行适配器为独立 @egret/engine/web 入口的 Canvas，核心根入口保留无 DOM 边界。限定实现检查已通过：97/97核心行为测试、25项负类型诊断及真实桌面Canvas像素/指针交互。跨realm拒绝修正后有限独立审阅通过；远端发布另行记录。最终限定结果由[实现记录](显示与帧执行实现记录.md)和[验证](../evidence/display-frame-verification.json)承载。

本包不验收完整文本/纹理/动画/UI/3D 执行、GPU 或 Native 支持、目标设备性能、编辑器、Agent 服务或完整迁移。此前 headless、CPU 资源与第三方研究记录保留原版本、数量、hash 和范围，不转为新显示帧验收。

日期：2026-10-08。状态：后续研究与验证建议；原始研究没有执行产品或新增实验，本页纳入知识库0.8.0。

纯 TS Scope、取消、同步事件、显示树与无 GPU Engine 生命周期可以立即独立实现。本轮首段已经开始实现并通过限定验证，实际结果与剩余差异见[核心框架实现记录](核心框架实现记录.md)，不把下文研究时的未执行边界自动改成全合同已通过。以下 8 项按推进需要排序；后七项不阻塞这一小切片，也不提前接受图形库、VM、字体依赖或性能结论。

候选合同有文档级反例复审；真实glTF+Canvas UI研究链17/17通过，限定本地桌面WebGL2。现有证据不包含完整新核心、WebGPU产品后端、原生SDK/VM、真实IME、AI任务或完整旧工程验收。

本次研究依据既有证据索引及候选合同，并核对官方文档与主仓库入口。打开源码页面只算路径核对；本次没有新增固定 SHA 完整源码审读。此前固定源码研究的范围只沿用各索引明确标注的窄路径。

## 可现在写

### G001 · 优先级 1

**具体问题：**候选Scope、取消、事件、显示树与Engine合同能否成为可编译且在重入、异常与迟到结果下自洽的自有核心？

**研究对象与路径：**

- 本项目候选合同与六组反例。路径：docs/公共API设计与命名规范.md；evidence/api-lifecycle-challenge-final.json。本次核查范围：本次已读。
- [WHATWG AbortSignal使用语义](https://dom.spec.whatwg.org/#interface-abortsignal)。本次核查范围：本次核对官方标准入口；仅作为浏览器适配约束，新显示树事件不冒充DOM完全兼容。

**现有证据不足：**六组反例在文档中已解决，原文档复审明确未编译、未运行。此后首段已编译并验证无DOM/无Node的取消、Scope、同步事件、显示树与headless生命周期子集，实际范围见[核心框架实现记录](核心框架实现记录.md)；标准AbortSignal的浏览器类型适配与真实宿主仍未验收。已有异步资源与可靠队列模型保持各自研究范围。

证据索引（相对知识库根）：evidence/api-lifecycle-challenge-final.json；evidence/engineering-norm-review-final.json；evidence/async-resource-probe-results.json。

**最小验证：**

1. 纯核心以无DOM/无Node环境类型声明编译；浏览器类型用单独fixture验证标准AbortSignal可接入。导入不启动时钟或注册全局对象。
2. 覆盖Scope逆序清理、abort回调重入、同owner/外owner/新迟到值、清理异常后继续、取消前后登记竞态与监听异常。
3. 覆盖整次派发快照、跨阶段新增/删除、once重入、两种stop、抛错后状态复原、活跃Event重派拒绝；显示树环/重挂载、外owner子树、跨Engine拒绝与失败原子性。
4. 用可控无GPU host覆盖启动失败回滚、同一关闭Promise、关闭重入/失败、重复关闭结果不变；只报告此切片实现结果。

**触发的决策：**缩小D016的未执行部分，冻结第一批公开声明与无GPU状态机；失败时改自有合同/实现，不等字体或GPU选型。

**通过后仍不能证明：**旧Egret事件兼容、真实GPU完成条件、跨VM/线程或完整引擎可用。

### G002 · 优先级 2

- [FreeType字符覆盖与栅格边界](https://freetype.org/freetype2/docs/reference/ft2-character_mapping.html)。路径：freetype/freetype: src/base/ftobjs.c、include/freetype/freetype.h。本次核查范围：本次已读API说明；ftobjs.c只核对入口，未审实现。
- [Pixi已有固定版本文本链](https://github.com/pixijs/pixijs/blob/5b41ee37fd36c61e089113345a8f12cf1c3323cf/src/scene/text/canvas/CanvasTextMetrics.ts)。路径：pixijs/pixijs@5b41ee37fd36c61e089113345a8f12cf1c3323cf: src/scene/text/canvas/CanvasTextMetrics.ts、CanvasTextGenerator.ts；src/scene/text/shared/AbstractTextSystem.ts。本次核查范围：既有reference-pixi-text记录已读；本次未重读源码。

**现有证据不足：**既有Pixi/PlayCanvas/Babylon窄源码研究支持整行Canvas基线与fontEpoch缓存；未读实际字体、未跑HarfBuzz/FreeType，也未定义跨provider索引/塑形/断行合同。系统字体一句smoke不能证明这些。

**最小验证：**

1. 固定HarfBuzz/FreeType版本与SHA，仅读shape/buffer/charmap/相应测试，写自有TextProvider输入输出与不承诺清单，不复制实现。
2. 用授权固定字体和一个小型金样集比较原文、UTF-16范围、glyph/cluster、advance、断行：简繁CJK/扩展汉字、e+combining、emoji ZWJ、阿拉伯混排、空格/换行。
3. 明确fallback/font coverage、bidi/断行与编辑光标分别由谁负责；字体替换使metrics/layout/raster/UV失效。先做CLI/桌面功能对照，实机输入另见G007。

**触发的决策：**决定D007/V004的可替换TextProvider边界、Canvas段落缓存与原生字体依赖；只有需求和证据要求统一排版时才扩大到共享shaping。

**通过后仍不能证明：**所有系统同像素、IME正确、中文图集预算或手机文字性能。
