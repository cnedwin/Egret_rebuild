# Product Components

English | [简体中文](产品组成.md)

The new Egret is a system spanning creation, execution, and publication. The module boundaries below are a candidate organization. Consult the [requirements](../registry/需求.json) and [deliverables](../registry/交付.json) for confirmed product requirements and implementation status respectively. No installable new Egret product currently exists.

| Component | Responsibilities and main outputs | Key boundary | Related deliverable |
| --- | --- | --- | --- |
| Rendering engine and runtime | Scenes, UI, animation, resource execution, input, scheduling, GPU backends, and recovery | Manages per-frame execution; AI inference stays outside the frame loop | V002 |
| Project model and development interfaces | Stable object identity, scene/resource structure, versions, references, commands, and diagnostics | Shared semantics for code, AI, and visual editing | V003 |
| Resource and animation pipeline | Import, processing, dependencies, atlases, fonts, skeletal animation, frame animation, 3D assets, and target builds | Preserves source assets and licensing information; runtime artifacts are tailored to hosts | V004 |

| Agent Skills and MCP interfaces | Read projects, propose and apply changes, invoke builds and tests, and explain feedback | Tool calls share project commands; protocol integration alone does not guarantee task success | V003, V005 |

## How a change passes through these components

A creator asks to “replace a 3D character while preserving the outfit UI's interactions.” Tools first locate the character, animations, materials, and references; check resources and target-host capabilities; propose a local diff; perform import and changes; preview and replay outfit operations; confirm rendering, events, and budgets; and generate a publishable artifact. On failure, return to a version that remains editable.

AI, the editor, and the publishing system should use the same location, version, and diagnostic semantics. The candidate does not require all tools to launch at once, and it does not predetermine the editor framework, cloud services, business model, or plugin marketplace.

## Boundaries between independent development and integration

Egret needs to own consistency across the rendering runtime, creation-project semantics, and migration. Mature components may be evaluated for fonts, codecs, foundational libraries, or specialist capabilities, but quality, package size, platform, version, and licensing costs must be recorded before adoption. The historical practice of “developing everything ourselves” is a source of experience, not an automatic requirement to rebuild every new module.

The community first participates in defining interfaces and acceptance, then contributes implementations along the selected module boundaries. Tool forms and dependency choices go through proposals and enter the [decision record](决策与开放问题.en.md).

## Independent core and public dependencies

R015 requires an independently implemented core. Egret writes scene/UI, frame scheduling and composition, resource lifecycles, animation semantics, project transactions, and migration rules to its own specifications; general-purpose public libraries are integrated as explicit dependencies. Core code and dependency capabilities are disclosed separately under the [independent implementation and third-party dependency rules](独立实现与第三方依赖规范.en.md).
