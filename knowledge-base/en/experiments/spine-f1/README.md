### Trusted session and time ownership

The experiment proposes `createF1ClockSession(options: EngineOptions): Promise<F1ClockSession>` in the optional first-party bridge, not the default Engine export. It creates a genuine Engine for the existing textured profile, captures its original `engine.clock.onTick` before exposing the Engine or invoking resource providers, and returns the frozen session with `engine` and `createResources(resourceScope, refs)`. Caller-supplied Clock replacements are not accepted. The session accepts the genuine configured `maxDeltaSeconds` only when it is at most **0.25**. A valid larger configuration starts the real Engine, then refuses `F1_CLOCK_PROFILE_UNSUPPORTED` and awaits its disposal. Cleanup rejection preserves the exact profile cause and cleanup error as `F1_CLOCK_SESSION_CLEANUP_FAILED`; no usable session escapes. Invalid Engine options retain their earlier SDK error. A successful caller owns `session.engine.dispose()`.

An instance created through the session uses `bindClock(subscriptionScope): GameClockSubscription`, owned by a genuine subscription Scope. Every delivered running tick advances once by its original delta; instance-local elapsed begins independently of Engine elapsed. No clamping, time debt, discarded interval or second update is introduced. Intervals above the configured Clock limit are refused before the bridge callback. Recover a rejected hitch with an actual pause/resume and a new source baseline; resume while already running does not recover it. Paused gaps are excluded. Rendering, capture, idle and zero-time observations do not advance animation.

An active binding excludes manual `step`, including `step(0)` and invalid deltas, and a second bind refuses `F1_CLOCK_BOUND`. Original manual factory instances refuse `F1_CLOCK_CONTEXT_REQUIRED` when asked to bind. Explicit handle disposal or completed subscription-Scope closure allows later manual stepping or rebinding. While the authentic Scope is `closing`, its tombstone still refuses direct step/bind with `F1_CLOCK_SCOPE_CLOSED`, including an abort listener before reverse cleanup. Closing callbacks retire safely without advancing or inventing a callback failure. Lifetime/profile/binding checks keep their accepted precedence before scalar validation.

Instance/resource disposal retires bindings before core/display cleanup; resource groups own borrowed page leases. Disposing an instance does not close its caller-owned instance Scope. An unexpected after-advance fault makes only that instance inert and retires its binding; no rollback is promised. The deliberately injected named fault verifies this boundary and B-instance independence, not a natural production fault. Every actually created handle must be disposed; a binding never created remains absent/null, with no fabricated disposal observation.

## Profile and ownership

The external official runtime is exactly `@esotericsoftware/spine-core@4.3.13`, revision `b7beb2ccbbce667a12c02f44d070644f59b04968`. F1 contains two untrimmed, unrotated region attachments, one translating bone, one non-looping `slide` animation and a 16×16 whole-page nearest/clamp texture. The logical `.png` atlas name is explicitly bound to 1024 original raw RGBA bytes; this does not implement PNG decoding or establish an Editor-export workflow.

`createF1ManualResources` loads two text headers and one Texture through genuine homogeneous groups. Each instance has its own Skeleton, AnimationState, renderer and retained display root. A private wrapper authenticates the core's unknown texture identity against the real lease. Immutable geometry copies only actual active command ranges before the core reuses its pools; Y is inverted once and the root is `(24,24)`. Float64 admission retains exact integer-channel/255 tint. The fixed observed protocol is two normal/light-tint commands, each four vertices and six indices.

`step` accepts finite deltas from **0 to 0.25 seconds**. Zero, capture and render do not advance animation or the Engine clock. Two active instances are an explicit F1 experiment limit. Scope/group and retained node lifetime checks precede advancement and follow callback-capable operations. Closing one instance preserves shared resources; closing the resource owner terminates instances before wrapper/group cleanup. Wrappers do not release group-owned leases. A failure after positive advancement makes that instance inert; no rollback or general scene transaction is promised. Unsupported F1 features are refused.
