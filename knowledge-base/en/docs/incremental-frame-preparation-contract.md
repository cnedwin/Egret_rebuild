# Incremental ordered frame preparation contract

English | [简体中文](../../Cns/docs/incremental-frame-preparation-contract.md)

M1.2 reduces repeated capture and preparation work and combines adjacent compatible 2D draws. The display tree, committed resource bindings and existing submission owner remain authoritative. Functional engineering was delivered through [PR #74](https://github.com/cnedwin/Egret_rebuild/pull/74). This contract defines the implementation and schema-6 measurement boundary. The completed schema-5 timing batch retains its valid `FAIL_TIMING_TARGET`. The latest seven-source candidate passed fixed preflight, correctness and operation-count checks under a fresh recipe. Its diagnostic sequence stopped on sampled OS foreground qualification; native cleanup completed, but no valid diagnostic pair or formal timing comparison followed. Formal performance acceptance remains OPEN. The [evidence record](incremental-frame-preparation-evidence.md) retains the original records and exact scope.

## Public behavior and immutable values

Existing Engine capture/render methods, frame profiles, Host options, package entries and resource ownership remain unchanged. Ordinary frames keep their structural input contract; textured submission still requires a genuine registered frame. No new public cache token, completion hook or bypass is introduced. Canvas retains its existing capabilities, and scene rendering uses the optimization only in its established 2D overlay stage.

A successful capture creates a fresh frame and commands array, with the existing frame-ID rules. Present image and geometry tables are also newly constructed; an ordinary empty image table may remain absent. Safe immutable matrix, rectangle and clip records may be shared. Subrecord identity stability is not an API guarantee: eviction or an ineligible key may produce equal new records. Mutable authoring state and upload arrays never become saved-frame backing storage.

Saved frames retain their values after later transforms, reparenting, binding replacement, resource release and producer disposal, under the existing replay contract. Each new capture revalidates current resource entitlement and constructs current first-use image and geometry tables. It assigns indexes from those tables, even when a matrix or clip record is reused. Host preparation resolves actual image and geometry identities from the submitted frame; an old ordinal or index never identifies a cross-frame resource.

## Capture, revisions and traversal

Private revisions record successful structural, transform, appearance/clip, content and binding changes. Validation and caller-field reads retain their original order before publication. Equality checks preserve signed zero. Committed Bitmap, Mesh/NineSlice and TextField changes use their existing authoritative writers; an uncommitted text request does not replace the displayed content. Counter restart invalidates both profile entries before reusing small revision values.

A node/profile candidate must match those revisions and the complete current parent matrix, alpha and ordered clip context. Parent references, child lists and subtrees are not cached. Traversal still reads the authoritative tree in painter order. Textured capture performs its full all-tree admission pass on every call, including hidden and suppressed descendants: node/edge identity, lifecycle, Engine affinity, authored contributions, triangle occurrences and unique geometry storage remain checked. This pass requires O(nodes) traversal; total work also depends on authored geometry and clips. Capture is not promised to run in O(changed nodes). Ordinary capture keeps its own established traversal and refusal order.

A node/profile with two consecutive replacement misses and no intervening hit temporarily retains a scalar-only admission probe. Initial cold capture still seeds the next static hit. Continuing changes reuse this bounded metadata instead of rebuilding payload storage. A successful stable probe observation permits a cold rebuild; only a complete result published after the normal final open check can supply a later hit. The probe is charged to the same owner and retains no clip graph. Its revision and parent-number hint does not authorize reuse: complete keys still decide every hit, including clip-only changes. Failed capture, eviction, revision restart and termination discard probes through the same lifetime path.

Visible contributions check their exact leases, live Texture authority and TextField Scope at the original positions. A cache hit cannot turn a released lease or closing Scope into valid input. Original distinctions between geometry checking, opacity suppression, emission charging and resource reads remain intact. The legacy rectangle-only collector remains uncached.

Only complete candidates become reusable after the collector's final Engine-open check. Failed or partial candidates are discarded. Later Engine frame-ID, freeze and registration steps remain separate; failure there need not roll back valid disposable derived values and cannot grant a frame identity. Node termination invalidates its entries, and genuine Stage termination clears its cache. The ordinary disposed-Stage behavior remains compatible, without opening a new cache after termination.

## Bounded CPU retention

| Owner | Combined limit | Retained scope |
| --- | ---: | --- |
| Genuine Engine Stage, ordinary and textured capture together | 65,536 entries and 16,777,216 logical bytes | Recent derived numeric records or scalar probes per node/profile, including pending candidates |
| WebGPU Host, geometry and packing together | 4,096 entries and 16,777,216 logical bytes | Complete keys, successful private results and stage costs, or resource-free numeric probes |
| WebGPU Host, extra batch concatenation | 8,388,608 bytes | Reserved and accepted concatenation backing storage |

Both entry and byte limits apply. Cache metadata has a 256-byte base per entry, with one additional 8-byte capture replacement marker; retained records, arrays and typed payloads receive explicit logical charges. Records cost 32 bytes plus 8 per field; arrays cost 24 bytes plus 8 per element; typed backing uses its actual byte length. A capture probe retains 408 logical bytes; a minimal complete capture entry with one matrix retains 616. Capture retention deduplicates identity within an entry. Host geometry and packing own separate copies and receive separate charges, even when their source records share an identity; aliases within one stage are counted once. The measured charge of an unchanged owned stage is retained without recursively rescanning it. Host keys that retain immutable image or geometry identities also charge their retained data. Capture entries hold neither those resources nor leases, Textures, Scopes, frames or strong references back to display nodes. Weak node indexes do not keep detached nodes alive; empty weak-index bookkeeping is not a physical heap bound.

An oversized or unavailable cache falls back to the original computation. Capacity pressure may evict older results. Optional cache allocation failure does not add a public refusal; required snapshot, geometry, packing and upload-copy failures retain their original behavior. Host close and terminal failure clear preparation retention. These logical allowances are separate from GPU residence, submission charges, caller-retained snapshots and other temporary allocations. They do not establish a process-memory or garbage-collection bound.

## Preparation equivalence and charging

Host lifecycle/reentry checks and ordinary input copying or textured frame admission precede reuse. A command ordinal and profile select a bounded candidate slot, but equality requires the complete numerical and identity key: backing dimensions, pixel ratio, preparation settings, command kind and attributes, transforms, ordered clips, crop, opacity/color, and current image/geometry identity. Numerical comparison uses Object.is semantics, including +0 versus −0. Resource equality is exact identity, not equal pixels or a content hash. Current command and projection-view indexes are rebound after a hit.

Continuously changing candidates stop retaining geometry and packing results after two replacement misses without an accepted hit. A bounded numeric probe reuses its existing number storage and holds no image, geometry or stage payload. Geometry and packing within one preparation call count as one observation. Only successful stage publication confirms an observation; a superseded or failed observation cannot rearm the cache. A later stable numeric observation permits fresh cold computation, never a cache hit. Exact current resource identities and the complete key remain necessary for reuse. A sequence-length change discards the probe and suppresses retention for that slot. The probe costs 256 + 80 + 24 + 8 × N logical bytes for N numbers, within the same Host limits.

Geometry reuse follows the original command stages. Rectangle packing is cached as a complete original consecutive rectangle run, preserving the order in which all represented positions, orientation checks, fees and payload allocations are processed. Splitting a run cannot create additional budget. Image and mesh packing remain at their original command positions. Failed computations are not cached.

A successful stage records its logical costs. A hit replays that stage's complete prepared-vertex, predicate and tuple-comparison charges only if every applicable remaining allowance fits. Replay is atomic: any insufficient dimension selects the original computation at that position, without a partial debit, so the original operation determines the first refusal and cause. Source-triangle admission and all frame-wide projection, upload, pending, device, readback and serial checks still run. Suppressed coverage, Float32 collapse and fewer native draws do not create new logical refunds.

Profile-specific precedence remains unchanged. Ordinary submission and ordinary scene overlays retain their original packing-before-pending/readback ordering. Textured and combined submission retain storage admission before payload packing, copying and uniform creation. Required per-submission copies remain at those positions; cached typed payloads are never passed directly to queue callbacks.

### Bounded preparation hot paths

Only ordinary TEXTURED Host preparation enables contained clipping and same-call clip-rectangle reuse, after genuine frame admission and with the original first-party ledger methods, including tuple admission. A successfully normalized subject fully contained in a canonical positive-winding axis-aligned four-corner clip may skip repeated intersection/normalization. Original predicate and tuple charges remain: 12n predicates for rectangles, 8n for images, and 8n predicates plus 2n(n+1) tuples for meshes. Both the local allowance and atomic global replay must fit; otherwise the original computation determines the first error. Required intersections, unsupported clips, generic/direct calls, custom or overridden callbacks, shared/MIXED profiles and B1 retain their original computation.

One preparation call may reuse successful clip-rectangle geometry by admitted immutable clip identity, under the same options, pixel ratio and ledger. The temporary context retains at most 64 clips, 256 XY points and 512 numeric fields, plus bookkeeping overhead; this is a logical inventory, not a physical heap bound. Successful misses publish an owned immutable copy and actual predicate cost. Hits atomically replay that cost or fall back at the original position; failed calculations are never cached. Entry 65 stays cold. Optional allocation failure disables reuse without swallowing required geometry failures. The dispatcher clears the context in finally before packing; it does not survive the call or frame.

Within one geometry/packing slot, a successful complete key comparison may be reused through a nonzero numeric owned-key identity. Every access still looks up the current Map entry and rejects probe state; the slot holds no additional key, entry or resource reference. Same-key publication preserves identity; replacement and rearm receive fresh identities. Clear, eviction, reentry or a different entry cannot authorize an old slot, and exhausted zero identities always perform the full comparison. Owned-key and probe accounting each include the additional 8 bytes within unchanged limits. These implementation boundaries have source review and focused validation; they do not establish native pixels or measured performance.

Ordinary TEXTURED Host admission may reuse successful numeric validation of immutable clip records within one call, only for its own captured frame/options chain. At most 64 clip references are retained; later distinct clips stay cold. Every occurrence still checks the original clip quota and performs the original source callback in order. Failed validation is never recorded, and finally releases all references. Direct/default calls and the other profiles keep their original admission behavior.

Corner generation uses one implementation without temporary validation or coordinate-pair arrays. It preserves the eager ten-field reads before validation, all pair-field reads before transformation, the per-point checked arithmetic and matrix reads, and determinant/zero-size ordering. The original output values and predicate charges remain authoritative. This is an allocation refactor, not an extra numerical shortcut or a performance guarantee.

Per-edge clipping has been integrated with independent source/result review and focused validation. The latest frozen candidate passed finite native correctness/count checks; diagnostic environment qualification and formal performance remain open. Under the existing ordinary TEXTURED selection and stock-ledger checks, a current normalized subject wholly inside one edge of a canonical axis-aligned clip may reuse that edge's identity transformation. The original cost is replayed atomically: 3n predicates for rectangles; 2n for images; and 2n predicates plus n(n+1)/2 tuples for meshes, using the current edge's vertex count. Local/global shortage leaves the original computation to determine its first error. Successful output copies remain required, with full mesh tuples preserved. Generic/custom calls, unsupported clips and other profiles retain their original paths; no cache or new authority is added. Focused validation does not establish native or performance acceptance.

## Adjacent batches and submission retirement

Batch planning occurs after the original logical admission, packing and uniform allocations. It preserves logical-command provenance and painter order. Sampled draws merge only when adjacent and compatible within the same submission stage: pipeline/kind, current image view and crop, opacity, ordered clips and the stage's sampling, blend and color interpretation must agree. Image and mesh pipelines remain separate. Compatible consecutive rectangle ranges can merge in their existing buffer, retaining per-vertex color and opacity.

A–B–A stays in that order. Material/clip changes, empty image or mesh contributions and the scene-to-overlay boundary interrupt merging. Unsupported states retain their existing refusal. No new material, blend profile, texture page or global texture sorting is implied.

Each logical unit first meets its original upload and device limits. Optional concatenation then respects the device buffer limit and available scratch, splitting only at original logical draw boundaries. If capacity or the optional concatenation allocation/copy is unavailable, submission uses unmerged payloads. This fallback does not catch original packing/uniform failures or native GPU errors. Original logical costs remain charged even when execution uses fewer buffers, bindings, uniforms or draws.

Scratch is reserved before allocation and includes both active candidates and accepted submissions. An unaccepted plan releases its reservation; an accepted plan retains it until the existing submission retirement completes. Queue fences alone do not release it. Error scopes, readback/map obligations, cleanup success, mixed buffer-return order, loss and unsafe close retain the M1.1 ownership rules. Failed cleanup keeps the original ledger responsibility. A cache hit never certifies old GPU buffer contents: each submission still uploads its own payload.

## Acceptance boundary

The complete prior SDK is the independent recomputation reference for equivalent operation sequences. The implementation adds no public debug switch or permanent second rendering authority. Correctness, actual native operation reduction, browser pixels, timing, memory observations and delivery status require separate evidence. There is no dirty-percentage threshold or promised speedup.

The M1 static, sparse and fully dirty workloads and their declared desktop conditions remain acceptance targets. Fully dirty comparison includes update work in the continuous span from update start through render return; the median of five per-run p95 values must remain within the declared 1.10 candidate/baseline ratio. A diagnostic Host elapsed span can bound preparation only within that diagnostic window; an excessive upper bound does not establish excessive preparation time. Unmeasured GPU time, physical memory, unavailable devices and incomplete environment conditions remain explicit. Full Spine support, texture pages, backend recovery and the remaining M1 packages retain their separate scope and acceptance.

## Capacity-paced measurement protocol — recipe schema 6

Recipe schema 6 retains `egret.m1-2-capacity-paced/1` and adds `engine-host-span/1`; its first diagnostic sequence is recorded separately from formal timing. It preserves the fixed static, exactly-1%-changed and full-dirty workloads, original native ownership rules and two-frame in-flight limit. Each diagnostic or timing trial first submits exactly two fresh initial-state frames synchronously, without advancing the workload or waiting between submissions, then waits once for both to retire. A full 30-second warm-up follows; its drain, the fixed workload reset and reset-frame drain precede the complete 60-second measurement window. Six diagnostic trials and thirty timing trials remain separate: timing has five baseline/candidate pairs per state, with alternating roles and rotated states.

At each real animation callback, record its entry clock before environment and capacity checks. An active Host with zero or one pending submission admits exactly one next workload ordinal and one fresh frame. With two pending submissions, record a capacity stall and request the next real callback without updating, capturing or submitting. An unexpected refusal, invalid capacity state or native error is an execution failure. There is no early capacity refund, speculative retry, synthetic frame, logical-update coalescing or per-frame `whenIdle` wait.

The window starts at the first actual callback entry T0 and ends at the first later entry T1 at or beyond T0 + D; the closing callback does not update or render. Record W = T1 − T0, requested duration D, overrun, request-to-first-callback delay and subsequent drain separately. For admitted entry times a1…aN, retain a1 − T0, every consecutive admitted-entry gap and T1 − aN. With no admission, retain W as one gap. These finite, ordered, nonnegative spans must sum to W; the fixed 0.000001 ms arithmetic tolerance applies only to consistency of that sum, never to a performance threshold. Leading and terminal spans are coverage observations, not invented frame intervals. Keep zero-length spans in raw evidence with zero weight.

`wallGapCoverage` sorts all gap durations g and weights each by g. Its duration-weighted nearest-rank quantile Q(p) is the smallest duration for which cumulative positive-duration weight reaches p × W. Compare p95 to 16.7 ms and p99 to 33.4 ms. This is an explicitly added coverage criterion; it does not reinterpret or replace the original count-based nearest-rank cadence from the interior admitted-frame RAF timestamp differences. Callback-entry performance.now observations and the browser's RAF timestamp argument are sampled separately. Preserve both without clamping or imposing an ordering between them; each sequence and each CPU span retains its own finite, nonnegative, monotonic checks. [High Resolution Time](https://www.w3.org/TR/hr-time-3/#sec-coarsen-time) permits coarsened timestamp observations; the [RAF API description](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame) distinguishes its timestamp from a performance.now read at callback entry. No threshold rounding, sample removal, hidden wait or shortened window is permitted.

Retain every raw warm-up and measurement callback's entry/exit times, RAF timestamp, admission decision, pending count, accepted ordinal/frame ID, component clocks and foreground flags in bounded storage. Missing component clocks remain absent, not zero CPU samples. Report admitted, capacity-stalled and closing callback CPU cohorts separately. Preserve admitted update, render and continuous update-through-render spans; the diagnostic mode additionally separates capture and Host. Full callback timing includes admission, recording and scheduling work up to its final clock; that clock cannot measure the subsequent timestamp-store epilogue and return, which remain explicitly disclosed. Do not pool cheap stalled callbacks into admitted engine CPU or subtract observation overhead. Missing records or storage overflow fail integrity.

Timing retains the actual workload.render → Engine → Host path. A collector-owned public HostAdapter delegate forwards the original receiver, surface, frame, lifecycle returns and renderer exceptions; it neither imports private product hooks nor bypasses genuine-frame admission. Each admitted timing callback must contain exactly one Host call for the identical returned frame. Two supplied-clock reads bracket that call and remain nested in the Engine span. Warm-up and measurement raw records retain hostEnter, hostExit, call count and frame/callback links; unavailable spans remain absent. Both baseline and candidate use this same observation, and its delegate, clock and recording costs remain in Engine/callback totals without subtraction. Untimed initialization/reset forwards without these extra clocks. The separate diagnostic mode remains fresh capture followed by Host and cannot supply five-pair formal timing evidence.

| Metric | Acceptance and interpretation |
| --- | --- |
| Original cadence | Count-based interior admitted-frame RAF intervals: p95 ≤ 16.7 ms and p99 ≤ 33.4 ms. |
| Added wall-gap coverage | Duration-weighted complete-window gaps: p95 ≤ 16.7 ms and p99 ≤ 33.4 ms. |
| Engine CPU | Admitted timing render span p95 ≤ 8 ms. In timing mode this synchronous span contains capture, Host preparation, packing and submit. |
| Fully dirty comparison | Candidate/baseline ratio of the five-run median update-through-render p95 ≤ 1.10. A relative pass cannot override absolute CPU, cadence or coverage misses. |
| Preparation upper bound | For each role/state, first compute each formal timing run's nested Host p95, then take the median of five runs. This containing Host span includes preparation, packing, encoding and submission; capture is outside it and remains within Engine time. A value ≤ 4 ms establishes the preparation bound (`true`); a larger or unavailable value leaves it unestablished (`null`), not failed. All three candidate states must establish the bound. Isolated preparation remains `UNMEASURED_IN_MAIN_WINDOW`; the original Engine CPU criterion remains independent. |
| Actual GPU time | `UNMEASURED` unless directly supported by a separate actual measurement. CPU spans and queue latency do not substitute for GPU timing. |

Aggregate each metric separately by role and workload using the median of five per-trial quantiles; retain every individual outcome, miss and sample count. Do not pool runs or require every trial to pass as an additional gate. Zero or one admission can form a complete recorded window but cannot qualify interior cadence or the paired relative CPU comparison. Missing cohorts and a zero relative denominator remain unavailable. A valid slow baseline remains in the comparison. Throughput, maximum gap, stall count/time and callback overhead are diagnostics; no FPS floor, stall-share cap, arbitrary sample floor or extra CPU threshold is added.

Ordinary timing budget misses and insufficient comparison samples remain in the fixed five-pair-per-state schedule. Stop on execution, integrity, environment, native, deadline or cleanup failure. A completed `FAIL_TIMING_TARGET` or `INCOMPLETE_TIMING_COMPARISON` result is distinct from incomplete execution. Formal acceptance still requires fresh, same-browser baseline/candidate evidence; original schema-3/4 incomplete runs and the completed schema-5 performance failure retain their original recipe identities and results. The new observation cannot retrospectively establish a bound for those runs.

## Reproducing the desktop comparison

Use Windows x64, Node **26.7.0**, **PowerShell 7**, and the installed **Playwright 1.62.1** package (including matching playwright-core). The default is headed Microsoft Edge through the msedge channel. Preparation may explicitly add the pair `--executable $browserExecutable`, where the variable is an absolute standalone-browser executable path; the recipe pins its raw length/SHA-256 and checks it before/after execution and against the observed process. Both roles share one browser selection. No browser silently replaces default Edge, and different browser identities cannot form one pair. Actual version, adapter and power observations remain separate; caller-added browser flags are not accepted. Invoke Node without extra execution arguments; nonempty NODE_OPTIONS or NODE_PATH, in any letter case, are refused. Keep AC power connected, the tested browser in the foreground, and the power scheme, browser executable and recorded device/driver inventory stable across paired trials. Do not run suites concurrently.

The fixed rendering surface is CSS/viewport/backing **1024 × 768**, with explicit Host pixel ratio **1**. The actual window DPR is preserved, must be finite and positive, must stay exactly stable per frame, and must match exactly across each pair. It is not rounded to one. Earlier profile-1 INCOMPLETE reports remain unchanged.

Choose two distinct, normally installed SDK roots: the complete M1.1 reference and the M1.2 candidate for this acceptance recipe. Set these PowerShell variables to absolute paths: $baselineRoot and $candidateRoot; an existing empty private $records directory for new raw build records; a new $prepared directory for snapshots; an existing private $runs directory for new mode outputs; $playwright for the installed package directory; and $powershell for the PowerShell 7 executable. Output directories must be outside the SDK roots, verifier checkout and installed runtime owners. Start from the checkout containing the reviewed verifier; all per-mode outputs must be new.

For a new independent reproduction, build both roots normally and retain each raw log and exit record; the loop below applies only to those newly prepared roots. Do not rebuild or modify the already frozen M1.1 formal reference for a new recipe: supply its authentic successful build record. If that build is inside a complete gate log, an exact raw-byte excerpt may be supplied with the original complete log, identity, byte interval, command boundary and actual parent exit retained; identify it as a derived excerpt, not a dedicated build run. Preparation itself does not build anything. Use PowerShell 7 with Node 26.7.0 selected:

~~~powershell
foreach ($role in 'baseline','candidate') {
  $sdkRoot = if ($role -eq 'baseline') { $baselineRoot } else { $candidateRoot }
  Push-Location $sdkRoot
  try { node tools/build.mjs *> (Join-Path $records "$role-build.log"); $buildCode = $LASTEXITCODE }
  finally { Pop-Location }
  [IO.File]::WriteAllText((Join-Path $records "$role-build.exit"), [string]$buildCode, [Text.UTF8Encoding]::new($false))
  if ($buildCode -ne 0) { throw "Build failed: $role" }
}
node tools/verify-incremental-rendering.mjs --prepare --baseline $baselineRoot --candidate $candidateRoot --baseline-build-log (Join-Path $records 'baseline-build.log') --baseline-build-exit (Join-Path $records 'baseline-build.exit') --candidate-build-log (Join-Path $records 'candidate-build.log') --candidate-build-exit (Join-Path $records 'candidate-build.exit') --output $prepared
if ($LASTEXITCODE -ne 0) { throw 'Preparation incomplete; inspect its private receipt' }
~~~

Preparation accepts seven required argument pairs plus the optional `--executable` pair, creating baseline and candidate copies plus a schema-6 recipe.json. It copies only the bounded core SDK sources, emissions, configuration/manifests and installed original robust-predicates 3.0.3 files; three package aliases point inside each copy. It verifies complete membership, exact bytes and link targets. Each manifest has the built-sdk role and FROZEN_BUILT_SDK_SNAPSHOT status. Baseline/candidate are comparison positions, not merge or review claims. The supplied successful log/exit records are bound to these bytes; the tool does not observe the earlier build runtime or independently prove source-to-emission equivalence. It performs no install, Git operation or SDK execution.

Run the five modes serially in the table order against the same snapshots and exact generated recipe, inspecting each saved result before continuing. Stop on execution, integrity, environment, native, deadline or cleanup failure. Ordinary timing budget misses or insufficient comparison samples remain in timing mode’s fixed five-pair-per-state schedule without retry or sample replacement. Exit 1 can also represent a fully executed `FAIL_TIMING_TARGET` or `INCOMPLETE_TIMING_COMPARISON`; inspect all thirty trials, execution/environment/cleanup fields and budget outcomes rather than equating that exit with interrupted execution. Preserve original output and use a fresh directory for a later attempt. Changed tool, profile or SDK bytes require a new preparation/recipe; the recipe also binds the raw bytes of five measurement tools and the English M1 plan.

$mode = 'preflight' # Then correctness, counts, diagnostic, timing; inspect each completed result first.
node tools/verify-incremental-rendering.mjs --baseline (Join-Path $prepared 'baseline') --candidate (Join-Path $prepared 'candidate') --recipe (Join-Path $prepared 'recipe.json') --playwright $playwright --powershell $powershell --mode $mode --output (Join-Path $runs $mode)
