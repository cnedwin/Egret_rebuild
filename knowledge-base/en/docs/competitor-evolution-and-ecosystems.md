## Cocos progressively unifies rendering and creation interfaces

At its October 2024 release,3.8.4 built builtin pipelines with CRP and enabled them by default for new projects, with a migration path for old projects. Maturity labels for customizable pipelines/WebGPU at that time do not establish today's status. Versions 3.8.5–3.8.8 continued addressing WASM loading time, property compression, offscreen MSAA, channel merging, and default-resource overhead. First-screen optimization extends from package size to initialization, requests, and loading order. [Pipeline documentation](https://docs.cocos.com/creator/3.8/manual/zh/render-pipeline/overview.html), [change history](https://www.cocos.com/creator-download).

Historical research viewed Cocos 4, CLI, and PinK as separation into engine, callable engineering tools, and AI editor. This round rechecked public Cocos 4/CLI Alpha releases, not PinK. CLI alpha.42 README lists creation, import, build, project information, MCP server, and simulator preview, with separate simulator build steps. main commands.md covers only some commands and cannot disprove preview entry points on its own. Egret can learn to establish unified projects and feedback loops first; public Alpha interfaces do not establish complete autonomous creation, transactional safety, or production reliability. [alpha.42 README](https://github.com/cocos/cocos-cli/blob/0.0.1-alpha.42/readme.md), [main commands](https://github.com/cocos/cocos-cli/blob/main/docs/en/commands.md).

Cocos UI batching depends on adjacent draw order, materials, textures, masks, and other conditions. Historical JSB optimization also illustrates native-computation/bridge-cost tradeoffs. Some are graphics-correctness constraints, others historical migration costs; neither proves restructuring is impossible. [UI batching](https://docs.cocos.com/creator/3.8/manual/en/ui-system/components/engine/ui-batch.html), [JSB optimization](https://docs.cocos.com/creator/3.8/manual/en/advanced-topics/jsb-optimizations.html).

## Laya reorganizes 2D and machine-callable workflows

Historical research records 3.2.5 adding MCP in April 2025;3.3.0 revising 2D rendering/UI expression/Native interaction/mini-game adaptation;3.3.1 changing batching/dynamic text/statistics; and 3.4-line CLI, Skills, and structured assets. Unrechecked history retains only its earlier evidentiary strength. Current official material supports layers for knowledge queries, scene operations, and GUI-free automation: CodingMCP queries versioned knowledge, IDE-MCP operates scenes, CLI supplies project commands, and Skills supplies work instructions. These entry points do not establish sustained-creation success rates. [3.3.0](https://github.com/layabox/LayaAir/releases/tag/v3.3.0), [3.3.1](https://github.com/layabox/LayaAir/releases/tag/v3.3.1), [AI roadmap](https://layaair.com/3.x/doc/guides/roadmap/ai/), [CLI](https://github.com/layabox/layaair-cli), [Skills](https://github.com/layabox/layaair-skills).

Official dates remain in conflict: old research placed 3.3.0 in August 2025 and 3.4.0 in June 2026. Current GitHub text shows 05 Aug and 12 Jun without years; the official services timeline instead gives 2025-01-04 and 2026-02-02. It is unclear whether these timeline dates denote previews, releases, or another milestone. They cannot be combined into launch dates, silently replace old records with earlier dates, or supply years to GitHub month/day text. The services page's2026-07-10 update is not a product launch date. [Official timeline](https://layaair.com/3.x/doc/services/), [3.3.0 release](https://github.com/layabox/LayaAir/releases/tag/v3.3.0), [3.4.0 release](https://github.com/layabox/LayaAir/releases/tag/v3.4.0).

When matching runtime is absent, CLI warns and falls back to the latest installed version. IDE MCP documentation also requires plugin, port, and cloud Key configuration. Verify knowledge-query version selection, format validation, successful builds, and actual gameplay/visual correctness separately. Installation, subscriptions, cloud availability, actual tool inventories, and failure behavior were not tested this round. [CLI](https://github.com/layabox/layaair-cli), [IDE MCP](https://layaair.com/3.x/doc/basics/developmentenvironment/ide-mcp/).

Egret should learn from maintainable adaptation/automation interfaces and test its own tradeoffs with complex UI, mixed rendering, and continuous-creation tasks. Fixed release issues cannot be described as current unfixed defects; official optimization figures do not establish cross-engine rankings.

## Godot reduces evolution costs through identity, earlier compilation, and module replacement

4.4 completed script/shader UIDs;4.6 introduced internal node identities and machine-readable extension interfaces, preserving references better through moving, renaming, and external-tool operations.4.4 ubershaders and 4.5 shader baker move some cost earlier, but this applies to Forward+/Mobile, not proven Web benefits. From 4.4 to 4.6, Jolt moved from optional experimental status to default for new 3D projects, retaining choice for existing projects. [UID explanation](https://godotengine.org/article/uid-changes-coming-to-godot-4-4/), [4.6 release](https://godotengine.org/releases/4.6/), [pipeline compilation](https://docs.godotengine.org/en/4.7/tutorials/performance/pipeline_compilations.html).

Godot 4.7 Web uses WASM+WebGL2 Compatibility. Documentation explicitly states no current WebGPU support. Forward+/Mobile and Godot 4 C# projects cannot export to Web in the same way; threading/deployment have further conditions. This round read versioned 4.7 documentation, so other access records cannot justify inventing a 404 here. Native pipeline precompilation/shader-baker benefits do not extend automatically to Compatibility/Web. Egret should manage object identity, interface versions, and capability configurations from its first version and pursue Web-specific optimization. This does not establish that Godot can never change backends. [Web export](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html), [pipeline compilation](https://docs.godotengine.org/en/4.7/tutorials/performance/pipeline_compilations.html).

## Hosts are changing delivery boundaries

Safari 26.0 released WebGPU, but system/device minimums still need verification. Browser availability does not imply availability in current WeChat or Douyin clients. Graphics, WASM, threads, files, and package limits require an independent WeChat/Douyin matrix, not yet fully verified. [WebKit announcement](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/), [Douyin adaptation](https://partner.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/game-engine/cocos-laya-egret).

Meta host scope is Instant Games, requiring initialization, loading-progress, and startup-lifecycle integration. Discord Activities imposes iframe, network-proxy, and URL-mapping constraints; Telegram Mini Apps exposes viewport, safe-area, fullscreen, and foreground/background states. Validate host services and graphics backends separately; ordinary Web export does not establish platform delivery. [Meta quick start](https://developers.facebook.com/documentation/games/build/quick-start), [Discord networking](https://docs.discord.com/developers/activities/development-guides/networking), [Telegram APIs](https://core.telegram.org/bots/webapps).

GDevelop directly competes in AI creation; having an Agent is not exclusive differentiation. Differences must show in sustained-editing success, player experience, delivery, and migration outcomes. [GDevelop official explanation](https://gdevelop.io/blog/make-games-with-ai-agent-gdevelop-automated-prompt).

## Implications for Egret

First establish unified identities/project semantics, a trimmable runtime, host-validated capability configurations, resource builds, and asynchronous feedback. Test candidate architecture with real samples. Official mechanisms support separating backends from host services and explicitly managing device loss, asynchronous readiness, and bridge lifecycles; these are engineering inferences, not implemented Egret capabilities or leadership.
