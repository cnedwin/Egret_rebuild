## Reproduction and ownership

From the repository root, `node tools/verify.mjs` runs the normal SDK sequence. `node --test tests/atlas-import.test.mjs tests/atlas-import-admission.test.mjs tests/atlas-import-heldout.test.mjs` selects the focused planner suite, and `node --test tests/atlas-import-composition.test.mjs` selects the CPU composition. The actual recorded counts above belong to their saved candidate and input identities; running these commands against another tree requires fresh results.

The planner imports no Engine/Runtime/Host and does not load a PNG or authenticate a lease. The optional entry reuses only the retained private public-root jsonc-parser 3.3.1 foundation; it adds no runtime dependency. The engine factories re-admit normalized frames under `trim-rotation-v1`. A caller supplies and owns the full-atlas lease; the example adopts its created resources into genuine Scopes and keeps completion separate from retirement.

The finite Native workflow parses metadata in Node, seals the plan and serves that fixed artifact to a browser session. Acceptance requires its own reviewed source/config/route closure, parser-text-plan-HTTP identity chain, literal pixel oracle, original RGBA and cleanup records before any result can be claimed. Browser consumption of a plan does not establish browser execution of the parser. The accepted collector Source and preparation interface are described in the example guide. The independently accepted saved browser result remains a separate domain from CPU evidence.
