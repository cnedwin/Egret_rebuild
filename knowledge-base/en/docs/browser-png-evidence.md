| rgb-red-green.png | 917780f34b6e830eceb3a99e7c5794af705f16193ba8b2d415c86b24aa0cc78d | [255,0,0,255, 0,255,0,255] |
| rgba-red-transparent-black.png | b94f4bc3c8e745088406b8f87bd06c99c6bbc2cd2646b9948a4cab0b89084ab0 | [255,0,0,255, 0,0,0,0] |

Both are original 8-bit RGB/RGBA, noninterlaced, untagged IHDR/IDAT/IEND files. Their bytes and literal oracles precede decoder execution. Controlled CPU framing fixtures with placeholder CRC/IDAT cannot stand in for these files.

The native plan requires default browser ports, genuine `engine.assets` leases, two decoded images and three image commands per frame. Canvas and WebGPU each submit N1/N2 plus exact saved-N1 replay after origin retirement. Planned totals are 6 submissions, 4 captures, 2 replays and 192 pixels/768 channels with tolerance 0; native transient observations are separately required as 4 decode/4 bitmap-close/4 source readback/8 reset attempts. These are planned requirements, with no actual observed count yet. The full transparent exterior is checked. Opaque red/green and transparent black intentionally avoid asserting arbitrary translucent/hidden-RGB fidelity.

The implementation's preflight checks PNG signature, bounded chunk framing/order, the admitted profile and CRC storage positions. It does not calculate CRC, inflate compressed data or implement a browser codec. Output is browser-normalized straight sRGB RGBA8, not lossless authored PNG bytes. A native pass would still be bounded to its actual browser/environment/fixture; it would not qualify all PNG or a device/platform matrix.
