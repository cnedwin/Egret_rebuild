# November 27 physical-device verification of recent changes

English | [简体中文](../../Cns/docs/november-27-claude-hardware.md)

This review follows the earlier [November hardware verification](november-browser-hardware.md), which covered the first-parent merges through #442. It identifies the 31 subsequently merged PRs whose source branch begins with `claude/`, up to [#515](https://github.com/cnedwin/Egret_rebuild/pull/515). The main test input was `13d70b73904266c11b23de4c09c239240a7162db`. While tests were running, [#516](https://github.com/cnedwin/Egret_rebuild/pull/516) merged; its new contract was tested separately on `477cc78b3f7135e5b90b9ff9f9b013b0dee6364a`, giving 32 inventoried PRs. The later publication of these records does not change either tested engine.

The [measurement record](https://github.com/cnedwin/Egret_rebuild/blob/main/docs/evidence/november-27-claude-hardware.json) lists every PR, its merge commit, the applicable verification route, original report and fixture digests, individual observations and remaining limitations.

## Devices and method

- Windows: foreground Edge 158.0.4370.33, NVIDIA GeForce RTX 5090 Laptop GPU, ANGLE D3D11 WebGL2 and a non-fallback Blackwell WebGPU adapter.
- Android: Galaxy Z Fold7 (SM-F966U1), Android 17, Chrome 157.0.8103.78, ANGLE Adreno 830 and Qualcomm Adreno 8xx WebGPU. The primary screen and label sessions used a native landscape viewport of 873 × 325 CSS pixels; the supplementary session used a native portrait viewport of 411 × 813. Both reported DPR 2.625. Browser touch events were injected into an owned USB-served page. No human fingers or browser viewport emulation were used. The tests did not change system orientation or observe the transition between sessions. The phone input, temporary USB stay-awake setting, prior pages and device lease were restored.
- The desktop screen-fit helper resizes the browser viewport. The screen suite also used scripted portrait/tablet parent dimensions and supplied insets in the physical GPU browser. These do not establish physical fold changes or real notch detection.
- The screen-check CLI remains a separate headless software/emulated-profile check. Node checks are also reported separately.

## Retained failure and tooling boundary

The unmodified `examples/play/verify-views.mjs` failed at its final outline regex on Windows. A second run reproduced the original failure and captured the actual focused `Buy 60` button. The test expects the text immediately after the button name, while the current outline includes the correct `[focused]` annotation. A separate check confirmed Sound/Buy/Sell roles, names, stable identifiers, bounds, enabled states and activate/focus actions, as well as the successful second purchase (gold state 480). The original failure remains in the measurement record. No engine or test change was included in this report. The first #516 phone attempt reserved no input because another live device lease was present; the later physical rerun passed on both APIs.

The earlier device discovery timeout, example-server route refusal and headless browser executable mismatch are retained as harness failures. The subsequent sessions used the normal Chrome foreground, admitted the exact test example files locally, and selected the installed software browser executable, respectively.

PRs #462, #484, #485, #487, #489–#492, #494 and #495 are guide, tooling, static-analysis, save-shape or agent-workflow changes. Their own tests remain applicable; software frame measurements in the guide are not promoted to hardware performance. PRs #447, #475 and the WeChat-specific parts of #474/#478 require an actual WeChat host/DevTools and its keyboard and publishing environment.

## Reproduction and remaining qualification

Use the tested main revision and Node 26.7.0. Run the repository's normal setup/build, then the unchanged `examples/play/verify-screen-fit.mjs`, `examples/play-taps/verify.mjs`, `examples/play/verify-gestures.mjs`, `examples/play/verify-views.mjs`, `examples/play/verify-view-parts.mjs`, `examples/label-budget/verify.mjs`, `examples/paragraph-canvas/verify.mjs` and `examples/screen-check/verify.mjs` scenarios. Where a helper normally forces software rendering, use a foreground hardware browser with the same fixture and assertions, explicitly selecting the backend and keeping the original result when a check fails. On a phone, use an owned localhost page and actual viewport; measure the coordinates before input. The measurement record includes the exact narrow-parent dimensions, input sequence results, adapter identities and PNG/readback digests needed to compare later runs.

This report does not establish real WeChat, Safari, Firefox, iPhone, a physical gamepad, a real screen reader, human touch usability, fold/rotation transitions or a physical notch. The complete model bake/preview CLI and real legacy-project migration through every fixed mode retain their own tests. These short correctness tests do not measure GPU execution time, power or sustained frame-time budgets. #55 and #92 remain separate.
