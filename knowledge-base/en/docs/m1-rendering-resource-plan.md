## Purpose and entry

Build a reusable rendering and resource foundation for complex 2D interfaces, atlas animation and the later complete Spine adapter. Preserve familiar display, resource and game-time concepts while removing repeated preparation and GPU allocation. The baseline is main ca62c980f372683dcb156bc5c284f4036a60f4cc, engineering preview 0.61.0. The [architecture plan](architecture-and-engineering-plan.md) remains the program specification; this document defines the finite M1 work packages and their shared acceptance.

M1 engineering entry requires reproducible setup and existing behavior, active protected PR CI, controlled current-ledger integration, independently reviewed shared contracts and the scenario/measurement profile below. It does not require complete automation of every historical maintenance policy. The architecture plan’s delivery tiers apply; complete protected merge gates remain mandatory. Each changed rendering package additionally requires its affected real-browser checks.

Complete M0 community acceptance remains distinct: an uninvolved human/fork rehearsal is still open in [#52](https://github.com/cnedwin/Egret_rebuild/issues/52); unavailable devices, authorized Editor exports and distribution qualification remain tracked in [#54](https://github.com/cnedwin/Egret_rebuild/issues/54). These conditions block the corresponding support/release claims and dependent tests, not independent M1 engineering. M0 stays open until its outstanding acceptance is met. Changing this dependency is an explicit planning decision, not a retroactive pass.

## Shared design decisions

| Area | Contract for M1 and its consumers |
| --- | --- |
| Authoritative state | Display tree, Scope, leases, clock, animation state and CPU bindings remain authoritative. Rendering caches are derived; cache eviction cannot dispose a game object or borrowed lease. |
| Frame identity | Public saved frames remain immutable and replayable after later edits/disposal within their existing contract. Mutable scratch arrays never escape into them. Internal fast paths require genuine engine ownership and cannot accept lookalike objects. |
| Ordering and batching | Preserve committed tree/slot order. Merge only adjacent draws with compatible target, pipeline/material, texture, sampling, blend, clip and color state. A mask, material change or transparent interleaving is an explicit boundary. |
| Image identity | Shared immutable image/page identity and region/UV metadata are separate. Trim, rotation, logical dimensions and nine-slice retain current coordinates. A CPU image generation is distinct from a GPU device generation. |
| Materials and clipping | The new profile must represent normal/additive/multiply/screen blending, light/dark tint and ordered clip boundaries needed by the selected Spine design. M1 implements its declared shared subset; unsupported required features refuse before presentation. Complete Spine semantics are M2 acceptance. |
| Color migration | Existing encoded-premultiplied output remains a versioned compatibility profile. A linear-composition profile has separate references and explicit selection; never silently reinterpret saved frames. |
| Lifetime and memory | Account separately for CPU decoded data, resident GPU data, in-flight work, temporary upload/readback storage and retained snapshots. Reuse native resources only after all relevant queue/error-scope/map obligations settle. |
| Recovery | A stable host facade owns replaceable device sessions. Rebuild preserves Engine, Stage, Scope, game clock and CPU demand. Old-device async completions cannot enter the new generation. |
| Replacement | Existing BitmapBindingTicket.commit remains synchronous CPU binding. Device readiness, GPU submission/completion and observed image correctness use separate results; they cannot redefine old return values or error order. Queue completion does not prove physical screen presentation. |
| Dependencies | Retain the four packages and engine → runtime/contracts, runtime → contracts. Browser executors remain explicit optional entries. No new Spine dependency in the default engine and no new native SDK in M1. |

### Measurement protocol — schema 6

Recipe schema 6 retains explicit capacity pacing under `egret.m1-2-capacity-paced/1` and adds `engine-host-span/1`. On each real animation callback, submit one fresh frame and advance the next workload ordinal only while fewer than two submissions are pending. A full Host produces a recorded stall without changing the workload. The original two-frame initialization and joint retirement, 30-second warm-up, 60-second measurement, five pairs per state and native ownership rules remain unchanged. Six diagnostic trials and thirty timing trials are separate fixed batches. The fixed schedule is not rerun selectively to remove misses.

Complete callback-entry windows retain leading, interior and terminal waiting. Admitted-frame CPU and original count-based RAF cadence remain separate from stalled/closing callback observations and their recording epilogue. The [incremental preparation contract](incremental-frame-preparation-contract.md) specifies the additional duration-weighted complete-gap p95/p99 criterion at 16.7/33.4 ms. This is new coverage semantics, not a reinterpretation of earlier cadence. Median-of-five aggregation remains separate by state and role, with all individual results retained.

Ordinary timing budget misses and unavailable comparisons continue through the fixed schedule; execution, integrity, environment, native, deadline or cleanup failures stop it. In every admitted timing call, a public HostAdapter delegate observes exactly one actual Host call within the existing workload.render → Engine → Host path. Both roles retain Host entry/exit clocks and callback/frame links in warm-up and measurement; delegate and two-clock overhead remains in Engine and callback CPU spans without subtraction. Capture remains outside the nested Host span and inside Engine time.

For each role/state, compute each run's Host p95 and then its five-run median. The containing Host span includes preparation, packing, encoding and submission. A candidate state's median ≤ 4 ms establishes its preparation upper bound; larger or missing bounds remain unestablished, not preparation failures. When using this sufficient-upper-bound evidence route, all three candidate states must establish the bound. The 4 ms target applies to preparation, not the entire Host: a larger Host span does not prove a miss, and any alternative direct measurement would need separately reviewed coverage of all required CPU preparation work. Pure preparation and GPU time remain unmeasured without direct evidence. The Engine p95 ≤ 8 ms, cadence, wall-gap coverage and full-dirty ratio ≤ 1.10 criteria remain unchanged. No additional FPS, sample-count, stall-share or CPU budget is introduced. Historical schema-3/4 incomplete runs and the completed schema-5 performance failure retain their original identities and outcomes; formal acceptance needs fresh actual same-browser paired results.

Historical executions and original recipes remain in the [incremental preparation evidence](incremental-frame-preparation-evidence.md), with original failures unchanged.

Record draw counts and batch-break reasons, copied/uploaded bytes, native allocations, logical residence/in-flight/temporary peaks and p50/p95/p99 CPU/frame times. Separate animation, capture, geometry, packing and upload preparation. Capture full relevant image regions with predeclared tolerances; font-region comparisons separate layout correctness from antialiasing differences. Hardware/driver/browser changes create a new baseline, not a continuation of an old speed comparison.

### Bounded implementation and recorded validation

The delivered refinement covers seven existing rendering/Host source files and retains the reviewed bounded preparation optimizations. Ordinary TEXTURED Host preparation can bypass repeated clipping only for a normalized polygon fully contained in a canonical axis-aligned clip, with the original logical fees replayed atomically. The same trusted preparation call can reuse at most 64 successful clip-rectangle results and clears that scratch context in finally before packing. These clipping changes do not enable direct/custom callbacks or other profiles. The geometry/packing cache can reuse a successful same-slot key comparison through a resource-free numeric identity while still looking up the current entry and checking probe state on every access; each owned key/probe includes its additional 8-byte charge. The [preparation contract](incremental-frame-preparation-contract.md) defines the fallback, lifetime and charging boundaries. Source review and focused checks alone do not establish browser pixels or performance. Sequence 6 has completed qualification and the fixed formal batch with a valid FAIL_TIMING_TARGET, and six existing browser regression suites have passed independent result review. M1.2/D60 remain OPEN; complete delivery gates remain pending.

Repeated numeric clip admission is now reused only within the ordinary TEXTURED Host's own immutable frame/options chain, with a 64-reference call-local bound and original per-occurrence fees and source callbacks. Corner generation removes temporary arrays while preserving all numeric checks, getter order and late determinant admission. Both changes have independent source review and focused checks. Per-edge contained clipping also retains the same ownership and atomic-fee rules and has independent review plus 177 passing focused tests. The earlier sequence 5 completed source-bound native correctness, operation-count and diagnostic qualification. Sequence 6 subsequently completed formal timing with a valid FAIL_TIMING_TARGET; formal performance acceptance remains OPEN. No new rendering profile or public API is added.

## Verification and delivery

For every package, define behavior and failure cases, run affected local checks, independently review the complete source/results/bilingual package, and qualify the final candidate through complete protected merge checks and affected real-browser correctness evidence. Keep long-run, performance and platform acceptance separate. Use the architecture plan’s delivery tiers; local push checks do not repeat complete merge execution.

Historical source/diagnostic records remain immutable. A changed renderer receives a reviewed current admission or versioned successor, with preserved historical reference. Buffer-pool changes relocate equivalent destruction/reentry/failure controls to actual eviction/close rather than deleting them. Do not refresh all hashes to make a gate green. If an affected verifier cannot admit the new behavior, migrate that verifier as part of the same behavior package and validate its refusal cases.

The PR records the base/candidate, measured scope, failures/repairs and final main tree. No release package or public website is implied. M1 closes only when all its required executable rows pass; unavailable platforms remain unaccepted. M2/M3 and complete production readiness are separate milestones.
