## Implemented behavior

createEngineForProfile(options, TEXTURED_FRAME_PROFILE_2D) explicitly selects egret.textured-frame2d/1. Negotiation captures the host ports once and enters the existing startup/cleanup path. Existing creation retains its old read order. All four capture/render methods share the ID sequence, lifecycle checks and synchronous barrier; new-frame rendering uses the captured new port without falling back to the old port.

Textured capture uses two bounded private iterative traversals with one cursor per ancestor. The first admits the complete tree's metadata, including hidden and empty content, before payload, lease or referenced-index work. The second emits visible Graphics, Bitmap and Mesh2D in painter order. Frames retain immutable image/geometry values rather than display leaves, Texture wrappers or leases; later retirement does not alter replay. Command/clip admission precedes command-record creation and clip flattening. Private ownership, no-rescan behavior and exact allocation ordering are source-review conclusions, not measurements made through inaccessible callbacks.

Legacy Canvas and WebGPU ports reject every authentic new-profile frame, including clear-only and rectangle-only frames, before legacy copying, payload reads or target/queue/ledger work. Canvas preserves active-before-busy priority; WebGPU preserves busy-before-active priority. These controlled checks used real captured frames and started hosts. They do not establish native browser pixels. Ordinary structural copies and proxies do not acquire private registration.

GPU plan Task 1 implements one private shared ledger for atomic whole-count reservations and actual predicate/tuple attempts. Rectangle/image preparation and represented packing share it through optional private seams; selected Mesh tuple normalization/cache retains complete attributes under its bounded policy. Argument omission preserves legacy paths.

Task 2 implements private full-tuple Mesh preparation, represented 32-byte XY/UV/light-RGBA packing and ordered rectangle/image/Mesh dispatch on that ledger. Authored degeneracy suppresses raster before rounded affine transformation; robust rank, represented collapse and reversal have distinct outcomes. Clipping preserves every attribute, represented collapse never refunds prepared reservations, and empty image/Mesh draws remain painter barriers. This accepted CPU helper is reused by the later admission and controlled-host implementation; later fixed desktop native observations have separate evidence.

Task 3 adds authenticated metadata admission, complete indexed/clip preflight and storage planning before Float32/projection payload allocation. Its first-party per-invocation failure authority preserves exact allocation/conversion causes and rejects classification by a foreign caller-thrown class alone. Admitted upload bounds, device/dimension/readback checks and deterministic quota priorities are CPU/source evidence; actual GPU allocation and reservation are exercised by the later controlled host.

Task 4 implements createTexturedWebGPUHost, its four readonly optional numeric extensions, own immutable profile advertisement and synchronous new port. Rectangle, Bitmap and Mesh share the existing startup, ordered submission, fences, quarantine and cleanup owner. Controlled fixtures check the 32-byte XY/UV/light-RGBA ABI, per-draw layouts, crop sharing, pending geometry admission and exactly-once retirement. These observable device-boundary descriptors and lifecycle counters do not validate native WGSL compilation or rendered pixels.

Task 6 verifies the explicit GPU facade, readonly options/status and synchronous port types while preserving the DOM-free root and Canvas graphs. Its copied-package controls check actual private-authority/type leakage and GPU-only isolation from valid baselines. The fixed CPU comparator separately verifies channel intervals, synthetic byte counterexamples and metadata/schema handling. These checks establish neither native browser operation nor GPU pixels.

## Reproducing the native collector

Use the fixed Node 24.19.0, pnpm 11.25.0 and TypeScript 7.0.2 toolchain, a separately installed Playwright 1.62.1 directory, and the default Microsoft Edge channel with no added browser flags. From a fresh repository clone:

    pnpm install --frozen-lockfile --ignore-scripts
    node tools/freeze-textured-webgpu-inputs.mjs
    node tools/verify-textured-webgpu.mjs --playwright "<absolute installed Playwright directory>" --channel msedge --output "<fresh absolute output directory outside this clone>"

The freeze command runs the existing fixed build with a 120-second timeout and 32 MiB capture limit. It records the actual outcome and only publishes ready inputs after successful execution and unchanged source inputs. It derives current source/emission graph, harness, lockfile, source-origin, exact shader literal and the twelve unchanged sensitivity recipes; it does not reuse a prior machine's build success. Tracked templates stay ready:false. Generated manifests, raw build output and a repository-relative receipt live under ignored work/textured-webgpu-freeze/. A previous attempt is never overwritten; archive or remove that generated directory yourself before a fresh attempt. After any source, harness, recipe, lockfile or source-origin change, make a fresh freeze before collection.

This command prepares inputs; the collector's actual native verdict and cooperative cleanup remain separate. Its existing operation/close/hard deadlines are 240/280/295 seconds. OS descendant retirement requires the separately recorded outer process evidence. The workflow makes no phone, performance, cross-device or complete-engine claim.
