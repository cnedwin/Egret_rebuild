# Community participation

English | [简体中文](../../Cns/docs/社区参与.md)

Egret collaborates publicly from early development. Start with the [contribution guide](../CONTRIBUTING.md). Core lifecycle, display-tree, and event code and a design knowledge base already exist. Participate through small code improvements, documents, samples, or design discussions. Actual remote-repository and license configuration is registered in the [current version](../current-version.json).

Start with documentation corrections, official-source tracking, metric definitions, authorized samples, or interface proposals. First-time participants need choose only one item and explain its problem, sources, recommendation, and verification approach. If the related ID is unknown, state “pending maintainer linkage.” No long-term commitment is required beforehand.

## From proposal to delivery

Use [RFCs](../templates/rfc-proposal.md) to compare approaches, then [ADRs](../templates/adr-decision-record.md) to record reviewed decisions. Implementation tasks first define interfaces, owners, dependencies, and acceptance, then open for contributors to claim. Use [experiments and acceptance](../templates/experiment-and-acceptance.md) to retain reproducible evidence. Record discussion opinions and measured results separately.

After the public repository workflow is enabled, report problems with Issues and submit changes through PRs. Maintainers should state adoption status, evidence, and next steps. Retain alternatives and objections when disagreements arise; the project lead organizes and confirms scope changes.

Register community coordination, document maintenance, technical review, and acceptance responsibilities as the project develops. The current maintainer list remains to be configured. Repository, license, and contribution workflows stay discoverable. Participants submit shareable code and samples and protect material permissions and private information under the [public communication policy](open-source-collaboration-and-public-communication.md).

## Trustworthiness of public implementation

Contributions retain research sources, third-party attribution, and own design rationale under the [implementation and dependency policy](independent-implementation-and-dependency-policy.md). The independent core follows Egret specifications; discussions, examples, and performance reports state implementation and test scope. [Acknowledgements](../ACKNOWLEDGEMENTS.md) index reference projects, actual dependencies, and tools so the community can follow sources to examine and improve designs.
