### 3.1. Private packing allocation boundary (0.5 amendment)

The packer receives the caller's validated `maxUploadBytes` and the actual device's captured `maxBufferSize` as primitive limits. Before allocating any output `Float32Array` or its backing storage, it must determine the actual surviving triangle count after the section 4 float32 conversion/winding/collapse rules, then check that exact output capacity against both limits. A host check performed only after packing does not satisfy the CPU bound. Do not clamp `maxPreparedVertices` to an upload-derived count: preparation's existing independent work bound remains unchanged, and predicted fan vertices may legitimately collapse to zero upload.

Use two passes within the private packer. First, convert each distinct prepared point once using the existing NDC expression with `Math.fround`, retaining the converted numbers in ordinary number/point arrays indexed by prepared point identity. Those exactly float32-representable numbers preserve the eventual packed bits for every fan reuse. Apply the existing finite/winding tests once per candidate triangle, retain only surviving triangle index triplets in input command/fan order, and accumulate per-command ranges, collapse count and maximum backing reconstruction displacement. Include converted points in displacement diagnostics even if their triangles collapse. Scratch point/index/range arrays remain bounded by the already enforced prepared-point, predicted-fan and command limits; allocate no typed scratch buffer for conversion/counting, do not expand budgets, and do not change the numeric algorithm.

Let V be the actual surviving vertex count. Check each count/range increment as a safe integer, check the existing u32 draw/range bound (violation: DEVICE_LIMIT), and establish V ≤ floor(Number.MAX_SAFE_INTEGER / 24) before computing `uploadBytes = V * 24`; an unsafe storage byte count is FRAME_BUDGET. Check `V > floor(maxUploadBytes / 24)` first (FRAME_BUDGET), then `V > floor(maxBufferSize / 24)` (DEVICE_LIMIT). Thus caller-budget failure takes precedence when both byte caps fail. Each code has the existing WEBGPU_ prefix. With stride 24 no padding is needed: for nonzero V the requested GPU vertex-buffer capacity and CPU output byteLength are exactly uploadBytes. All these checks precede the output typed allocation and every frame surface/GPU mutation.

Second, allocate exactly `new Float32Array(V * 6)` and populate it from the retained converted points and surviving indices, with the existing per-command premultiplied color/layout. Do not reconvert points, reclamp coordinates, or recompute triangle winding/collapse during this materialization pass. A zero-length output is allowed for V=0; it consumes zero upload bytes and creates no GPU vertex buffer. Continue the existing clear-only frame, pending-frame, readback and retirement rules unchanged. Host reservations use this exact GPU capacity before the first mutation; no new pending-CPU accounting is introduced.

Private packer validation reasons are `precision|budget|device`, mapped respectively to PRECISION_UNSUPPORTED, FRAME_BUDGET and DEVICE_LIMIT. Arbitrary CPU allocation faults in either pass remain raw faults, not private validation errors; preflight maps them to FRAME_INVALID with the identical original cause, leaves the host active and an armed readback unbound, and performs no frame surface/GPU mutation. Never turn an allocation failure into empty coverage. This amendment adds no public options/types/error codes, testing seam or device capability requirement.

## 4. Frozen numeric algorithm and limits

This is bounded float64 geometry, not arbitrary finite-number exact geometry. The fixed coordinate envelope is **0 or 2^-100 ≤ abs(value) ≤ 2^20** for all matrix/rectangle scalar inputs, DPR, their nonzero corner-construction arithmetic intermediates, transformed backing points, and newly constructed point components. Logical frame dimensions additionally follow backing rules. Values outside it reject the entire frame with GEOMETRY_RANGE, even for invisible commands. Normalize negative zero to zero. Predicate internals, determinant estimates u/v, interpolation t/s, NDC and color arithmetic do not use this coordinate envelope: they use their explicit finite/sign/interval checks below. This deliberately rejects extreme scales/translations/cancellation instead of asking an orientation predicate to cure overflow/underflow. It is an application support range requiring fixtures, not a proven universal error bound. No global epsilon, near-collinear angle cutoff, grid snapping, or fixed pixel-displacement rejection is permitted.

Use `sign = -Math.sign(orient2d(ax,ay,bx,by,cx,cy))` to obtain the conventional algebraic cross-product sign. Literal (0,0),(1,0),(0,1) must give adapted +1. Check returned predicate values are finite; unexpected nonfinite/zero contradictions fail precision. Its sign classifies represented binary64 points; magnitude is only a rounded determinant estimate. A matrix with robust determinant zero (orient2d(0,0,a,b,c,d)==0), or width/height zero, contributes no primitive coverage; a degenerate clip removes the command. This test precedes corner topology decisions but follows complete input/arithmetic preflight. Thus exact singular transforms cannot acquire artificial area from rounded corner arithmetic.

Form corners in local order (x,y),(right,y),(right,bottom),(x,bottom), transform using `((a*x)+(c*y))+tx` and `((b*x)+(d*y))+ty`, then multiply each result by nominal DPR. Normalize nondegenerate polygon winding so adapted signs are positive. Remove exact adjacent duplicate points (including closing duplicate); remove a collinear middle point only when it is between its neighbors in both coordinates. Fewer than three distinct points or all-collinear results are supported no-op. Mixed turn signs, repeated nonadjacent vertices, or a nondegenerate transformed rectangle with inconsistent convexity fail precision.

Intersect subject with each normalized clip edge in input clip order, then with viewport [0,W]×[0,H], using closed half-planes (adapted sign≥0). Keep boundary endpoints unchanged; emit an intersection only for strictly opposite nonzero endpoint signs. For a crossing, order segment endpoints lexicographically (x then y) before computing, so reversing traversal uses identical arithmetic. Compute `u=abs(orient2d(A,B,P))`, `v=abs(orient2d(A,B,Q))`; require u>0,v>0 and both finite. Compute `sum=u+v` and `t=u/sum`; require sum and t finite. For strictly `0<t<1`, preserve the existing component-by-component operation order and bits: `I=P+t*(Q-P)`. Only when `t===1`, compute `s=v/sum` directly, never `1-t`; require s finite and `0<s<=0.5`, then construct each component as `I=Q+s*(P-Q)` in that operation order. Every other t or invalid complementary weight rejects precision, including t rounded to 0. Apply the same coordinate envelope and closed endpoint min/max component bounds to either construction. A constructed I that rounds to an endpoint is permitted; this is not an endpoint substitution, clamping, tolerance or snapping rule. Within one clipping edge cache crossings by exact unordered endpoint pair and reuse the same I object. Reuse each surviving point when making the fan. Do not use predicate magnitude as an exact area or claim exact rational intersections.

After each edge, apply duplicate/collinear normalization and the convexity checks above; an invalid topology rejects, never becomes fabricated empty geometry. Do **not** require a rounded constructed I to have exactly zero predicate against its generating line; that would reject ordinary intersections. The resulting small edge displacement is an acknowledged raster boundary limitation, measured with independent rational fixtures. Exact collinear/touching represented cases that construct no crossings remain exact no-ops. Rounded near-touching configurations may reject on topology or yield subpixel coverage; arbitrary real-number touching after multiple rounded intersections is not promised. Ordinary near-collinear examples within the envelope must pass the plan's positive fixtures; classification alone is insufficient acceptance.

Triangulate each convex result as a fan without command merging. Store backing coordinates until GPU packing. Convert each distinct point once to float32 NDC `(2*X/W-1, 1-2*Y/H)`; re-use its packed bits in all triangles. The y flip reverses expected orientation. Reject nonfinite conversion or any triangle whose nonzero sign reverses that expected winding. Zero-area float32 triangles are supported no-sample geometry and are omitted; do not reject every narrow/sliver shape. Record float32 collapses and maximum backing-pixel reconstruction displacement in test artifacts, not a new public failure threshold. Emit contiguous per-command ranges; retain input painter order and skip only legitimate zero-vertex ranges. Shared fan vertices are identical; separately clipped adjacent commands are not promised universally watertight boundaries.

## 5. One production pass, color and readback

Use first-party WGSL passing vec2<f32> position to vec4(position,0,1) and flat constant premultiplied RGBA to fragment output. Vertex stride **24** bytes: float32x2 position at offset 0/location 0; float32x4 color at offset 8/location 1. Flat interpolation prevents needless per-fragment color rounding. Triangle-list, no index/uniform/bind group, no depth/stencil, cullMode none, sample count 1, alphaToCoverage false, all color channels enabled. Explicit viewport/scissor cover W/H. Set complete pass state once; draw ranges in input order.

RGB channels are encoded sRGB integers/255, multiplied once by the already-inherited command alpha; clear RGB is similarly premultiplied, zero alpha means transparent black. Blend color **and** alpha: operation add, srcFactor one, dstFactor one-minus-src-alpha. This is encoded-channel source-over, not linear-light blending. Canonical byte semantics are rgba8unorm. Capture `navigator.gpu.getPreferredCanvasFormat()` during start and accept only `rgba8unorm` or `bgra8unorm`; build exactly one otherwise-identical pipeline targeting that actual format. Reject any other format; never use an -srgb view. BGRA UNORM changes storage order, not RGBA shader/blend arithmetic. Configure colorSpace srgb, alphaMode premultiplied, usage RENDER_ATTACHMENT plus COPY_SRC only if enableReadback. No diagnostic mirror, offscreen canonical target, duplicate draw pass, or unrelated test shader is needed.

After all preflight/reservations, assign canvas.width/height only when different, read them back, and require exact W/H. Configure at start and after changed dimensions using the captured configuration; recheck terminal state at every external boundary. Every accepted frame clears the **entire** attachment with loadOp clear/storeOp store, including rounded excess pixels, and uses a newly obtained current-texture reference within that synchronous invocation. Browsers may return the same texture object to multiple calls before expiry; host must not promise a distinct object per frame. Never retain/use a current texture after the synchronous encoding/submission call or across await. Empty frames still clear. Same-size full reset comes from the clear, not Canvas2D reset semantics.

`requestReadback()` is opt-in, active-only and Promise-returning; all misuse rejects its Promise. One armed or in-flight ticket maximum: disabled→READBACK_DISABLED, existing ticket→READBACK_PENDING; ordinary state codes otherwise. It arms the **next frame that passes preflight** and never submits a frame itself. Rejected input/backpressure leaves the ticket armed. At the first mutation of an accepted attempt bind its ticket to the reserved serial/frameId; a later error rejects that ticket. stop/close rejects an unbound armed ticket with STOPPED/CLOSED; an already submitted ticket is allowed to finish normally unless its frame fails. Call pattern: `const pixels = host.requestReadback(); engine.renderFrame(options); const result = await pixels;` The promise is internally rejection-observed so ignored tickets do not produce unhandled rejections; caller still observes its original rejection.

Reserve `rowPitch=ceil((W*4)/256)*256`, `stagingBytes=rowPitch*H`, `outputBytes=W*H*4`, safe-integer checked, and both capacities against maxReadbackBytes before mutation. Create MAP_READ|COPY_DST staging buffer. After the **same production render pass**, append copyTextureToBuffer from the **same current canvas texture** to the **same command encoder**, with bytesPerRow=rowPitch, rowsPerImage=H and copy extent W,H,1. Submit once. No target texture needs host allocation. After submission start mapAsync(READ), immediately observe it, and obtain a queue fence (after map request); retain owned buffers, not current texture, until completion. Copy mapped rows into owned tight RGBA output before unmap, swapping B/R only for bgra8unorm. Do not unpremultiply, apply transfer functions, flip rows, or copy padding. Resolve only after map, queue fence and all associated scopes succeed and buffers retire; error/loss rejects. Return top-left-origin rows. Returned bytes certify the production target's pixels, not browser composition or physical display. Real screenshots after a browser rendering opportunity remain separate acceptance.

## 6. Lifecycle, scopes and cleanup authority

`start()` from new caches one Promise before external work, enters starting, obtains context/device/pipeline, installs loss/error observation as soon as a device arrives, validates limits and configures, then enters active only after startup scopes settle cleanly. Starting/active repeated start returns that same settled/pending Promise. Acquire uses captured navigator.gpu.requestAdapter() then adapter.requestDevice() with default options, no optional feature/limit requests; null adapter is ADAPTER_UNAVAILABLE. Borrow uses exactly the supplied device and captured device.queue, never a supplied unrelated queue. Borrowed device/queue/context require a cooperative exclusive lease through close; external submission, scope manipulation, context reconfiguration or device destruction violates the lease. Host cannot enforce this across other libraries. Acquired device belongs to host; borrowed device is never destroyed. Context unavailability includes another canvas context mode; do not switch modes as fallback.

stop is synchronous/idempotent: new/starting/active→stopped, closes submission gate and cancels unbound ticket; failed stays failed; closing/closed stay unchanged. Starting cancellation eventually rejects START_CANCELLED; check generation after every await. A late acquired device is still observed and destroyed during close without configuring the surface; late borrowed devices are left intact. start after stopped/failed/closing/closed returns a rejected Promise with STOPPED/FAILED/CLOSED (closing uses CLOSED), never restarts. render/requestReadback require active; new/starting→NOT_STARTED, failed→FAILED with first cause. render takes busy **before any frame read**; nested render→REENTRANT. Getter-driven stop/close aborts before the next host mutation/submission; callbacks never reopen a terminal gate.

Reserve a positive monotonically increasing safe serial for each attempt entering mutation; do not reuse on throw and never use frameId as GPU generation. Exhaustion rejects before mutation. For startup and each mutation attempt push scopes in order **out-of-memory, internal, validation**; always pop the number successfully pushed in reverse order in finally, with immediate fulfillment/rejection handlers. Never await with scopes open. GPU object creation/encoding/writeBuffer/submit/configure are inside the scopes. Scope outcomes attach to startup (serial null) or the specific serial, not resolution order. Validation/OOM/internal outcomes get their corresponding codes; a pop rejection becomes SCOPE_FAILED. Install a device uncapturederror listener via addEventListener, preserving other listeners; uncaptured error is terminal. Immediately handle device.lost as DEVICE_LOST, except deliberate owned destroy after safe cleanup. Do not wait for a healthy device.lost Promise in close.

render synchronously copies/prepares/reserves, uploads into a fresh VERTEX|COPY_DST buffer (when nonempty), encodes, submits, creates completion tracking, and returns **undefined**. No async renderer/thenable is permitted. Synchronous post-preflight mutation exceptions → RENDER_FAILED, terminal; no rollback claim. Queue rejection → QUEUE_FAILED. Readback map/copy failure → READBACK_FAILED. Asynchronous backend failures close the gate, preserve firstFailure, reject affected waiters and schedule diagnostic delivery. Each serial has an **outcome-settlement barrier distinct from successful resource retirement**. This barrier settles on success or failure after every host-owned fence/scope/map continuation settles and never awaits public close. Observe/drain all outcomes; do not use fail-fast Promise.all to abandon other resource owners. Success allows ordinary retirement. Rejected fence/map, broken scope proof or other unproven completion latches unsafe and retains ownership/accounting until best-effort cleanup. If writeBuffer happened without submit, still fence its queue work. A truly unresolved driver operation can remain pending; a settled rejection cannot create a success-only-retirement deadlock.

`whenIdle()` snapshots lastSerial plus current startup Promise and existing ledger entries; later ordinary submissions are outside that snapshot. New without work resolves; starting waits startup; stopped waits accepted work; failed rejects firstFailure; closing waits the captured work (not an invented presentation fence); closed-safe resolves unless a prior rendering failure remains; closed-unsafe rejects CLOSE_UNSAFE. A captured failed serial/startup or device-wide loss before settlement rejects. Already settled success cannot be revoked. Retired successful entries need not be retained; keep cumulative first terminal failure and bounded pending ledger. Fulfillment means captured queue work/scopes/readback handlers settled successfully, not that the display scanned out.

Diagnostic callbacks run in a microtask only after bookkeeping and all synchronously open scopes are closed. Capture callback identity once and invoke with undefined receiver; exceptions are isolated. Assimilate returned values using Promise.resolve with immediate rejection handler; cross-realm promises/thenables and throwing then getters must not leak unhandled rejections. Callback failures increment a bounded safe-integer counter (saturate at Number.MAX_SAFE_INTEGER), replace lastCallbackFailure with DIAGNOSTIC_CALLBACK_FAILED, and are **not** recursively reported to that callback or made GPU failures. Do not await user-returned promises in close: a callback returning close()/whenIdle() must not deadlock. Callback continuations may update diagnostic-only counters after close but hold no GPU/context authority; suppress not-yet-delivered callbacks once closed. No new callbacks are scheduled during final listener teardown.

`close()` caches its Promise **before** any reentrant operation, enters closing, closes the gate, rejects unbound ticket, and waits startup acquisition/rollback, active CPU finally barrier and **settled tracked outcomes/CPU continuations**, never success-only retirement. Startup records failure and relinquishes its barrier; it must never await the public close that waits it. After all tracked outcomes settle, choose safe or unsafe cleanup. A rejected proof takes the best-effort branch, retires local ownership/accounting exactly once as cleanup attempts finish and rejects CLOSE_UNSAFE; this bookkeeping retirement does not prove safe return or successful rendering. No host-internal timeout. Normal close captures a final queue fence after final host work, requires fulfillment and no unexpected loss, unmaps/destroys owned buffers, unconfigures only its leased context, removes only its listeners, then destroys only acquired device. Recheck loss through the proof boundary; deliberate final owned destroy is not a rendering failure. Late acquisition must be cleaned before close settles. No acquired device/work requires only safe local cleanup. Startup/render validation failure alone need not prevent safe cleanup where fence/scopes settle and ownership return is proven. Existing Engine's CPU-assets-before-host-close ordering is valid only because GPU resources here belong to host; future GPU texture assets require their own in-flight lifetime protocol.

On unexpected device loss, rejected completion proof, broken scope ledger, cleanup throw or unprovable safe return, perform best-effort owned cleanup and reject CLOSE_UNSAFE with original cause; set cleanupOutcome unsafe and state closed. Normal close sets safe and closed. Never destroy borrowed device, remove canvas, clear other listeners, or turn loss/map rejection/timeout into successful rendering or safe close. All repeated close calls return the identical Promise including rejection. A hung driver/acquisition can leave it pending; Engine timeout rejects the caller without cancellation or release. Existing Engine quarantine persists on rejected close; successful late close can release under current Engine semantics. Rendering failure and cleanup outcome are separate facts. No force-release API is added.
