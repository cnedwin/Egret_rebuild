# Migrate a classic game to the Android player

English | [简体中文](../../Cns/docs/classic-game-android.md)

A commercial migration has three separate results: an inventory of the original client, editable code for the new engine, and evidence that the delivered binary plays correctly. Keep the original source read-only until it has been compared with a build from the delivery folder.

| Step | What to preserve | How to check it |
| --- | --- | --- |
| Inspect | Manifest script order, both RES manifests, theme declarations, external channels | Read the missing-file and adapter lists, including entries loaded by server configuration at runtime. |
| Compile | The project's trusted TypeScript compiler, reflection metadata and namespace order | Record compiler and source digests. Compare each emitted script with a second clean run. Diagnostics identify the original file and position. |
| Convert | EXML rules, timeline labels, image pieces, endian order and text styles | Compare actual component construction, an interaction, packet bytes and animation pixels using an authored test scene. Keep unresolved skin entries in the migration report. |
| Run on Android | Game scope, script groups, bounded local assets, external callbacks and save namespace | Open, cancel and reopen the same scene. Background and resume during a packet, text edit or music playback. Exercise sign-in and payments with the operator's test service. |
| Deliver | Editable inputs, native Activity, channel libraries, tool versions and instructions | Move the delivery to a fresh directory, type-check a changed game and produce signed APK and AAB files with an external test key. |

Use the CLI's `inspect` and `compile-classic` commands from the migration guide. Games within the supported Web conversion profile can also use `convert`, edit the output, run `rebuild`, and compare a saved playthrough with `verify`. The emitted `api-usage.json` lists direct references to `egret`, `eui`, `RES` and `dragonBones`, sorted by frequency and linked to locations in the generated JavaScript. Pass it to `checkLegacyBindings(bindings, entries)` from `@egret/legacy/coverage` after installing the adapters. Inspect missing names and dynamic lookups. Pass trusted, ordinary adapter objects. A present descriptor establishes the name only. Aliases, destructured imports, instance methods and handler semantics need a playthrough. Compilation of business scripts alone leaves their engine and host dependencies to be linked. [Egret Migrate commands](https://github.com/cnedwin/Egret_rebuild/tree/main/tools/egret-migrate)

The optional `@egret/legacy` package supplies the classic packet API and scene helpers. Add `--legacy` when preparing the portable kit for these imports. Use an existing game scope to acquire visible map cells and character parts. Parts that finish loading after a change of scene must release their leases. The converter can tile an oversized MovieClip atlas and preserve frame labels, offsets and transparent pixels across tile boundaries. [Compatibility reference](https://github.com/cnedwin/Egret_rebuild/tree/main/tools/egret-migrate/compat) · [Windows pixel sample](https://github.com/cnedwin/Egret_rebuild/blob/main/docs/evidence/migrate-paged-movie-edge.json)

Use `services.host.call` for named operations implemented by the Activity. Grant network access through an explicit origin profile. A callback that arrives after close cannot reattach the old game. Use `editText` for confirmed or canceled editing, `waitForBack` for a modal and `music` for streamed packaged audio. A Fold7 running Android 17 returned the 12-byte little-endian test packet carrying “起航” across two WSS sessions. System sound quality, human IME composition and operator SDK callbacks require their own acceptance. For local distribution, run `node tools/egret-migrate/pack.mjs --legacy --npm <npm-cli.js> --out <new-folder>` to create the compatibility package. The archive includes the original engine license and notices. Install the resulting `.tgz` from an empty consumer project. A content-addressed game revision supports fast iteration without recreating the host project. Build the release from the same editable inputs and record the exact kit digest.
