# RFC: 〈Proposal title〉

English | [简体中文](../../Cns/templates/RFC提案.md)

> Use this template to submit a proposal with its Issue / PR. This file records an approach for review, not an approved decision.

- Proposal ID: RFC-NEW
- Author / date / version: to be completed
- Status: proposed, not yet approved
- Related requirements / hypotheses / sources: to be completed; mark unknowns pending linkage
- Scope: runtime / migration / knowledge base / other

## Problem and evidence

Who encounters which problem? List sources, dates, and observation scope, distinguishing facts, hypotheses, and inferences.

## Approach and alternatives

Specify interfaces, inputs/outputs, compatibility boundaries, dependencies, and failure behavior. Compare cost, risk, and reversibility.

## Verification and decision request

Provide sample permissions, baselines, measurement conditions, acceptance thresholds, stop conditions, and unverified items. Which scope or tradeoff needs confirmation?

## Review record

Opinions, objections, modifications, and conclusions: to be completed. After approval, link D-NEW; a maintainer assigns the formal ID and enters the decisions registry. Unapproved approaches retain proposal status.

## Implementation sources

For code or dependencies, attach an [implementation source record](implementation-origin-record.md), distinguishing independent core, public dependencies, and research references. Follow the [independent implementation policy](../docs/independent-implementation-and-dependency-policy.md). Renaming, changing languages, or AI rewriting does not prove originality.
