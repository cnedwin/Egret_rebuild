# Experiment and acceptance: 〈Deliverable or hypothesis title〉

English | [简体中文](../../Cns/templates/实验与验收.md)

> Complete conditions when planning and results after execution; label them separately. This template does not replace the [delivery registry](../registry/deliverables.json).

- ID / date / executor / acceptance reviewer: to be completed
- Related sources / hypotheses / decisions / requirements / deliverables: to be completed
- Status: planned, not executed

## Prior agreement

Verification questions, authorized samples, and boundaries: to be completed. Record environment, versions, baselines, steps, metric units, statistical definitions, passing thresholds, stop conditions, and fallback plans. Mark undefined thresholds awaiting confirmation.

## Actual results

Execution date, actual environment, original results, and evidence locations: to be completed. If not executed, state “no measured results.” Record failures, deviations, and uncovered scenarios together.

## Acceptance conclusion and registry updates

Pass / fail / insufficient evidence: to be completed, with the acceptance reviewer's basis. Tool checks, research conclusions, or plans do not constitute delivery acceptance. Link new evidence to the source registry and update hypotheses and delivery status. Submit decisions for review when they need changes, retaining original records.
