### 十二项关键核查

下列“官方事实”表示对应页面本轮可读取并支持该陈述；“工程推断”是对白鹭的研究建议。所有能力均未在本轮做引擎运行实测。

#### research-01：Creator 正式产品和引擎仓库标签分别登记

**官方事实。** Cocos 下载页首项为 Creator 3.8.8，标注 2025-12-16。当前页面支持这一正式编辑器快照；没有据其他仓库标签更新编辑器版本。[Creator 下载与更新说明](https://www.cocos.com/creator-download)。

**工程推断。** 白鹭应锁定编辑器、运行时、构建工具三个版本，避免用其中一个仓库的标签替代整套产品版本。此项保留旧结论，未核验 Creator 二进制、所有发布渠道或所有平台可用性。

#### research-02：Cocos4 和 CLI 已有公开 Alpha 发行

**官方事实。** 官方 release 页面分别显示 4.0.0-alpha.34 和 0.0.1-alpha.42，均带 Latest 标签。文本显示发布时间为 20 Sep 12:10 / 12:13，未直接显示年份，因此本报告不补推完整日期。[Cocos4 alpha.34](https://github.com/cocos/cocos4/releases/tag/4.0.0-alpha.34)、[CLI alpha.42](https://github.com/cocos/cocos-cli/releases/tag/0.0.1-alpha.42)。

**工程推断。** 可研究公开接口与版本配合；Alpha 标签不能升级为稳定生产承诺。Latest 仅表示该页面的发行标记，不证明与 Creator 3.8.8 共用全部平台矩阵、可靠性或工程兼容性。

#### research-03：Laya 3.4.1 引擎可确认，IDE 与日期仍需复核

**官方事实。** 官方 GitHub release 标题为 LayaAir 3.4.1 Engine Library，带 Latest，正文包含引擎与 IDE 更新条目，显示 31 Aug 07:18，文本未显示年份。官网动态下载入口此次仅返回单行页面，未读到 IDE 下载版本及 8 月 29 日日期。[3.4.1 发行](https://github.com/layabox/LayaAir/releases/tag/v3.4.1)、[官网动态下载入口](https://layaair.com/#/engineDownload)。

**工程推断。** 当前写作可确认引擎发行存在；“IDE 3.4.1 / 官网 2026-08-29”保留为旧研究记录，不能标成本轮重新确认，也不能因页面抽取失败改为不存在。

#### research-04：Godot 4.7.2 本轮有多处官方一致证据

**官方事实。** 官方维护公告、下载归档、Windows 当前下载页和 GitHub release 均指向 4.7.2 stable；官网明确写 2026-08-18。当前下载页仍将它作为 Godot 4 下载入口。[维护公告](https://godotengine.org/article/maintenance-release-godot-4-7-2/)、[版本归档](https://godotengine.org/download/archive/4.7.2-stable/)、[当前下载](https://godotengine.org/download/windows/)、[GitHub 发行](https://github.com/godotengine/godot/releases/tag/4.7.2-stable)。

**工程推断。** 此项保留旧结论。若后续工具遇到 404 或内部错误，应记录那次访问失败并寻找其他官方交叉证据，不能覆盖本次成功记录或编造版本状态。

#### research-05：Godot 4.7 Web 有明确后端和语言边界

**官方事实。** 本轮读取的版本化 4.7 文档要求 WASM 与 WebGL 2.0；Web 仅使用 Compatibility，Forward+/Mobile 不支持 Web，且文档明确写当前不支持 WebGPU；Godot 4 的 C# 项目不能导出 Web。线程和部署条件另有约束。[4.7 Web 导出](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html)。

**工程推断。** 这说明 Web 交付必须独立定义能力范围；不能外推成 Godot 永远无法新增 WebGPU，也不能把原生导出功能直接视为 Web 能力。此项保留旧边界。

#### research-06：多后端抽象可以共享语义，同时保留多条能力路径

**官方事实。** Godot 4.7 的 Forward+/Mobile 经 RenderingDevice 使用 Vulkan、D3D12、Metal，Compatibility 使用 OpenGL；切换可能需要场景调整，回退也可能改变画面。Laya 当前 3.x 架构文档把 RenderDriver 的 WebGL/WebGPU/OpenGLES/LayaX 与文件、输入、媒体等 PAL 适配分开。[Godot 4.7 渲染层次](https://docs.godotengine.org/en/4.7/tutorials/rendering/renderers.html)、[Laya 3.x 架构](https://www.layaair.com/3.x/doc/basics/architecture/)。

**工程推断。** 白鹭可共用场景语义、资源描述和生命周期，在后端能力不足时选择经过验证的渲染路径。共享抽象不证明同功能、同画面、同性能；后端回退与宿主适配分别验收。

#### research-07：Godot 管线预编译收益不能外推到 Web

**官方事实。** 4.7 管线编译文档明确限于 Forward+/Mobile；ubershader 与 pipeline precompilation 不适用于 Compatibility，shader baker 也不支持 Web。Compatibility 仍有预先显示材质等旧式预热方式。[4.7 管线编译](https://docs.godotengine.org/en/4.7/tutorials/performance/pipeline_compilations.html)。

**工程推断。** 白鹭验证应区分着色器生成、管线就绪、首次使用和首帧其他开销。不能将一种后端的预编译机制写成所有后端通用收益。此项保留旧结论。

#### research-08：WebGPU 能力选择和设备丢失是不同状态

**官方事实。** GPUWeb API 参考列出 device.features、limits 和 lost Promise。官方 explainer 说明 adapter 的能力上限与实际创建 device 的能力不同；设备丢失可由 GPU 重置、内存错误、外部设备变化等触发。[GPUDevice 接口](https://gpuweb.github.io/types/interfaces/GPUDevice)、[GPUWeb explainer](https://gpuweb.github.io/gpuweb/explainer/)。

**工程推断。** 白鹭需探测所需能力、保存可重建资源描述，并把设备代次与失效状态纳入运行时；新设备能力可能需要重新选择路径。浏览器提供 API 不等于目标小游戏宿主、GPU 和系统组合都通过验证。

#### research-09：异步管线提供可等待就绪点，仍需处理失败与失效

**官方事实。** GPUDevice 的 createRenderPipelineAsync / createComputePipelineAsync 返回 Promise；API 参考说明成功返回时管线可用，失败通过 GPUPipelineError 拒绝，并建议用异步创建避免编译阻塞 queue timeline。[GPUDevice 异步管线接口](https://gpuweb.github.io/types/interfaces/GPUDevice)。

**工程推断。** 白鹭可用缓存键、编译队列和设备代次保护异步结果；并分别记录请求、就绪、使用和失败。不应据 API 存在承诺零编译成本、零卡顿、固定完成时长或整个首帧就绪。本轮未测试浏览器的实际编译行为。

#### research-10：JS/WASM 桥接可实现，但生命周期与数据传递必须设计

**官方事实。** Emscripten 支持 ccall/cwrap、显式导出、Embind 以及从 C/C++ 调用 JS；直接调用涉及基本类型或指针转换。官方文档说明 WASM 内存增长会使已有视图失效；Embind 的堆内存视图可避免特定复制，但其有效性和底层对象寿命不由运行时代管。[代码互操作](https://emscripten.org/docs/porting/connecting_cpp_and_javascript/Interacting-with-code.html)、[Embind](https://emscripten.org/docs/porting/connecting_cpp_and_javascript/embind.html)。

**工程推断。** 白鹭应定义边界对象所有权、批量数据布局、内存增长规则和销毁协议；堆视图的局部免复制不证明 GPU 上传或端到端零复制。WASM、JSB 或 C++ 标签本身不证明更快，应以候选实现测量桥接频次与成本。

#### research-11：Cocos CLI 的公开工程接口已经可供研究

**官方事实。** 锁定 alpha.42 的 README 列出创建、导入、构建、工程信息、MCP server 和 simulator preview；模拟器有单独构建步骤。main 的 commands.md 只列部分命令，不能以该文件的范围否定 README 中的接口。[alpha.42 README](https://github.com/cocos/cocos-cli/blob/0.0.1-alpha.42/readme.md)、[main 命令说明](https://github.com/cocos/cocos-cli/blob/main/docs/en/commands.md)。

**工程推断。** “已有可调用工程入口”可确认；“完整自主制作、事务安全、自动视觉验收、连续修改成功率”没有因此得到证明。白鹭的差异须进入真实任务与失败恢复验证，而不能仅声明支持 MCP。

#### research-12：Laya 知识 MCP、IDE MCP、CLI 与 Skills 分层记录

**官方事实。** 官方 AI 路线将 CodingMCP 定位为版本化知识查询、IDE-MCP 为场景操作、CLI 为无 GUI 工程自动化。CLI 仓库列 create/build/validate/run 和版本管理；找不到匹配运行时会警告并回退到最新已安装版本。Skills 仓库公开 CLI 与 IDE 插件开发说明；IDE MCP 使用文档要求插件导入、端口和云端 Key 配置。[AI 路线](https://layaair.com/3.x/doc/guides/roadmap/ai/)、[CLI](https://github.com/layabox/layaair-cli)、[Skills](https://github.com/layabox/layaair-skills)、[IDE MCP](https://layaair.com/3.x/doc/basics/developmentenvironment/ide-mcp/)。

**工程推断。** 可确认不同层的公开入口。资源格式校验、构建成功与玩法/视觉正确分开验收；知识查询的版本选择不等于工程动作事务。未验证套餐、云服务当前可调用性或 AI 自主完成率。

### 合同模型做了什么

Node版本24.19.0，Windows x64；种子20261008。8个独立布局区域，每区128个对象，200轮变更对照独立全量计算；另验证静止、稀疏、重复失效和全失效。模型是固定层级的尺寸与位置，不包含完整EUI、文本测量、祖先依赖或重挂父节点。

80个种子透明/矩形裁剪场景将相邻批次展开后，使用相同逐命令CPU合成器比较；另给出全局纹理排序改变颜色的反例。前者主要证明输入顺序保持，不是独立批次消费者验证；合成器忽略pipeline且按单命令使用clip，因此不能证明批内共享状态兼容。它不包含任意遮罩、骨骼、文字和真实材质执行。

镜像测试覆盖重复包、命令原子回滚、对象销毁复用、代际、序号缺口、新epoch图形快照及容量3的背压。审计新增包头/命令格式、无效快照原子性及身份一致性反例；资源新增设备丢失期间/恢复后的旧完成、零持有后重新持有的取消任务、同一owner旧租约的迟到释放与使用反例。它没有可靠事件outbox/水位/重发；图形快照可跳过缺失纯状态，不能保证缺失必达事件恢复。资源complete仍是合并加载/上传回调，rebuild是同步状态模拟，owner为集合而非完整逐租约计数，不是异步GPU实现。没有执行实际JS/C++、WASM共享堆、二进制解析或GPU同步，实际桥接性能尚未测量。

稀疏变化仍需读取所在区域128个对象；全失效仍更新1024个对象。这里只记录操作量，没有CPU计时、FPS或速度倍数。后续计划覆盖的重挂父节点、动态祖先、复杂文字和失效循环不能写成已经测过。

### 浏览器与像素结果

环境：Edge154.0.4258.62，新的无界面临时测试profile。浏览器报告WebGL2经ANGLE/D3D11，renderer字符串包含NVIDIA GeForce RTX5090 Laptop GPU；未独立认证实际硬件路径。页面为本地安全上下文，crossOriginIsolated=false，SharedArrayBuffer不存在，WebGPU接口及设备创建可用。

WebGL使用32×32的RGBA8目标、深度附件、全屏三角形和矩形scissor。近处图元遮挡远处图元；两层半透明颜色按指定顺序叠加；裁剪外颜色保持；资源重建后读回同样结果。中心正常颜色为[70,140,51,255]，交换顺序后为[134,77,51,255]。WebGPU清屏读回[64,127,191,255]，按预先设定的每通道±2容差通过。

容差、32×32、8秒超时等是实验参数，不是产品规格。此实验没有相机/模型/纹理资产、文字、骨骼、性能采样、手机或任何小游戏宿主验证，也没有WebGPU device-loss/异步shader编译测试。

### 审计反例与修正

独立审计先复现了无效包被接受、坏快照先改epoch/next、旧设备完成错误恢复可用性；实现方增加7项检查，运行结果确为17通过/7失败，修正模型后24项通过。随后复核发现旧租约的迟到release仍可能清理同一owner的新资源，新增2项检查确为24通过/2失败，再修正use/release的租约代次校验，最终26项全部通过。初版、两次失败版和中间修正版各两份源码均在后续修改前归档，对应结果包含SHA256。

资源修正增加设备代次、丢失状态与持有任务代次；快照先校验并构造临时映射，再提交。可靠事件恢复与独立批次消费者仍未覆盖，已写入白皮书合同及工程下一轮任务；不由通过数量推导恢复合同完整或性能优势。详细处置见[第一轮审计](第一轮研究.md#audit)。

### 浏览器首次失败与修正

第一次上下文恢复检查出现webglcontextrestored超时。测试在丢失事件内解析Promise后立即申请恢复；改为后续任务再申请恢复，第二次通过。Chromium公开实现是在事件派发返回后更新允许恢复状态，因此结果与该时序解释一致；本轮没有追踪当前Edge的内部调用，不能声称确认了所有浏览器的唯一根因。[Chromium实现](https://chromium.googlesource.com/chromium/src/+/HEAD/third_party/blink/renderer/modules/webgl/webgl_rendering_context_base.cc)、[Khronos扩展规范](https://registry.khronos.org/webgl/extensions/WEBGL_lose_context/)。

首次失败结果保留。四个对应源码文件是在修正后按首次结果SHA256恢复并逐一核验一致的历史快照，位于[attempt-1说明](../experiments/browser-probe/history/attempt-1/README.md)；这不是修正前主动归档的提交，也不是第二次源码替代旧版。第二次没有页面脚本异常；有一项页面资源404诊断，对应未提供favicon的测试页面，未作为图形结果或产品故障结论。原始诊断保留。

### 范围与方法

检查三份候选设计、需求和交付边界、研究记录、实验源代码及结果摘要。独立审阅者先提出模型反例，实现方增加失败测试后修正；审阅者以内存执行方式重现失败与通过，并逐项核对源码SHA256，没有额外启动浏览器、运行历史源码或改写结果文件。

研究核查为12项关键主张、27条官方来源；局部合同最终26项通过，浏览器图形最终7项通过。检查数只描述实际案例，不能用它表示引擎恢复合同、混合渲染或平台覆盖已完整。
