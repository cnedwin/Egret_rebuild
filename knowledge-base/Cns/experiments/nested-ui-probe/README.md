# 嵌套UI失效传播与矩形命中研究模型

[English](../../../en/experiments/nested-ui-probe/README.md) | 简体中文

本实验由真实执行的纯Node模型与测试侧独立全量oracle组成。它补充第一轮固定8区域模型没有覆盖的祖先尺寸、兄弟位置、结构变更与命中关系；不是完整EUI、真实文字或引擎性能验收。

## 可复跑方法

在知识库目录运行，无需安装依赖：

```powershell
node 'experiments/nested-ui-probe/run.mjs'
node 'experiments/nested-ui-probe/run.mjs' --unsafe-isolation
```

第一条覆盖当前通过报告；第二条运行测试侧故意破坏的隔离策略，写入独立失败报告，预期退出码1。不要用当前源码的`--red`或`--audit-red`覆盖历史红基线。所有报告都有UTC执行时间、环境、逐案结果、限制与model/run的SHA256。首次红基线、初版通过、审计红基线及错误隔离报告额外内嵌执行当时源码，便于按hash复核；不需要保存或执行任何历史zip。

## 有限语义

- 树节点有唯一字符串ID；有序子节点垂直排列。宽/高分别支持非负有限固定数值、`content`或`{ref: '节点ID', factor: 非负数}`同轴尺寸引用。默认`content`，factor默认1；不提供任意百分比、约束求解器、flex/grid、锚点、旋转或缩放。
- 研究输入预算：最多128节点，固定尺寸/padding/gap/字形advance/wrapWidth/lineHeight均不超过1e6，引用factor不超过8，glyphWidths最多4096项且每个索引必须有自身数值。越界或稀疏数组在候选验证阶段原子拒绝。两个1e308高度即使各自有限也不属于支持范围；不能承诺任意有限输入都有有限布局。128节点无环尺寸图的保守上界可用`B(d) <= 128*B(d-1)+1e10`、深度不超过128推导，尺寸和世界坐标之和均低于JS数值上界，避免偷偷在每次事务内全量求尺寸。当前fixture都是整数；没有证明任意小数计算误差、任意规模或超深递归的行为。
- uniform padding作用于上下左右。内容宽取可见直接子节点最大宽加两倍padding；内容高取可见直接子节点高度之和、相邻可见子节点gap之和及两倍padding。固定尺寸不自动拉伸、缩小或裁剪子节点。所有节点世界坐标由祖先平移累加，根坐标固定为(0,0)。
- 隐藏节点及其后代不参与命中；隐藏直接子节点不占父节点流布局空间，但保留自身测量尺寸和树身份。隐藏和恢复、插入删除、重挂父节点都会更新有关尺寸依赖与布局位置。重挂同一父节点的index指移除后目标列表的下标。
- 同轴测量依赖包含content子节点和显式引用。提交前验证整张依赖图；内容祖先被后代反向引用产生的循环、树循环、重挂到自身/后代、重复ID、缺失引用和非法fixture均拒绝。先编辑候选副本，再验证提交；拒绝后源树、缓存尺寸与世界矩形保持原值。尝试操作的诊断计数仍反映实际工作，不承诺诊断计数回滚。
- clip为节点世界边界矩形，与全部祖先clip取交集。没有clip的父节点不会隐式裁掉溢出子节点。命中按深度优先显示序列逆序查找，返回第一个可见且同时在边界和有效clip内的ID；矩形左/上边包含、右/下边不包含。容器本身也可命中。变更后先`flush()`再`hit()`；不提供事件冒泡、pointer capture、任意遮罩或空间索引。
- 文本只接受外部`glyphWidths`、固定`wrapWidth`与`lineHeight`。按宽度fixture贪心分行，单个超过wrapWidth的advance不拆开，空fixture仍为一行。内容尺寸来自行宽/行数加padding；fixed尺寸仍独立于fixture分行宽。不加载字体、不发现fallback、不执行Unicode分段、字形塑形、CJK、emoji或IME；不能把此测试写成这些能力已经验证。

## 增量算法与oracle独立性

`model.mjs`持有同轴尺寸缓存与反向依赖表，沿新旧依赖并集标记相关尺寸；flush只重算脏尺寸并复用未变分支。相关容器更新直接子节点局部位置，再传播世界矩形、可见性与clip。固定祖先阻断尺寸值依赖，但其子节点位置仍依赖变化，不是整棵子树的合法传播边界。

结构与属性事务目前都复制并验证完整源树/依赖图；变更帧仍遍历全部节点求世界状态。这里的增量仅在尺寸缓存与部分直接子节点排列，不是完整的局部世界更新。静止flush跳过尺寸与世界求解，但仍复制N条快照记录。不能把这些退路和观测序列化成本隐去后声称加速。

`run.mjs`的oracle只读源树，从零构建平坦索引，用独立的待解决集合逐轴全量求值，再从世界游标直接计算矩形；命中使用独立裁剪边界判定。它不导入任何model计算helper，也不读取model缓存。手算常量另钉住75→85的根高度、19→29的兄弟坐标、重挂位置、文字行数以及clip边界，减少两个实现共享相同错误语义的风险。

## 实际结果与反例

当前18项通过/0项失败，包括静止、稀疏、全失效、固定祖先、隐藏/恢复、插入删除、重挂、外部文字fixture变高、显式尺寸引用、两种循环原子拒绝、矩形clip与半开边命中、非法输入、稀疏字形数组/数值预算以及100步种子混合编辑。100步中每步额外比较12个命中点，共1200次，加上每次oracle对照的6个固定命中点。

首次红基线1通过/15失败：尚未实现模型，真实矩形输出为空，oracle布局断言失败，源码已内嵌保留。其通过项为独立负控反例，不是当时模型通过。随后初版实现16项全部通过，初版通过结果与源码另行保留。独立审阅指出稀疏数组绕过Array.some以及有限数相加溢出；加入两项新反例实际得到16通过/2失败，保留审计红基线后才修复为密集逐索引验证与上述预算，最终18通过。

修复后错误隔离策略实跑16通过/2失败：测试侧在a1变化后丢弃a子树以外的尺寸/排列失效，稀疏测试和种子编辑测试都产生oracle差异。稀疏例中根高错误保持75，正确应85；后续b错误停在y=39，正确应49；tail错误停在66，正确应76。当前通过报告另外保留逐节点错误/正确矩形对照。这说明给任意子树贴“隔离区”标签会漏掉祖先尺寸和兄弟位置。

## 工作量观察

8节点手工树初始和全失效均为16次尺寸计算（宽/高分别计数）；稀疏a1变高为6次尺寸计算，对照oracle全量16次。稀疏变化同时仍复制8节点、验证8节点与16个维度依赖节点、遍历8个世界状态。静止为0次尺寸/世界求值，仍复制8条输出记录。

报告逐案列出源树复制节点、编辑查找访问、树/依赖验证节点与边、失效传播访问、尺寸求值与依赖读取、直接子节点排列、世界求值/实际写入、clip交集及快照复制节点；固定命中点另外记录实际边界扫描量。不同计数单位不能相加当作CPU时间，数组/JSON成本没有按字节统计，oracle运行和测试断言也不是生产成本比较。

本实验没有计时、FPS、性能倍数、浏览器或GPU画质。没有覆盖完整EUI、真实字体、异步测量、预算以外的数值/规模、极深递归、列表虚拟化、运行对象复用或实际宿主设备；100步固定种子不等于状态空间穷尽。结论只支持继续研究依赖传播合同。
