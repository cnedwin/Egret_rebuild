# 可靠跨界事件内存研究

[English](../../../en/experiments/reliable-event-probe/README.md) | 简体中文

这是第二轮局部合同研究，输入为[技术白皮书](../../docs/技术白皮书.md)和[第一轮审计](../../docs/第一轮审计.md)。玩法TS仍是权威，本文没有实现生产引擎、真实音频执行、网络、进程间通信或WASM桥接。测试消费的是实际内存事件与副作用数组，未断言mock调用。

## 合同与范围

- 图形`epoch`只管理可重建视觉镜像，不能修改事件outbox或消费水位。
- `producerSession + streamId + sequence`构成稳定`eventID`。`consumerSession`绑定一个仍存活的消费会话；生产者、流或消费者身份不符的事件/ACK拒绝。模型身份只接受不含分隔符的标识，协议版本为1。
- 新事件先进入有界outbox，发送不移除。确认当前身份、连续消费水位及已交给传输的序号后，累计ACK才能删除对应outbox项。重复/较旧合法ACK不删除更新项。
- 消费者只消费水位的下一项，缺序号时不执行副作用、不缓存乱序项、不返回跳跃ACK，等待生产者重发补齐。已消费项重发只返回当前水位ACK。
- 容量不足返回`null`，不接受新事件、不删除已接受项、不消耗新序号；调用方必须处理拒绝与后续重试。非法配置/副作用在入队前抛错。
- 传输获得独立副本，修改已返回的事件不能改写接受记录。模型中的`pending()`表示向传输交付并标记已发送；丢包/ACK丢失通过丢弃实际交付副本与回复来构造，未使用真实网络。

同一实例中副作用是同步数组追加，并与水位更新在一次同步执行中完成。原型支持的是**公平重试条件下的有序、单次内存消费**；没有持久原子副作用，不保证进程崩溃恢复或跨进程exactly-once。状态重置反例中，相同eventID在新实例中产生第二次副作用，明确证明此限制；这没有执行操作系统进程崩溃。

## 可证伪结果与保留链

1. [首次红阶段](../../../evidence/reliable-event-probe-red-results.json)：11项，1通过/10失败。最小错误模型发送即移除、乱序直接消费、快照重置事件状态、ACK无身份校验。唯一通过项是旧图形快照反例：丢失带`sound-A`的epoch1包，随后切到epoch2快照，旧包重发仍被拒绝，实际副作用为空。
2. [输入反例红阶段](../../../evidence/reliable-event-probe-red-input-results.json)：补非法生产者输入后12项，1通过/11失败。两份红阶段报告都保留当时model/run完整源码文本与SHA256，后续修正未覆盖它们。
3. [当前结果](../../../evidence/reliable-event-probe-results.json)：13项，13通过/0失败。前12项构成红绿测试集合，其中11项从失败转为通过，旧图形快照丢事件反例全程通过；第13项是状态重置下双重副作用的边界刻画，未宣称此边界被修复。通过数字只覆盖报告列出的具体案例。
4. [源码复跑与定向变异核验](../../../evidence/reliable-event-probe-verification-results.json)：9项，9通过/0失败。两份红报告按保存源码重跑，分别复现1/10和1/11；三份报告的源码hash、逐项状态与计数核验通过。另把重复执行、缺口消费、发送即删、容量忽略、图形恢复清空事件及错误ACK身份六种错误逐一注入临时模型，六种都被现有实际消费测试发现。这是作者自检，不能代替独立审计或完整变异覆盖；验证脚本的源码与hash嵌入该报告。

测试名下的`breakCaught`说明测试针对哪一种错误变更；期望消费序列由手工字面量定义。当前运行器一次执行该原型全部案例，包括丢包恢复、ACK丢失去重、乱序缺口、图形恢复、背压、过期ACK、未发送/未来ACK、非法事件/ACK、传输副本隔离与旧累计ACK。

## 本机复跑

在本实验目录运行，无安装步骤：

```powershell
node 'run.mjs'
```

默认写当前结果JSON；失败返回退出码1。可用`--output=<文件路径>`另存复验，`--preserve-sources`把当次源码文本同时嵌入报告。报告时间为实际UTC运行时间，环境记录实际Node版本、运行时名称、平台和架构。`sourceHashes`覆盖model与run，SHA256由实际UTF-8源码生成；红阶段`sourceSnapshots`可恢复原文件复跑并核验对应hash。公开候选把历史元数据中的本机绝对位置改为文件名，原记录私下保留，嵌入源码正文与摘要不改。

## 尚未覆盖

没有持久outbox、水位或副作用事务，生产者崩溃可丢事件，消费者崩溃可重复副作用。没有消费者会话重新绑定、永久失败/死信、跨多流总序、多消费者、外部副作用异常、超时重试调度、序号耗尽、字节内存上限、长时压力/吞吐、二进制解析、真实图形epoch重建或安全认证。ACK身份检查防止结构上过期/错流的确认，不防同身份的恶意伪造。消费审计数组会随案例增长；有界性只指未确认outbox项数与sent集合，不等于总内存有界。永久丢包、永久无消费者或持续背压不能由本模型自动克服。
