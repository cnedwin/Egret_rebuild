# 命名图集契约 — SS1

[English](../../en/docs/spritesheet-contract.md) | 简体中文

工程预览 0.45.0。此原创增量让命名图标与序列动画共用一张真实图集租约和一份不可变矩形表。编译后的 Engine、Runtime 根入口新增 `createSpriteSheet`，以及仅类型的 `SpriteSheet`、`SpriteSheetFrameInput`；不新增依赖、公开子路径、Engine 实例方法或第二套动画时钟。

## 公共接口

```ts
createSpriteSheet(
  atlasLease: AssetLease<Texture>,
  frames: readonly SpriteSheetFrameInput[],
): SpriteSheet;

interface SpriteSheetFrameInput {
  readonly name: string;
  readonly x: number;
  readonly y: number;
  readonly width: number;
  readonly height: number;
}
```

不可直接构造、已冻结的 `SpriteSheet` 外观包含只读 `frameCount`、`names`、`atlasWidth`、`atlasHeight`、`isDisposed`，以及 `getRegion(name)`、`createBitmap(name)` 和幂等 `dispose()`。方法与 getter 必须使用原对象本身作为接收者；把方法借给另一图集无效。公开类型不暴露可构造类或装配端口。

## 输入与边界

租约必须是资源管理器签发、真实且存活的 `AssetLease<Texture>`，关联真实且开放的 Engine 上下文。Texture 必须覆盖整张图像：原点为零，尺寸等于图像尺寸；裁剪后的 Texture 会被拒绝。既有合法 Runtime 上下文装配仍受支持，准入不依赖 Engine 类实例的私有名单。图集创建不获取新租约，也不释放原租约。

帧数组包含 1–1024 个自有索引记录和自有 length。每项必须为非空对象，排除数组和函数，并拥有自有 `name/x/y/width/height` 字段；额外字段不读取、不采用。五个字段按上述顺序暂存，完成整张表的读取后才做语义校验。数组索引缺失或项目并非记录时，在该位置拒绝。每次调用方可控制的操作成功后都会检查资源生命期，此检查位于读取操作的 catch 之外。

名称必须是精确字符串，长度 1–128 个 UTF-16 码元，全表名称合计最多 32768 个码元。大小写、空白、代理码元及 `__proto__` 均原样保留，不裁切、不规范化；完全重复的名称无效。`names` 保留输入顺序。坐标必须是安全整数：`x/y >= 0`、`width/height > 0`；边界之和仍须安全且位于图像内。负零转换为零。允许矩形重叠，也允许多个名称指向相同矩形；旋转、裁边、轴心和图集打包不属于 SS1。

图集拥有已冻结的元数据与矩形。调用方后来修改数组或记录，不会改变已发布的表；未知字段不会进入元数据。这是拥有副本的契约，不代表物理内存或垃圾回收结论。

## 资源所有权与生命期

`getRegion` 返回精确名称对应、由图集拥有的冻结矩形。图集关闭、租约释放、Texture 关闭或 Engine 关闭后，元数据与有效名称查询仍可读取。

`createBitmap` 返回使用原租约和指定裁剪的真实 Bitmap，所有权归调用方。每次调用返回新对象；图集不缓存它，也不自动放入 Scope。调用方应立即将其交给 Scope 管理。关闭图集会撤销继续创建 Bitmap 的能力，并放下其存活租约、图像引用；不会释放租约，也不会关闭调用方的 Bitmap。因此，只要自身资源仍然有效，已有 Bitmap 与序列控制器可以继续使用。

创建顺序先检查精确接收者、图集关闭状态、Engine 开放状态及同图集重入，再读取存活图集和名称。忙碌守卫覆盖构造与设置裁剪；可信操作成功后，在发布对象前再次检查生命期。构造已返回对象而后续失败时，只关闭该局部 Bitmap 一次；构造尚未返回对象便失败时，不虚构局部清理。保留主错误代码和原始 cause，包括调用方抛出 `undefined`；相关清理错误单独保留。

内部 Bitmap 接缝只捕获原构造、裁剪、关闭三个操作。有限原型验证仅涉及图集入口初始化前后替换 Bitmap 的 `sourceRect` setter 或 `dispose` 方法，不扩展为抵御祖先类或 JavaScript 内建对象任意修改的承诺。公共根入口不导出此接缝。

## 公共组合

以下租约已经由真实 Engine 资源管理器获取，并由调用方资源 Scope 管理；其图像为原创 6×2 图集。可运行示例包含原始像素、提供者注册与完整清理。

```ts
import { createSequenceClip, createSpriteSheet } from '@egret/engine';

const sheet = resources.use(createSpriteSheet(lease, [
  { name: 'red', x: 0, y: 0, width: 2, height: 2 },
  { name: 'green', x: 2, y: 0, width: 1, height: 2 },
  { name: 'blue', x: 3, y: 0, width: 3, height: 1 },
  { name: '__proto__', x: 3, y: 0, width: 3, height: 1 },
]));
const actor = resources.use(sheet.createBitmap('red'));
const icon = resources.use(sheet.createBitmap('__proto__'));
engine.stage.addChild(actor);
engine.stage.addChild(icon);
const clip = createSequenceClip({
  atlasWidth: sheet.atlasWidth, atlasHeight: sheet.atlasHeight,
  frames: [
    { ...sheet.getRegion('red'), durationSeconds: 0.125 },
    { ...sheet.getRegion('green'), durationSeconds: 0.25 },
    { ...sheet.getRegion('blue'), durationSeconds: 0.125 },
  ],
});
engine.advanceTime(0); // Absolute source baseline; no tick.
const playback = engine.createSequencePlayback(animation, actor, clip);
playback.start();
engine.advanceTime(0.125); // Absolute source time; selects green.
sheet.dispose(); // Existing caller-owned Bitmaps keep their lease.
```

在仓库根目录执行 `node examples/spritesheet-headless.mjs`。记录型宿主验证公共组合与显式时钟推进；捕获和渲染不会推进动画时钟。该示例不绘制原生像素。

## 拒绝类别与验收

| 拒绝 | 含义 |
| --- | --- |
| `SPRITE_SHEET_LEASE_INVALID` / `SPRITE_SHEET_ATLAS_INVALID` | 租约身份无效／完整图像图集准入 |
| `SPRITE_SHEET_INPUT_INVALID` | 数组、记录、必填字段或原始类型拒绝 |
| `SPRITE_SHEET_NAME_INVALID` / `SPRITE_SHEET_LIMIT` | 空名称或重名／帧数与 UTF-16 限额 |
| `SPRITE_SHEET_REGION_INVALID` / `SPRITE_SHEET_FRAME_UNKNOWN` | 矩形无效／精确名称不存在 |
| `SPRITE_SHEET_READ_FAILED` | 调用方可控制的读取操作抛出，保留原始 cause |
| `SPRITE_SHEET_INVALID` / `SPRITE_SHEET_DISPOSED` / `SPRITE_SHEET_REENTRANT` | 接收者／撤销／同图集创建守卫 |
| `SPRITE_SHEET_BITMAP_FAILED` | 可信 Bitmap 构造或裁剪操作抛出 |

既有 Engine、Texture、租约生命期错误保留自身权威。成功的 getter 若终止资源，会返回终止生命期拒绝，不误标为读取异常。由于完整暂存先于语义校验，后续来源读取异常可能先于较早的语义错误。

SS01–SS10 是规格类别，不是 Node 测试数量。公共行为、原操作故障单元、精确消费者诊断、包策略、记录型示例、原生不透明像素及最终交付分别留证。参见[核验阅读](命名图集证据.md)。完整 Spine R020/V020、迁移 R008/V006、完整 UI/EUI、手机／原生 SDK 与性能仍须分别验收。
