# 证据通道：绑定到确切字节的检查

[English](../../en/docs/evidence-lane.md) | 中文

改动产品文件，不再需要先登记一份后继身份才能合并。把产品文件和记录下来的字节做比较的那些检查仍然存在，也仍然可以运行。它们只出报告，不做裁决。

产品文件指某个包的源文件或构建产物：`packages/<name>/src`、`dist`、`web`、`rendering` 之下的任何文件。

## 为什么

六个边界工具、一个共享的严格类型辅助模块和它的十二个调用者、B1 验证器、两个维护工具，各自记录了产品文件的 SHA-256。改一行源码，就要在其中每一个里登记一层新记录，而每一层都保留着之前的所有层。第一轮 2D 成本削减改了四个源文件，却要改动 23 个与渲染无关的工具和测试文件。

一个记录下来的哈希只证明一件事：被检查的就是这些字节。它不说明这些字节是对的，对下一个版本也什么都没说。评审者需要合并检查回答的是：产品的行为是否还在，对外的类型是否还一样。这两件事现在直接检查。

## 什么决定能否合并

`node tools/verify.mjs` 依次运行：

| 检查 | 确立什么 |
| --- | --- |
| `build` | 每个包都能编译 |
| `check-boundaries` | 包的依赖方向、批准的导入边、核心不依赖 DOM |
| `check-spine-content` | 可选的 Spine 依赖及其声明 |
| `resource-scene-boundary` | 资源场景的模块闭包 |
| `atlas-frame/boundary` | 图集帧场景的模块闭包和路由 |
| `check-type-lanes` | 十四个功能的使用方代码按记录编译通过、按记录报错 |
| `check-types` | 其余对外类型样例及其诊断 |
| `test` | 证据通道之外的每个行为测试文件 |
| `verify-spine-f2-source` | Spine 实验源码 |

其中没有一项拿产品文件和记录的哈希做比较。

## 从保留的类型检查中移除的条件

`check-types` 有三处记录了产品字节。现在都已移除：

- mesh 通道按 `Mesh2D.d.ts` 的哈希来选择期望的诊断。现在它期望泛型声明报告的那一条；报告别的诊断的声明会在比较本身失败。
- scene 通道把它的编译闭包里的每个声明与记录的哈希比较，并把这些声明的清单与记录的清单比较。现在它只要求编译器自带的库、它的样例和它的配置与记录的字节一致。
- 同一通道还记录了浏览器声明内部 33 处缺失的浏览器名称的行号和列号，任何让某个声明移动一行的改动都会被它拒绝。现在它要求每条诊断都是已记录的代码之一、位于引擎的浏览器声明内部，并且至少有一条。它的另外五条通道没有变化。

`tests/project-boundaries.test.mjs` 里的类型门禁用例，在给四个包的每个声明产物各加一行首行和一行末行之后，把整个门禁再运行一遍。

## 类型通道

一条类型通道是 `tests/types` 下的一个编译配置，加上编译器为它打印的确切文本行。正向通道什么都不打印。反向通道打印使用方必须得到的错误。这张表是 `tests/types/type-lanes.json`。

~~~text
node tools/check-type-lanes.mjs
node tools/check-type-lanes.mjs --record
~~~

第一条命令编译每条通道并比较。第二条命令按编译器现在打印的内容重写这张表。只有在确实打算改变对外类型时才使用它，然后阅读差异：每一行变化都是使用方会看到的变化。表里不记录任何文件身份，所以不动对外类型的改动永远不会碰到它。

编译器用模块在本机上的位置来称呼它。工具把检出目录替换成 `<repository>`，这样一张表可以用于每台机器。

这些通道是在此前绑定字节的类型重放全部通过的那棵树上录制的。那些重放拥有的 28 条通道里，有 23 条与它们保存的诊断逐行一致；另外 5 条在辅助模块内部早已被后来的观测取代。

## 哪些成了证据

`tools/lib/evidence-lane.mjs` 列出针对某一组确切产品字节编写的工具和测试文件。

| 类别 | 检查 |
| --- | --- |
| 源码和产物身份 | SpriteSheet、序列播放、浏览器 PNG、位图资源槽、位图绑定票据、图集导入这六个边界工具，以及它们的测试文件 |
| 类型重放 | 十四个绑定到已记录的源码和声明身份的 `*-types` 工具，`tests/strict-successor-boundaries.test.mjs` 和 `tests/sequence-reset-types.test.mjs` |
| B1 验证器 | `tests/b1-webgpu-verifier.test.mjs` |
| 维护历史 | `tests/publication/incremental-checks-evidence.test.mjs`：按记录的字节重建工具早期版本的那些用例 |

维护历史用例绑定的不只是产品文件的字节，还有工具的字节：它们重放 `tools/check-types.mjs` 和各边界工具过去的样子。

~~~text
node tools/evidence.mjs --list
node tools/evidence.mjs --tools
node tools/evidence.mjs
~~~

报告把每项检查标为 `HOLDS` 或 `STALE`。一项过期的检查，对它编写时面对的字节是成立的。对当前的字节，它什么都没说，正反两个方向都没有。它不是失败，也不是通过。

`node tools/current-identities.mjs` 报告 `examples`、`verification`、`knowledge-base/evidence` 下哪些已保存的证据文件记录的身份已不是当前身份。`--write` 把每个产品文件的身份写入 `current-identities.json`（Git 忽略该文件），并打印这张表的一个摘要。这个摘要指代构建出来的整个产品；证据可以把它和提交一起记录下来。合并到 `main` 之后，CI 在运行摘要里打印这个摘要和两份报告。

证据通道引入时，其中每个工具对当时的文件都成立。有十七个维护历史用例从那一刻起就是过期的，因为它们重放 `tools/check-types.mjs` 的已记录字节，而同一次改动把类型重放从这个文件里移走了。

要更新一份证据，就针对当前文件重新运行它的工具或流程，并把结果连同运行时的身份一起保存。更新是一次有意的动作，有它自己的评审。它永远不是合并某个改动的条件。

## 移动了的测试，和一个改动了的测试

以证据工具为对象的测试文件，本身也是证据。`tests/project-boundaries.test.mjs` 原先两种都有：包边界用例和七对资源使用方对照保留在原处，对严格类型工具的重放移到了 `tests/strict-successor-boundaries.test.mjs`。两者共用 `tests/helpers/project-fixture.mjs`。没有删除或改写任何用例。

`tests/spritesheet-fault.test.mjs` 是行为测试，它曾把两个构建产物模块的三组旧身份作为前置条件记录下来。现在它在启动时读取一次构建出来的这一对模块，并在各用例运行期间要求整个 SDK 保持这些字节不变。它的故障注入仍然要求被替换的代码块恰好出现一次，否则拒绝。

共享基线检查在推送前运行三个正例。其中 B1 产物闭包这一项绑定到产物字节，现在属于证据；保留两项。

## 放弃了什么

证据工具在检查字节的同时也顺带检查了别的东西，例如一个功能允许加载的确切模块清单。凡是 `check-boundaries`、保留下来的边界检查或某个行为测试覆盖了同一条规则的，合并时仍然强制执行。只有证据工具覆盖的，现在只报告，不强制。

记录下来的哈希还让未经评审的产品文件改动无处可藏。现在这一点由对改动本身的评审来承担。

## 贡献者规则

- 不要把拿产品文件和记录哈希做比较的检查加进合并序列。`tools/verify.mjs` 会拒绝列表里出现证据工具。
- 需要确切字节的新检查，从一开始就属于证据通道。
- 不要为了让证据工具重新成立而给它们加后继层。要么更新证据，要么让它保持过期。
- 非产品文件的哈希不受影响，例如第三方声明和冻结的编译器输入。
