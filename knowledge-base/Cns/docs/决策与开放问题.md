# 决策与开放问题

[English](../../en/docs/decisions-and-open-questions.md) | 简体中文

技术选择将产品约束转成可维护实现，每项都需要理由、替代方案、可测后果及替换条件。因此产品要求与技术决策分开记录：[需求登记](../registry/需求.json)定义范围，[决策登记](../registry/决策.json)保存候选取舍和证据。

## 当前的技术候选

D001–D016设计集合覆盖增量提取、有序UI/三维执行、帧计划、前向渲染、后端、桥接、UI、动画、资源、调度、诊断和版本。D013处理构建分离，D014处理模块化原生Runtime，D015处理可选GPU-AI，D016处理工程/API/质量结构。该集合登记为proposed且无批准负责人/日期；后来的有限包实现不自动批准全部更广选择。实验专属记录分别保留自身范围。

接受方案需考虑正确性和性能证据、失效条件、迁移及维护成本和回退方法。临时原型方案允许替换。D005保留原生图形实现选择，D006按测量确定实际Rust/C++/WASM热点。

## 按依赖推进的开放问题

| 问题 | 需要的依据 | 影响 |
| --- | --- | --- |
| Q001 轻量 3D 的标杆玩法和规模 | 场景、角色、特效、动画、UI 及交互清单 | 帧时间、内存、渲染功能和资源预算 |
| Q002 首批宿主与最低设备 | 创作者需求、发行场景和能力探测 | 后端、兼容下限、发布顺序 |
| Q003 可接受的效率和质量门槛 | 同质量基线、设备与持续测试 | H001 至 H004 的量化验收 |
| Q004 旧工程支持版本与样本 | 自有或授权工程、外部依赖和历史行为基线 | V006 范围、自动化目标与成本 |
| Q005 创作者的修改路径 | 无开发经验者及已有手游经验者的任务测试 | 编辑器、代码可见度、Agent 工具 |
| Q006 团队、预算和交付日期 | 模块范围、验证结果和人员能力 | 里程碑承诺与职责分配 |
| Q007 公开仓库、授权和治理 | 拟公开资产清单、第三方组件许可、维护职责 | 社区代码入口、许可证与发布方式 |
| Q009 原生SDK设备与VM所有权 | App/SDK宿主、实际VM构建、owned/borrowed设备、D3D11接入是否必要 | 原生图形库、FFI与发布范围 |
| Q010 编译反馈与AI增强预算 | 代表工程、计时阶段、模型/SDK硬件条件、同画质成本 | H008及可选D015取舍 |
| Q008 商业模式与服务边界 | 创作者价值、成本、导出和持续维护需求 | 本地/云端分工、收费与生态服务 |

Q001–Q004先形成可执行验证需要的内容、宿主、预算和旧样本边界，其余问题随依赖具体化收敛。开源建设已确定；Q007持续核查具体资产、仓库信息、许可和维护治理，不使全部工程等待所有答案。
