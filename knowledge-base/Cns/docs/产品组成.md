# 产品组成

[English](../../en/docs/product-components.md) | 简体中文

白鹭以共同工程模型连接创作、执行与发布。渲染和Runtime提供可运行基础，工程服务、资产处理与创作工具让它能够编辑和交付。下表描述完整产品的职责方向。当前有限核心包见[核心进展](core-progress.md)，[需求](../registry/需求.json)与[交付](../registry/交付.json)区分正式范围及完成工作。私有SDK预览不等于完整可安装创作产品。

| 组成 | 职责与主要输出 | 关键边界 | 交付关联 |
| --- | --- | --- | --- |
| 渲染引擎与运行时 | 场景、UI、动画、资源执行、输入、调度、GPU 后端和恢复 | 管理每帧执行；AI 推理不进入帧循环 | V002 |
| 工程模型与开发接口 | 稳定对象身份、场景与资源结构、版本、引用、命令、诊断 | 成为代码、AI 与可视化编辑的共同语义 | V003 |
| 资源与动画管线 | 导入、加工、依赖、图集、字体、骨骼、序列帧、3D 资产和目标构建 | 保留源资产与许可信息；运行产物按宿主裁剪 | V004 |
| 创作工作台 | 创作意图、场景/UI 编辑、代码、试玩、诊断、修复与撤销 | 每次修改都对应明确对象和工程差异 | V005 |
| Agent Skills 与 MCP 接口 | 读取工程、提出并执行修改、调用构建与测试、解释反馈 | 工具调用共享工程命令；协议接入本身不保证任务成功 | V003、V005 |
| 平台适配与发布工具 | 宿主能力配置、SDK 服务、打包、上线检查、版本更新 | 图形 API、宿主服务和渠道审核分别验收 | V005 |
| 旧白鹭工程迁移工具 | 盘点、确定转换、AI 修复、对照测试、差异报告和回滚 | 不以启动成功代替完整迁移验收 | V006 |
| 样本与质量基础设施 | 性能基线、行为回放、视觉比对、设备矩阵和回归资产 | 测试样本的授权、版本和可重复性明确 | V001 |
| 知识库与社区协作 | 需求、方案、证据、交付和变更的共同入口 | 从第一天公开文档、知识库和设计讨论；受限资产保留授权边界 | V007 |

## 一项修改如何经过这些组成

替换角色并保留装扮界面，先通过稳定引用定位角色、动画、材质与UI规则。工程服务检查资源和目标能力，准备局部差异，在已知版本上执行导入及编辑。真实Runtime预览结果并回放装扮交互，导出前检查渲染、事件及适用预算；失败回到可继续编辑的版本。

AI、可视化工具和发布共用定位、版本与诊断合同。各组成可以增量交付，不预先承诺编辑器框架、云服务、商业模式或市场。

## 自研与整合的边界

白鹭负责Runtime语义、持久工程和迁移之间的一致性。字体、编解码及专业库在质量、包体、平台、版本、许可和维护成本明确后可作为显式依赖；组件选择依据需求与技术证据。

社区先参与可审查接口与验收示例，再按选定边界贡献实现。提案和替代在[决策记录](决策与开放问题.md)保留理由。

## 自主核心与公共依赖

R015要求场景/UI语义、调度与合成、资源生命周期、动画合同、工程事务及迁移规则遵循独立编写的白鹭规格。通用依赖保留自身身份。[实现规范](独立实现与第三方依赖规范.md)分别记录来源、第三方能力及许可义务；AI辅助工作同样经过普通审查与验证。
