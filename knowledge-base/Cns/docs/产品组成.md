# 产品组成

[English](../../en/docs/product-components.md) | 简体中文

新白鹭是一套从创作到运行和发布的体系。以下模块边界是候选组织方式；确认的产品要求与实现状态分别查阅[需求](../registry/需求.json)和[交付](../registry/交付.json)。当前没有可安装的新白鹭产品。

| 组成 | 职责与主要输出 | 关键边界 | 交付关联 |
| --- | --- | --- | --- |
| 渲染引擎与运行时 | 场景、UI、动画、资源执行、输入、调度、GPU 后端和恢复 | 管理每帧执行；AI 推理不进入帧循环 | V002 |
| 工程模型与开发接口 | 稳定对象身份、场景与资源结构、版本、引用、命令、诊断 | 成为代码、AI 与可视化编辑的共同语义 | V003 |
| 资源与动画管线 | 导入、加工、依赖、图集、字体、骨骼、序列帧、3D 资产和目标构建 | 保留源资产与许可信息；运行产物按宿主裁剪 | V004 |
| 创作工作台 | 创作意图、场景/UI 编辑、代码、试玩、诊断、修复与撤销 | 每次修改都对应明确对象和工程差异 | V005 |
| Agent Skills 与 MCP 接口 | 读取工程、提出并执行修改、调用构建与测试、解释反馈 | 工具调用共享工程命令；协议接入本身不保证任务成功 | V003、V005 |
| 平台适配与发布工具 | 宿主能力配置、SDK 服务、打包、上线检查、版本更新 | 图形 API、宿主服务和渠道审核分别验收 | V005 |
| 旧白鹭工程迁移工具 | 盘点、确定转换、AI 修复、对照测试、差异报告和回滚 | 不以启动成功代替完整迁移验收 | V006 |
| 样本与质量基础设施 | 性能基线、行为回放、视觉比对、设备矩阵和回归资产 | 测试样本的授权、版本和可重复性明确 | V001 |
| 知识库与社区协作 | 需求、方案、证据、交付和变更的共同入口 | 从第一天公开文档、知识库和设计讨论；受限资产保留授权边界 | V007 |

## 一项修改如何经过这些组成

创作者要求“换一名 3D 角色，并保留装扮 UI 的交互”。工具先定位角色、动画、材质及引用；检查资源和目标宿主能力；提出局部差异；执行导入与修改；预览并回放装扮操作；确认渲染、事件及预算；生成可发布产物。失败时回到可继续编辑的版本。

AI、编辑器和发布系统应使用同一套定位、版本与诊断语义。候选方案没有要求所有工具同时上线，也没有预先确定编辑器框架、云端服务、商业模式或插件市场。

## 自研与整合的边界

渲染运行时、创作工程语义和迁移的一致性需要由白鹭掌握。字体、编码、基础库或专业能力可以评估成熟组件，但引入前要记录质量、包体、平台、版本与许可代价。历史“全部自研”是经验来源，不自动成为所有新模块必须重做的要求。

社区首先参与接口和验收定义，再按已选定的模块边界贡献实现。工具形态与依赖选择经过提案，进入[决策记录](决策与开放问题.md)。

## 自主核心与公共依赖

R015要求核心独立实现。场景/UI、帧调度与合成、资源生命周期、动画语义、工程事务和迁移规则由白鹭按自己的规格编写；通用公共库以明确依赖接入。核心代码与依赖能力分别披露，执行[独立实现与第三方依赖规范](独立实现与第三方依赖规范.md)。
