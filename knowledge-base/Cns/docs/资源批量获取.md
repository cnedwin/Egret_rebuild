## API 与使用

RG1 新增一个 Engine 实例方法，以及引擎根入口的三个**仅类型**导出：`AssetGroup`、`AssetGroupState`、`AssetGroupOptions`。

```ts
createAssetGroup<T>(
  scope: Scope,
  refs: readonly AssetRef<T>[],
  options?: AssetGroupOptions,
): AssetGroup<T>;
```

不透明、冻结的 group 提供只读 `state`、`ready: Promise<readonly AssetLease<T>[]>` 和 `dispose(): void`。状态为 `pending`、`ready`、`failed`、`disposed`。输入中的 `T` 必须同质且保持不变性；没有异质元组重载。必需的私有类型品牌拒绝结构伪造，不生成运行时品牌。没有 group 构造器、根入口工厂、新分组子路径或 runtime 分组外观。

调用方登记 provider，并提供 `HostAdapter`。以下示例采用既有的真实 Texture/Bitmap API，展示 CPU 夹具，不进行下载、解码或 GPU 上传：

```ts
import {
  Bitmap, createAssetRef, createAssetType, createEngine,
  createImageData2D, createTexture, isTexture,
} from '@egret/engine';
import type { AssetGroup, HostAdapter, RenderFrame2D, Texture } from '@egret/engine';

export async function captureScene(host: HostAdapter): Promise<RenderFrame2D> {
  const engine = await createEngine({ host });
  const scope = engine.createScope();
  const type = createAssetType('scene texture', isTexture);
  const fixtures = new Map([
    ['red', new Uint8Array([220, 40, 40, 255])],
    ['blue', new Uint8Array([40, 80, 220, 255])],
  ]);
  try {
    engine.assets.register(type, {
      async load(ref) {
        const pixels = fixtures.get(ref.id);
        if (pixels === undefined) throw new Error('Unknown fixture');
        return createTexture(createImageData2D({ width: 1, height: 1, pixels }));
      },
      dispose(texture) { texture.dispose(); },
    });
    const group: AssetGroup<Texture> = engine.createAssetGroup(scope, [
      createAssetRef(type, 'red'), createAssetRef(type, 'blue'),
    ], { concurrency: 2 });
    const leases = await group.ready;
    const red = scope.use(new Bitmap(leases[0]!));
    const blue = scope.use(new Bitmap(leases[1]!));
    blue.x = 1;
    engine.stage.addChild(red); engine.stage.addChild(blue);
    return engine.captureFrame({ width: 2, height: 1 });
  } finally {
    scope.dispose();
    await engine.dispose();
  }
}
```

group 拥有成员的清理权；Bitmap 借用这些租约。`scope.use(member)` 会拒绝并返回 `OWNERSHIP_CONFLICT`，原始 Scope 也不例外。提前调用 `member.release()` 仍然幂等，不改变已 ready 的 group，也不撤销其他租约。借用者必须在整个使用期间保持其精确成员存活。实际执行的夹具版本为 `examples/asset-group.mjs`；场景退役后，其保存的 CPU 帧仍包含自有图像快照。这份 CPU 输出不建立原生像素验收。

## 准入、调度与退役

- 接受实际 Array，共 **0–128 个输入位置**，重复项也计数。长度读取一次；每个数字位置必须是自有属性，并读取值一次。原型提供真实 ref 的空洞仍拒绝。不得消费调用方迭代器或保留可变输入/options。options 是非 null、非 Array 的对象，只读取 `concurrency` 一次；仅 `undefined` 使用默认 **4**，合法值为整数 **1–16**。这是工程边界，没有实测吞吐量声明。
- 调用方读取前，检查开放 Engine 和真实同引擎、开放的 Scope。每次读取或 proxy/getter 抛出之后，按 Engine、Scope 顺序复核生命周期；生命周期变化优先，否则保留原抛出值为 cause，包括 `undefined`。加载前，管理器预检全部输入中的真实 ref、已登记 provider 及既有/输入内的 ID/type 配对，不创建身份、代次或需求预留。
- 先把惰性 group 纳入 Scope，再开始加载。准入期间递归调用工厂得到 `ASSET_GROUP_REENTRANT`。激活前清除准入 busy，因此同步 provider 回调可以创建另一个 group。私有组装捕获原始管理器和 Scope 操作。runtime 根入口的仅类型组装端口为 `AssetGroupOperations`，包含 `admitGroupRefs`、`acquire`、`claimGroupLease`、`releaseGroupLease`。可选的 `EngineContext.registerAssetGroupOperations` 回调将冻结的真实管理器操作交给 Engine 私有闭包；普通 context 与既有文字缓存行为保持原样，不新增 runtime 根入口值导出。
- `concurrency` 限制本组已启动、尚未由结算处理器退还槽位的获取调用。调用 acquire 前先占槽，并观察每个结果；仅在 pending 且存活时按输入顺序补位。这个局部等待窗口不限制全局网络活动、provider 线程或其他 Engine 需求。重复位置获得不同的真实租约，管理器仍可合并其加载/value。
- 全部位置成功后，才发布一个冻结、按输入顺序排列的成员数组；空输入立即 ready。本组首先观察到的终结转换获胜。获取/成员提交失败先设为 `failed`、拒绝 ready，再执行本组取消/释放回调。管理器拒绝可能先于 group 的 Promise 处理器运行 provider abort 钩子；钩子触发的销毁因此可能先获胜。
- 失败/销毁停止排队启动，只撤回本组等待者，并按**输入逆序**尝试释放全部已知成员，错误不阻止后续尝试。外部等待者/租约继续存活。迟到的 provider value 仍由管理器负责；已经交付、但在 group 终结后才到达其处理器的租约，由该处理器释放。provider 永不完成也不阻止 pending ready 及时结算。Scope 销毁同步退役已知成员，迟到结果不能复活 group。
- Engine 关闭先将**所有被跟踪的 pending/ready group 设为 disposed**，结算其 pending ready，再执行首个 group 的 abort/释放回调，之后沿用既有关闭序列。销毁 ready group 保留其先前成功的 Promise；failed/disposed 不再变化。Engine 关闭不增加等待 provider 空闲或 group 清理的 Promise。

预检是一个快照。其他需求随后可能占用排队项的 ID，此时原始 acquire 检查仍有最终权威。invalidate 可能使同一结果包含**不同的实际资源代次**。ready 不承诺同步资源快照、版本兼容或多资源事务。

## 错误与诊断

| 边界 | 结果 |
| --- | --- |
| Engine/Scope 准入 | 既有 `ENGINE_CLOSED`、`SCOPE_CLOSED`；伪造/外来 Scope：`ASSET_GROUP_SCOPE_INVALID`。 |
| 输入/options/准入重入 | `ASSET_GROUP_REFS_INVALID`、`ASSET_GROUP_OPTIONS_INVALID`、`ASSET_GROUP_REENTRANT`；保留调用方读取 cause。 |
| 全输入管理器预检 | 既有 `ASSET_REF_INVALID`、`ASSET_PROVIDER_MISSING`、`ASSET_TYPE_MISMATCH`、`ASSET_MANAGER_CLOSED`。 |
| 外观接收者/成员提交 | `ASSET_GROUP_INVALID`；真实租约身份、引擎亲和性或归属拒绝：`ASSET_GROUP_MEMBER_INVALID`，作为获取失败的 cause。 |
| pending 失败/销毁 | `ASSET_GROUP_ACQUIRE_FAILED` 保留原获取错误；`ASSET_GROUP_DISPOSED` 保留观察到的 `ENGINE_CLOSED`/`SCOPE_CLOSED`，开放时手动销毁为 `undefined`。 |
| 清理 | 管理器捕获的 provider 销毁错误保留 `ASSET_CLEANUP_FAILED` 和原 cause；仅 group abort/释放操作直接抛出时报告 `ASSET_GROUP_CLEANUP_FAILED`，phase 为 `assets`、severity 为 `error`。两者都不替换终结 ready；Engine 关闭期间保留清理 cause。 |

group 自创建起就在内部观察 ready 拒绝；使用者仍应处理 `await group.ready`。接收者检查和捕获操作是有限权威控制，不是通用沙箱保证。
