## 如何推进选择

把问题拆为机制事实、白鹭实现与适配、产品效果。固定版本源码和官方规格支撑机制判断；实现与适配需要对应回归；性能、功耗、包体与宿主兼容需要实际运行环境。当前环境能够完成的研究与可逆实现持续推进，设备相关结论保留待测状态。

| 情况 | 行动 | 形成的设计与验证 |
| --- | --- | --- |
| 标准机制及成熟实现符合白鹭目标 | 固定版本与已读范围，提炼机制和错误路径；明确公共依赖与自主模块 | 采用已知原理，自主模块验证规格正确性 |
| 接口、宿主或资源模型不同 | 评估公开接口集成成本，形成白鹭适配合同或独立设计 | 验证边界交接、生命周期、迁移与失败路径 |
| 多个方案各有代价，当前缺少量化条件 | 选可替换的研究基线，记录备选与切换条件 | 推进可逆实现，在对应环境补比较 |
| 上游维护记录揭示缺陷或语义缺口 | 核对issue、合并PR与受影响版本；依赖跟踪修复，自主模块补对应回归 | 保留具体反例与适用版本，不外推整套项目质量 |
| 问题涉及真实设备表现 | 登记最小设备矩阵、输入、测量方法与未测项 | 先完成平台无关合同，实机结果决定支持范围 |
| 属于白鹭差异化或缺少可用方案 | 开展必要的新设计与原型研究，记录替代方案和失败输入 | 用正确性、产品任务和成本证据决定保留方案 |

采用方式统一登记为机制研究、研究运行依赖、显式第三方依赖或自主实现。资料阅读形成研究依据；集成与架构决策按各自状态管理。基础机制的研究和可逆适配可以在既有需求范围内继续，具体产品选择由相应技术决策与验收记录确定。

## 每条参考留下什么

记录官方仓库或文档URL、tag与完整commit、文件或接口、已读与已运行范围、取得文件的hash、维护日期、许可线索、适用机制、与白鹭合同的差异，以及集成回归和替换条件。主分支用于发现路径；形成版本化设计依据时固定快照，不把不同版本组合成未经说明的整体。

研究优先检查关键调用链和错误路径。缓存检查键、失效、持有和销毁；恢复检查数据来源、异步取消及外部资源责任；文字检查实际测量、绘制与上传。README、厂商性能数字和项目热度作为背景资料，不替代这些机制证据。

拟采用依赖时，分别核查实际文件、字体、资源、转码器和下游依赖的声明。依赖保持独立身份，本地补丁记录上游基线和修改。自主实现记录白鹭规格、设计取舍和研究依据，按[实现来源模板](../templates/实现来源记录.md)接受来源复核。

## 研发与验证分工

| 工作 | 主要产出 | 证据边界 |
| --- | --- | --- |
| 成熟机制研究 | 固定版本摘要、维护反例、接口与语义比较 | 源码与文档说明所读范围，未运行内容保持未运行 |
| 自主核心实现 | 规格、代码、回归、实现来源与设计说明 | 行为通过限于对应切片，不扩展为完整产品通过 |
| 第三方集成 | 依赖清单、适配代码、声明、集成回归 | 依赖能力与白鹭适配能力分别归属 |
| 产品与设备验证 | 同任务样本、功能画质对照、设备与宿主结果 | 支持范围和收益以实际环境结果为依据 |

白鹭重点投入复杂UI与3D合成、有限内存下的资源生命周期、轻量构建、AI持续编辑的工程合同、旧工程语义迁移和目标平台体验。通用设施的依赖选择通过白鹭接口整合，工程原件、稳定身份、诊断与撤销由白鹭层统一组织。

已有71项局部研究结果保持原范围。Three r186参考链17项检查属于第三方研究运行；三个自主headless包已有44/44行为检查和11项负类型断言。它们分别回答不同问题，测试数量不作为跨范围完成度。GPU、Native、真实宿主、性能与CI仍待对应验收；本次文档整理未重跑或扩大既有结果。
