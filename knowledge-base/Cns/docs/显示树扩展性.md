## 源码诊断与基线

在源码基线 `d58e624942ec485d66003ec9bb48e5edab6a6374`，`addChild` 的预检和最终验证遍历接收者的既有后代，随后又对整棵树提交绑定。因此，持续向已绑定的平坦容器逐个追加子对象会重复访问旧兄弟，累计遍历呈二次增长。`numChildren` 与 `getChildAt` 复制子列表快照；即使对象位于尾部，分离仍通过 `indexOf` 搜索。

| 2,000 | 199.83 ms | 2.49 ms | 1.08 ms |
| 4,000 | 976.23 ms | 2.32 ms | 2.46 ms |

## 挂接边界

对已绑定接收者，挂接检查接收者及**完整的待挂接子树**，在初始可用性检查后保留接收者自身的可绑定回调，不会重新执行接收者下无关既有后代的可用性钩子。在接收者可绑定回调之前检查 Engine 开放状态；若待挂接钩子关闭 Engine，仍优先返回 `ENGINE_CLOSED`。这项更窄的回调边界是明确约定的行为。**初始未绑定**接收者仍保留包括既有后代的整树预检和最终绑定验证，即使预检钩子在过程中将其绑定，也保持该路径。

子类钩子可能重入并改变任一棵树。可执行回调的预检结束后，挂接必须重新读取当前 Engine 与内部树状态，再以不调用回调的方式检查存活、Stage 根限制、环路及完整待挂接子树的归属。跨 Engine 和绑定不一致仍拒绝。只有最终验证全部成功后才提交绑定及内部分离／挂接；拒绝不会由该操作留下部分绑定或重挂接。钩子的副作用仍属于其自身回调范围。释放与清理所有权继续遵循既有生命周期约定。

## 成本边界

| 操作 | 有界改动及保留成本 |
| --- | --- |
| 向已绑定接收者追加 | 避免重复访问无关旧兄弟；待挂接子树与祖先环路检查仍需工作量。 |
| `numChildren`／`getChildAt` | 直接以常数时间读取数量／索引，不复制列表。 |
| 分离最后一个子对象 | 直接检查并移除末尾元素。 |
| 移除任意中间子对象 | 搜索和数组移动仍随兄弟数量线性增长。 |
| 向初始未绑定树追加 | 整树发现／绑定仍可能重扫既有后代。 |

本增量不对树构造、任意重挂接、释放、遍历或渲染作全局 O(N) 保证，也不证明性能领先。
