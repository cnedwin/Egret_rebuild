## 共享基础与不同执行顺序

每个运行实例在一个选定 GPU 后端上共享纹理、buffer、shader/pipeline 缓存、上传队列、帧临时资源和统计。逻辑场景统一，但 UI 使用布局、文字测量和命中结果生成有序列表；3D 使用相机、剔除、LOD 和材质生成不透明/透明列表。

UI 只在允许范围内合并相邻兼容项；scissor、stencil 与 alpha mask 分别声明状态/离屏依赖。2D 骨骼遵守 slot 顺序、裁剪与换装语义，不能为减少批次任意重排。3D 不透明项可按材质/深度策略排序，透明项按正确性规则组织。基线帧计划先渲染 3D 与可选后处理，再以独立清晰度合成屏幕 UI；世界空间 UI 和穿插 2D/3D 必须声明位置、深度及颜色转换。减少 DrawCall 需同时检查 CPU 排序、顶点准备、带宽和过绘成本。[Cocos 3.8 合批文档](https://docs.cocos.com/creator/3.8/manual/en/ui-system/components/engine/ui-batch.html)提供顺序和状态约束参考。

## 跨宿主能力与降级

启动时协商 profile：后端、纹理格式、目标/采样限制、计算、异步 pipeline、worker/共享内存、文字/输入、存储与生命周期；构建时验证资产兼容。不能把浏览器、小游戏/小程序、原生宿主和 Unity 内嵌宿主视为同一能力环境。

基础路径不依赖线程或共享内存；增强路径缺失时使用 CPU 变形、较简粒子、较少灯光/后处理及对应压缩格式。后端切换重建资源和管线，执行视觉回归；无法保留的必要效果在导出前明确阻断或要求选择替代，不静默删掉玩法。运行时 OOM/长时降频采用可解释质量档与恢复滞回；不能仅凭 API 存在认定宿主可用。[Godot 4.7 Web 文档](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html)限定其 WebGL2/线程条件，这些事实不能直接充当新白鹭宿主认证结果。

## 低开销与能源策略

CPU 优先消除重复布局/测量、全树扫描和短寿命分配，缓存键须包含字体、尺寸、语言、主题与裁剪状态。GPU 优先减少过绘、无用离屏目标、全尺寸后处理与重复上传；图集、批次大小、缓存面积设内存预算。桥接记录每帧次数、字节、等待和队列深度，批量变更与事件回传，避免为命中测试和测量强制同步。

静止 UI 可停止无用视觉采样或跳过允许的呈现，仍正确处理输入、计时、游戏事件和宿主要求。可见性、动画距离、目标帧率与 3D 分辨率共同控制持续负载；后台暂停可取消工作。功耗必须真机测量，温度/频率/帧时只能在标注条件下作为代理。[Android ADPF](https://developer.android.com/games/optimize/adpf)可提供部分原生环境的热/性能信号，不假定浏览器和全部宿主可用。

[Filament FrameGraph](https://google.github.io/filament/notes/framegraph.html)提供资源依赖/寿命设计参考；[KTX2 规范](https://registry.khronos.org/KTX/specs/2.0/ktxspec.v2.html)支持 mip 与通用纹理载荷。这些能力均不证明本方案能更快、更省或更轻。

## 三个原型验证门槛

下表是完整运行时原型的候选验收计划，并非本轮已完成的实验。当前研究包括有限模型合同、局部像素/上下文行为及已执行的固定 glTF 蒙皮圆柱参考链，尚未包含完整复杂 UI、完整 3D 角色/场景、完整 2D 骨骼、实际跨语言桥接或性能计时。模型漏洞、修复与复验保留在[第一轮审计](../archive/第一轮研究.md#audit)及[第二轮验证记录](../archive/第二轮研究.md#execution)/[审计](../archive/第二轮研究.md#audit)，第三轮真实资产结果见[第三轮集成记录](../archive/第三轮研究.md#execution)与[审计](../archive/第三轮研究.md#audit)；这些局部研究不能替代以下门槛。

| 原型 | 内容与观测 | 通过门槛 |
|---|---|---|
| P1 复杂 UI | 变高虚拟列表，CJK/emoji/输入，多层遮罩、主题切换；静止、稀疏更新和全脏三档。测布局/准备 CPU、分配/GC、合批、文本清晰度与命中。 | 固定回归无关键视觉/交互错误；全脏不出现失效循环；缓存预算有效。三档结果均记录，不能仅取静止优势。 |
| P2 混合渲染 | 3D 场景/角色、透明 VFX、复杂 UI、2D 骨骼裁剪/顺序/换装及序列帧。测 CPU/GPU P50/P95/P99、上传、过绘、中间目标、桥接和峰值内存。 | 事件、挂点、遮罩、排序与颜色正确；增强/基础路径满足预定视觉等级；未解决的尾部卡顿或资源峰值阻止选型批准。 |
| P3 后端/运行时 | 同资产跨待选宿主：冷加载、首交互、首次 shader/特效、换资源/卸载、后台恢复、设备丢失和 20–30 分钟持续运行。 | 资源/镜像可恢复，无重复事件或失效句柄；重复装卸无持续内存增长；队列有界。加载、帧时与能源预算必须按设备事先约定并满足。 |

所有原型先锁定设备、宿主/版本、画质、总/可见节点与资源、release 构建、网络、亮度和热状态，再对照合理优化的等价作品实现；记录失败案例与波动。P3 的持续运行时长是实验建议，不是已批准的产品预算。首批宿主顺序、团队、工期与数字性能预算尚待确定；可先完成探索，不能宣告性能验收。V001 研究部分为 in_progress，V002已有局部headless核心，V003—V006 产品实现仍未开始；R008 仍属于首个完整发布目标，V006 依赖 V001—V005。两三年优势目标还需版本回归与持续作品验证，详见[核心优势与验证](核心优势与验证.md)及[交付计划](交付计划.md)。

第二轮已部分验证独立事件流、逐租约异步资源、嵌套布局/命中和批次共享状态，并实际运行程序生成的WebGL混合场景。它们没有覆盖完整资产、文字/骨骼语义或目标设备预算；当前合同细化与下一步门槛以[技术白皮书](技术白皮书.md)、[工程规划](工程规划.md)及[第二轮验证记录](../archive/第二轮研究.md#execution)为准。

## 0.13已实现边界

实际内部DAG保持engine → runtime/contracts与runtime → contracts。无DOM `engine/rendering`采用独立ES2022 composite编译项目，仅引用contracts；浏览器`engine/web`引用该项目并保留独立输出。robust-predicates 3.0.3是精确外部包根入口例外，不是TS项目引用或新内部包；两个浏览器入口继续隔离。上文graphics/hosts/native包属于更广候选架构，不表示目录已实现。GPU缓冲所有权属于WebGPUHost，CPU资源清理不证明未来纹理生命周期。
