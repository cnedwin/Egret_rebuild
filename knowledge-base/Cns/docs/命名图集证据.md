## 能力与所有权

`createSpriteSheet(lease, frames)` 在一个真实的整图纹理租约上建立冻结的命名矩形表。Runtime 与 Engine 根入口复用同一个工厂以及两个擦除类型 `SpriteSheet` / `SpriteSheetFrameInput`。不增加依赖、公开子路径、Engine 方法、资源加载或动画时钟。名称保留空白与 `__proto__`；调用方修改输入不能重写已发布元数据。

`createBitmap(name)` 创建真实的调用方自有 Bitmap，借用同一个租约。图集既不拥有这些 Bitmap，也不释放调用方租约。图集退役后不能再创建 Bitmap，但不可变名称、尺寸和矩形仍可读取。已创建 Bitmap 可依自身资源生命周期与已交付的 `Engine.createSequencePlayback` 继续使用；退役后的元数据读取不会重新赋予渲染资格。

完整暂存、上限、生命周期／错误优先级及有限原始 Bitmap 原型保障见[契约](命名图集契约.md)。公开示例路径是 `examples/spritesheet-headless.mjs`；此处工具／源码路径均为字面引用，不新增知识库外部超链接。

## 保留的失败与修订

最初构建回执是 ARRAY2：构建成功，第一轮 CPU 因测试的函数记录构造而失败，声明的第三个 actor 没有保存回执。随后经过有限测试修正的公开 CPU 和保留运行分别通过。原始清单继续保留独立评审 PENDING 标签；其保存字节由另一份已接受的实际评审赋予资格，不回写原标签。

第一轮整合类型运行中，独立 SpriteSheet 通道通过，但在保留 Sequence 通道失败，尚未到达追加的 SpriteSheet 通道。当前公开命名空间图中的 SEQP-N16 仅有一条实测 TS2740 消息变化；文件、行 89、列 40、代码 2740 及其它元组均不变。精确后继表通过保留及整合门禁。这是实测诊断表更新，不是运行时修复，也不能证明编译器内部的具体原因。

Native R1 源码评审拒绝了两处 schema 绑定：计划把接受结论写在 `status`，产品身份行位于 `/reviewedPins`。有限 R2 适配仅命名这一确切计划 schema，其它角色的 verdict 规则保持不变。Native 准入生产器另修复了四个已准入 TypeScript physical owner 的复用。这些源码修订没有启动浏览器。

## 实际不透明浏览器实验

已保存的正常宿主 actor 于 2026-10-13 的 04:13:02.2072968–04:13:06.6220315 UTC 完成，退出码 0，未超时。报告环境为默认无界面 Edge 155.0.4283.45（msedge，无额外 flags 或浏览器环境覆盖）、Playwright／playwright-core 1.62.1、Node v24.19.0，以及 Windows win32 x64 release 10.0.26300。这些是运行时观察，不是物理 GPU 或性能测量。

每个后端绘制八个新捕获帧，并在原调用方／资源退役后重放原始 N1；重放使用不同宿主及不同的应用自有 WebGPU device。N1 为 idle；once 播放依次到 green、blue 与完成，同一 Bitmap 随后准入 loop，在 pause 期间保持 red，resume 无隐式 tick，并到达循环边界。每后端记录六个公开 tick；捕获、渲染与重放不推进播放。

原宿主／重放宿主安全返回、pending native/startup 计账为零后，才销毁取得的应用 device。两个 device-loss Promise 均以 destroyed 原因完成；浏览器、服务器和 context 关闭，无隔离或清理错误。记录的 Windows 自有 Job 在 ACK 前取得指派，随后 active-zero 并关闭，原始流完整且无 fallback。这只赋予该有限自有运行资格，不证明任意 OS 进程退役、物理硬件能力或内存回收。

最终证据绑定 708 个前／后身份、103 个原始／served module 身份，以及 328 条准入的 loopback GET 请求。一条已分类的 Canvas 回读提示不构成性能证据；早先源码／准入 PENDING 截止点和 R1 源码拒绝继续分别保留为历史。
