# 提交式 UI 数据面板

[English](../../en/docs/ui-data-panel.md) | 中文

这是 M3.1 的首个实现配置：可调整尺寸、支持变高行和稳定数据键、显式准备与提交的数据面板。完整 M3.1、段落文字、键盘焦点、原生编辑、无障碍和移动设备验收仍未完成。验证与交付状态单独记录。

## 所有权与发布

可选入口 `@egret/engine/ui` 提供 `createUiRoot` 和 TypeScript 契约。每个根节点由真实 Engine 和打开的 Scope 管理，直接挂到原始 Stage 下，保留已有兄弟节点的顺序。独立根节点分别准备内容。现有手动显示 API 与 `planLinearLayout` 保留原有契约。

组件树支持叶子、行、列和一个虚拟列表。布局采用显式／最小／最大尺寸、内边距、间距和交叉轴对齐。叶子可同步测量，或通过既有图形实现绘制纯色填充。颜色沿用 RGB 整数与 alpha 表达。根视口尺寸明确；内在尺寸与拉伸互相依赖的循环、未知属性和不支持的布局模式均拒绝。

调用设置方法或 `invalidate`，等待 `prepare()`，再在帧捕获和输入分发以外调用 `commit(token)`。准备阶段构建离树内容及完整几何。发布之前，旧图像、裁剪、行身份和命中区域继续有效。尚无已提交版本的根节点显示为空且不接收交互。

就绪令牌属于一个根节点且仅能使用一次。无变化令牌不重复布局或绑定。待完成令牌表示行窗口仍需有界补充，应再次显式准备，而不能提交。被新意图取代的结果不会写入当前几何。发布前失败保留旧提交；发布后输入协调或解绑直接抛出的错误进入 `postCommitErrors`，Scope 捕获的清理失败继续通过既有诊断报告。

托管根节点、容器壳和行包装器拒绝直接修改几何、命中区域、父子关系及直接销毁，必须通过所属 UI 管理器更新。自定义行内容仍由绑定 Scope 所有，通过新内容版本替换。在准入与发布时，逻辑 Stage 必须保持单位变换。普通 Stage 变换仍可修改，但修改后的时段不属于此 UI 配置的已限定范围。

## 数据、准备与复用

数据源提供不可变版本：唯一字符串键、内容版本、预估高度和值，以及成对的 `bind`／`unbind`。绑定获得真实 Scope、取消信号、键、代次、宽度和密度，返回离树且完全就绪的内容与实测高度。既有文字和图像所有者继续负责栅格准备与资源租约，UI 不新增资源管理器。

设置操作可能先接受较新的目标版本、完成暂存行退役，再以 `UI_CLEANUP_FAILED` 报告直接观察到的清理失败。该错误不回滚已接受的意图，之前提交的画面保持不变。被中断的准备以 `UI_STALE` 及其清理原因拒绝。

每个绑定保留创建时捕获的 bind/unbind 函数对及接收对象。每次进入 bind 都对应一次 unbind，包括失败情况。替换适配器，或改变依赖序号绘制的数据，需要相应的数据源版本与内容版本变化。重排跟随稳定键，绑定时的序号只作参考。

列表保留顶部可见键及行内偏移。键被删除时，优先选择旧顺序中后续仍存在的键，再选择最近的前序键。显式滚动意图覆盖锚点保留，最后统一限制滚动范围。高度查询和稀疏单点更新采用 Fenwick 索引。结构变动及宽度／密度变化以线性时间重建有界数值状态，不宣称对数时间编辑。

只有当前窗口创建显示对象。非交互容器壳可以复用，但每个绑定都有新的交互目标。完整新版本发布后，由既有指针路由器协调已退出的目标，按住的接触点不会变成另一数据键上的接触点。离树目标可能不再收到路由取消事件，既有接触观察者与 unbind 提供终止通知。

必需的异步工作完成前继续显示旧的完整内容。取消会及时结束公开准备 Promise；忽略取消的提供方仍占用未结束调用预算，直至实际完成。这样既限制队列增长，也不会将逻辑取消误报为原生工作结束。

## 输入与保留行

可选的 PointerInput 必须来自同一 Engine，复用既有事件及捕获操作。行通知包含原始事件、已提交键／序号、绑定代次和布局版本。UI 布局变化不会改写宿主视口版本。同一 Engine 的指针观察者和路由事件，包括旧鼠标路由，均排斥同时发布 UI。

切换输入时，旧桥接必须关闭或无活动接触，新桥接必须处于活动状态且无接触；不会为了切换而取消无关会话。首个配置固定宿主 Canvas 逻辑尺寸，调整内部面板与重建浏览器坐标映射是不同操作。

保留令牌为后续焦点／组合输入集成保留已经实现的行。离开屏幕的保留行继续绑定，但隐藏且不可交互。在释放之前，删除或重新绑定保留行会被拒绝。这些所有权令牌不代表键盘焦点或 IME 已实现。

## 边界与证据

| 限制 | 首个配置 |
| --- | --- |
| 逻辑记录 | 50,000 |
| 布局节点／深度 | 4,096／64 |
| 视口／密度 | 每轴至多 16,384 逻辑像素／8 |
| 行高／总长度 | 1–1,048,576／至多 2^40 逻辑像素 |
| 常驻容器壳 | 默认 128，可配置至 2,048 |
| 预留行 | 每侧默认 2，至多 32 |
| 仅保留行／令牌 | 默认 2，至多 8 行／16 个令牌 |
| 绑定内容 | 至多 32 个显示节点，深度 8 |
| 窗口补全 | 每个意图至多八轮显式准备 |

计数描述逻辑记录、绑定、容器壳、测量和未结束调用。数值索引字节不包括 JavaScript 堆、GPU 内存及调用方保留的快照。无法从对象数量推断任意适配器的资源所有权；不可观测的需求／租约总量保持不可用状态。

集成 UI／输入回归通过 158 项，失败、取消和跳过均为零。实际桌面验证使用 Windows 10.0.26300、Node 26.7.0、Playwright 1.62.1 与默认无头 Edge 155.0.4283.62，WebGPU 和 WebGL2 分别通过。每个后端检查 177 个精确像素、35 个实际鼠标位置和十次原始帧捕获，覆盖延迟替换期间完整旧画面不变，以及保留原始帧的逐字节回放一致。52 次进入的绑定均对应一次终结回调；缓存、Scope、输入、字体与提供器的清理观测通过。这些是功能和逻辑所有权证据，不代表物理回收或计时结果。

`examples/ui-data-panel/verification-summary.json` 为附带原始结果哈希的公开摘要，不替代保留的原始证据。此前示例容量、缺少尺寸和沙箱启动失败分别保留。受保护 CI 与 main 交付单独记录。完整 M3.1、手机输入与性能验收继续开放。参见 [M3 计划](m3-ui-text-input-plan.md) 和 `examples/ui-data-panel/README.zh-CN.md`。
