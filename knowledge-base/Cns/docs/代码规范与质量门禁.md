## 规则等级与变更方式

必需规则保护公开行为、所有权、来源、可重复构建和真实错误处理；推荐规则改善阅读与维护；例外必须注明原因、范围、验证和撤销条件。语义例外需评审，不能用一行lint禁用变成新事实。格式由固定工具自动统一，不进行手工审美评审；生成文件按生成器格式，第三方文件保留上游格式。

修改公共合同先改schema/API说明、列行为差异和受影响样本，再实现；实现与受影响回归一同提交。代码任务附需求、设计决策、来源及完成标准，不能只有“重写得更现代”。模块README简要说明职责、输入输出、依赖、状态权威、扩展口和验证入口。

## TypeScript与模块

| 方面 | 候选要求 |
| --- | --- |
| 类型检查 | 核心启用strict、noUncheckedIndexedAccess、exactOptionalPropertyTypes、verbatimModuleSyntax；公共签名显式返回类型，外部输入从unknown进入校验，禁用无解释any/非空断言。 |
| 模块目标 | 浏览器打包入口使用匹配bundler的模块配置；Node CLI使用匹配Node的配置。共享strict基线，不能用一份DOM/Node混合配置掩盖环境差异。 |
| 导入 | 类型明确import type/export type；包间通过workspace和exports解析，不把TS paths当运行时包映射；禁止从别包src/internal/dist深层导入。 |
| 数据建模 | 状态用带判别字段的union；undefined表示缺失，null只在schema明确可空时使用；永久ID、实例句柄、资源代际、设备epoch及任务ID使用不同类型。 |
| 类与组件 | 熟悉的对象API与紧凑执行数据分层；私有字段private/protected，跨模块操作通过窄接口；新主路径显式defineComponent/注册，不依赖全局反射或import副作用。 |
| 枚举与导出 | 公共协议使用可校验的稳定字符串/数值值域；不公开需要消费者相同编译方式的const enum。已有旧enum由兼容转换，不借此改写历史。 |
| 并发 | Promise必须await、return或显式交给任务管理器，不能悬空；同步事件handler禁止未处理Promise；异步结果绑定输入版本并处理取消/失败。 |

TypeScript官方说明type-only导出可从JS输出移除，paths不会改写输出路径，workspace更接近消费者的真实包解析；这些机制用于设计检查项，不作为包体收益证明。[模块参考](https://www.typescriptlang.org/docs/handbook/modules/reference.html)

格式候选采用UTF-8、LF、TS两空格、双引号、分号和尾逗号；建议行宽100，由格式工具统一。Rust由rustfmt处理。类型名PascalCase、成员camelCase、目录kebab-case；主类文件保留白鹭PascalCase名称。注释解释理由、不变量、单位、边界和来源，不复述代码动作。公共API简注与示例优先提供可供社区使用的英文版本，设计说明可保留中文；国际化文本不硬编码进逻辑。

不以文件行数、类数量、抽象层数、100%覆盖率或一律零分配作为质量门。函数职责和可独立理解的模块边界优先；热点分配、SoA、对象池和native下沉必须有端到端证据，不能用规范禁止一切普通业务分配。

## 状态与生命周期

持久工程、运行游戏状态、GPU/原生投影、派生缓存各有唯一权威。业务属性由runtime持有；GPU镜像可重建，不能成为第二套隐式游戏状态。对象ID不等于指针、路径或名称；资源generation不等于deviceEpoch，玩法事件会话也不因设备恢复重置。

对象detach、dispose、任务cancel、lease.release和物理资源回收分别命名。共享资源必须显式租约，借用者不隐式转为owner；关闭顺序按API合同。GPU在途资源通过完成条件回收；SDK借用device/surface不能自行destroy。失败、重复清理、取消/完成竞态、队列满、迟到结果和关闭中重入必须有明确终态。

所有队列有容量、背压和溢出处理；重试有限，标明哪些任务幂等。后台恢复重置时钟基线，禁止无限补帧；事件顺序不能由状态合并吞掉。长任务支持taskId、查询、取消、超时和源版本，旧构建或旧资源结果不能覆盖新项目。

## 错误与诊断

可预期的加载、能力、取消和关闭失败以EgretError及稳定code表达，保留cause；非法调用可同步抛错。批量工程校验返回Diagnostic集合；取消单列终态。诊断包含阶段、对象/资源/效果、任务或工程版本、profile及可定位源位置，不靠匹配错误字符串。

禁止空catch、无声占位或删除必要效果后报成功。适配层可提供明确替代或占位，并告知是否影响验收。finally和Scope继续执行全部清理，聚合清理错误；原始失败不能被后续清理异常悄悄覆盖。生产诊断去除凭证和个人网络信息，开发映射可在发行时裁掉。断言验证内部不变量，不能替代外部输入校验。

## Rust 原生 SDK 与跨语言

Rust是D014中尚待比较的候选。未来采用时默认安全代码，unsafe集中在窄FFI/GPU边界；每处SAFETY说明指针长度、对齐、有效期、线程、别名及所有权。安全封装承担调用前校验，不能要求业务层到处知道unsafe前提。[Unsafe Rust](https://doc.rust-lang.org/book/ch20-01-unsafe-rust.html)

错误返回Result，外部输入不随意unwrap，不用panic表示正常业务失败。C ABI暴露固定宽度值、版本化结构、opaque handle与slot/generation，不暴露Rust Vec/String或未承诺布局。buffer区分copy、borrowed和transferred，说明allocator配对和失效时点；WASM memory增长后重新获取视图。

panic和C++异常不得穿越默认ABI。符合构建策略时可在窄入口捕获unwind并标记失效；catch_unwind不能捕获panic=abort，也不是本机崩溃隔离。C++异常在C++侧转成明确错误。命令协议检查版本、长度、字节序、溢出、对象代际和线程归属，错误包不得部分改变当前状态。[Rust FFI](https://doc.rust-lang.org/nomicon/ffi.html)、[catch_unwind](https://doc.rust-lang.org/std/panic/fn.catch_unwind.html)

CPU逻辑、GPU提交、IO/解码线程有明确owner和结果提交队列；后台任务不直接写TS游戏状态。建立Cargo workspace共享版本与lint基线，具体crate只有实际职责出现时才创建。[Cargo workspaces](https://doc.rust-lang.org/cargo/reference/workspaces.html)

## 图形 Shader 与数值

统一记录2D/3D坐标、单位、矩阵约定、clip depth、UV、纹理格式、颜色空间及alphaMode。默认现代profile在线性光合成，使用明确预乘边界；旧工程的非线性混合或alpha行为由兼容profile对照。零alpha避免除零，颜色纹理与数据纹理分别解码。2D的像素密度与3D世界单位不能混用。

WGSL/GLSL实现各自声明能力和变体，后端差异集中在adapter；业务不遍布后端名称分支。效果声明输入、pass、中间纹理尺寸、采样、遮罩顺序和能力退路；不能承诺任意WGSL自动等价转成WebGL。编译错误映射到effectId、变体、原始shader位置与工程版本。缺能力时阻断必要效果或使用已经声明且对照过的简化方案，不能静默改变玩法。

布局、事件、骨骼slot和透明合成顺序先保证正确，再优化批次、pipeline和pass。DrawCall更少不直接等于更快或省电；动态3D分辨率不降低屏幕UI清晰度。数值输入检查NaN/无穷、非法尺寸和容量；容差由用途、金样与设备条件定义，不随失败临时放宽。

## 工程与 Agent 提交

编辑器、CLI、MCP和自动迁移调用同一project服务。命令携带baseRevision、transactionId、稳定目标ID、前提和差异；校验后原子提交或完整回滚。并发冲突拒绝并重读，状态不明先查询，不用“最后写入获胜”覆盖别人的修改。工程提交不承诺外部服务的全局事务；资源导入、构建和发布副作用分别有任务、结果版本及权限边界。

AI参与开发时使用项目规格与行为样本，输出变更范围、来源、诊断、实际运行结果及剩余问题，并保留模型/工具版本和参与范围。白鹭核心按自有规格独立编写；第三方依赖、版本、补丁和发行声明明确登记，执行[独立实现规范](独立实现与第三方依赖规范.md)。自动扫描提供复核线索，来源与许可核查仍需结合具体文件和依赖。

源文件由代码patch服务修改，结构化场景由schema命令修改，两者共同进入工程事务、校验和撤销；不能假装任意业务代码都可由JSON字段表达。生成文件只改权威源与生成器，手改文件需受更新保护。发布前查看可审阅差异与验证结果；工具角色不能自己把建议提升为已验收产品。

## 自动质量门禁

首期候选工具基线为一个workspace包管理器、一个TS格式器、一个TS lint栈、一个测试runner及Rust自带检查；建议pnpm、Prettier、ESLint/typescript-eslint，并在实际选型时锁版本。类型检查沿用D013快速转译/增量诊断/完整发行检查分离；Vite候选仅用于适合的Web开发入口。完整工具栈仍为候选；首段已固定pnpm/TS并用Node内置测试器验证，Prettier/ESLint、Rust和CI未配置。

| 门禁 | 需要证明什么 | 执行边界 |
| --- | --- | --- |
| 格式与类型 | 自动格式、严格类型、外部输入校验、无悬空Promise | 受影响包快速检查；发布执行完整检查，不能用skipLibCheck隐藏第一方合同问题。 |
| 依赖与API | 允许的包依赖DAG、exports/API声明快照、纯核心无DOM/Node污染 | 从实际构建和发布目录导入；不只检查源目录别名能解析。 |
| 语义与失败 | 捕获冒泡/once、尺寸顺序、取消、Scope迟到、租约、事务、恢复 | 独立断言/自有金样，保留反例与失败；不重复helper调用自证。 |
| 目标与预算 | 2D/混合/Native包成分、首交互、帧时分位、峰值内存、预览与诊断延迟 | 固定场景/版本/profile/设备/画质；真实宿主证明支持，真机才能证明能耗。 |
| 来源与发行 | 自写范围、第三方清单、补丁、资产权利与生成来源 | 变更时更新，发行前核对；不把研究链称自主核心。 |

行为测试优先高失败成本合同：派发中增删/重入、最后租约释放、旧epoch fence、丢包/背压、取消与完成竞态、并发冲突/回滚、设备恢复和迁移关键流程。简单注释/格式修订无需新增复述实现的测试；变更后只扩展受影响验证，有新失败或不确定性才扩大范围。

性能记录包括冷预览、热反馈、完整诊断、发布构建、资源转换、首次shader、CPU/GPU帧时分位、峰值内存、首交互与Agent修复成本。具体产品阈值由代表样本和目标设备建立后登记，不能把旧研究fixture容量当产品预算。类型检查、合同模型、桌面浏览器和真机结果分别标明范围。

## 提交与社区评审

提交围绕一个可理解问题，描述触发、前后行为、设计理由、受影响合同与实际验证；API/格式变更附迁移信息。PR检查清单包括生命周期、跨宿主假设、来源、诊断和所需回归。贡献者可以先提交文档或故障金样，不能被要求先读私有原包。

例外记录采用稳定编号、owner、原因、范围、到期或撤销条件；owner未任命不伪造姓名。依赖升级独立记录变更及受影响回归，版本和锁文件一起审阅。公共包版本、schema、桥接、工具协议及测试样本可追溯，撤回结论留历史。

本轮规范交付不代表上述门禁已配置或通过；实际实现与验收仍由代码、可复现产物和[交付登记册](../registry/交付.json)确认。

## 浏览器门禁与公开清单

每次推送必须执行`node tools/prepush.mjs`，检查公开结构、核心/类型/边界、headless行为与知识库结构；它不启动浏览器。渲染变更按影响另执行`node tools/verify-canvas.mjs --playwright <installed-playwright-module> --channel msedge --output <private-output-directory>`与独立`node tools/verify-webgpu.mjs --playwright <installed-playwright-module> --channel msedge --output <private-output-directory>`。使用已接受的固定依赖，浏览器默认启动无附加flags；源码身份比对相同的既有构建结果可明确注明后保留。

发现与登记路径均按Windows大小写不敏感方式排除私有执行、依赖及生成目录；清单不能覆盖排除规则。普通公开AGENTS文档仍有效；仅保留两个精确路径/hash的Three r186历史研究构建例外。结构检查不能产生翻译含义或公开审阅批准。
