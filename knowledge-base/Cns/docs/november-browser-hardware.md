# 11 月桌面与 Android 显卡验收

[English](../../en/docs/november-browser-hardware.md) | 简体中文

在 Windows 的 RTX 5090 Laptop 上，WebGL2 缩小带 mipmap 的图片时可能将整张图画成背景色。仓库自带的 mipmap 示例就能复现。另一个问题在 Windows 和 Android 上都有：按文档启动示例服务器，新的 3D 模型画廊返回 HTTP 404。两处修复均已在最初复现问题的设备上验证。

本次梳理了东八区 11 月 17 日起至 [84a56177，即 PR #442](https://github.com/cnedwin/Egret_rebuild/pull/442) 的 98 次主干合并。[采集记录](https://github.com/cnedwin/Egret_rebuild/blob/main/docs/evidence/november-browser-hardware.json) 按主要验证方式列出全部 PR 和本轮实际抽测的负载。Android 原生改动复用已有的 [Fold7 安装、玩法、资源、桥接和录像回放记录](https://github.com/cnedwin/Egret_rebuild/tree/84a56177/runtime-sdk/measurements)。仅涉及构建、文档、发行和 CI 的改动沿用各自的检查。

## 修复及对照

| 实机发现 | 修复和复验 |
| --- | --- |
| 在 NVIDIA D3D11 驱动的 Edge WebGL2 上，三个缩小区域全部读到背景灰度 32。未使用 mipmap 的对照图仍然可见。Fold7 原本就能正常显示。 | 多级纹理的缩小滤波改用 `NEAREST_MIPMAP_NEAREST`。单级纹理和放大路径继续使用最近邻。Windows 上只改滤波参数、保持上传字节相同就能恢复画面。正式构建在 Windows 双后端的三个区域均读到灰度 188，标准差为零，无相邻红色渗入。Fold7 WebGL2 修复后也通过原像素检查。 |
| `pnpm example:browser` 启动后的模型画廊链接返回 404。 | 服务器开放画廊入口及模型注册表中的文件。两台设备均能打开 24 个模型，切换真实尺寸并转动视角。HTTP 回归测试逐一检查注册文件及一个应当拒绝的文件。 |
| Windows 灯笼示例原先以点灯前几乎没有金色像素作为验收条件。首次测到抵达神龛前有 41 个金色采样点，抵达后有 156 个。 | 改为检测神龛被点亮时新增的亮区。关掉神龛灯光和粒子的反向对照只从 44 增至 47，按预期被拒绝。原游戏在桌面端通过全部七项官方场景，包括点亮三座神龛和重新开始。 |
| 按钮的父节点缩小一半后，要求的 44 CSS 像素命中宽度实际只剩 22。两台设备的双后端都仅命中中心，四个角全部漏点。 | 命中区现通过完整的祖先变换，将屏幕上的 CSS 方形映射回节点本地坐标。直接挂载、父级半缩放和镜像旋转三组，在四条路径上均命中全部五个点。不可逆变换保留有限的本地回退。 |

## 同一版本的真机覆盖

Windows 使用前台 Edge 158.0.4370.33 和 RTX 5090 Laptop GPU。Galaxy Z Fold7（SM-F966U1）使用 Android 17、Chrome 157.0.8103.78 和 Adreno 830。成对运行的场景均明确选择 WebGL2 或 WebGPU。

| 负载 | 在设备上检查的行为 |
| --- | --- |
| World3D 和 Play3D | 24 个程序化模型、两套骨架姿态、GLB 几何与颜色往返、布料移动、裁剪、天空与雾、导航与空间音频状态、画布字体、叠加界面、指针捕获和 Play3D。每台设备有 12 张图通过原有跨后端像素容差。追加场景验证了近光源选择、隐式和显式混合、屏幕标记，以及骨轴不同的骨架之间的动作重定向。 |
| 共享 2D 和 Play | 渐变描边、遮罩、变换后的边角、透明度钳制、缩放穿零、线性与 sRGB 混合、界面焦点与输入、存档迁移，以及 Story 的完整结局。各后端的纯色和采样路径均绘出相同的 34,560 个白色像素。WebGL2 的 240 条命令合为两次实际绘制，含最终呈现。在 3D 反射对照中，连续六帧的原生绘制和面板计数均为 2、1、1、2、1、1。 |
| 内容、物理和浏览器服务 | 同源构建的 JSON 和二进制骨架均加载了两页图集。96 × 48 原生回读的左右半图逐像素一致，每侧有 72 个红色和 144 个蓝色像素。关闭后，资源组、实例和源资源计数归零。两台设备均验证了定长杆与绳索约束、碰撞回调移除物体、拒绝递归步进，以及存档回滚和重开。默认音频在 setup 前解码 14 个预设；关闭内置音频后，默认解码次数为零，调用方可只创建一个上下文。 |

Fold7 上的 Breakout、Platformer、Memory 和 Lanterns3D 均在双后端完成并重新开始。灯笼神龛亮起后，WebGL2 和 WebGPU 分别新增 59 和 54 个金色采样点。旧版计时器、慢帧追步、隐藏遮罩像素和瓦片变化也通过了两台设备的双后端检查。

两台设备的双后端均通过五种图像源、IndexedDB 与离线资源替换、粒子混合、视频 MIME 选择与 404 后回退、横向滚轮和减少动态效果的验证。Windows 按实际显示缩放后浏览器送达的滚轮增量验收。

针对 #435，在 Windows 前台浏览器用新旧实现转换同一张 1,024 × 1,700 游戏图集。新路径在 12 对中全部更快，中位耗时从 6.500 降至 5.025 毫秒，成对节省中位数为 1.475 毫秒。混合透明度对照在 12 对中有 7 对更快，中位节省 0.150 毫秒；中间透明度对照仅有 4 对更快，中位反而慢 0.200 毫秒。两组对照都未呈现一致收益。输出字节一致。这组数据衡量 CPU 图集转换，完整游戏帧和 GPU 耗时另计。

## 采集期间新增的合并

采集期间又合入了 [#443](https://github.com/cnedwin/Egret_rebuild/pull/443) 和 [#444](https://github.com/cnedwin/Egret_rebuild/pull/444)，第二轮使用 41cb0cb8。两台设备的双后端都观察到，硬边处理在三角形数相同的情况下，将箱体表面法线与轴对齐的比例从 86.08% 提高到 100%。移动相机时实际绘制的三角形数依次为 1,800、432、96、1,800；回到近处后像素复原。烘焙工具导出的木箱为 89,584 字节、3,000 面，加载后赋予相同木材质，与运行时生成的网格逐像素一致。七种程序化表面分别开启颜色细节和凹凸后，均产生了可见变化。

本次单次启动时，新画廊在 Windows 构建 24 个模型耗时 7.89–8.02 秒，Fold7 为 10.20–14.80 秒。随后 90 个前台帧回调的 p95 在 Windows 为 4.3 毫秒，在 Fold7 为 41.5–41.6 毫秒。单次启动不能建立版本间性能回退的结论。

另在 UI 叶节点自己的 Scope 中创建实际浏览器标签，文本高度和提交布局均为 30。释放叶节点后，四组设备路径的字形像素都归零，游戏 Scope 继续可用。

## 帧间隔及尚未覆盖的范围

固定的 119,000 三角形负载在每个后端采集了 60 个前台浏览器帧回调。下表单位为毫秒，CPU 列测量页面线程的渲染调用耗时。

| 设备 | WebGL2 回调 p95 | WebGPU 回调 p95 | CPU p95，GL / GPU |
| --- | ---: | ---: | ---: |
| Windows | 4.2 | 4.2 | 0.2 / 0.3 |
| Fold7 | 16.7 | 16.7 | 1.3 / 1.7 |

可交互画廊使用不同的相机和视口。在 Fold7 本次打开画廊时，24 个模型的构建分别耗时 9.23 秒（WebGL2）和 11.43 秒（WebGPU），随后 90 个帧回调的 p95 分别为 41.5 和 41.2 毫秒。示例的首次模型构建和帧间隔值得分别优化。GPU 执行时间、功耗和持续温控另需测量。

手机输入通过浏览器协议送达实体设备。真人听感、辅助技术使用、实体手柄、Safari/iPhone 与其他 GPU 系列仍需各自的证据。短测结果不用于 #55 和 #92 的正式性能预算验收。Spine 使用自制数值素材；商业编辑器导出素材的兼容性另有验收范围。
