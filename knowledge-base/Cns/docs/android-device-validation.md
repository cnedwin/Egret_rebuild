## 装备字体修正

首次持续运行约五分钟后，在第一次字体切换时出现 `ASSET_LOAD_FAILED` 并停止。短路径回放确认底层原因是 `PARAGRAPH_FONT_NOT_REGISTERED`：装备样式明确请求 `Noto Sans CJK SC`，而候选组把同一份内置 CJK 字体注册为 `Noto Sans`。Provider 正确拒绝了未注册字体。保留首次失败，不将它改写为长时通过。

示例现在按捕获的 `ParagraphFontSet.fontFamilies` 构造样式：命名字体存在时继续使用原 CJK 选择，否则使用该组明确声明的 fallback 栈。文章与虚拟行在异步准备前捕获字体组，并复制、冻结该栈。默认／固定字体输出保持不变。修正不涉及核心渲染、Provider 准入、资源管理器、清单、字体文件、字节预算或 SDK API。额外增加重复 CJK 别名可能在三个字体组重叠时超过既有 64 MiB 限制，因此使用已经选定的组。

## 节拍与计时

两后端共六个前台 Spine 窗口，每个八秒，分别取得 482–483 次被动 rAF 回调。RESET 前、报告中的操作顺序后、重放初始帧后，间隔中位数均为 16.6 ms，p95 为 16.7 ms。采样窗口中 Engine 时钟／播放实例与 Host 状态不变：示例需要显式推进，因此回调频率不是动画或渲染 FPS。报告中的操作顺序还在非 staged 阶段调用 `stale`；记录其 `STAGE_FIRST` 拒绝。

更新频率较低的段落长跑中还观察到约 41.4 ms 的被动间隔。同期只读显示 dump 中，活动设备／基础显示信息的 `renderFrameRate=24.000002`，应用覆盖层为 `60.000004`。这些是系统元数据，不是屏幕实际扫描频率的测量。它们与 rAF 同时出现，不能据此证明 RESET、渲染器故障或某一平台策略。[Android 帧率说明](https://developer.android.com/develop/ui/views/animations/adaptive-refresh-rate)介绍了内容及交互相关策略；本设备 dump 显示 `hasArrSupport=false`，不能由此宣称支持该项 ARR 功能。

每类操作各二十个交错预热完成样本：静态 p50／p95 为 45.5／51.6 ms，宽度重排为 48.8／79.3 ms。每次包含公开 UI／缓存工作、捕获、渲染／读回及示例诊断。这些端到端完成时间不是纯渲染 CPU／GPU、触摸延迟或 M1.2 预算结果。

另一个不载入引擎的 HTML 目标执行了 90／30／90 秒的被动／CSS 动画／被动阶段，三者中位数均为 16.6 ms、p95 为 16.7 ms，没有复现段落页较慢的回调。差异仍限定于场景，根因尚未确认。

诊断分位数采用排序后 floor(n × p) 的上位索引，并限制在样本范围内。亮度没有固定：未执行亮度修改命令，读回值仍从 64 变为 46。不能据此进行显示功耗或对比温度验收。

持续运行每五秒执行一次 UI 操作，每五分钟替换字体，每两分钟切换密度，并连续记录被动 rAF 时间戳和具名温度传感器。它覆盖变化中的只读 UI，不是持续 60 fps 游戏或重 GPU 负载。历史 performance.memory 读数从约 56.8 MB 增至 103 MB；下方补充验证限定了这一缓存、分桶指标的含义。未将引擎分配、示例历史、采集缓冲及等待回收的垃圾分别隔离，因此保留该增长，不归因为泄漏，也不宣称零增长。USB 充电及温度数据不能确立整机电耗；GPU 时间戳、物理内存、显示呈现计时未取得，不据此宣称零泄漏或通用温度达标。

## 手机控制及证据边界

本地控制器使用正式 ADB 与 [CDP Input](https://chromedevtools.github.io/devtools-protocol/tot/Input/) 接口。专用 DOM 夹具观察到注入点击、滑动、同时双指与释放、真实三星软键输入、键盘显示／收起，以及单独标识的 Unicode CDP 插入。后者替换了正在组合的文字，不能当成追加或原生中文候选验收。该夹具验证控制原语，不代表尚未完成的 Egret 原生编辑 SDK，也不替代其他贡献者的触摸控件。

仅移除自建目标和映射，恢复 USB 保持唤醒的原值。常规唤醒后锁屏界面消失，未输入凭据。折叠屏截图按 64 位编号选择当前默认物理显示屏。原生安全字段缺失或含糊时拒绝输入。初始休眠窗口没有 rAF、截图触发期限，均保留为不完整观测。两个特效用例在首次成功关闭后，采集器重复关闭被拒绝；保留该采集器问题，不据此修引擎或重复整套像素验证。

冻结路径中成功返回的浏览器解码后响应与所记录文件一致。Spine 恢复采集只改变 HTML 中主模块启动顺序，以便 Host 创建前装入既有原生观察器；原始／执行版散列分别记录。favicon 404、受控 HTTP 503 与有意中止的请求不算成功读取冻结内容。CDP 解码体不是压缩后的网络传输字节。SDK 输入、示例修正、演进中的本地采集器版本、清理计数和独立评审分别记录。

后续验收仍包括指定完整 Spine Editor 导出／参考素材及许可条件、Android／iPhone 硬件和真人输入覆盖、原生编辑／IME 与无障碍、自发驱动故障／操作系统终止、M4 混合负载以及物理性能／电耗预算。M1.2 仍为 10.3 ms 对 8 ms，保持 OPEN。原创程序化 Spine 夹具及既有 Noto／CanvasKit 保留原来源声明。

## 回调、内存与生命周期补充验证 — 2026-11-07

本轮沿用同一台手机和 Chrome 版本，应用基线为已发布的 `0d1bce5`。选定 SDK、第三方与素材构建输入均重新核对了原快照；相对最初基线，仅 PR #129 已评审的示例源码与指南不同。既有固定像素／功能矩阵和原始 30 分钟记录直接复用。本轮没有修改引擎、示例、依赖、预算或触摸实现。[脱敏观测摘要](https://github.com/cnedwin/Egret_rebuild/blob/main/verification/android-device/2026-11-07.json)分别保留范围与源码身份。

### 回调间隔

每后端四个 20 秒窗口分别覆盖被动回调、自有页面的注入点击、浏览器原生 transform 动画及取消后的被动回调，p50／p95 均约为 16.6／16.7 ms。另一个成对探针重放原来的五次预热和二十组交错 static／重排操作，再采样 60 秒，两后端仍约为 16.6／16.7 ms。替换循环后的采样单独保留。

历史约 41.4 ms 的现象在本轮**没有复现**。启动取证期间浏览器进程发生过重启，先前的调度状态没有保留。历史触发条件继续待查，不能由本轮认定原因或宣称已修复渲染器。没有强制刷新率或亮度；被动回调间隔仍不是动画 FPS、Engine CPU、GPU 时间或物理呈现计时。

### 内存口径

旧字段来自 `performance.memory`，不能作为实时、纯 JavaScript 活跃堆曲线。新目标中的该值始终为 47.4 MB，而精确计数明显变化，甚至在应用关闭后仍不更新。[Chromium 提交 abe0507666c40](https://chromium.googlesource.com/chromium/src/+/abe0507666c40/third_party/blink/renderer/core/timing/memory_info.cc)对分桶读数使用二十分钟缓存，底层计算还包含 V8 external memory。这是测量限制的机制佐证，未取得所装 Chrome 156 的准确源码标签。原始 56.8→103 MB 数值保留在历史记录中，不能单独确立泄漏。

在目标中执行诊断 GC，分别观察 `Runtime.getHeapUsage` 的 JS-used、embedder 与 backing-storage 字段；诊断 GC 不进入计时窗口。文章／列表独立保留字体组时，123 次公开操作后的 JS used 在 WebGPU 上约为 4.29→5.70 MB，在 WebGL2 上约为 4.37→5.65 MB。私有堆路径指向受管字体源字节、原生字体借用及用于共享字体对象比对的字节，以及栅格／Host 驻留和保存的读回。原生快照另列出 32 MiB CanvasKit WASM 后备存储。这些属于不同记账域，不能相加当作整机物理内存。

第二个探针在每次替换后把两棵 UI 根同步到当前字体代际，执行二十轮相同操作：

| 观测 | WebGPU | WebGL2 |
| --- | --- | --- |
| 记录检查点的活动字体组 | 1 | 1 |
| 第 8–20 轮段落缓存 | 32 项；图像 12,178,336 字节 | 32 项；图像 12,178,336 字节 |
| 后期检查点的 backing storage | 第 8–20 轮为 68,263,155 字节 | 第 18、20 轮为 89,271,072 字节 |
| 第 20 轮 JS used | 5,867,072 字节 | 5,837,976 字节 |
| 关闭并诊断 GC 后的 backing storage | 5,207,199 字节 | 5,214,060 字节 |

WebGL2 还按既有 Host 的 32 MiB／256 页上限保留就绪源图像页；这一策略与其较高的 backing-storage 平台值一致，不能与段落缓存账本混为一谈。最终字体／源／缓存的逻辑所有者均清理。少量 JS 增长还包含预热编译和持续追加的示例诊断历史。第一组探针关闭 Network 域、释放控制台结果后，保留的 backing 计数未下降。这些结果不证明通用零泄漏、正常负载的 GC 时机、物理 RAM／VRAM 归还或完整 M4 内存验收；本轮有限调查没有提供修改 Engine 内存实现的依据。

### 保留失败与后续验收

启动时的可选 HTTP 协议发现与 Chrome 原生 SIGTRAP／PID 变化同时出现，未隔离出原生原因。后续采集省略该端点，启动记录中的浏览器 PID 保持不变。未执行浏览器 force-stop、重置或清缓存。它仍是浏览器原生采集失败，不是引擎回归。只有在明确未被凭据锁定时才请求普通锁屏界面消失，平台认证仍然有效。

最终读回保留原有 21 个目标编号、转发／反向映射、旋转、刷新率、保持唤醒和亮度值；恢复最后观测到的原组件并让屏幕回到休眠。不认证活动或标签页的内部状态完全一致。原始堆快照、屏幕／账号／设备标识和原生 dump 保留在私有记录中。

历史回调触发条件、完整 M4／X-MTouch/1 混合负载、原生编辑／中文 IME／无障碍、iPhone／设备矩阵、完整授权 Spine 素材和无法测量的物理 GPU／呈现／能耗仍开放。为保留既有标签页，未终止共享浏览器来模拟系统杀进程；物理折叠／传感器和无线网络中断也不由程序化旋转或受控传输替代。M1.2 仍为 **10.3 ms 对 8 ms**，保持 OPEN。
