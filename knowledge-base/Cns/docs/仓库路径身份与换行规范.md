# 仓库路径身份与换行规范

[English](../../en/docs/repository-identity-and-line-endings.md) | 简体中文

本规范约束仓库工具与公开交付，引擎运行时 API 保持原有契约。

## 路径必须包含所属根与完整相对文件名

公开文件指纹由所属根内的相对路径、字节长度和 SHA-256 组成。路径统一使用 `/`，保留实际大小写及全部目录层级，不能用文件名代替完整路径。公开键拒绝绝对路径、反斜线、空片段、当前或父目录片段、Windows 备用数据流以及末尾点或空格。

执行命令和访问文件时的物理位置属于另一个领域。工具接受 Windows 盘符或 UNC 绝对路径的两种分隔符写法，按 Windows 语义比较词法所属根；POSIX 比较保留大小写及反斜线字面含义。词法一致只说明写法等价，不能证明文件系统对象身份。文件读取还要检查包含关系、真实目录项大小写和符号链接，不由此授予通用 Junction 别名或私有导入权限。

编译器诊断路径使用同一所属根转换规则。行号、列号、错误码及完整消息仍然严格比较。消息变化属于结果变化，不能用路径规范化掩盖。

## 先保留原始字节，再计算指纹

SHA-256 始终覆盖原始字节。计算源码指纹时不得规范化 CRLF、BOM、文本、Unicode 或空白。路径表示可以跨平台，内容身份仍然必须精确。

仓库 `.gitattributes` 使用 `* -text` 禁止隐式文本转换，防止 Git 在工作文件已完成审查后悄悄改变内容，包括贡献者启用了 `core.autocrlf` 的情况。Git 仍可正常展示文本差异，无须修改全局 Git 设置或执行全仓重新规范化。参考 [Git 属性文档](https://git-scm.com/docs/gitattributes)。

编辑器默认要求自研文本使用不带 BOM 的 UTF-8、LF 和一个末尾换行。Markdown 的硬换行空格保留其语义。保留的上游原件与历史原始材料使用编辑器例外，不得顺手重新格式化。

## 显式写入新创作文本

Node 创作入口是 `tools/write-repository-text.mjs --path <owner-relative-file>`，通过标准输入传入创作文本。PowerShell 封装是 `knowledge-base/tools/Write-CanonicalText.ps1 -RelativePath <owner-relative-file> -Text <text>`，可用 `-Node` 指定 Node 可执行文件。父目录须已存在。这些入口用于第一方创作文本，不得用于复制保留原件、原始回执或历史证据。

纯工具 `canonicalTextBytes` 将新创作 CRLF 转为 LF，保留内部空行及 Markdown 硬换行空格，仅移除多余的末尾 LF，并为非空文本保留一个末尾 LF；空文本产生空字节。它拒绝 BOM、单独 CR、NUL 和孤立 UTF-16 surrogate。写入器在记录新内容指纹之前应用该规则，指纹读取仍严格保留原始字节。

验证时知识库检查使用 `-CheckOnly`，避免检查操作替换已有历史结果记录。

## 每次交付前检查全部新增或修改文件

强制仓库规范门禁检查公开可见文件，包括尚未跟踪的新文件。新增或修改的自研文本必须是有效 UTF-8，不含 BOM、CR 或 NUL，并以一个换行结束，不能多出末尾空行。先按明确规则识别必须检查的文本，再进行解码，格式损坏的文本不能伪装成二进制绕过检查。二进制扩展名和保留原件有明确规则。

精确基线记录旧有非规范文本的完整相对路径、字节长度及原始 SHA-256，仅完全相同的旧字节获得豁免。修改此类文件时必须采用规范文本，并完成相关源码及证据审查。基线不允许以后的 CRLF 修改，也不允许重写历史指纹。

暂存文件与 Git 实际对象字节及工作文件比较；发布模式还要求干净检出，并比较完整已提交快照。使用 NUL 分隔的 Git 清单，保留空格与 Unicode 文件名，避免命令行拆分。发现差异就拒绝交付；门禁本身不修复、暂存或重写文件。

新的验证与交付工具必须复用共享身份工具，不能再加入仅文件名比较、忽略平台的统一小写转换或内容规范化哈希。贡献规范及推送钩子将这些检查应用于后续工作包。

## 证据与边界

0.45.1 实施记录分别说明纯路径测试、真实隔离 Git 对照、完整本机门禁、实际推送、PR 合并和主干读回。编辑器提示本身不能构成强制检查。逻辑清理或仓库检查通过，不能证明实体设备性能，也不能证明完整 PNG、Spine 或迁移能力。原有失败记录与源码身份继续保留。
