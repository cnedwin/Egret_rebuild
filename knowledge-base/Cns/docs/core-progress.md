## 当前实现与边界

| 范围 | 已实现的有限契约 | 仍待验证 |
| --- | --- | --- |
| A2 Task 1 | 自有 CPU 源像素投影，区分预乘与直通颜色表示 | 浏览器上传／采样精度 |
| A2 Task 2 | 矩形与图片保持 painter order 的混合准备与图片 pass 描述 | 真实 WebGPU 执行与像素 |
| A2 Task 3／C1 | 有界图片顶点打包、在途工作与清理／错误来源的源码和模拟验证 | GPU 完成、设备互操作与性能 |
| A2 Task 4 | Canvas 图片源准备、帧复制及原始来源错误分类修正 | 实际 Canvas 图片像素与浏览器对照 |
| A2 Task 5a | CPU 上传／混合参考公式和显式逐通道误差界检查工具 | Task 5b 的浏览器校准、Task 6 的确认及 P0–P7 |
| B0／B1 | binary64 数学、拥有自身数据的 CPU 网格及精确 float32 打包 | GPU 场景、材质、蒙皮与动画 |
| RES 声明 | 严格 JSON 声明检查与冻结报告 | 文件、解码、执行及完整 R008／V006 迁移 |

图片由不可变 CPU 图像身份和裁剪视图进入帧准备。准入、投影、打包、执行与回收分别承担边界；一个资源租约或一份源码级 pass 描述不能替代 GPU 完成。错误分类依据内部登记的来源，不能信任调用者构造的错误类或 code。关闭与安全归还仍遵循宿主生命周期契约；预算是确定性工作／字节准入，不是堆内存或真实 OOM 恢复承诺。

Canvas 仍位于显式 web 入口，WebGPU 位于 opt-in 入口；引擎根入口保持无 DOM，导入本身不启动宿主。内部数学、网格、打包与 RES 辅助模块不构成新增公共 facade；不支持深层导入作为稳定产品 API。

## CPU 参考公式

Task 5a 的工具逻辑身份为 tools/texture-oracle.mjs。expectedUploadRGBA 对整数直通通道选择 floor((C*A+127)/255)；expectedEncodedOver 在预乘、编码域中计算连续 binary64 source-over，包含显式 opacity。它没有 UNORM 量化或颜色传递转换。assertTexturePixel 接受调用者明确提供的四通道绝对误差界，全部参数通过预检后才比较；不提供默认、未知或根据结果拟合的容差。这些工具不接收／认证浏览器 profile，也不证明 native 混合精度。独立有理数 fixture 与实际设备校准各有自己的权威。
