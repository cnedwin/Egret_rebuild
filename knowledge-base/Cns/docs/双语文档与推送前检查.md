# 双语文档与推送前检查

[English](../../en/docs/bilingual-documentation-and-prepush-checks.md) | 简体中文

白鹭面向全球社区维护完整的中英文阅读版本。R019 适用于文档、代码和证据更新：每次向 GitHub 推送前，补齐两种语言、来源鸣谢及关键英文注释。

## 阅读版本与共用状态

知识库阅读文档分别放在 en/ 和 Cns/。英文路径使用英文命名；仓库、包和示例的默认文档使用英文，并配有 .zh-CN.md 中文版本。每组文档互链，API 名称、编号、版本、数值、来源和验收条件保持一致。

中文登记册为状态原始记录。英文 JSON 视图登记对应中文来源和摘要，保持编号、状态、日期、依赖与数值一致，共同表达同一套产品状态。代码、原始日志、封存证据、资产和上游法律声明保持各自身份。

## 英文代码注释

对容易误解的职责和契约使用英文注释，包括所有权、取消、释放、重入、错误及宿主生命周期。注释解释约束的理由，避免逐行复述。注释、规格与实现必须一致。

## 每次推送的检查

1. 审阅贡献的公开范围、来源、依赖和鸣谢。
2. 补齐双语阅读文档，同步登记册视图、链接与当前文件身份。
3. 补充关键英文注释并审阅技术含义。
4. 对最终候选运行 node tools/prepush.mjs，完成公开结构、构建、依赖边界、类型、行为、无界面示例和知识库检查。
5. 启用仓库钩子后提交经过审阅的文件。提交前钩子检查暂存的原始字节，推送前钩子检查干净的已提交快照。
6. 实际核对推送提交、PR 和合并内容。

启用钩子：git config --local core.hooksPath .githooks。检查使用精确字节，并遵循[仓库路径与换行规范](仓库路径身份与换行规范.md)。

## 翻译与审阅

使用[术语表](术语表.md)统一用词，翻译完整技术陈述及其条件和不确定项。目标、部分实现和已验证结果分别表述。清单与哈希检查覆盖度和文件身份，贡献者与审阅者负责文字含义。

## 浏览器检查与公开清单

常规 prepush 不启动浏览器。渲染改动需要执行 [AGENTS](https://github.com/cnedwin/Egret_rebuild/blob/main/AGENTS.zh-CN.md) 中适用的真实浏览器检查，使用已记录的依赖和默认启动设置。复用早期结果时，应明确核对相关源码与构建身份未变。

依赖缓存、生成输出、私有配置、凭据和未整理的内部交流不进入公开清单。共享证据和法律原件保留来源；阅读文档更新不改写其结果。
