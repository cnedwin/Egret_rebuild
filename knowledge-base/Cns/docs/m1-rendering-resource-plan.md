## 目标与准入

为复杂二维界面、图集动画及后续完整 Spine 适配建立可复用的渲染和资源基础。保留熟悉的显示、资源和游戏时间概念，减少重复准备和 GPU 分配。基线为 main ca62c980f372683dcb156bc5c284f4036a60f4cc，工程预览 0.61.0。[整体架构计划](architecture-and-engineering-plan.md)继续作为项目规格，本文规定有限的 M1 工作包及共享验收。

M1 工程准入要求环境和既有行为可复现、受保护的 PR CI 实际有效、当前账本可受控集成、共享契约经过独立评审，并采用下述场景与测量配置。不要求把每项历史维护策略全部自动化。原有完整推送和合并门禁继续保留；每个修改渲染行为的工作包还须通过受影响的真实浏览器检查。

完整 M0 社区验收单独保留：[#52](https://github.com/cnedwin/Egret_rebuild/issues/52) 的独立真人/fork 演练尚未完成；缺少的设备、授权 Editor 导出素材及分发资格继续由 [#54](https://github.com/cnedwin/Egret_rebuild/issues/54) 跟踪。这些条件阻塞对应支持/发布声明及依赖它们的测试，不阻塞独立的 M1 工程。M0 在剩余验收完成前保持开放。调整阶段依赖是明确的规划决策，不是追认未执行项目通过。

## 共享设计决策

| 领域 | M1 及其使用方遵守的契约 |
| --- | --- |
| 权威状态 | 显示树、Scope、租约、时钟、动画状态和 CPU 绑定保持权威；渲染缓存是派生数据，淘汰缓存不得销毁游戏对象或借用租约。 |
| 帧身份 | 已保存的公共帧保持不可变，在原契约范围内可于后续修改/销毁后重放。可变临时数组不得进入公共帧；内部快速路径必须验证真实引擎所有权，不接受形似对象。 |
| 顺序与合批 | 保留已提交的显示树/slot 顺序；仅合并目标、管线/材质、纹理、采样、混合、裁剪和颜色状态兼容的相邻绘制。遮罩、材质变化及透明层穿插均是明确边界。 |
| 图片身份 | 共享不可变图片/纹理页与区域/UV 元数据分离；trim、旋转、逻辑尺寸和九宫格保持当前坐标语义。CPU 图片代际与 GPU 设备代际不同。 |
| 材质与裁剪 | 新配置须表达选定 Spine 设计需要的 normal/additive/multiply/screen 混合、明暗双色和有序裁剪边界。M1 实现其声明的共享子集；缺少必需特性时在呈现前明确拒绝。完整 Spine 语义属于 M2 验收。 |
| 颜色迁移 | 既有编码空间预乘输出保留为版本化兼容配置；线性合成配置具有独立参考和显式选择，不得悄然重新解释保存帧。 |
| 生命周期与内存 | 分开核算 CPU 解码数据、GPU 驻留、在途工作、临时上传/回读和保留快照。相关队列、错误作用域及映射义务全部完成后才能复用原生资源。 |
| 恢复 | 稳定宿主外观负责可替换设备会话；重建保留 Engine、Stage、Scope、游戏时钟和 CPU 资源需求。旧设备异步结果不得进入新代际。 |
| 替换 | 既有 BitmapBindingTicket.commit 保持同步 CPU 绑定；设备就绪、GPU 提交/完成和观察到的图像正确性使用独立结果，不重新定义旧返回值或错误顺序。队列完成不证明屏幕已物理呈现。 |
| 依赖 | 保留四个包及 engine → runtime/contracts、runtime → contracts 关系。浏览器执行器保持显式可选入口；默认引擎不新增 Spine 依赖，M1 不开发原生 SDK。 |

## 工作包与依赖

每行代表可独立评审的完整行为，不按辅助函数另建实验项目。配套规格、回归测试、浏览器证据和双语文档随对应工作包交付；后续工作复用同一生命周期和验证体系。

| 工作包 | 实现与主要文件 | 验收与依赖 |
| --- | --- | --- |
| M1.1 热态 GPU 提交 | 重构 engine/web/WebGPUHost.ts 和 prepareTexturedSubmission2D.ts，使合格驻留图片不再重复提取像素。通过职责明确的私有辅助模块，有界复用完成后的顶点/统一变量缓冲与绑定。保留完整准入、错误优先级、回读、B1 合成及图片缓存限制。 | 依赖工程准入。同帧热态提交不重复复制像素/上传纹理，并复用已完成的原生分配。像素/几何/透明度变化、并发帧、压力、回读、停止/关闭、原生调用抛错及设备丢失时，像素与所有权均正确。真实浏览器结果、分配/上传计数和耗时分别记录。 |
| M1.2 增量有序帧准备 | 重构 runtime 的 frameCapture.ts/texturedFrameCapture.ts、显示失效机制及引擎准备逻辑。跟踪结构/变换/外观/资源修订，合并多次写入；保留完整计算参考。增加相邻兼容合批，不按纹理全局排序。 | 建立在 M1.1 所有权基础上。静态、1% 变化和全脏场景与完整参考一致，覆盖祖先变化、隐藏/重挂节点、边界/命中、裁剪及保存帧重放；缓存不得绕过限制。全脏开销不得超过声明的回归容差。 |
| M1.3 纹理页与共享渲染配置 | 分离不可变图片页、纹理区域和 GPU 驻留。以显式新配置调整 imageProjections2D.ts、准备/打包、ImageData2D/纹理视图及图片/纹理绘制路径；增加有界目标复用和完整材质/裁剪键。 | 依赖 M1.2 绘制顺序。多个区域共享一次页上传；trim/旋转/九宫格及透明边缘符合固定参考，无区域串色、跨代复用或保留帧变异。兼容配置参考和明确能力拒绝继续保留。 |
| M1.4 WebGL2 兼容执行器 | 新增显式可选浏览器入口，消费共享配置和帧/资源计划。执行器内部负责 GL 状态、资源代际、着色器、帧缓冲/回读及上下文丢失恢复。 | 依赖 M1.3 契约。WebGPU/WebGL2 共享支持样例符合声明的图像参考；不支持的特性明确拒绝。Canvas 保留既有限定能力，不把网格/滤镜近似宣称为回退支持。 |
| M1.5 资源清单、恢复与综合验收 | 为 project 描述补齐稳定 ID、源文件/设置/版本/目标身份和依赖列表，在既有 AssetManager/租约上构建加载。通过稳定宿主外观重建设备会话，分阶段上传，设备就绪与 CPU 绑定分离；完成综合场景和测量报告。 | 依赖 M1.1–M1.4。规范清单可复现；依赖缺失/成环有明确诊断；取消/替换和迟到结果保持所有权。可用浏览器完成真实丢失/重建和压力循环；每项 M1 场景有明确结果，不可用宿主/设备行保持未执行。 |

每个工作包实施前，在其经过评审的实现规格中固定具体私有函数签名；不得仅为测试方便增加公共契约。首包保持现有所有公共签名，辅助模块拆分不建立第二个宿主或生命周期权威。

## 场景与观察

保留整体架构 U/A/X/L 负载定义。M1 渲染负载采用 U 的 10,000 逻辑/1,000 可见节点及八层裁剪，包含静态、精确 1% 变化和全脏状态。另有小型确定性正确性场景，组合文字、图集动画、透明层顺序、裁剪、交互及双资源替换。两类场景使用原创生成图片和明确坐标，测量前记录精确输入/构建哈希；小场景不能代替规模负载。

50,000 条变高列表和完整文字/IME 仍属 M3；20 个独立完整 Spine 实例及选定版本全部特性仍属 M2。M1 必须预留它们的数据、顺序和材质需求，并纳入既有有限网格/动画集成，不宣称后续能力已完成。混合 X 负载继续采用明确子集，不把全部最大值直接相加。

L 保留 100 次资源/场景/取消循环、每个可执行后端十次真实丢失/重建循环及 30 分钟持续运行。软件注入故障检验确定性错误行为，不能代替真实浏览器设备/上下文丢失；可恢复和终止故障分别记录。

## 测量配置与预算

以下为初始工程验收目标，不是实测结果、生产上限或手机能力声明。采集候选结果前固定场景版本、设置和阈值；修改须公开评审并形成新对比记录。

| 配置 | 固定条件与目标 |
| --- | --- |
| D60 可用桌面 | Windows 11 build 26300；2026-10-18 枚举到 Intel Core Ultra 9 275HX、Intel Graphics 驱动 32.0.101.8826 和 RTX 5090 Laptop 驱动 32.0.16.1742。每次运行记录实际浏览器选中适配器、浏览器版本、电源状态与可执行文件；枚举到 GPU 不等于浏览器已选用。采用精确的 1024 × 768 CSS 与后备像素、显式 Host 渲染像素比 1、请求浏览器缩放系数 1、前台和发布构建，不加额外图形参数。Profile 2 原样记录实际有限正数 window DPR，不进行舍入；要求每帧保持精确稳定，配对运行的值也精确相同。window DPR 不替代显式 Host 像素比。 |
| D60 时长 | 静态/稀疏/全脏各预热 30 秒，再做五次各 60 秒运行。目标帧间隔 p95 ≤ 16.7 ms、p99 ≤ 33.4 ms；引擎 CPU p95 ≤ 8 ms，其中渲染准备 ≤ 4 ms；实际 GPU 计时可用时目标 p95 ≤ 8 ms，否则记未测。取五次运行各自 p95 的中位数对比，并保留全部运行。 |
| 回归阈值 | 相同机器/浏览器基线下，等价全脏负载 CPU p95 不得恶化超过 10%；失败需修复或明确评审取舍。无论速度如何都必须正确，不预先承诺统一提速百分比。 |
| 逻辑内存 | 固定 M1 场景：保留解码源数据 ≤ 128 MiB；新配置评审前，就绪图片驻留 ≤ 32 MiB / 256 项；可复用缓冲/目标驻留 ≤ 32 MiB；在途上传 ≤ 64 MiB；CPU 临时上传 ≤ 32 MiB。回读与调用方保留帧单列。现有更严格的单次调用限制继续生效，这些目标不提高公共限制。 |
| 启动与恢复 | 应用 JavaScript 总计 ≤ 1 MiB gzip，不含可选 Spine 和源素材；固定首次交互场景素材传输 ≤ 4 MiB。目标冷浏览器缓存、10 Mbit/s、往返 80 ms 下首次交互 ≤ 5 秒，记录实际限速方式；从观察到设备/上下文丢失回调，到新代际帧的回读符合声明参考，保留 CPU 源时 ≤ 2 秒，需相同限速重载时 ≤ 5 秒。提交和队列完成单列；该时长包含回读，不测量物理显示延迟。未测限速或恢复的行保持未执行。 |
| 移动端与其他宿主 | Android 中端、iOS 和小游戏宿主继续作为 #54 外部验收行。对应支持声明前须确定并测试精确设备、按内容分档的 30 Hz 预算、温度/功耗及 OS/浏览器组合。桌面目标不代替这些行；它们缺失不阻塞独立于桌面外平台的 M1 实现。 |

Profile 2 从后续测量起明确渲染输入。此前因精确 window DPR 条件被拒绝的运行保留原始未完成状态。新条件必须使用新清单和配对测量，不重新解释旧结果。

配方 schema 4 在每次诊断或计时试验前增加固定初始化：在初始状态连续同步提交恰好两份新帧，不推进负载，两次提交之间不等待；随后只等待一次，直到两次提交均完成退役。确认 Host 没有故障，帧、上传、读回及几何在途费用均为零，再开始完整的 30 秒预热。两次提交对应原有的两帧在途上限，不允许重试或追加初始化帧。初始化提交单独记录，只观察前四次预热尝试及任何失败现场；观察不决定帧选择、不改变调度，60 秒测量的成功路径不增加状态读取、逐帧等待或样本过滤。初始化仍受原总体期限约束。这定义的是初始化完成后的对照，不测量启动延迟，也不证明此前失败由冷初始化造成。此前 schema 3 的失败保留未完成状态，后续测量必须使用新配方。

记录绘制次数及无法合批原因、复制/上传字节、原生分配、逻辑驻留/在途/临时峰值，以及 p50/p95/p99 CPU/帧时间。分别统计动画、捕获、几何、打包和上传准备。按预定容差采集完整相关图像区域，文字区分开记录布局正确性与抗锯齿差异。硬件/驱动/浏览器变化形成新基线，不能延续旧提速对比。

## Spine 输入与素材边界

M1 设计参考采用已检查的外部 @esotericsoftware/spine-core 4.3.13，上游版本 b7beb2ccbbce667a12c02f44d070644f59b04968；已记录的 137 文件元组树摘要为 e3690c1f8fc3c2b8123bfcfe37d50d7f56878fbef8143fe5cd11d0cc97eaf0cf。这是精确的既有工程输入，不表示它是最新版或对应某个兼容 Editor 补丁版本。

按[完整支持需求](Spine动画支持需求与验收.md)覆盖 JSON/二进制导入、骨骼/slot/皮肤/附件、选定版本全部时间线和约束、轨道/事件、含适用反向裁剪的裁剪、明暗双色、全部混合模式、图集页和恢复。已有程序化 F1/F2 夹具不证明真实 Editor 导出兼容。M1.3 冻结共享配置前，须从固定运行时版本导出完整接口需求清单，将每项特性对应至材质、裁剪、纹理、顺序、时间或资源需求。M2 产品验收前仍须具备精确授权 Editor 素材、行为验证及适用分发资格核查；这些输入缺失不阻塞 M1.1。缺少输入不能成为缩减完整 Spine 要求的理由。

Spine [官方运行时说明](https://esotericsoftware.com/spine-runtimes)和[固定源码版本](https://github.com/EsotericSoftware/spine-runtimes/tree/b7beb2ccbbce667a12c02f44d070644f59b04968/spine-ts/spine-core)说明语义运行时与渲染的边界。出处和原始许可声明与白鹭原创 Apache-2.0 代码分开；M1 不捆绑新的运行时，也不证明许可权利。

## 验证与交付

每个工作包依次明确行为及失败情况，观察有意义的回归失败，再实现、运行针对性与完整检查、独立评审源码/结果/双语内容、执行受影响浏览器矩阵，最后通过正常提交/推送 hook 和受保护 PR CI。源码评审不等于执行，AI 评审不等于真人上手。

历史源码/诊断记录保持不可变。渲染器变化须取得经评审的当前准入或版本化后继，并保留历史参考。缓冲池变化将等价销毁/重入/失败控制移到真实淘汰/关闭点，不能删除控制，也不能批量刷新哈希让门禁变绿。受影响采集器无法接纳新行为时，将迁移纳入同一行为工作包，并验证拒绝情况。

PR 记录基线/候选、实测范围、失败/修复及最终 main 文件树，不隐含发布安装包或网站。只有 M1 所有必需可执行行通过才能关闭 M1；不可用平台仍未验收。M2/M3 和完整生产就绪属于后续里程碑。
