## 目标与准入

为复杂二维界面、图集动画及后续完整 Spine 适配建立可复用的渲染和资源基础。保留熟悉的显示、资源和游戏时间概念，减少重复准备和 GPU 分配。基线为 main ca62c980f372683dcb156bc5c284f4036a60f4cc，工程预览 0.61.0。[整体架构计划](architecture-and-engineering-plan.md)继续作为项目规格，本文规定有限的 M1 工作包及共享验收。

M1 工程准入要求环境和既有行为可复现、受保护的 PR CI 实际有效、当前账本可受控集成、共享契约经过独立评审，并采用下述场景与测量配置。不要求把每项历史维护策略全部自动化。采用整体架构计划的交付分层；受保护的完整合并门禁继续保留；每个修改渲染行为的工作包还须通过受影响的真实浏览器检查。

完整 M0 社区验收单独保留：[#52](https://github.com/cnedwin/Egret_rebuild/issues/52) 的独立真人/fork 演练尚未完成；缺少的设备、授权 Editor 导出素材及分发资格继续由 [#54](https://github.com/cnedwin/Egret_rebuild/issues/54) 跟踪。这些条件阻塞对应支持/发布声明及依赖它们的测试，不阻塞独立的 M1 工程。M0 在剩余验收完成前保持开放。调整阶段依赖是明确的规划决策，不是追认未执行项目通过。

## 场景与观察

保留整体架构 U/A/X/L 负载定义。M1 渲染负载采用 U 的 10,000 逻辑/1,000 可见节点及八层裁剪，包含静态、精确 1% 变化和全脏状态。另有小型确定性正确性场景，组合文字、图集动画、透明层顺序、裁剪、交互及双资源替换。两类场景使用原创生成图片和明确坐标，测量前记录精确输入/构建哈希；小场景不能代替规模负载。

50,000 条变高列表和完整文字/IME 仍属 M3；20 个独立完整 Spine 实例及选定版本全部特性仍属 M2。M1 必须预留它们的数据、顺序和材质需求，并纳入既有有限网格/动画集成，不宣称后续能力已完成。混合 X 负载继续采用明确子集，不把全部最大值直接相加。

L 保留 100 次资源/场景/取消循环、每个可执行后端十次真实丢失/重建循环及 30 分钟持续运行。软件注入故障检验确定性错误行为，不能代替真实浏览器设备/上下文丢失；可恢复和终止故障分别记录。

### 下一次测量协议 — schema 6

配方 schema 6 保留容量节拍协议 `egret.m1-2-capacity-paced/1`，增加 `engine-host-span/1` 观测。每次真实动画回调中，仅在 pending 少于两次提交时推进下一负载序号并提交新帧；Host 已满时记录等待，不改变负载。原有两帧初始化及统一退役、30 秒预热、60 秒测量、每状态五对及原生所有权规则保持不变。六次 diagnostic 与三十次 timing 是分别执行的固定批次，不为去除未达标结果而选择性重跑。

以回调进入时刻定义的完整窗口保留开始、中间和末尾等待；已提交帧的 CPU 与原有按帧计数的 RAF 节奏，独立于等待/结束回调及其记录尾部。[增量准备契约](incremental-frame-preparation-contract.md)规定新增的完整间隔按时长加权 p95/p99 判据，数值为 16.7/33.4 ms。这是新的覆盖语义，不重新解释旧的节奏。五次中位数仍按状态与角色分别计算，并保留全部单次结果。

一般计时预算未达标或比较不可用继续固定序列；执行、完整性、环境、原生、期限或清理失败则停止。每次获准 timing 调用沿用 workload.render → Engine → Host 路径，通过公开 HostAdapter 委托观测恰好一次真实 Host 调用。两侧均在预热和测量中保留 Host 进入/退出时钟及回调/帧对应关系；新增委托和两次时钟读取的开销计入 Engine 与回调 CPU 区间，不作扣减。捕获位于嵌套 Host 区间之外，仍计入 Engine 时间。

每个角色/状态先计算每次运行的 Host p95，再取五次中位数。Host 包含准备、打包、编码与提交；候选某状态的中位数 ≤ 4 ms 时建立该状态的准备耗时上界，更大或缺失保持未建立，不能判为准备失败。候选三个状态均须建立上界。没有直接证据时，独立准备与 GPU 时间继续未测。Engine p95 ≤ 8 ms、帧节奏、墙钟间隔覆盖和全脏比值 ≤ 1.10 保持不变，不新增帧率、样本数、等待占比或 CPU 预算。历史 schema 3/4 不完整执行与 schema 5 已完成的性能失败保留原身份及结果，正式验收需要同一浏览器的新实际成对测量。

历史执行及原配方详见[增量准备验证记录](incremental-frame-preparation-evidence.md)，原始失败不改写。

记录绘制次数及无法合批原因、复制/上传字节、原生分配、逻辑驻留/在途/临时峰值，以及 p50/p95/p99 CPU/帧时间。分别统计动画、捕获、几何、打包和上传准备。按预定容差采集完整相关图像区域，文字区分开记录布局正确性与抗锯齿差异。硬件/驱动/浏览器变化形成新基线，不能延续旧提速对比。

### 下一次测量前的有限实现调整

当前改动限于七个既有渲染/Host 源文件，保留已评审的有界准备优化。普通 TEXTURED Host 准备中，只有已规范化多边形完全处于标准轴对齐裁剪矩形内部时，才可省去重复裁剪，并原子重放原有逻辑费用。同一次可信准备调用最多复用 64 个成功的裁剪矩形结果，临时上下文在 finally 中、打包前清空；这两项裁剪改动不启用直接/自定义回调或其他 profile。几何/打包缓存可用不持有资源的数值身份复用同一槽已成功的键比较，但每次访问仍读取当前条目并检查探针状态；每个自有键/探针增加的 8 bytes 纳入原额度。[准备契约](incremental-frame-preparation-contract.md)规定回退、生命周期与计费边界。源码评审和聚焦检查不证明浏览器像素或性能，仍需新的原生验证和完整固定计时批次。

重复裁剪数值准入仅在普通 TEXTURED Host 自有的不可变帧/options 链中复用，每次调用最多保留 64 个引用，保留每次出现的原费用和源回调。角点生成去除临时数组，同时保留全部数值校验、getter 顺序和末尾 determinant 准入。这两项改动已有独立源码评审和聚焦检查。逐边包含裁剪同样沿用原所有权与原子计费规则，已有独立评审和 177 项聚焦测试通过。最新绑定源码的原生正确性及计数检查已通过，诊断环境资格与正式性能仍待完成。不增加渲染 profile 或公开 API。
