# 共享二维真机结果

## Graphics、混合模式和滤镜

实测起点为 [db9772ee](https://github.com/cnedwin/Egret_rebuild/commit/db9772ee104e77b5c34e4c59bbc6f7dde7e90419)。修复候选为提交 `435b394b`。最后四项 Android 控件检查使用 `e4ac428e`，相对原候选仅合入 [#307](https://github.com/cnedwin/Egret_rebuild/pull/307) 的三个登记文件。修复将 WGSL 扩散着色器中的保留字 `from` 改名，并让滤镜示例验证器使用原生背板回读。测试沿用现有示例和独立像素公式，输入由浏览器协议注入。

Windows Edge 157.0.4341.46 和 RTX 5090 Laptop GPU 的首轮 Graphics 与混合用例通过，WebGL2 滤镜截图因分数布局坐标上的边缘像素插值出现偏差。发光边缘截图的 RGB 为 (199, 149, 56)，期望值是 (206, 155, 57)。同一引擎和场景的原生 WebGL2 回读为 (207, 155, 57)，符合原容差。WebGPU 则在 `CreateShaderModule` 阶段被 Dawn 拒绝，原因为扩散着色器使用了保留字 `from`。修复保留滤镜公式和截图，使用 GPU 完成帧的整像素对照期望值。

| 设备 | WebGL2 | WebGPU |
| --- | --- | --- |
| Windows Edge 157.0.4341.46，RTX 5090 Laptop | 10 项专项用例通过 | 10 项专项用例通过 |
| Galaxy Z Fold7 Chrome 157.0.8103.78，Adreno 830 | 10 项专项用例通过 | 10 项专项用例通过 |

每个后端共三项 Graphics、两项混合、两项滤镜和三项压力用例。滤镜核对六个方块各十六个位置，覆盖开启和关闭。透明擦除同时验证浏览器合成与原生 RGBA。压力用例在 640 × 360 背板上分别对 4,096 个不同三角几何项、500 对重叠混合绘制和八组滤镜采集 60 个串行完成帧。几何用例验证超限拒绝。滤镜用例验证原生设备丢失及恢复后的新世代、像素和所有权关闭。资源计数为逻辑值，串行间隔用于对应负载诊断。

Fold7 首轮交互探针读取时，控件仍处于原状态。一次补测还观察到滚动后的可视视口偏移。最终探针把布局坐标换算为可视视口坐标，等到预期状态再回读像素，并记录浏览器分发的触摸事件。Android 测试期间定期检查亮屏和解锁状态，结束时恢复原亮屏设置和浏览器标签页。

## 共享帧成对计时

比较 [af7a08c2](https://github.com/cnedwin/Egret_rebuild/commit/af7a08c22e275087a8ce57575076ce689e12e92f) 与 [8b607c4d](https://github.com/cnedwin/Egret_rebuild/commit/8b607c4dde8cf1045084a37eb45b3458896d9e65)，隔离 [#285](https://github.com/cnedwin/Egret_rebuild/pull/285)、[#287](https://github.com/cnedwin/Egret_rebuild/pull/287)、[#288](https://github.com/cnedwin/Egret_rebuild/pull/288) 三项优化。每台设备按 ABBA 顺序采集，配对使用相同浏览器、后端、输入及 1,280 × 720 背板。每行采 40 个串行样本，并记录 120 次 rAF 帧尝试的接纳与退役。设备支持时独立尝试 40 次 GPU 计时。原生回读与计时查询独立于帧节奏采样。GPU 计时不可用或查询失效时保留状态与空值。

| Windows 负载 | 后端 | 两组配对的准备中位数变化（ms） | 两组配对的 Host 提交中位数变化（ms） | 两组配对的 rAF p95 变化（ms） |
| --- | --- | ---: | ---: | ---: |
| 5,000 个全脏裁剪位图 | WebGPU | −0.55／−1.10 | −1.10／−1.00 | 0／0 |
| 5,000 个全脏裁剪位图 | WebGL2 | −1.40／−0.75 | −1.20／−1.05 | −3.80／0 |
| 5,000 个移动矩形 | WebGPU | −0.60／−0.75 | −1.05／−0.80 | −4.00／0 |
| 5,000 个移动矩形 | WebGL2 | −1.70／−0.85 | −2.00／−1.20 | −4.20／−0.10 |

Windows 上的密集负载 CPU 开销下降，静态与稀疏行方向不一。首轮 WebGPU 矩形的最后一个样本在末尾准备或清理阶段失去系统前台，专项复跑通过同一前台校验并用于对比。WebGPU 时间戳中位数在可用精度下为零，WebGL2 GPU 时间在两组成对样本间有波动。现有证据无法确认稳定的 GPU 收益或普遍的帧节奏改善。

Fold7 的全脏裁剪位图在双后端、两组配对中的独立准备计时均缩短，Host 总提交耗时上升。按 ABBA 顺序，120 次尝试中的 WebGPU 拒绝数为 0／16／11／9，WebGL2 为 4／12／12／7。WebGL2 回调间隔 p95 为 16.7／33.2／33.2／33.1 ms。该负载的 WebGPU GPU 计时中位数四次均为 1.966 ms，WebGL2 无可用 GPU 计时。电池传感器读数为 31.5 至 32.4 °C，用于记录测试条件。

Fold7 另一次带分段探针的 WebGPU 测量复现了全脏 Host 提交增时 +3.20／+1.05 ms。其中最大的同步耗时段是 Host 内的准备阶段（+2.35／+1.20 ms）。独立捕获增加 +1.95／+1.00 ms，较后的原生提交段增加 +0.30／+0.10 ms。Host 内准备与独立准备测量结果的方向不同。这些同步墙钟区间可能包含运行时调度或垃圾回收，阶段内部归因仍开放。静态 Host 提交在两组诊断对照中方向相反。

本次只验收固定对照中的变化。[#55](https://github.com/cnedwin/Egret_rebuild/issues/55) 跟踪既有正式帧节奏验收，[#92](https://github.com/cnedwin/Egret_rebuild/issues/92) 跟踪混合场景和长期运行的正式验收。
