## 交付结果与进入条件

M2 交付可复用的内容构建和独立启用的 Spine 集成：导入获准使用的 JSON/binary 导出与多页图集，创建状态独立的动画实例，与白鹭图形共同合成，并在替换、恢复资源时保留游戏状态。完整支持指明确选定版本的全部适用功能，以及明确验证的后端和宿主。

已实现的可选整合在选定 4.3 系列中使用官方 Core 4.3.13，适用单独运行库条件。这是实际固定依赖，不代表最新包或完整版本资格。M2.1 固定 Editor/导出版本、runtime 包/提交/摘要和样例权利。4.2 适配及更早旧版各自增加后续兼容记录；修改版本字符串不构成迁移。

M1 已提供功能性的渲染、租约、清单和恢复基础。其有效的正式性能失败仍未关闭；合并 M2 功能不能使该结果自动通过。接口设计、导入器和聚焦实现可以独立推进，同时明确保留 M1 性能及 M2 场景预算的集成、发布条件。

M2 不实现完整可视化工作台、AI Agent 平台、旧工程迁移、原生 SDK 或完整 3D 角色动画，而是提供这些方向所需的资源、诊断和播放接口。M3 可在共享接口评审后推进；M4 负责组合后的核心验收。

## 架构与关键取舍

### 1. 构建产物，按类型加载

内容路径为：源文件 → 类型化导入器 → 不可变产物/依赖记录 → 原清单准入 → 类型化 provider/租约 → 实例 → Engine 拥有的图形快照。资源 ID 保持稳定的项目身份；构建键包含源字节、导入器/工具版本、设置、目标配置和依赖键。运行身份还包含实际产物与表示约定。

保留获得的原 `.spine` 工程、JSON/binary 导出、atlas 元数据和源图像；派生产物可重新构建。白鹭工程持续可编辑，但不能把导出骨骼文件等同于原创作工程。导入器不得为修补不兼容而改写原文件。

M2.1 生成图像、图集、序列、Spine 和字体清单产物。普通图像解码到明确参考表示；打包、裁切、旋转页保持逻辑尺寸和采样语义。mip、边缘扩展及可选 KTX2/Basis 目标变体需要固定编码器和精确 Host 能力配置。压缩变体不可用时，只能选择明确兼容的已声明产物或报构建错误，不能默默改变过滤和颜色。第三方编码器选型须形成资格记录。

保存反向依赖和按内容寻址的输出。受支持输入、工具、设置、目标相同，应重现相同的规范化清单及确定性产物字节。排除或明确标注编码器可变元数据。改变图集页只使依赖产物失效；改变 runtime 兼容系列则使对应骨骼导入失效。提供缓存未命中原因，不新增全局指纹维护流程。

### 2. 官方语义与独立白鹭集成

通过版本适配器使用官方语义 runtime，独立实现白鹭的加载、所有权、调度、命令转换、呈现、诊断和恢复。不选择重写全部姿态、约束、混合算法：这会形成第二个兼容性工程，却没有优势证据。独立 Spine canvas/player 同样不满足统一 UI/场景顺序合成。

共享资源私有保存骨骼初始数据和图集/页映射。准入后将上游可变数据对象按不可变方式管理；实例组合皮肤不能修改共享皮肤。每个实例拥有姿态、附件、轨道、混合、约束/物理状态、事件队列和订阅。上游对象及池化数组不能成为公开帧或资源权限。

用已有 GameClock 或显式调用方 tick 推进语义状态，每个 tick 一次；渲染采样不推进状态。不可见时减少几何工作，不能丢弃必要事件或改变约束状态。可见性策略与动画精度调整必须明确且可测。

初始播放配置明确版本，以下默认值限定工作量，并非实测性能结论：

- 每个准入 tick 携带递增身份和非负游戏时间增量。重复或重入 tick 在修改前拒绝。速率默认为 1，0 表示暂停，支持有限正速率；负速率改用显式反向 seek。恢复以当前游戏时钟为基准，不推算后台经过的墙钟时间。
- 含物理状态的实例按不超过 1/60 秒的分段推进，末段可更短以到达准确目标时间。保留所选 runtime 的创作约束设置和内部求解步长；适配器分段不能代替它们。每次 advance 默认最多八段，超限在提交前返回诊断；调用方可显式安排有界追赶，不能静默丢弃时间。
- seek 默认抑制玩法事件。物理 seek 从零时刻 setup 状态创建私有暂存实例，按相同分段规则重放已记录的轨道、皮肤和变换命令。后续可用完整且经过验证的检查点加速，不能浅拷贝姿态冒充检查点。默认每调度片最多 120 段、总计最多 3,600 段；超出已准入历史或预算时拒绝，不替换可见状态；取消则销毁暂存实例。
- 显式事件重放只允许正向 `(oldTime, newTime]` 区间，保持所选 runtime 的事件队列顺序，包括循环与轨道变化，默认每请求最多 1,024 个事件。反向 seek 不倒放玩法事件；seek 成功后才发布完整重放批次，超预算给出诊断，不部分发送。
- 状态推进提交后、UI 布局前分发事件。回调触发的动画状态修改在下一次推进边界生效；销毁立即抑制该实例后续回调。监听器异常沿现有错误通道报告，不重放已发送事件，也不回滚已提交时间。隐藏实例默认继续推进；停用视觉工作不能停用必要事件或物理。

实例创建时记录这些策略上限。应用可通过显式配置选择其他正数有限上限；变更须通过等价参考测试，不能削弱已发布的支持记录。不新增隐藏 RAF/计时器循环。

### 推进失败与候选操作契约

M2.2 负责以下状态和发布规则，M2.1 核对所选上游运行时是否满足。普通推进前校验 tick 身份、时间差和准入步数限制。普通推进修改单个实例，不为承诺通用回滚而每帧复制完整骨骼／物理状态。推进中发生意外失败时，将该实例标记为故障，抑制尚未提交的事件批及新几何，仅保留最后成功发布的视觉快照。故障实例拒绝后续推进，直到按准入历史显式重建或由应用重置；诊断明确可变语义状态没有回滚。其他实例和游戏时钟继续。已分发事件保持已分发，历史帧保持不可变。提交后的监听器异常继续遵循既有独立处理规则。

跳转和资源替换使用私有候选，成功前不修改活动实例。几何发布属于独立提交域：分配／转换失败不能发布半帧，也不能暗中回滚已提交的动画时间／事件。M2.3 定义该失败的诊断及保留快照行为，M2.4 联合资源替换验证。实例故障与图形发布失败不能报告成同一种状态。

重放历史包括有序轨道／混合、皮肤／附件、速率、根变换及准入的外部约束／物理输入，并记录游戏时间／tick 身份。不受支持的上游直接修改使重放资格失效。历史具有显式字节／命令上限；只有存在经验证的完整检查点时，淘汰历史才可推进最早可重建位置，否则拒绝依赖已丢失历史的跳转。不允许无界命令日志或推断墙钟输入。工作包在暴露重放 API 前记录准确上限，既有步数／事件限制继续有效。

验收增加真实推进中故障、预校验拒绝、语义提交后几何发布失败、事件监听器异常、候选取消和历史缺失跳转。断言各实例状态、新旧快照、时间及事件结果，并验证未受影响实例继续推进。固定普通更新须证明热路径不包含完整实例复制。这些是行为／分配检查，不是性能验收。

### 3. 统一图形路径，明确兼容性

优先验证选定官方 renderer-core 输出，使用其已求值的网格变形与 Spine 自有裁剪，包括 inverse clipping，再复制三角形、页引用和颜色到白鹭拥有的有序几何。不能用现有矩形裁剪链近似 Spine 裁剪。M2.1 必须验证该输出 API 对选定版本功能的完整覆盖；缺口触发具体适配器/协议设计，不能假定支持。

这样无需为导入 Spine 先新建一套通用 GPU stencil 框架。白鹭独立负责父级 UI 裁剪、材质转换、提交、缓存和 GPU 生命周期。原矩形 UI 裁剪保持有效；更丰富的 UI mask 由 M3 共享裁剪接口负责。Spine slot 边界和相邻 UI 保持创作顺序，只合并相邻兼容绘制。

normal/additive/multiply/screen、light/dark tint、图集 PMA/straight alpha 和色彩空间均须映射到明确公式与参考。已有 `add-preserve`/`multiply-factor` 名称不能证明 Spine 等价。保持 shared-frame/1 原像素语义，仅在准确表达创作结果确有需要时增加版本化 profile；不能静默改变全部资源的 gamma 或 alpha 约定。

WebGPU 与 WebGL2 使用同一准入绘制数据并保持相同参考结果。Canvas 保持声明的基础能力，在发布前拒绝不支持的必需功能。几何发布须原子完成并使用复制或独占数据；重放旧帧不能看到上游缓冲复用。GPU 缓冲和页归设备代际所有，沿用 Host 完成/退役规则。

### 4. 替换与恢复保留运行中的游戏

用现有依赖组准备候选资源集合。网络、解码、语义构造及 GPU 就绪各有计数和有界队列。取消一个使用者只释放其需求；完成或取消过程仍计费到真实操作结算。

动画替换暂存资源与语义状态，验证必要名称、皮肤、轨道和设备代际，所有参与者就绪后在一个帧边界提交绑定。失败保留旧呈现和状态。策略明确兼容播放位置是保留还是显式复位；目标动画缺失不能静默替换成另一动画。

设备恢复只重建设备状态，保留实例时钟、轨道、皮肤选择和已消费事件位置。旧代际工作不得向新代际发布。资源替换与设备恢复使用不同代际标记，提交时两者都必须匹配。GPU 驻留本身不授权 CPU 场景修改。

## 四个可协作工作包

### M2.1——可重建内容产物与 Spine 资格验证

**交付：** 带依赖失效和目标变体的构建/导入管线；首版本完整功能/权利/参考清单；可定位的 JSON/binary/多页诊断。复用 project/resources、project/atlas、project/spine 边界，只加入经评审的可选导入集成。

**依赖：** M1 清单/资源功能基础。通用导入和样例规格工作可以开始；有许可的创作/导出及 runtime 分发决定仍是外部验收输入。

**验收：** 不变构建重现准入清单/产物，验证缓存命中和选择性失效；畸形、环依赖、缺失、摘要不符和取消构建不能破坏可用工程。JSON/binary 样例覆盖选定导出版本；图集裁切/旋转/PMA/mip 和目标变体有参考结果。每项选定版本功能都有明确 owner 的样例、准确行为预期及宿主/后端记录；缺许可或素材保持阻塞，不计通过。

### M2.2——独立实例与完整播放

**交付：** 可选产品适配器、共享类型化资源、实例私有姿态/皮肤/轨道/物理状态、完整选定版本语义、时钟/事件/seek 控制和资源退役。在相同时间模型下补齐序列播放控制，保留原采样 API。

**依赖：** M2.1 准入产物/版本/权利及共同确定的公开生命周期接口。早期可使用确定性记录输出验证，但这只能证明语义。

**验收：** 事件/附件/轨道顺序准确匹配独立创作预期，约束和时间线覆盖选定版本；共享数据的两个实例可独立变化；组合皮肤、中断、暂停/速率/seek、有限重复和回调销毁符合契约。取消、迟到加载、构造失败及最终租约释放不遗留活跃实例/订阅。原 F1/F2 保留为回归，不作为完整功能样例集。

### M2.3——完整有序 Spine 图形

**交付：** 独立实现共享渲染转换、版本化颜色/采样约定、全部必需附件/裁剪/tint/blend、多页复用，以及 WebGPU/WebGL2 上与普通 UI/有限 3D 的交错合成。

**依赖：** M2.1 功能/参考清单及 M2.2 绘制/实例接口冻结；边界稳定后可与 M2.2 并行。经资格验证的官方 Core 仍为显式依赖。

**验收：** 每个选定后端运行必需功能参考；离散绘制顺序准确、数值/像素在事先声明容差内通过，并有错误 tint/blend/页/裁剪/顺序控制。包含透明边缘、负缩放、高 DPI、旋转/裁切页、旧帧重放和迟到销毁。功能缺失阻止对应完整支持记录通过；独立 canvas 叠层不满足验收。

### M2.4——内容生命周期与动画场景验收

**交付：** 场景级资源替换/恢复集成，以及一个可编辑的动画/换装样例：20 个共享多页资源、状态独立的 Spine 实例和 200 个序列实例；另外保留精确功能样例。

## 官方出处与未决项

资料核对日期为 2026-10-21；上游说明不是白鹭实测结果。

- [Spine 版本规则](https://esotericsoftware.com/spine-versioning)：导出与 runtime 的主/次版本必须一致；包补丁号与 Editor 补丁号不同。固定准确身份，不使用浮动 latest。
- [4.3 API 参考](https://esotericsoftware.com/spine-api-reference)：当前文档包含物理、绘制顺序文件夹和 inverse/convex clipping。完整矩阵应来自选定 release，不能只取这些示例功能。
- [官方 TypeScript runtime](https://github.com/EsotericSoftware/spine-runtimes/blob/4.3/spine-ts/README.md) 和 [Core 包清单](https://github.com/EsotericSoftware/spine-runtimes/blob/4.3/spine-ts/spine-core/package.json)：语义 Core 与渲染集成分开；所读清单写明 4.3.13。这不是 npm registry 最新版查询。
- [Runtime 架构](https://esotericsoftware.com/spine-runtime-architecture)：共享初始数据、独立可变实例，为上述所有权分层提供依据。
- [Runtime 许可](https://esotericsoftware.com/spine-runtimes-license) 和 [Editor 许可第 2 节](https://esotericsoftware.com/spine-editor-license#s2)：Spine 不属于 Apache-2.0；集成、分发与工具包使用者义务适用，可选打包不免除这些条件。保留告知，明确本项目实际的集成/分发权利依据；runtime 权利与样例再分发权利分别确认。本文不表示许可已确认。
