## 本批必须保留的契约

### 原生编辑与已提交 UI

引擎模型负责已提交值／修订及 UTF-16 源选区。真实可聚焦 input／textarea 负责活动组合、选区和编辑几何；不重复显示编辑值或语义节点。beforeinput／input／composition 进入一条有序流，不重复提交，也不在组合输入中途重写。

激活保留源选区和稳定控件／滚动锚点；退出按明确策略结束组合，准备匹配段落／布局后提交受影响 UI 域。原生与 CanvasKit 行断点可能不同，需要预先声明字体相关重排／锚点容差，不能猜字符宽度。

M3.3 同时负责活动原生编辑器的浏览器字体注册／就绪及清理。CanvasKit 注册不会注册 CSS FontFace；复用已准入字体的资源身份和租约，明确 fallback 与重排策略，待所属会话结束后退役被替换注册，不另建资源管理器，也不假设原生与 CanvasKit 换行完全一致。

虚拟列表把活动／焦点／组合行计入既有活动容器上限。有界保留，或回收前明确转移焦点。迟到字体、被替代的程序修改、视口／键盘变化、失焦、取消、销毁和回调错误不能复活旧会话或混合布局修订。鼠标／触摸路由保留原所有者。

首个完整增量包含普通单／多行编辑、选区、粘贴、emoji 删除、撤销／重做及程序修改冲突行为。测试代表性 CJK、RTL 和组合文字；区分受控事件、真实浏览器操作与真实 IME／硬件观察。不支持的原生变换／裁剪明确限制。

### 一个混合参考工程与早期预算核查

M4.1 沿当前公共 API 扩展同一工程，不为每个子系统建立资源管理器、渲染器或时间循环。复用已有内容和独立夹具，在适用处通过工程事务保存稳定创作 ID／声明，把原生对象及临时播放状态留在持久化数据之外。

首轮可使用明确标注的开发子集。最终 X-D60/1 和 X-MTouch/1 仍需原完整场景语义、数量、设备及目标。20-Spine／200-序列组件示例不能证明带复杂 UI 的八 Spine／80 序列混合档位。

扩展完整场景前，明确实际必需 JS、provider WASM／Unicode 数据、字体与其他素材，测量冷启动就绪路径，分别记录源、provider、栅格、Host 和在途驻留。当前段落使用 CanvasKit／SkParagraph，不再另建独立 ICU／HarfBuzz／FreeType 实现。已有原始负载字节不是压缩传输结果。

M3.2 与 M4.1 负责预算核查，M4.2 负责正式测量。保留已公布 X 上限及原失败；真实 provider／内容限制需要变更档位时，在采集验收前公开有理由的版本化后继，并保留原目标。不能删除语言、把必需初始化推迟到首次交互标记之后，或只为通过而增大限制。

### 动画兼容与发布

M2.1 负责准确产物／源／运行库身份、素材权利及变体准入；M2.2 负责语义推进、独立实例、失败与有界跳转／重放。已有物理分段、历史、seek／事件预算及拒绝规则保持有效，除非明确评审的兼容契约替代。

M2.3 负责复制后的有序几何和准确 Alpha／颜色／采样。绘制失败保留最后自有画面，不假装已提交动画事件被回滚。M2.4 负责资源／实例候选准备、兼容策略、CPU 提交与 Host 代际整合。

当前 RESET 不保留任意轨道／时间。保留模式先声明兼容资产 ID／名称／轨道／皮肤／事件历史，暂存候选，不支持的映射明确拒绝而不静默重置。独立实例和全局游戏时钟不等待表面恢复；源／实例与设备代次不同。

## 开发与交付节奏

围绕一个完整行为增量集中实现和接入示例，再统一运行受影响类型／行为测试及必需真实浏览器检查，修复实际失败，完成一次独立源码／结果／双语评审。避免重复无关历史矩阵。

正常提交／推送 hooks 和最终完整合并门禁保持必需。日常采用聚焦反馈；最终候选由不变的 Windows 集成门禁、便携 CPU 作业及既有绑定 GitHub Actions 的规则验收合并。准确输入比对允许复用历史浏览器／设备证据，代码变更使受影响范围重新验证。

里程碑性能、长时生命周期及真机／IME／无障碍验收与普通合并反馈不同，只在实际前置和声明具备时执行，不在每次文字修改后重复。必需失败继续开放。每类 Windows 失败沿既有[治理与 Skill](windows-ci-governance.md)处理，不新增维护项目。
