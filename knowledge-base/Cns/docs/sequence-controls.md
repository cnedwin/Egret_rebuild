# 序列帧控制与已提交事件

中文 | [English](../../en/docs/sequence-controls.md)

本配置在 M2.2 范围内扩展序列帧动画，在既有不可变片段、共享纹理租约和 Engine 时钟上提供独立实例控制。完整 Spine 播放、动画资源替换及 M2.2 整体里程碑仍然开放。下文记录本次序列帧实现的行为测试和实际桌面浏览器结果；这些结果不代表性能或手机适配验收。

## 使用与所有权

可选入口 `@egret/engine/animation` 导出 `createSequenceController` 及其 TypeScript 契约。通过真实 Engine、属于它的开放 Scope、真实 Bitmap 与 SequenceClip 创建控制器，并指定 `profile: 'egret.sequence-control/1'`。现有 `SequencePlayer.applyAt`、`Engine.createSequencePlayback` 和根入口导出保留原契约；可选控制器和数值实现不进入默认入口的运行时依赖图。

每个控制器持有自己的播放状态，借用目标的精确资源绑定。创建后为 idle，不修改 Bitmap。新旧播放配置共享目标占用规则：同一 Bitmap 只能有一个有效占用，每个 Engine 合计最多 256 个。已经停止的历史句柄不能释放后来的占用。应用仍可直接修改 Bitmap 或独立使用 SequencePlayer；共享占用约束仅针对这两个协作的播放配置。

一个按需创建的协调器使用真实 Engine 时钟，管理最多 64 个新控制器。其内部 Scope 属于 Engine，独立于应用 Scope。关闭一个应用 Scope 不能取消其他控制器的时钟注册。最后一个有效控制器退出后，释放该注册与内部 Scope。Scope 取消和 Engine 关闭先撤销待交付事件，再进入通常的逆序清理。

终止时释放目标占用、播放器借用、回调、标记、队列及活跃所有者引用；Bitmap 与纹理仍属于应用。终止句柄只保留无活动引用的状态和采样数据。Scope 可在自身关闭前保留历史已接管句柄；逻辑释放不能证明物理垃圾回收。

## 播放与跳转

操作包括 `start()`、`pause()`、`resume()`、`setRate(rate)`、`seek(request)`、`stop()`、`dispose()` 和 `getStatus()`。方法要求原始接收者；状态和事件均为不可变快照。

- `start()` 只应用一次零时刻。正倍率进入 running，零倍率进入 paused；现有句柄没有重新开始操作。
- 倍率为 0 至 16 的有限数，默认 1。设为零先结算原有运行区间再暂停。在暂停状态设正倍率不会隐式恢复，之后需调用 `resume()`；零倍率不能恢复。
- `totalPlays` 默认 1，表示总播放次数，接受 1 至 1,000,000 的整数或 `'infinite'`。有限播放完成时停留在最后一轮的最后一帧，并释放控制器的活跃借用。
- `seek({timeSeconds})` 静默替换绝对序列时间、重置时钟基线，不发出事件，即使到达完成位置也如此；允许向后静默跳转。
- `seek({timeSeconds, replayEvents: true})` 仅允许向前，发出旧时间之后至目标时间的事件。超过有限终点的请求直接拒绝，不进行钳制。
- stop 与 dispose 立即生效且幂等。完成、停止、故障均为终止状态；需要重播时创建新控制器。停止不会补发末尾标记或完成事件。

正常运行控制会结算自上次观察真实时钟以来的区间，因此先前公共时钟回调阻止协调器执行时，不会静默丢掉该区间。暂停时间和后台墙钟时间不会自动补入。公共 GameClock 的首个错误和最大步长规则保持不变。

## 事件与回调顺序

标记是单独编写的控制器元数据，不修改 `egret.sequence/1` 内容格式。每个标记包含符合 `[A-Za-z][A-Za-z0-9_.-]{0,63}` 的唯一 ASCII ID，以及从零到片段时长的有限时间，最多保留 64 个。同时间标记保持编写顺序，报告原始索引。

开始时仅发出一次初始零时刻标记。正常推进发出 `(旧时间, 新时间]` 范围内的标记。共享循环边界上，上一轮末尾标记先于下一轮零时刻标记。最终有限完成时不产生不存在的下一轮零时刻标记，并在末尾追加一个完成事件。静默跳转会消费目标边界，后续推进不能重复该边界的事件。

协调器先按创建顺序准备并提交全部符合条件的控制器，再按该顺序交付已提交的事件批次。一个新控制器的绑定或监听器失败，不阻止其他新控制器推进。这种隔离不会屏蔽先于协调器执行的无关公共或旧播放回调错误。

在任何真实时钟回调或本配置的事件、诊断交付期间，普通控制进入有界队列，只能在严格晚于当前时钟 tick 的边界执行。该边界先结算旧运行区间，再依次应用队列命令，最终只发布一次目标采样。因此，回调中请求的暂停在下一边界生效；需要立即取消时使用 stop/dispose。读取参数 getter 时的重入直接拒绝，不视为回调命令。

交付期间之外，普通控制同步执行，不能超越已排队命令。只有静默跳转可替换待处理意图，并报告 `ANIMATION_COMMANDS_REPLACED`；stop/dispose 立即丢弃待处理工作。如果正常推进先于队列命令到达完成位置，完成优先并报告 `ANIMATION_TERMINAL_COMMAND`，不能恢复已经终止的句柄。

监听器必须返回 `undefined`。抛出异常或其他返回值不会回滚已经提交的画面、时间和已交付事件；除非被释放或取消撤销，后续事件继续执行。无效异步返回会被观察但不会等待。诊断回调在提交之后、相同交付保护下执行，每个受影响控制器每次边界只报告首个回调失败。

## 数值与工作量边界

时长为 D 时，循环边界定义为 binary64 值 `B(k) = k * D`，通过有界整数搜索选择循环并计算标记次数。精确计算得到的边界映射到局部零时刻；有限完成例外，映射到最后一轮的局部 D。本配置不以原始余数或除法决定循环，也不改变原有循环采样器。

例如 D = 0.2 时，时间 1 就是 B(5)，选择第 5 轮、局部零时刻。字面值 0.6 小于 B(3) = 0.6000000000000001，仍处于第 2 轮内部。不使用 epsilon 吸附。无法表示的内部位置或标记时间在发布前拒绝。正次正规时长仍可用于能够表示且符合边界的请求；超出循环范围的请求在展开事件前拒绝。

| 边界 | 数值 |
| --- | --- |
| 每个 Engine 的新控制器数／合并目标占用数 | 64／256 |
| 每个控制器的标记数／复制的 ID 字节数 | 64／4,096 |
| 倍率 | 有限 0–16 |
| 有限总播放次数 | 1–1,000,000 |
| 片段时长与累计序列时间 | 时长为正、时间非负，均不超过 2 ** 32 秒 |
| 非终止循环索引 | 小于 1,000,000 |
| 每个控制器排队的标量命令数 | 16 |
| 单次完整转换的事件数，含完成事件 | 1,024 |
| 协调器单次边界的控制器数／事件数 | 64／65,536 |

有限总时长必须为正、可表示且不超过时间边界。即使没有监听器，也要预检事件序号安全算术。事件数在分配和目标写入前检查。极端允许的复合转换每个控制器最多进行 43,520 次标记搜索和 340 次循环搜索迭代；64 个控制器合计最多 2,807,040 次。这些是有限工作量边界，不是实测性能承诺。

## 失败与发布

纯计算阶段准备整个时间区间及符合条件的命令。成功转换只写目标一次，再发布状态与事件批次。预检拒绝不改变此前仍有效的画面，也不推进已提交时间或事件；待处理命令保留，供明确恢复或替换。最新问题记录可以改变。

借用绑定失效时进入终止的 `faulted`，报告 `ANIMATION_BINDING_INVALID`；意外目标应用失败时进入 `faulted`，报告 `ANIMATION_APPLY_FAILED`。两者均不发布失败转换的事件或新控制器时间。清理会尝试全部剩余释放，并单独记录清理失败。保留的采样不能恢复已经释放的纹理、被销毁的 Bitmap 或外部替换的绑定；这类失败不保证旧画面仍可渲染。此前捕获的不可变渲染帧遵循独立的渲染契约。

## 验证与范围

行为参考使用原创四色共享图集和两个独立控制实例。验收矩阵覆盖字面帧、时间与事件顺序、非二进制时长的规范边界、倍率、暂停、跳转、新旧目标占用、数值边界、取消、回调顺序和故障隔离。实际 WebGPU、WebGL2 检查还需比较像素、裁剪以及不推进播放的保留帧重放。各项声明必须由当前执行和结果证据支持后才能验收。

[可运行示例](../../../examples/sequence-controls/README.zh-CN.md)通过真实内容管线构建原创 PNG、图集和序列帧输入。[已保存的结果摘要](../../../examples/sequence-controls/verification-summary.json)记录了 Windows、Node 26.7.0、默认无界面 Edge 155.0.4283.62 和 Playwright 1.62.1。WebGPU 与 WebGL2 各通过 15 项固定检查及 185 次精确像素比较，覆盖 11 步时间序列、完整事件记录、十进制边界、故障隔离和 96,000 字节保留帧比较。采集保留 40 份原始 RGBA、28 张 PNG 以及 677 项实际输入的冻结身份，并验证源文件、快照完整性和清理结果。控制器退役后，全部 256 个公开时钟订阅槽均可用，第 257 次申请被拒绝；五项持有租约全部释放。这些是逻辑生命周期和有限浏览器行为的实测结果，不是物理内存或速度测量。

本配置提供序列帧控制，不代表完整 Spine、通用动画调度器、物理内存行为、原生手机输入或帧耗时目标通过。M1.2 全脏 10.3 ms、目标 8 ms 仍然开放。参见 [M2 计划](m2-spine-content-plan.md)、[原有播放契约](时钟驱动序列动画契约.md)、[时钟契约](游戏时间核心契约.md)和[内容构建契约](content-build-pipeline.md)。
