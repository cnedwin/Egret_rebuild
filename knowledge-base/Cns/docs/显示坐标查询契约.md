# 显示坐标查询契约

[English](../../en/docs/display-coordinate-query-contract.md) | 简体中文

日期：2026-10-10。状态：已实现的实验契约，已记录有界执行。实现和验收证据另行记录。本契约在现有[显示与帧语义](显示与帧执行合同.md)上增加有界 CPU 坐标查询，不建立新的平台支持、性能结果或完整旧版兼容性结论。

## 公共 API 与值

```ts
export interface Point2D {
  readonly x: number;
  readonly y: number;
}
export interface CoordinateQueryOptions {
  readonly maxNodes?: number;
}

// DisplayObject；DisplayObjectContainer、Sprite、Bitmap、Stage 继承
localToGlobal(localX?: number, localY?: number,
  options?: CoordinateQueryOptions): Point2D;
globalToLocal(globalX?: number, globalY?: number,
  options?: CoordinateQueryOptions): Point2D;
```

两个类型均由 `@egret/engine` 根入口仅作类型导出。Point2D 属于 contracts，CoordinateQueryOptions 属于 runtime。不增加 Point 类、公共求逆／矩阵辅助函数、新入口或可执行类型工厂。核心保持无 DOM／Node 依赖；导入不启动调度器或宿主活动。

每个缺省或 undefined 坐标独立默认为零。坐标必须为有限 number 原始值；null、装箱数值、字符串、NaN、无穷大均拒绝，且不作类型转换。成功查询返回全新冻结的 `{x,y}`，数值有限，所有负零归正零。结果不持有活动节点、Engine、租约、宿主或调用方 options 的引用；重挂、释放和关闭后仍可保留使用。查询不改变显示状态、所有权、资源或帧序号。

第三参数是新的查询 options；历史 Egret API 在此位置接受可变输出 Point。本契约不修改调用方结果对象，旧版适配器仍待实现。新建的 Point 形状对象不是类型上有效的 options 字面量；但含有效 maxNodes 和额外 x/y 字段的结构化变量仍可能被接受。未知字段被忽略，不会成为输出存储位置。

## 坐标空间与变换权威

使用内部显示实例身份、父节点和变换权威。公开变换、parent、isDisposed、子列表 getter 的重载，以及子类验证钩子，均不提供查询权威。真实节点的 Proxy 包装是不同身份，不视为有效接收者。已真实登记的 DisplayObject 子类继承这些方法。

单位矩阵位于实际最上层祖先之上。计入每个节点的自身变换，包括 Stage 或已脱离显示树的根。脱离的子树使用实际根空间，不会通过保留的 Engine 归属继承原 Stage 变换。Stage 自身 localToGlobal 也包含自身视觉变换。不存在隐式全局 Stage。

rotation 为角度制，先 `% 360`，再转换弧度并计算三角函数。局部变换依次施加缩放、旋转、平移。令 C=cos(angle)、S=sin(angle)，局部系数为 `(C*scaleX,S*scaleX,-S*scaleY,C*scaleY,x,y)`。从根到接收者按父矩阵乘局部矩阵合成。对父矩阵 p、局部系数 a,b,c,d 及平移 x,y，保留以下 binary64 表达式顺序：

```text
world.a  = p.a*a + p.c*b       world.b  = p.b*a + p.d*b
world.c  = p.a*c + p.c*d       world.d  = p.b*c + p.d*d
world.tx = p.a*x + p.c*y + p.tx
world.ty = p.b*x + p.d*y + p.ty
```

世界矩阵按 `X=a*x+c*y+tx`、`Y=b*x+d*y+ty` 映射点。保留现有帧捕获计算和三角函数值，不把直角旋转吸附成精确整数，也不补偿或重排正向求和。每步合成矩阵必须有限。完整矩阵和映射结果有限时，localToGlobal 接受零／负缩放及奇异矩阵，允许普通 binary64 下溢。矩阵或点结果非有限时，整体拒绝；即使请求点没有使用溢出的矩阵系数，也不能通过。

visible、alpha、裁剪、Graphics、纹理内容／租约使用权、帧尺寸和像素比率均不影响这些坐标。查询不需要绘制、布局验证、后端访问或资源获取。本范围不增加边界、命中检测、可变 Point／Matrix、跨节点转换、缓存或调度器。

## 已存矩阵的精确求逆与数值边界

globalToLocal 求解已完成、有限的 binary64 世界矩阵。奇异性判断以已存系数精确计算线性行列式 `a*d-b*c`。仅精确零行列式产生 COORDINATE_TRANSFORM_SINGULAR，不设条件数阈值。即使前面的帧式合成把非零作者缩放压成零，也以完成矩阵的秩为准。

私有求逆使用固定规模二进制有理数计算、内置 BigInt 和局部 binary64 解码。有限数可精确表达为 N*2^e，其中整数绝对值至多 53 位，e 在 [-1074,971]。精确计算：

```text
det = a*d - b*c
nx  = d*globalX - d*tx - c*globalY + c*ty
ny  = a*globalY - a*ty - b*globalX + b*tx
localX = nx/det; localY = ny/det
```

求解前先判断 det=0；零分子返回正零。非零商只在最终阶段按最近值、相同距离取偶数舍入为 binary64。精确乘积／指数对齐及最终商舍入分别保留系数与右端项的极端指数，因此中间归一化、平移相减或舍入后的乘积消去不能静默吞掉可表示结果。这些固定表达式的行列式至多 4197 位、分子 4198 位、舍入／比较操作数 4251 位，位于内部保守 8192 位上限内。不接受调用方精度、任意项列表，不增加依赖或通用数值 API。

对精确非零商，通过整数位数及精确移位比较确定二进制指数 k。k>1023 报范围错误，k<-1075 舍入为正零；否则正常数使用量子 2^(k-52)，次正常数使用 2^-1074，以整数商／余数和奇偶性决定舍入。处理正常／次正常进位及最大有限值的溢出中点。两个坐标均舍入为有限值后才发布一个冻结 Point2D；舍入为无穷大则整体报范围错误。负数与正数采用对称舍入，所有舍入零归正零。

这规定的是已存矩阵有理数逆解的舍入，不承诺精确实数层级坐标或近奇异矩阵的统一误差界限。系数／输入的微小变化可能造成大幅输出变化；正确舍入已存矩阵求解不会恢复合成或普通正向映射已丢失的精度，不保证正向与逆向往返一致。最终逆解允许按最近偶数规则下溢为零；世界矩阵合成溢出仍在求逆前报错。固定位数只建立操作数规模边界，不建立延迟、分配基准或实时适用性结论。

## 输入准入、生命周期、读取与预算

options 可为 undefined 或非 null、非数组对象；函数及其他原始值拒绝。maxNodes 缺省／undefined 为 4096，显式值必须是不经转换的 [1,65536] 整数；null 无效。数组准入只判定一次，maxNodes 通过普通属性查找只读一次，包含继承 getter。不枚举未知键，不单独检查原型，不保留 options。

节点预算包含接收者和全部实际祖先，包括 Stage 或已脱离的根。等于预算的路径成功，多一个节点报 COORDINATE_TREE_LIMIT；硬上限 65536。祖先遍历为迭代形式，不扫描后代，重复身份报 DISPLAY_TREE_INVARIANT。每次调用自己的遍历／分配有界；options getter 自身的任意工作及重入调用累计工作不在此预算内。本契约不改变深树清理。

错误优先顺序如下：

1. 先认证接收者身份，再读取任何公开接收者或 options 字段；无效身份报 COORDINATE_RECEIVER_INVALID。
2. 检查接收者存活，再检查绑定 Engine 开放状态。两者均无效时 OBJECT_DISPOSED 优先于 ENGINE_CLOSED。脱离但已绑定的对象仍受 closing／closed 限制，未绑定的活动节点不需要 Engine。
3. 先验证坐标原始值，再准入 options。对象候选的 Array.isArray 只在窄 catch 内执行一次；已撤销对象／数组 Proxy 的实际准入异常以 `EgretError('COORDINATE_INPUT_INVALID',{cause})` 保留，不再次探测，也不读取 maxNodes。语义形状失败在该 catch 外处理。
4. 成功准入后捕获一次 maxNodes。任何读取异常用 COORDINATE_INPUT_INVALID 包装并保留准确 cause，包括 undefined 或 EgretError。不能依异常类型／代码改判；读取源同时触发关闭／释放并抛出时，源异常优先。
5. 成功读取后，在预算值验证和实际路径采集前重新检查存活／开放。getter 已完成的变换／重挂变化被观察到；getter 触发关闭／释放时不发布结果。重入查询各自拥有局部状态。
6. 在发布前检查路径预算、每个节点存活／开放、合成矩阵、正向映射或逆向精确行列式／最终舍入，以及最后的路径生命周期。逆向精确奇异判断优先于假设性的坐标范围失败。

| 错误 | 含义 |
| --- | --- |
| COORDINATE_RECEIVER_INVALID | 未登记、伪造或 Proxy 接收者。 |
| OBJECT_DISPOSED / ENGINE_CLOSED | 既有终结对象或绑定 Engine 限制。 |
| COORDINATE_INPUT_INVALID | 坐标／options 值无效，或保留准确 cause 的源准入／读取异常。 |
| COORDINATE_TREE_LIMIT | 实际祖先路径超过 maxNodes。 |
| DISPLAY_TREE_INVARIANT | 权威祖先路径出现重复身份。 |
| COORDINATE_ARITHMETIC_RANGE | 完成矩阵／正向点非有限，或最终舍入逆解坐标非有限。 |
| COORDINATE_TRANSFORM_SINGULAR | 有限已存世界矩阵的线性行列式精确为零。 |

查询不发送诊断、不消耗帧 ID、不建立所有权／绑定、不获取或释放资源。这些操作查询的生命周期规则不改变既有标量属性读取行为。

## 精简验证计划

行为／类型验收使用构建后的 `@egret/engine`，不由此获得私有数值模块导入权限。手算字面结果是主要判据；直角例子采用 1e-10 绝对容差，二进制有理数例子用精确断言。往返检查仅为补充。

| 公共设置／输入 | 必须得到的结果 |
| --- | --- |
| 父 x=10,y=20,scaleX=2；子 x=3,y=4,rotation=90 | 子 (1,2) → 全局 (12,25)；全局 (4,28) → 子 (4,6)。 |
| 同一树，Stage x=7,y=-3,scaleX=3,scaleY=-2 | 子 (1,2) → (43,-53)；脱离父节点后恢复 (12,25)；Stage 原点 → (7,-3)。 |
| x=5,y=-7,scaleX=-2,scaleY=3 | (4,-2) → (-3,-13)，逆向返回 (4,-2)。scaleX=0 时正向允许 (5,-13)，逆向报奇异。 |
| scaleX=2^600,scaleY=2^555；全局 (0,2^-500) | 逆向 (0,2^-1055)，精确可表示且非零。 |
| 等比缩放 2^1023，x=-2^1023；全局 (2^1023,0) | 逆向 (2,0)，即使普通平移相减会溢出。 |
| scaleX=1,scaleY=2^-46，或缩放 (2^600,2^-600) | 对应全局 (2*scaleX,3*scaleY) → (2,3)，不设条件阈值。 |
| scaleX=2；globalX 依次为 MIN、3*MIN；MIN=2^-1074 | 逆向 x 依次为 +0、2*MIN，符合次正常数最近偶数中点舍入。 |
| 单位缩放，globalX=MAX，x=-2^969／-2^970／-3*2^969 | 逆向 x=MAX／范围错误／范围错误；MAX=Number.MAX_VALUE。 |
| Stage + 父 + 叶，maxNodes=3／2 | 成功／树预算错误；默认 4096／4097 个节点具有同样边界。 |

还需检查身份／冻结结果归属、渲染／纹理状态无关性、恶意公开 getter、已撤销与继承 options、读取 cause 优先顺序、getter 触发变更／释放、脱离后保留的 Engine 归属、负数镜像、负行列式零分子、正常／次正常进位、正向溢出及只读公共无 DOM 类型。

乘积消去覆盖先采用公共父／子 Sprite 均旋转 45 度，父缩放 (1,2^-120)，子绘制小 Graphics 矩形，通过公共 captureFrame 观察子矩阵。区分性夹具以实际捕获系数 `(a,b,c,d)=(1/2+2^-53,1/2,-1/2,-1/2+2^-53)` 为条件：普通舍入 `a*d-b*c` 为零，精确行列式为 2^-106，全局 (0,2^-106) 逆向为 (1/2,1/2+2^-53)。计入覆盖前必须在固定运行时断言这些系数身份；若不一致，应推导另一公共夹具，不能静默跳过、用往返替代或引入未经授权的私有导入。

共享合成算术提取必须保留帧捕获系数、抑制顺序、错误和快照；其发射模块图变化要求重新执行受影响的真实 Canvas／WebGPU 矩形验证，CPU 等价不能证明渲染构建未变。仅当 B1 的有界模块图／场景行为受影响时才另跑 B1 门禁。证据记录实际源码身份、环境、命令和未覆盖项；计划中的检查不建立通过的验收结论。

## 来源与独立实现

本规范为第一方设计，以已登记的显示／帧权威和独立推导的仿射／二进制有理数数学为依据。实现应从这些契约独立编写，不要求把历史引擎实现作为源码输入。第一方代码／文档保持 Apache-2.0，不增加第三方产品依赖。AI 协助、实际实现输入和作者审阅，分别与研究参考和验收证据记录。保持包依赖图：engine 依赖 runtime／contracts，runtime 仅依赖 contracts，contracts 没有包依赖。保持严格核心类型和现有包导出；生产宿主、迁移适配器、边界与命中检测继续独立验收。
