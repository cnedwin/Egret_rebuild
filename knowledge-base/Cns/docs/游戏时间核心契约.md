# Engine 自有显式游戏时间核心

[English](../../en/docs/game-clock-contract.md) | 简体中文 · [验证记录](游戏时间核心证据.md)

工程预览 **0.25.0** 新增由 Engine 持有的游戏时钟，以秒为单位显式更新。调用方提交绝对源时间，渲染仍是单独的显式操作；构造、订阅与观察都不会启动定时器。[证据页](游戏时间核心证据.md)分别记录 CPU 行为、类型、源码对照、完整核心验证及交付截止状态。这项时间基础不实现 Tween、MovieClip、自动序列播放、浏览器后台检测或完整动画。

## 公共入口与所有权

使用既有 `@egret/engine` 根入口及两个既有 Engine 工厂。`EngineOptions.clock` 可选，`engine.clock` 是只读服务，`engine.advanceTime(sourceSeconds)` 返回 tick 或 undefined。没有公共时钟工厂、构造器、dispose 服务、owner 端口或新增包子路径。

根入口新增六个**仅类型**名称：`GameClockOptions`、`GameClockState`、`GameClockTick`、`GameClockHandler`、`GameClock`、`GameClockSubscription`。时钟和订阅类型具有不透明身份；结构相似值与 Proxy 不会取得运行时权限。

| 接口 | 契约 |
| --- | --- |
| `GameClockOptions.maxDeltaSeconds?` | 只读有限数，须大于 0 且不大于 1；默认 0.25。 |
| `clock.state` | 只读 `running`、`paused` 或 `closed`。 |
| `clock.elapsedSeconds`、`clock.tickId`、`clock.maxDeltaSeconds` | 只读缓存标量；经过时间与 ID 初始为 0。 |
| `clock.onTick(scope, handler)` | 真实的同 Engine Scope；返回独立、由 Scope 持有的订阅。 |
| `GameClockHandler` | `(tick: GameClockTick) => undefined`；仅同步执行。 |
| `clock.pause()`、`clock.resume()` | 显式暂停与重新建立基线。 |
| `subscription.isDisposed`、`subscription.dispose()` | 只读终结状态及同步幂等释放。 |
| `GameClockTick` | 全新冻结记录，只有只读 `tickId`、`elapsedSeconds`、`deltaSeconds`，不持有 owner 引用。 |

两个工厂先保留既有 profile／renderer／diagnostic／timeout 准入顺序，再于 surface 预留或启动前验证时钟配置。不支持的 profile 不读取 options。`options.clock` 读取一次；对于非 null、非数组的对象，`maxDeltaSeconds` 读取一次。undefined 使用默认值，无关字段不读取；时钟持有自己的冻结标量快照。非法值或读取失败产生 `CLOCK_OPTIONS_INVALID`，保留抛出的 cause，包括已撤销 Proxy 的原生错误。

## 显式使用

应用提供既有 HostAdapter。下面使用独立选定的源时间秒数；核心不读取系统时钟或动画帧。

```ts
import { createEngine } from '@egret/engine';
import type { HostAdapter } from '@egret/engine';

async function updateExplicitly(host: HostAdapter): Promise<void> {
  const engine = await createEngine({ host, clock: { maxDeltaSeconds: 0.25 } });
  try {
    const scope = engine.createScope();
    let gameSeconds = 0;
    engine.clock.onTick(scope, tick => {
      gameSeconds = tick.elapsedSeconds;
      return undefined;
    });
    engine.advanceTime(10); // baseline; no callback
    engine.advanceTime(10.125); // gameSeconds = 0.125
    engine.captureFrame({ width: 8, height: 8 }); // separate operation
    engine.clock.pause();
    engine.clock.resume();
    engine.advanceTime(20); // fresh baseline; gap excluded
    engine.advanceTime(20.125); // gameSeconds = 0.25
    void gameSeconds;
  } finally {
    await engine.dispose();
  }
}
```

## 源时间准入、暂停与卡顿恢复

源时间必须是大于或等于 0 的有限数，-0 规范化为 +0。Engine 生命周期和同 Engine 阶段检查先于数值验证。非法或倒退样本不改变已接受的下限、锚点、时间、ID 或监听器。首个样本和相等样本返回 undefined，不调用回调。

运行时以普通 binary64 计算 `sourceSeconds - anchor`。delta 等于上限可以接受，超出上限则原子拒绝为 `CLOCK_DELTA_LIMIT`；不截断、分段、追赶、不缩放速率，也不隐式重建基线。正 delta 更新先准备 tick／候选快照，再于回调**之前**提交源时间、经过时间和 ID。所有到达的回调与调用方收到同一 tick 对象；后续失败仍保留此次提交。

| 操作 | 结果 |
| --- | --- |
| `advanceTime(10)` | 建立基线；经过时间 0、ID 0，不回调。 |
| `advanceTime(10.125)` | ID 1、经过时间 0.125、delta 0.125。 |
| `advanceTime(11)`，随后 `advanceTime(11.125)` | 两次均失败；锚点保持 10.125。 |
| 运行时 `resume()`，再 `advanceTime(11.25)` | resume 无作用，超限 delta 仍失败。 |
| `pause(); resume(); advanceTime(11)` | 新基线；经过时间保持 0.125。 |
| `advanceTime(11.125)` | ID 2、经过时间 0.25、delta 0.125。 |

暂停样本仍验证／更新已接受的单调源时间下限，但不产生游戏更新。重复 pause／resume 无作用。恢复后的时钟需要新的非倒退基线，不清除源时间下限；调用方若重置源时间域，须继续保持单调输入或创建另一 Engine。宿主 timeout 的毫秒继续保持既有生命周期含义，不是游戏时间秒数。

## 订阅顺序与清理

每个时钟固定上限为 **256 个活跃订阅**。每次注册独立，即使使用同一 handler。准入先检查 Engine 生命周期、同 Engine Scope 身份、捕获的 Scope 原始状态操作、handler 可调用性及容量，再发布句柄；公共 Scope 覆盖不提供替代权限。返回的冻结句柄已经属于指定 Scope；同 Scope 重复 use 保持去重，另一 Scope 则收到既有所有权拒绝。

每次 tick 按注册顺序固定候选。已释放候选跳过，新注册等待下次 tick；复用空槽不会经旧候选执行新句柄。释放句柄只移除其回调。Scope 保持既有逆序清理，释放一个 Scope 不会暂停整个时钟。历史已释放句柄可能留在 Scope 记账中直到 Scope 关闭；这不是实际内存或堆上限。

回调可以暂停或 dispose Engine。暂停跳过后续候选，不撤销 tick。活跃派发中的 `resume()` 拒绝为 `CLOCK_REENTRANT`，即使尚处于 running。同 Engine 嵌套时间更新或时间／帧交叉在新 payload 读取前拒绝；既有帧内再入仍为 `FRAME_REENTRANT`。另一 Engine 相互独立。

Engine dispose 先缓存共享 Promise、进入 closing，立即关闭时钟并终结句柄。Scope → Stage → AssetManager → 宿主清理须等待活跃同步回调的 finally 屏障，同时保留既有帧屏障；不会等待非法回调 Promise。关闭后仍可读取缓存的时间／状态及句柄释放状态，真实时钟的变更操作拒绝为 `ENGINE_CLOSED`。宿主关闭 deadline 不能抢占同步用户工作。

## 错误与显式动画消费

回调抛出值后停止后续候选，报告一条 engine／error 诊断 `CLOCK_CALLBACK_FAILED`，外层 EgretError 精确保留 cause。非 undefined 返回值使用相同外层码及 `CLOCK_CALLBACK_RETURN_INVALID` cause。原生 Promise／thenable 的拒绝被观察处理但不 await；观察失败或诊断观察者失败不能替换主错误。再次提交已提交的源时间不重放失败候选；失败订阅仍保留直到释放。

其他具名拒绝包括 `CLOCK_SOURCE_INVALID`、`CLOCK_SOURCE_BACKWARDS`、`CLOCK_SCOPE_INVALID`、`CLOCK_HANDLER_INVALID`、`CLOCK_CALLBACK_LIMIT`、`CLOCK_INVALID`、`CLOCK_SUBSCRIPTION_INVALID`。真实 closing／closed Scope 保持 `SCOPE_CLOSED`，既有所有权拒绝也保持不变。算术与安全序号准入使用 `CLOCK_TIME_RANGE`、`CLOCK_TICK_ID_EXHAUSTED`、`CLOCK_SUBSCRIPTION_ID_EXHAUSTED`；不可达的耗尽边缘由源码审阅，不通过伪造公共状态证明。

SequencePlayer 仍为显式消费者：Scope 可持有播放器及订阅，handler 调用 `player.applyAt(tick.elapsedSeconds)` 后返回 undefined。调用方继续持有 Bitmap 及其精确资源租约；单独向后调用 `player.applyAt(0)` 仍合法。advance 不获取资源或渲染，capture／render 不推进时钟。见[既有播放器契约](显式时间序列播放器契约.md)。
