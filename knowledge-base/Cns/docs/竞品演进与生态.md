## Cocos 把渲染和制作接口逐步统一

3.8.4 在2024年10月正式交付时，以 CRP 构建内置管线并让新项目默认使用；旧项目有迁移路径。当时可定制管线与 WebGPU 的成熟度标签不能外推为今天状态。3.8.5 至3.8.8 继续治理 WASM 加载时机、属性压缩、离屏 MSAA、通道合并和默认资源开销。首屏治理从包体走向初始化、请求和加载顺序。[管线文档](https://docs.cocos.com/creator/3.8/manual/zh/render-pipeline/overview.html)、[更新记录](https://www.cocos.com/creator-download)。

旧研究记录将 Cocos4、CLI 与 PinK 观察为引擎、可调用工程工具和 AI 编辑器的拆分，本轮重验了 Cocos4 与 CLI 的公开 Alpha 发行，未重验 PinK。CLI alpha.42 README 列出创建、导入、构建、工程信息、MCP server 与 simulator preview，模拟器另有构建步骤；main commands.md 只覆盖部分命令，不能单独用来否定预览入口。这启发白鹭先建立统一工程与反馈闭环，Alpha 的公开接口不证明完整自主创作、事务安全或生产可靠性。[alpha.42 README](https://github.com/cocos/cocos-cli/blob/0.0.1-alpha.42/readme.md)、[main 命令](https://github.com/cocos/cocos-cli/blob/main/docs/en/commands.md)。

Cocos UI 合批依赖相邻绘制顺序、材质、纹理及遮罩等条件；JSB 历史优化也体现原生计算与桥接成本的权衡。这些有些属于图形正确性约束，有些是历史迁移成本，都不证明其无法重构。[UI合批](https://docs.cocos.com/creator/3.8/manual/en/ui-system/components/engine/ui-batch.html)、[JSB优化](https://docs.cocos.com/creator/3.8/manual/en/advanced-topics/jsb-optimizations.html)。

## Laya 重新组织 2D 与机器可调用工作流

旧研究记录包含 3.2.5 于2025年4月加入 MCP、3.3.0 重做2D渲染/UI表达/Native交互及小游戏适配、3.3.1 调整批处理/动态文本/统计，以及3.4线的CLI、Skills和结构化资产等进展。未重验的历史条目仍只具有旧来源效力。本轮官方资料支持知识查询、场景操作与无GUI自动化分层：CodingMCP 查询版本化知识，IDE-MCP 操作场景，CLI 提供工程命令，Skills 提供工作说明；这些入口不证明连续创作成功率。[3.3.0发行](https://github.com/layabox/LayaAir/releases/tag/v3.3.0)、[3.3.1发行](https://github.com/layabox/LayaAir/releases/tag/v3.3.1)、[AI路线](https://layaair.com/3.x/doc/guides/roadmap/ai/)、[CLI](https://github.com/layabox/layaair-cli)、[Skills](https://github.com/layabox/layaair-skills)。

日期存在尚未解决的官方来源冲突：旧研究将3.3.0置于2025年8月、3.4.0置于2026年6月；本轮GitHub页面只显示3.3.0为05 Aug、3.4.0为12 Jun，文本未显示年份；官方services发展历程分别写2025-01-04、2026-02-02。尚未确认发展历程指预览、正式发行或其他里程碑，不能合成首发日期、用更早日期静默替换旧记录，或给GitHub月日补年。services页更新日期2026-07-10也不是产品首发日期。[官方发展历程](https://layaair.com/3.x/doc/services/)、[3.3.0发行](https://github.com/layabox/LayaAir/releases/tag/v3.3.0)、[3.4.0发行](https://github.com/layabox/LayaAir/releases/tag/v3.4.0)。

CLI 找不到匹配运行时会警告并回退到最新已安装版本，IDE MCP 文档还要求插件、端口与云端 Key 配置。知识查询的版本选择、格式校验、构建成功与实际玩法/视觉正确分别核验；本轮未测试安装、套餐、云服务可用性、真实工具列表或故障行为。[CLI](https://github.com/layabox/layaair-cli)、[IDE MCP](https://layaair.com/3.x/doc/basics/developmentenvironment/ide-mcp/)。

白鹭应借鉴其把适配与自动化流程变为可维护接口的思路，同时用复杂 UI、混合渲染和连续创作任务验证自己的取舍。发行中的已修复问题不能作为当前未修复缺陷；官方优化数字也不能直接变成跨引擎排名。

## Godot 用身份、编译前移和模块替换降低演进成本

4.4 补全脚本/着色器 UID，4.6 引入节点内部身份与机器可读扩展接口；移动、改名和外部工具操作更能保留引用。4.4 的 ubershader 与4.5 shader baker 把部分成本前移，但这条优化适用于 Forward+/Mobile，不能直接声称 Web 获益。4.4 到4.6 的 Jolt 从可选实验走向新3D项目默认，既有项目保留选择。[UID说明](https://godotengine.org/article/uid-changes-coming-to-godot-4-4/)、[4.6发布](https://godotengine.org/releases/4.6/)、[管线编译](https://docs.godotengine.org/en/4.7/tutorials/performance/pipeline_compilations.html)。

Godot 4.7 Web 使用 WASM + WebGL2 Compatibility，文档明确当前不支持 WebGPU，Forward+/Mobile 和 Godot 4 C# 项目不能按相同方式导出 Web；线程与部署另有条件。本轮读取了4.7版本化文档，不能因其他访问记录臆造本次404。原生管线预编译和shader baker的收益不能外推到Compatibility/Web。这给白鹭的启发是从第一版管理对象身份、接口版本和能力配置，利用 Web 的专门优化机会；不能据此认定 Godot 永远无法改变后端。[Web导出](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html)、[管线编译](https://docs.godotengine.org/en/4.7/tutorials/performance/pipeline_compilations.html)。

## 宿主正在改变交付边界

Safari 26.0 发布 WebGPU，但系统和设备下限仍需核对。浏览器里可用，不意味着微信或抖音当前客户端同样可用。微信/抖音的图形能力、WASM、线程、文件与包限制要独立建立矩阵；当前未完成全量覆盖核验。[WebKit公告](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/)、[抖音适配文档](https://partner.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/game-engine/cocos-laya-egret)。

Meta 宿主范围确定为 Instant Games，其初始化、加载进度和启动生命周期需要接入。Discord Activities 有 iframe、网络代理及 URL 映射约束；Telegram Mini Apps 有视口、安全区、全屏与前后台状态。宿主服务适配和图形后端应分别验证，普通网页导出不等于平台交付成功。[Meta快速开始](https://developers.facebook.com/documentation/games/build/quick-start)、[Discord网络](https://docs.discord.com/developers/activities/development-guides/networking)、[Telegram接口](https://core.telegram.org/bots/webapps)。

AI 创作也有 GDevelop 等直接竞争，不能将“有Agent”当作独占优势。差异需要落在持续修改成功率、玩家体验、交付和迁移结果上。[GDevelop官方说明](https://gdevelop.io/blog/make-games-with-ai-agent-gdevelop-automated-prompt)。

## 对白鹭的行动含义

先建统一身份和工程语义、可裁剪运行时、按宿主验证的能力配置、资源构建与异步反馈；用真实样本检验候选架构。本轮官方机制支持区分渲染后端与宿主服务、显式管理设备丢失、异步就绪和桥接生命周期，但这是工程推断，不能升级为白鹭已实现或已领先。

R011 对应研究、验证与自审循环，V008 是候选设计文档包。局部合同模型和浏览器研究已执行，模型审计修复复验及实际检查数量见[技术验证记录](技术验证记录.md)；D全部proposed、H全部untested，V001研究部分in_progress，V002已有局部headless核心，V003—V006产品实现仍未开始。首批宿主顺序、团队、工期和数字性能预算未确认；R008仍为首个完整发布目标，V006依赖V001—V005。研究证据进入来源与候选说明，只有真实同任务实测才可能形成优势结论。技术候选见[渲染引擎与运行时](渲染引擎与运行时.md)，验证边界见[第一轮研究核查](第一轮研究核查.md)和[核心优势与验证](核心优势与验证.md)。
