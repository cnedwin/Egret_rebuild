## 保留的失败与覆盖修正

功能 RED 先经过真实初始化的 Engine／显示／Scope 行为，不属于导入、setup 或泛化 TypeError 故障。普通矩形保持原始 2×3 fixture，即使前瞻用例文字举例为 2×2。

独立核心审阅发现，已撤销 Proxy 配置可能越过保留 cause 的错误封装。真实专项 RED 保留该失败；修正后的专项见证及两个工厂公共对照均通过。这是独立的准入缺陷，不是能力缺失 RED。

两次初始类型运行因诊断预测错误而失败：错误 Scope 预期 TS2345，实际 TS2740；私有准入 import 预期 TS2305，实际 TS2724。准确输出继续保留；只修正不准确的预期诊断，源码表达式、负例意图及未抑制 checker 权限保持不变。后续严格运行通过全部 234 条诊断。首轮边界对照为 17/18，namespace fixture 未能解析直接工作区 contracts 包；修正公共入口解析后通过 18/18，没有放宽边界规则或指定 mutation 原因。

尽管初始结果为 21/21，独立 fixture 审阅仍发现两处缺失断言：只检查 payload 不能证明回调前公共经过时间／ID 已提交，活跃 resume 也只在 pause 之后检查。两处有界补充保留全部 21 个测试声明、真实基线及先前字面值；补充公共运行通过 21/21。原始 fixture 版本与结果继续分别记录。

## 对照实际建立的证据

公共测试覆盖标量快照、默认／自定上限、精确 cause／优先级、首个／相等／非法／倒退样本、卡顿拒绝原子性、pause／下限／resume、256 个活跃注册、复用槽位后的注册顺序、抵抗覆盖的真实 Scope 准入、共享关闭 Promise 及真实清理屏障。它们检查四个帧方法与时间派发交叉、既有帧内再入、独立 Engine、已提交回调失败、非法返回的拒绝观察及终结后的真实 facade。

序列消费者使用自有不透明 6×2 图像、同代次的两份真实独立租约、Bitmap、SequencePlayer 及其 Scope 自有订阅。持续时间为 0.125／0.25／0.125，裁剪为 2×2、1×2、3×1；游戏时间 0.125 选择帧 1，单独 `applyAt(0.375)` 及向后 `applyAt(0)` 仍合法。捕获不产生 tick 或再次获取资源；保存的 CPU 帧／图像值在退休后继续存在，不属于原生／GPU 像素证据。

GC19 明确为仅静态范围：安全 ID 准入、有限且严格增长的经过时间和、有限槽位／候选存储及 finally／owner 清除。不使用伪造的公共序号耗尽、私有状态注入、实际堆／GC、回调抢占或吞吐量声明。GC20 的类型／源码／回归范围与公共运行时行为分别记录；前瞻规格为 20 个组，这个组数不是实际执行的 21 项测试数。

## 范围与来源

源码属于按白鹭规格独立实现、AI 协助的第一方工程，复用既有 Engine、Scope、资源及显式 SequencePlayer 契约，不新增外部 scheduler 实现或依赖。这只说明所选实现资料，不是全局原创性或训练来源认证。第一方代码和文档保持 [Apache-2.0](https://github.com/cnedwin/Egret_rebuild/blob/main/LICENSE)，既有第三方声明保持不变。
