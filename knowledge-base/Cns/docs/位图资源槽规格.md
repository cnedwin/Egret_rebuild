# 位图资源槽规格

[English](../../en/docs/bitmap-resource-slot-spec.md) | 简体中文

资源槽为同一个 Bitmap 提供显式的异步 Texture 替换。新资源加载、失败或取消期间，旧的有效绑定继续显示；只有最后一次被接受的请求可以提交。本契约定义资源绑定就绪，GPU 上传、画面呈现、多资源切换及动画重定向分别验收。

## 公共接口

既有构建入口 `@egret/engine` 增加一个 Engine 方法和两个擦除类型：

```ts
type BitmapResourceSlotState =
  'idle' | 'pending' | 'ready' | 'failed' | 'conflicted' | 'disposed';

interface BitmapResourceSlot {
  readonly state: BitmapResourceSlotState;
  replace(ref: AssetRef<Texture>): Promise<void>;
  cancel(reason?: unknown): void;
  dispose(): void;
}

Engine.createBitmapResourceSlot(scope: Scope, bitmap: Bitmap): BitmapResourceSlot;
```

句柄被冻结，每个方法和 getter 都要求准确的接收者。本增量不新增公共构造器、自由工厂、包子入口或依赖，也不改变 Host 协议。

创建要求 Engine 开放、Scope 为该 Engine 的真实开放 Scope、Bitmap 为同 Engine 的真实存活对象，并持有非空的有效 Texture 租约。保留当前裁剪。一个 Bitmap 同时只能有一个资源槽；一个 Engine 最多有 256 个存活资源槽。释放资源槽会释放占用和容量。

## 所有权

初始 Bitmap、父节点和租约继续由原有所有者管理，资源槽只借用它们，不释放或恢复初始租约。资源槽仅向 Scope 登记一个句柄，并且只拥有替换请求实际获取的新租约。

成功替换使用新 Texture 的完整基础区域，同时更新自然尺寸。父节点与顺序、位置、缩放、旋转、锚点、可见性、透明度、裁剪、监听器及显式命中区域保持原值；不会自动调整布局或命中区域。

通过 Bitmap 观察到的租约仍是借用。手动复用或裁剪资源槽拥有的租约，不会转移所有权。需要在资源槽释放后继续使用的手动绑定，应独立获取租约。

## 请求顺序与结果

1. 检查接收者、Engine／Scope 内在生命周期、资源槽状态和准确的当前绑定，再同步验证类型化引用、Provider 和 ID 兼容性。
2. 普通无效输入同步抛错，不替换已经等待中的请求。
3. 每次接受新请求，都先将它登记为最后意图，再取消前一个请求。每次接受的调用返回独立且已处理拒绝的 Promise。
4. 获取和准备期间保留旧绑定。发布前再次检查请求仍然有效，且旧资源与候选资源的租约和 Texture 均有效。
5. 在无应用回调的区间内提交绑定及所有权元数据，设置 ready 并以 undefined 完成 Promise，之后才释放上一个自有租约。

成功表示绑定曾在一个同步提交点生效。等待方恢复执行之前，后续请求或清理回调可能已经再次改变或释放绑定。

| 结果 | 状态与 Promise |
| --- | --- |
| 当前请求成功 | ready；以 undefined 完成 |
| 获取或准备失败 | failed；BITMAP_RESOURCE_REPLACE_FAILED，保留原始原因链 |
| 被后续请求取代 | BITMAP_RESOURCE_SUPERSEDED；新意图保留自己的状态 |
| 显式取消 | BITMAP_RESOURCE_CANCELLED，保留准确原因，包括 undefined；已有自有绑定则回到 ready，否则 idle |
| 资源槽／Scope／Engine 释放 | disposed；等待请求为 BITMAP_RESOURCE_DISPOSED，保留生命周期原因 |
| 手动绑定／裁剪冲突 | conflicted；等待请求直接为 BITMAP_RESOURCE_BINDING_CHANGED |

取消不依赖 Provider 配合完成。如果获取已交付租约、但 Promise continuation 尚未执行，过期工作必须释放该准确租约。未以租约交付的 Provider 返回值仍由 AssetManager 清理。资源槽不会直接销毁 Provider 值或撤销外部等待者。

加载器、类型检查、取消监听器、释放器及诊断回调允许重入。所有已经启动的获取都安装成功和失败观察者；外层操作不能在回调后重新登记已经过期的请求。

## 手动改动与资源撤销

每次成功的非空手动租约／裁剪赋值都会改变私有绑定令牌。因此，同租约赋值、裁剪重置和 A→B→A 即使公共值相同，仍然构成冲突。失败的手动赋值不改变令牌。

下一次资源槽控制或候选结果处理会检测冲突。资源槽保留目标占用直到显式释放，不把手动绑定接纳为新基线，也不在清理中覆盖它。

如果手动改动复用了资源槽自有租约，释放资源槽时保留手动字段，但仍释放自有租约；此后新捕获可能失败。使用独立自有租约的手动绑定可以继续有效。

外部释放未改变令牌的初始／当前租约，或销毁其 Texture，属于另一类失败。原字段保留，但有效性已被外部撤销，不在旧画面保持保证内。等待请求以 BITMAP_RESOURCE_REPLACE_FAILED 失败，保留 ASSET_LEASE_RELEASED 或 TEXTURE_DISPOSED 原因。同步控制观察到该情况时，抛出既有资源原因，不接受新请求。

## 生命周期与清理

控制优先级为：接收者 → Engine 开放 → 真实 Scope 成员身份／开放 → 资源槽终态 → 目标存活／准确绑定 → 引用准入。状态 getter 只验证接收者并读取记录，不轮询或清理。

Scope 进入 closing 后，通过捕获的内在状态拒绝重入的新工作。既有 Scope 逆序清理释放唯一句柄，不等待 Provider。在更早的 Scope 取消监听器内观察状态，可能仍看到句柄清理前的记录状态。

Engine 关闭时，先将所有资源槽置为终态并清除准确匹配的自有借用，再调用任何取消、释放或诊断回调，并早于等待活动画面结束。dispose 可重复调用，关闭后仍然可用。

清理只清除匹配的已提交自有令牌，不清除初始借用或后续手动绑定。逻辑路由和所有权单元先于回调退休，全部清理义务均尝试执行。Provider 释放错误保留 AssetManager 的 ASSET_CLEANUP_FAILED 诊断；额外资源槽清理错误使用 BITMAP_RESOURCE_CLEANUP_FAILED。提交前失败保留主要原因和立即观察到的次要清理错误，清理不能撤销已提交的成功。

以上为逻辑所有权保证，不证明 Provider 物理中断、垃圾回收、GPU 退休或 AssetManager 历史 ID 有界。

## 准入与稳定错误

| 条件 | 错误码 |
| --- | --- |
| 方法／getter 使用其他接收者 | BITMAP_RESOURCE_INVALID |
| 外部、伪造或代理 Scope | BITMAP_RESOURCE_SCOPE_INVALID |
| 关闭中的／已关闭的 Engine 或真实 Scope | ENGINE_CLOSED / SCOPE_CLOSED |
| 外部、伪造或代理目标 | BITMAP_RESOURCE_TARGET_INVALID |
| 已释放目标 | OBJECT_DISPOSED；等待中的 Promise 以 BITMAP_RESOURCE_DISPOSED 拒绝，cause 为 OBJECT_DISPOSED |
| 初始绑定为空 | BITMAP_RESOURCE_TEXTURE_REQUIRED |
| 已有活动占用／第 257 个存活槽 | BITMAP_RESOURCE_TARGET_BUSY / BITMAP_RESOURCE_LIMIT |
| 释放／冲突后的控制 | BITMAP_RESOURCE_DISPOSED / BITMAP_RESOURCE_BINDING_CHANGED |

类型化引用、Provider 和 ID 错误保留既有 AssetManager 错误码。replace／cancel 中 Engine／Scope 关闭优先于资源槽终态错误；dispose 始终可用。

## 实现与验证

Runtime Bitmap 管理准确绑定令牌，并按准确 EngineContext 缓存窄桥。每个操作验证 Context 和真实对象身份。准备令牌保留在私有表中、绑定目标，并在成功提交时单次消耗；伪造、复制或其他 Context 的令牌不能发布。无应用回调的写入之前，再次验证原绑定和候选资源的租约／Texture 有效性。公共 Runtime 装配只能获得自身 Context 的权限。

Engine 所有者在公共对象暴露前捕获真实 Manager 操作和原始 Scope 权限，核心不依赖 DOM／Node。既有 SpriteSheet 原始操作单元保留各自的独立权限。

实施依次验证准入与借用、请求及交错、生命周期及组合，然后完成严格接口、源码边界、浏览器与完整发布门禁。每个阶段保留失败记录，区分已编写 fixture 和实际执行验收。参阅[核验记录](位图资源槽核验.md)。

## 组合边界

同一个 Bitmap 用于替换前，应停止／释放 SequencePlayer 或 SequencePlayback。并发裁剪写入会冲突；绑定旧准确租约的播放器不能自动重定向到新纹理。其他 Bitmap 上的序列动画保持独立。

BitmapButton 拥有内部 display 及皮肤裁剪。其内部 Bitmap 不属于资源槽支持目标，这是调用前提；工厂不声称能识别 Button 内部对象。独立 Button 可以控制普通目标。

保存的不可变画面在后续替换或释放后继续保留原图像与裁剪值。资源槽成功不表示画面已经呈现；后续画面验证或 Host 失败不回滚绑定。
