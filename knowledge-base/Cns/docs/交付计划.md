# 交付计划

[English](../../en/docs/delivery-plan.md) | 简体中文

交付把可运行引擎连接到完整创作与发布流程。共同样本定义目标，Runtime及资产能力提供执行，工程服务支持安全修改，工作台将其连接到真实发布与持续维护。完整旧迁移属于同一首个完整发行目标。

当前有界预览已推进至0.54，[核心进展](core-progress.md)及[包记录](../README.md)说明已交付能力。下述阶段描述更广产品，不承诺发布日期；首批宿主、人员、工期、预算和数字性能门槛仍待确定。[交付登记](../registry/交付.json)保存状态，[工程规划](工程规划.md)说明可执行工作包。

## 交付阶段与依赖

| 阶段 | 需要交付的结果 | 进入下一阶段的条件 |
| --- | --- | --- |
| 共同样本与基线 V001 | 复杂 UI、混合 2D/3D、旧工程样本；宿主/设备配置；行为与性能测量口径 | 样本有授权，功能与画质固定，能重复测量；首批范围明确 |
| 渲染运行时原型 V002 | UI 更新原型、混合渲染原型、加载/调度/恢复原型 | 正确性、帧时间、内存、首次可交互和持续运行结果能支撑或推翻技术候选 |
| AI 工程接口 V003 | 对象/资源 ID、工程格式、命令、事务、诊断、版本与撤销 | 连续修改能定位对象、保留玩法、获得反馈并恢复；不是单次生成演示 |
| 资源动画管线 V004 | 2D/3D 导入、字体图集、骨骼和序列帧、目标资源与构建清单 | 与运行时语义一致，错误可定位，源资产和依赖可追溯 |
| 工作台与平台交付 V005 | 创作、编辑、试玩、修复、打包、真实宿主运行和更新闭环 | 所声明宿主/设备上完成关键流程；接口文档与支持矩阵一致 |
| 一键迁移工具 V006 | 工程盘点、转换、AI 修复、新旧验证、独立产物、差异报告与恢复 | 声明支持范围内完成行为、视觉、动画、资源、状态、平台与性能对照，并计量人工及 AI 成本 |
| 知识库与社区基础 V007 | 需求、候选架构、证据、交付、维护规范与贡献模板 | 从第一天公开文档、知识库与设计讨论；后续每次变化继续核验，公开仓库、许可证与发行信息明确登记 |
| 候选设计文档包 V008 | R011 对应的技术白皮书、PRD 与工程规划0.7候选版，关联实际验证、研究核查与独立审计 | 文档互相一致、边界和失败证据可追溯，接受进一步审阅；文档交付不批准技术候选，也不计作引擎产品实现 |

V003、V004 与迁移原型应随核心原型参与接口设计，避免等新内核完成后再补齐旧语义。V005 的平台交付次序由 Q002 决定；V006 最终依赖 V001—V005，包括继续编辑与实际平台发布闭环。R008/V006 始终属于首个完整发布目标的正式范围，不因初期样本少、原型限制或文档完成而被降为可选功能。

## 完整Spine验收

R020要求完整且版本正确的Spine集成。V020登记前置为V001，集成同时需要适用资源、渲染、工程和宿主接口。V002/V004/V005/V006加入对应Spine验收义务，最终依赖集合不变。文档、上游能力、导入计划和基础播放都是中间产物；[Spine门槛](Spine动画支持需求与验收.md)定义完成条件，完整能力仍开放。

## 每次验收必须留下什么

审查将需求和决策连接到产物版本、环境、输入、实际结果、容差、未解决问题及复现。比较固定功能和画质，迁移执行约定旧新流程。[验收模板](../templates/实验与验收.md)规定记录形态。

源码产物说明实现，执行报告说明观察，登记摘要说明范围。失败门槛保留原观察，真实后继通过后另记；新叙述不能代替证据。R011将研究、推敲、验证与审查连接成持续工程循环。

## 成熟实现与验证分工

R012将成熟算法及有版本机制研究作为工程输入。白鹭核心遵循独立规格，公共依赖明确归属。[采用记录](开源参考实现与采用方案.md)及[第三轮集成](../archive/第三轮研究.md#execution)/[审计](../archive/第三轮研究.md#audit)说明已执行参考链及V002/V004有限研究进展。设备测量单独进行，手机缺席不阻止无GPU前提工作。

## 研究的后续作用

宿主与技术比较研究决定有用实验，不建立产品领先。[第一轮研究](../archive/第一轮研究.md#research)保留Laya IDE/旧网页日期未验及官方日期冲突。旧源码审阅未建立全部旧构建、许可或复用途径。效率、自动迁移和创作完成率的数字目标由样本基线收敛。
