[English](../../en/docs/bitmap-resource-slot-evidence.md) | 简体中文

此前一次完整运行在保留 fixture 处失败：3,349 项中 3,347 项通过、2 项失败。隔离复制清单缺少新增严格类型驱动，另两份故障 fixture 仍引用旧 Bitmap 产物身份。修复仅限三份 fixture 文件，保留断言与故障对照；专项重放 41/41 通过。上表完整结果来自修复后另一次全新运行。

公开行为套件覆盖准入、最新已接受意图、失败／取消请求、重试、共享获取、延迟租约交付、手工改绑、清理重入及 Scope／Engine 的内在关闭。自定义上下文的运行时组装单元检查与真实 Engine 行为分开。保存帧与新捕获各自检查资源使用权。

一组专项回归将成功手工改绑与随后释放租约或销毁 Texture 组合起来。绑定 token 已改变时，应优先判为绑定冲突；token 未改变时撤销使用权，仍按资源失败处理。检查覆盖成功和失败的 provider reaction 及直接控制。上述用例通过后，独立源码审查认可了选定五份生产源码及其声明。

## 实际浏览器范围

[示例](https://github.com/cnedwin/Egret_rebuild/blob/main/examples/bitmap-resource-slot/README.zh-CN.md) 使用 32×24 渲染表面，设备缩放因子为 1。它组合持久目标、父级变换和裁剪、独立位图 Button、字面 Texture provider 及原生指针输入。记录环境为 Edge 155.0.4283.45、Playwright 1.62.1，每次运行使用全新上下文，不附加启动参数。

| 观测 | 普通案例 | 敏感性对照 |
| --- | --- | --- |
| 后端／上下文数量 | 2：Canvas 和 WebGPU | 2：全新 Canvas 和 WebGPU |
| 检查点 | 28，每个后端 14 个 | 28，相同完整流程 |
| 原始 RGBA 帧 | 30，包含两个启动屏障 | 30，包含两个启动屏障 |
| 比较的采样点通道 | 672 | 672 |
| 采样点差异 | 0 | 每个对照准确出现一处指定启动差异 |

每个检查点按独立规定的六个 RGBA 点进行零容差比较。收集器先保存完整原始读回，再由 Node 根据已保存字节独立计算点偏移。60 份原始帧共 184,320 字节均经过独立认证。这证明原始字节留存与规定采样点检查，不代表每个像素均已验证。四张截图仅作辅助；四个启动屏障和敏感性对照不计入普通检查点数量。

流程覆盖：B 等待／失败时保留 A、取消 C 及其忽略取消后的完成、C 取代 B、过期 B 迟到、显式 B 成功、销毁自有绑定、从借用 A 重建，以及独立手工绑定在资源槽销毁后保留。每次运行记录六个准确请求结果、四次目标激活及原生 Button 路由／回调顺序。七次 provider 销毁尝试按多重集合核对，不承诺全局销毁次序。

30 个原始 WebGPU 读回 Promise 全部兑现。记录的关闭状态中，provider 任务、定时器及读回的待处理数均为零；WebGPU Host 安全关闭，没有待处理帧、上传字节或读回字节。静态可达模块与实际请求分别记录：WebGPU 在 104 个模块的允许闭包内实际请求 97 个模块，七个延迟 3D/b1 模块未执行；Canvas 实际请求其允许的 73 个模块。

独立保存结果审查复核了源码快照、原始进程记录、原始产物、请求／事件结果及严格编译器输入。故意错误的原始 import-map 目标会在浏览器启动和快照生成之前被拒绝。源码审查、实际运行结果与仓库交付各自保留范围。

## 复现与扩展

按[示例指南](https://github.com/cnedwin/Egret_rebuild/blob/main/examples/bitmap-resource-slot/README.zh-CN.md)运行普通核心验证及收集器命令。收集器要求单独捕获的当前输入快照和仓库外全新输出目录，保留原始读回并拒绝输入漂移。源码策略不执行产品模块；严格检查调用原版编译器，而非模拟诊断。

此案例使用字面 Texture provider。网络图片解码、真实共享图集、文字／字体集成、多资源切换和动画重定向属于后续组合工作。实体移动设备、平台 SDK、物理呈现、内存／功耗／温度基准、完整 Spine、完整 UI 及通用 3D 渲染均不在本案例验收范围；相关需求保持开放。
