## 已实现能力

显式选择的 `egret.shared-frame2d/1` 配置将不可变图像页、逻辑纹理区域、双色材质和有序显示捕获结合起来。多个区域可以共享一次规范化图像页上传；裁边、四分之一转角、九宫格及显式隔离边界保留原有坐标和绘制顺序。共享 Host 继续使用既有 Engine、Scope、租约、提交及清理机制。

`createSharedWebGPUHost` 由 `@egret/engine/webgpu` 导出；可选的 `@egret/engine/webgpu/scene3d` 入口提供 `createSharedSceneWebGPUHost`，将有限的不透明 B1 场景与共享 UI 合成，最后统一转换一次输出。此场景 Host 必须显式选择不透明输出；普通共享 2D Host 也支持预乘透明画布输出。既有编码颜色配置保留各自的解释和参考结果。

[契约](shared-render-profile-contract.md)规定精确的采样域、颜色公式、混合模式、限制及不支持的情况。共享渲染尚不包含完整 Spine、通用 3D 材质、设备恢复或 WebGL2 执行；这些仍按 [M1 计划](m1-rendering-resource-plan.md)中的独立工作包推进。

## 发现与修复

独立源码评审发现：保留池登记前已创建的目标纹理，如果捕获销毁方法失败，可能丢失资源归属并错误退还待回收计费。公开 G15 用例实际重现颜色待回收费用由应有的 256 字节变为 0。现在先分配原始归属槽，在访问外部方法前保留返回纹理，仅在登记及租约记录完成后转移归属。清理结果未知时保留记录与计费，不重复销毁。同一用例修复后通过，原失败记录保留。

首次原生运行因最终输出着色器使用 WGSL 保留字 `target` 而在启动时失败。将变量声明及加载引用改为 `workingTexture` 后，第二次完整运行通过，参考像素和容差均未改变。此前的构建与受控端口验证没有暴露这一原生编译问题。

首次完整核心尝试共 4,087 项，3,740 项通过、347 项失败。其中 328 项包含 Windows 目录链接权限错误，另 19 项需要为新架构有限更新旧接口、依赖图或源码身份准入。这次尝试不属于通过的回归结果。维护过程中保留历史快照及诊断库存，通过评审后的当前后继接纳新架构；后续通过的重放不替换这份失败记录。

第二次完整核心尝试共 4,145 项，4,131 项通过、14 项失败。其中十二项来自三处旧准入夹具假设：当前 Host 身份、缺失的合成 Mesh 导入目标，以及新增的共享 B1 动态边。有限修复仅涉及测试，随后十二个聚焦用例全部通过，包括原有的指定拒绝检查；这些修复没有修改产品或检查器规则。

另两项在完整类型重放并行运行期间报告完整原始字节/Git 清单不一致。临时生成的类型文件提供了具体的竞争机制，但两次失败当时的精确瞬态文件名未被保留。原有两个归属控制串行重跑后均通过，清单和恢复检查保持不变。因此，全仓库生成器、编译/构建任务与核心检查按串行顺序运行，让清单检查观察稳定仓库；完整检查继续保留，不通过过滤生成文件规避问题。失败的完整核心记录原样保留；随后第二次集成推送门禁串行完成完整核心检查，4,145 项全部通过。

发布检查共 250 项，249 项通过、一项失败，原因是隔离的诊断投影夹具未提供当前后继上下文。显式提供旧版和当前上下文后，两个聚焦用例通过，原有命名空间、字节漂移、同级路径及后缀拒绝仍保留。后续完整集成运行通过全部 251 项发布检查。

首次集成推送门禁在发布、构建、边界及完整类型入口通过后，于单独的 PNG 类型门禁失败，当时尚未进入完整核心检查。Texture 新增视图元数据使 PNG 负例通道的 32 个元组中一个完整 TS2740 诊断元组发生变化。修复保留冻结的历史 JSON，仅在精确登记的 Texture 源码/声明身份对匹配时选择该当前元组。单文件漂移及两种真实旧版/当前混合身份均在编译前被拒绝；其他元组及全部五通道保留原检查。六次身份控制调用和第二次完整推送门禁均通过。此局部后继不新增 PNG 完整编译器输入闭包的证明主张。

## 采集器兼容性补充验证

本次工具补充验证于 2026-10-18 06:39:00 UTC 完成，单独记录在此；前文 05:08:50 UTC 的完整门禁截止时间及结果保持不变。

混合场景采集器现在仅接纳 Host 的两个固定字面量 B1 依赖，同时核对导入方与目标路径；缺失、重复、无关目标及其他导入方的动态边均被拒绝。SequencePlayer、SequencePlayback 与 SpriteSheet 采集器显式接纳最多 256 个模块的完整双后端联合闭包，并在报告中使用相同上限；共享辅助函数的默认 128 模块上限及 4 MiB 产物字节上限保持不变。对应源码及全部传递依赖继续纳入封存清单。

历史浏览器工具的 16 项测试全部通过，记录的输入前后稳定。当前混合场景的实际闭包为 127 个模块，三个序列帧/SpriteSheet 联合闭包分别为 129 个模块。受控夹具验证原默认上限的拒绝、256 模块边界的接纳、257 模块及超过 4 MiB 的拒绝，每个指定突变均有独立健康基线和恢复验证。这些检查仅将 SDK 产物作为静态源码读取，不执行 SDK 或启动浏览器；它们证明采集器准入与报告一致，后续浏览器结果及完整交付门禁仍分别验收。

对单独的提交复用采集器进行源码检查时，还发现了较早的模块及动态导入假设；本次补充验证未确认该工具在当前构建下的自测或原生性能验收。

## 复现与贡献

`node tools/build.mjs`

`node tools/shared-render-types.mjs`

`node tools/shared-rendering/check-native-cases.mjs`

`node tools/browser-verify.mjs --suite shared-webgpu --playwright <absolute-installed-playwright-package> --output <absolute-fresh-directory-outside-repository>`

使用选定工具链、已安装依赖的真实目录及新的私有输出目录。不需要下载浏览器或增加宽松图形参数。输入或清理情况不确定时记为 INCOMPLETE，实际数值不符记为 FAIL；错误模型必须实际触发指定数值失败，异常或启动失败不能充当成功的反例。

实现与测试素材均为 AI 辅助独立编写、经过单独源码评审的第一方 Apache-2.0 工作。既有第三方依赖和声明继续保留。当前桌面证据不关闭 [#52](https://github.com/cnedwin/Egret_rebuild/issues/52) 的真人/fork 演练或 [#54](https://github.com/cnedwin/Egret_rebuild/issues/54) 的设备与素材资格。
