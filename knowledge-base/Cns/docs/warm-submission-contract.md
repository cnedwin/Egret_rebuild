# WebGPU 热提交契约

[English](../../en/docs/warm-submission-contract.md) | 简体中文 · [验证记录](warm-submission-evidence.md) · [M1 计划](m1-rendering-resource-plan.md)

M1.1 在图像和原生分配可以安全复用时，减少重复渲染同一画面的准备工作。普通 2D、纹理 2D、B1 场景加普通叠层、场景加纹理叠层四条路径共用一个 Host 提交与退休责任主体。公开 API、帧协议、着色器、颜色解释、包入口和 Host 协议保持不变。

## 图像准备

Host 先执行该路径原有的校验和存储准入，并通过实际打包确定绘制覆盖。只有真正参与绘制、精确对应当前 Host 中 READY 图像项的视图，才能省去像素裁剪。图像身份、裁剪区域、设备会话和当前驻留修订共同决定资格。另一个图像对象中的相同像素、不同裁剪、冷视图和没有实际覆盖的视图，都不能借用其他绘制的复用资格。

打包、逐绘制 uniform 和原有逻辑计费仍然执行。全部命中的帧仍承担相同的上传、几何、投影、待完成帧和读回准入计费。复用不能使无效输入获得准入，也不能在拒绝时消耗已申请的读回票据。已保存的不可变捕获保留原有重放契约；释放实时 lease 仍可使新捕获失败。

私有准备模块将绘制打包与投影物化分开，原有冷路径包装函数保留“打包 → 拷贝 → uniform → 所有者复查”的顺序。普通与 B1 普通叠层路径保留 2D 打包先于待完成量／读回准入的顺序；纹理与组合路径保留整体存储准入先于载荷分配的顺序。这些不同的错误优先级属于有意保留的兼容行为。

## 缓冲区所有权与有界复用

可复用的整块缓冲区包括 vertex（usage 40）、index（24）和逐绘制 uniform（72）。查找要求同一 Host／设备会话内 usage 与字节长度精确匹配。每项借出的分配只属于一个尚未完成的提交，逐绘制 uniform lease 保持独立。重复的场景几何仍可在同一提交内按既有规则共享。新帧始终重写当前顶点、索引和 uniform 数据。复用不会沿用过期的几何、alpha 或矩阵内容。

闲置保留受 **33,554,432 字节与 4,096 项**双重限制。提交先确定完整精确命中集合，再按最早闲置顺序淘汰未命中项，为可保留请求腾出空间。超大或溢出候选维持临时分配，不增加公开拒绝条件。原生清理回调重入前，归还预留已计入保留容量。混合冷暖请求也按原请求顺序归还。

实现采用精确 usage／size 索引及链式 FIFO 顺序。在通常的哈希表成本模型下，规划成本为 O（请求数 + 选中淘汰项数），不会为每个绘制重复扫描全部闲置缓冲区。这是实现复杂度属性，不是实测帧时间改善，也不是 JavaScript Map 最坏复杂度保证。

读回 staging 缓冲区（usage 9）与深度纹理维持临时资源；原有 map、unmap 和清理证明不变。现有图像缓存仍有独立的 32 MiB／256 个 READY 项限制；缓冲区保留不会扩大图像容量。

## 绑定身份

可查找的绑定缓存最多 **4,096 项**。完整键包含设备会话、精确 layout、适用时的图像分配 token 与 view、sampler、uniform 分配身份、offset 和绑定 size。16 字节图像 uniform 不会与 64 字节场景 uniform 混用。即使输入值相同，图像与 Mesh 的不同 layout 仍保持独立。

完整键通过固定深度的身份索引查找。命中更新链式 LRU 顺序；容量淘汰移除最久未使用的可查找项。图像或缓冲区销毁前，反向索引移除依赖绑定，同时清除空索引分支。未退休的提交记录持有各自的绑定引用。淘汰可查找元数据不等于销毁绑定或释放底层原生资源。

绑定只有在 uniform 缓冲区安全归还后，才可进入查找目录。使用图像的绑定还要求对应的精确图像条目处于 READY 状态，包括新候选成功发布的情形。冷图像竞争中的落选项、临时缓冲区和失败记录均不发布绑定。元数据发布失败会清空并停用绑定目录，资源所有者仍保持明确。

## 提交、退休与关闭

1. 保留该路径原有 CPU 顺序和完整准入；在提交序号及原有账本计费生效前，选择只读的当前图像与缓冲区计划。
2. 在首次原生淘汰销毁回调前，登记全部 lease 与清理所有者、固定图像命中项并领取缓冲区命中项。同步提交期间仍保持 busy；嵌套渲染得到原有重入拒绝。
3. 保留原生 scope、上传、render pass、submit、fence 和读回顺序。返回的原生对象先进入所有者，再执行可能失败的 getter 或状态检查。
4. 单独的 fence 不足以授权复用。原有 scope、queue 及已请求 map／readback 义务必须全部安全完成。被拒绝或未知的证明保留原有隔离行为。
5. 在退休帧的原有计费仍可见时预留归还容量；清理 staging、溢出及其他临时资源，完成图像资格判断，再复查 Host 与记录状态，随后发布缓冲区归还及合格绑定。
6. 未完成的所有权转移保留在记录中，供显式 close 接续。结果未知的原生销毁持续计费，不重试，也不成为可用容量。缓冲区只清理一次的标记继续表示已经尝试原生销毁，不表示闲置。
7. stop、失败、已交付的设备丢失通知和 close 立即禁用复用。close 保留原有完成屏障，再清理闲置缓冲区与图像所有者。最终关闭中的记录不再补充缓存。

私有辅助模块只管理元数据，不调用 GPU、不决定完成、不获取设备、不改变场景，也不建立第二个生命周期责任主体。预先捕获的集合操作使元数据转移不依赖可被替换的 prototype 回调。

## 兼容与验收

idle 完成现在允许有界保留缓冲区，不再意味着所有绘制缓冲区均已销毁。显式 close 仍对每个已捕获的原生清理操作尝试一次。原有依赖退休回调的测试改用真正的临时 staging 或压力／淘汰场景，并保留原有待完成计费与失败断言。

受控计数证明操作次数与身份复用；原生读回只证明指定浏览器和适配器上的限定图像域。两者均不证明物理显存、速度、功耗、手机支持或设备丢失恢复。[验证记录](warm-submission-evidence.md)分别记录这些证据域，并保留失败尝试与修正。

增量捕获／合批、共享纹理页与新材质、WebGL2、资源 manifest 和设备会话重建依次属于后续 M1 工作包。完整 Spine 属于 M2 验收。本包不增加这些能力。

实现与夹具是采用 AI 辅助、基于 Egret 既有 Host 和资源契约独立开发的第一方成果，采用 Apache-2.0，不增加运行时依赖。既有来源与第三方声明保留在[来源记录](https://github.com/cnedwin/Egret_rebuild/blob/main/source-origin.json)中。
