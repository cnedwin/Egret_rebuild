# 资源场景集成

[English](../../en/docs/resource-scene-integration.md) | 简体中文

资源场景把真实图像、动画、文字、选择和渲染连接为可运行应用。两个角色提供了规模较小、便于检查的场景，用于验证共享资源、独立状态、异步变化和完整关闭。它组合既有公共 API，保留核心无 DOM/Node 依赖、包边界和 Host 协议。[示例说明](https://github.com/cnedwin/Egret_rebuild/blob/main/examples/resource-scene/README.zh-CN.md)介绍具体操作。

## 组合与所有权

首次启动时，两个角色分别获取独立租约，指向同一解码后的图集 Texture。每个角色都有稳定的显示根节点、由双帧 SequencePlayback 驱动的身体，以及独立的服装 Bitmap。选择属于业务身份，显示实例和租约属于当前所有者。因此资源变化时可以保留目标、变换和选择，同时撤销旧请求的提交权限。

Bitmap 资源槽借用应用的初始服装绑定，只拥有后续新获取的替换租约。只有当前角色实例中匹配的最新请求，才可更新已经生效的业务选择。请求等待、失败、取消或被取代时，原选择仍可用。应用在首次替换成功后关闭初始借用，不会重新使用已经释放的绑定。

图集切换有明确的准备和发布边界。准备阶段获取完整租约，不改变身体。发布时停止旧播放，更换现有身体的精确租约，并创建从零相位开始的新播放控制；发布后再关闭旧所有者。准备失败时旧播放继续；后续提交失败时关闭对应实例，并要求显式重进。另一个角色保留独立租约与播放状态。

无 DOM 的 Session 负责 Engine、Scope、资源、显示、动画和文字组合。浏览器入口负责原生 PNG 传输、精确的自有字体、输入接入、呈现和外层关闭。资源就绪、画面完成和交互就绪各自记录。示例本地接口提供真实组合对象与有界观察，不增加 SDK 诊断权限。

## 渲染路径

| 模式 | 显示与执行 |
| --- | --- |
| `canvas-2d` | 普通 Engine、帧捕获和 CanvasHost，以 Bitmap 徽标呈现二维场景。 |
| `webgpu-scene-textured` | 显式纹理 Engine/Host，以真实 Mesh2D 徽标和相同屏幕界面叠加在两个不透明索引三维四边形上。 |

两种模式均使用 192×128 逻辑像素，密度为 1。GPU 场景使用正交投影、单位模型视图和二进制精确坐标：红色位于 z=-3，在 z=-7 的蓝色前方。颠倒绘制顺序仍应保持遮挡结果；交换真实深度提供独立的错误对照。Canvas 静态依赖闭包排除可选 GPU 场景及其基础几何依赖。

浏览器入口委托真实 PNG provider 的默认端口，先获取并验证本地原始字节，再按需延迟交付。SDK 需求取消和原始源工作各有结果。取消的延迟源可以完成而不产生 Texture；从已预热管理器条目交付的过期租约，需要单独验证所有权。最多允许两个延迟门、四个源任务、一份外部预热租约和 256 条活动记录。

每次 GPU 呈现都在提交前请求原始回读，等待该结果及 Host 空闲。Canvas 在同步绘制后读取原生像素。保留的完整 RGBA 原件携带应用 Host 生命周期、适用时的 Engine 时期、帧 ID、提交序号、标签和尺寸。字面内部点与固定文字区域定义比较范围；保留整帧不代表每个边缘像素或物理显示效果均已正确。

## 字体与独立预期

六张第一方 RGBA8 PNG 描述两版图集和四种服装颜色。保留的红绿徽标不重新编码。[资源来源记录](https://github.com/cnedwin/Egret_rebuild/blob/main/examples/resource-scene/assets/provenance.json)标明原始字节、来源和权利。

Ahem 覆盖固定的 `X X`/`XX` 场景。原始 Noto Sans SC normal-400 发布者子集用于指定的 `左侧 已选择` 和 `右侧 已选择`，保留原始 WOFF2、发布者 CSS 以及 OFL 和版权声明。FontFace 成员身份、精确选中的字体和 load/check 结果用于确认应用准备状态；通用覆盖及 Canvas 内部字体选择另有证据要求。

[可移植参考元数据](https://github.com/cnedwin/Egret_rebuild/blob/main/tools/resource-scene/reference/manifest.json)记录两份没有使用白鹭或应用生成的原始 Canvas RGBA 测量。原始测量保留 Edge 155.0.4283.45、Playwright 1.62.1、Windows build 10.0.26300/x64、记录的字体和 12px 场景。另一次直接 Canvas 测量在 Edge 155.0.4283.62 上复现了完全一致的两份完整参考缓冲及每个字符串的十二项度量。因此当前准入仅接受这两个精确浏览器版本，其他环境字段保持不变；原 manifest 和参考数据不作修改。参考等价本身不代表新的原生场景验收通过。固定源区域 (4,4,64,16) 按声明的基线推导，平移 (68,4) 到场景区域 (72,8,64,16)。白字源 alpha 在预设黑色或蓝色背景上合成。仅半透明文字 RGB 允许一个字节的 UNORM 舍入差异；不透明 RGB、alpha 和字面点严格相等，不进行画面对齐或调色拟合。

## 重建与关闭

静止回放先关闭原 Session、租约、包装对象、缓存、provider、字体和 Host，再让新的原始 Host 接收保留的真实叠加帧与场景。该 Host 完成自己的回读、空闲和关闭后，应用进入挂起状态。随后重建根据封闭的版本 1 业务快照创建新的 Engine 时期，保留选择、在场状态、服装、图集和暂停策略；播放相位归零。应用 Host ID 用于区分这些生命周期，不是设备句柄。

关闭在调用清理代码前，先发布稳定的 Promise，并同步进入不再接纳新操作的关闭状态。它撤销当前需求、结算自有延迟门，并等待原始启动、获取、文字、源任务及呈现工作；调用方另行关闭 PNG provider。文字工作结束前保留字体。只有原始 Host 安全关闭后才重置或移除表面；不安全或未结算的工作保留报告并隔离。主要 `undefined` 异常和有序次要异常均保留明确发生记录。

## 验证与验收

源码、专项 CPU 与编码、实际浏览器结果、保存结果复核、双语公开审查、完整本地门禁和仓库交付分别验收。源码收集器保留原始 HTML 和十四个精确 import-map 别名，锁定选定的公共源码、编译产物、声明闭包及资源，并通过声明的物理所有者解析 robust-predicates 3.0.3。每个源码拒绝对照都有独立的完整健康基线。原生核验工具还须把自身实际执行源码绑定到经过审查的完整快照。

浏览器流程包含七个独立上下文：Canvas 与 GPU 普通场景各一个，两种模式的错误服装与错误时间各一个，以及 GPU 错误深度一个。普通流程包括真实鼠标与 DOM 操作、乱序交付、原始 Error/undefined 失败、预热租约关闭、图集切换、裁剪和旋转、移除重进、保存帧回放、重建及等待请求时关闭。指定的错误结果不计入普通验收。

2026 年 10 月 16 日的桌面运行完成七个独立上下文，保留 64 份原始 RGBA 画面：两个普通模式各 27 份，五个错误对照各两份。每个普通模式通过 348 个字面点样本，比较 27,648 个固定中文区域像素，实际观察差异为零。指定的服装、时间和深度错误分别被检出。

每个普通流程关闭原时期的 16 个 PNG 加载和九个已发放 Texture，再关闭重建时期的六个加载和五个 Texture。所有已发放 Texture 均由原 disposer 回收。源工作、文字、回读和 Host 关闭完成，没有遗留任务；每个流程保留 255 条活动记录。页面错误和未分类控制台诊断均为零。Canvas 频繁回读的精确建议原文保留，Host 默认上下文设置保持不变。

原生验证发现两处集成缺陷：普通 Bitmap 徽标使用不支持的宽高赋值，界面则在重进准备阶段读取资源槽状态。公开缩放属性和准备阶段的操作保护修正了这些问题。徽标回归检查先观察到原来的 2×1 尺寸，修复后通过预设的 16×8 尺寸；专项套件共 58 项通过。原生鼠标操作将画布移入可见区域，并记录实际视口命中。

复现时先运行 `node tools/verify-resource-scene.mjs --repository <absolute-repository> --application-root <absolute-repository> --snapshot <new-external-json> --snapshot-only` 并审查捕获输入。随后对同一快照运行工具，去掉 `--snapshot-only`，加上 `--playwright <installed-1.62.1-directory> --output <new-external-directory>`。工具使用默认 Edge 启动方式，不加额外标志，要求上文记录的精确环境。完整本地门禁和 GitHub 交付分别记录；此原生结果不代表远程 CI 通过。

通用中文排版、回退与输入法、触控及完整 UI、生产宿主、设备丢失恢复、导入和带动画的三维角色、完整 Spine R020/V020、目标手机功耗与性能，以及完整旧项目迁移 R008/V006，仍保持开放。
