# 显示与帧执行合同

[English](../../en/docs/display-and-frame-execution-contract.md) | 简体中文

版本：0.12.0 候选。本文是自主实现规格；通过情况按后续实际证据登记。沿用既有 Apache-2.0、白鹭命名、strict TypeScript 与无隐式全局 Stage 的约束。

本工作包让自主核心能够呈现二维矩形场景。完整文本、纹理、骨骼、滤镜、3D、GPU 后端、通用输入命中和完整迁移继续属于总交付范围，本包不替代它们的验收。Canvas 是首个执行此合同的后端，WebGPU/WebGL 后端随后消费同一份有限协议；不把 Canvas 试验写成 GPU 或手机性能结论。

## 组成与接口

- contracts 增加 `Matrix2D`（a、b、c、d、tx、ty）、`Rectangle2D`（x、y、width、height）、`ClipRectangle2D`（matrix、rect）、`RectangleCommand2D`（kind=`rect`、matrix、rect、color、alpha、clips）、`FrameOptions2D`（width、height、clearColor 可选、clearAlpha 可选）、`RenderFrame2D`（frameId、width、height、clearColor、clearAlpha、commands）及 `RenderHostAdapter extends HostAdapter`。后者的 `renderFrame(frame: RenderFrame2D): undefined` 同步提交；在途设备工作仍由唯一的 host.close 合同证明完成。
- runtime 增加 DisplayObject 的 x、y（默认0）、scaleX、scaleY（默认1）、rotation（度，默认0）、alpha（默认1）、visible（默认true）与 clipRect（默认undefined）；增加 `Sprite extends DisplayObjectContainer` 和其 Graphics。`Graphics.beginFill(color: number, alpha?: number): this`、`drawRect(x, y, width, height): this`、`endFill(): this`、`clear(): void` 构成当前绘图子集。
- engine 增加 `captureFrame(options: FrameOptions2D): RenderFrame2D` 与 `renderFrame(options: FrameOptions2D): RenderFrame2D`。前者只获取快照，后者额外调用创建引擎时固定的宿主 renderFrame 函数及其原接收者。基础 HostAdapter 仍可用于所有已有 headless API；无渲染端口时 renderFrame 抛 `RENDERER_REQUIRED`。
- `@egret/engine/web` 提供 `createCanvasHost(options: CanvasHostOptions): CanvasHost`。options 必须包含 HTMLCanvasElement `canvas`，可提供 pixelRatio（默认1）及 maxBackingPixels（默认16,777,216）。CanvasHost 满足 RenderHostAdapter。它单独用 ES2022+DOM 编译，根入口仍以 ES2022、types=[] 编译。

Matrix2D 的点映射为 X=a*x+c*y+tx、Y=b*x+d*y+ty。局部矩阵先缩放、再旋转、再平移；世界矩阵为父矩阵乘局部矩阵。Canvas 的像素比例仅由执行器应用，不写入逻辑世界矩阵。Stage 的可视属性遵守相同规则。

## 数据与显示语义

所有数值必须是 number 原语且有限。alpha、填充 alpha、clearAlpha 在闭区间[0,1]；color、clearColor 是[0,0xffffff]内的整数。矩形位置可为负，width/height 非负；帧 width/height 必须大于0。scale可为负或0。visible必须是boolean。非法赋值保持原状态；零面积矩形与零透明度图元不产生绘制命令。未提供或为 undefined 的 clearColor 独立默认 0x000000，clearAlpha 独立默认 0；null 非法。只提供颜色而没有 clearAlpha 时，背景仍透明。

beginFill 的默认 alpha=1；未激活填充时 drawRect 抛 `GRAPHICS_FILL_REQUIRED`。endFill 停止后续填充，不删除已有图元；clear 删除图元并重置填充。drawRect 在调用时复制当前填充，后续修改填充不改变已有矩形。

clipRect 是本地坐标中的纯裁剪矩形，不包含滚动偏移。复制并冻结传入值；不能把此有限属性宣称为旧 scrollRect 的全部兼容语义。自身图元和所有后代都继承它；旋转裁剪保留完整矩阵，不能悄悄降为轴对齐 scissor。

绘制遵循显示树顺序：节点自身图元按绘图顺序出现，然后按子节点索引递增访问；较高索引后画，显示在上层。透明度为祖先与本节点 alpha 及填充 alpha 的乘积；不可见或透明度0的节点屏蔽整个子树。遍历使用权威内部树、变换和绘图状态，不能读取可覆盖的公共 getter 或调用用户绘制钩子。使用迭代遍历，避免深树依赖调用栈。每个 Sprite 拥有一个稳定只读 Graphics 门面，不支持共享或重新绑定。

运行时可视属性、公开树结构和 Graphics 修改先验证存活与已绑定引擎处于 open；离树但仍绑定的对象也遵守退出限制。内部处置仍在 closing 期间使用无回调的 detach/terminate，终态 dispose 仍可用。clipRect 的外部字段访问可能执行用户代码，因此先取副本、再重新验证存活/引擎状态、最后一次性提交。关闭和处置不得被可视属性覆盖阻断。

帧为全量、深不可变的值快照：矩阵、矩形、裁剪链、命令数组及帧头均复制并冻结；没有 DisplayObject、Graphics、Scope、租约或宿主引用。世界矩阵及派生值溢出时整帧失败，禁止向后端交付部分帧。frameId 是每个引擎的成功捕获序号，从1开始，范围为正安全整数；它不是持久工程ID、资源代际或设备epoch。渲染失败可以消耗已成功捕获的 frameId。

## 重入、失败与关闭

captureFrame/renderFrame 在读外部options之前设置忙状态。忙期间再次捕获或渲染抛 `FRAME_REENTRANT`。外部字段访问或后端回调可以请求dispose；引擎必须立即进入closing，并拒绝后续修改与提交，但Scope/Stage/资产清理、host.stop、host.close都等待当前帧调用退出。finally释放忙状态及frame-idle屏障，无论参数、构建或后端是否失败。

创建时从 options 读取一次并固定宿主，并在 surface 预留前读取及固定其 renderFrame 方法；类型不合法或 getter 失败发生在预留之前。调用使用原函数和原接收者，不依赖可覆盖的函数.call。后续替换宿主属性不会替换本引擎的端口。外部帧 getter 后，以及帧 ID 提交/后端调用前，再次检查 open；提交前关闭不消耗帧 ID。核心不从根入口读取 DOM 或启动调度。

错误代码：`DISPLAY_VALUE_INVALID`、`GRAPHICS_VALUE_INVALID`、`GRAPHICS_FILL_REQUIRED`、`INVALID_FRAME_OPTIONS`、`FRAME_TRANSFORM_INVALID`、`FRAME_ID_EXHAUSTED`、`FRAME_REENTRANT`、`RENDERER_REQUIRED`、`INVALID_RENDERER`、`FRAME_RENDER_FAILED`。沿用 OBJECT_DISPOSED、ENGINE_CLOSED 和原关闭失败合同。后端异常诊断 phase=`graphics`、code=`FRAME_RENDER_FAILED`，异常保留原cause；诊断回调错误仍遵守既有隔离规则。渲染端口返回非undefined时视为失败；close仍由宿主完成其在途工作，不能用此错误宣称工作已经停止。

## Canvas执行器

创建及导入不开始绘制；start取得2D context，失败使用现有启动回滚。surface 固定为传入 canvas 本身，避免不同宿主绕过 Engine 的独占规则。stop 同步封闭后续绘制；close 幂等、为终态并等待本宿主当前绘制退出；stop/close 后 start 拒绝。借用 canvas 不被删除，不取得外部 DOM 事件或设备的关闭权。宿主运行期间独占其位图和 2D 上下文状态。

active 时重复 start 幂等；start 前 stop 也进入终态。未启动绘制抛 CANVAS_HOST_NOT_STARTED，stop/close 后抛 CANVAS_HOST_CLOSED。适配错误包括 CANVAS_HOST_INVALID、CANVAS_FRAME_INVALID、CANVAS_FRAME_REENTRANT、CANVAS_BACKING_LIMIT、CANVAS_CONTEXT_UNAVAILABLE、CANVAS_CONTEXT_LOST、CANVAS_RENDER_FAILED。Engine 提交把适配错误包为 FRAME_RENDER_FAILED 并保留 cause。适配 close 不销毁借用元素/上下文，也不宣称清理外部所有的事件。

读外部帧字段前先占用绘制忙状态；所有字段和命令校验并取稳定副本后再次检查 active，再改 canvas 尺寸或上下文。背板尺寸为 ceil(width*pixelRatio)、ceil(height*pixelRatio)，两维必须为不超过 4294967295 的正安全整数，乘积不得超过 maxBackingPixels。还须拒绝非有限的矩形端点、变换后角点和像素比例缩放矩阵。检查实际赋值尺寸和可检测的上下文丢失，不虚报分配成功。此预算属于适配配置，不是硬件上限。pixelRatio 和 maxBackingPixels 是创建时固定值，前者有限且正，后者正安全整数。非法输入和预算失败发生在画布修改前。

完整校验后，每个接受帧都重新赋值已验证的背板 width/height，包括尺寸不变时，重置位图、裁剪、当前路径与状态栈。设置单位变换、source-over、globalAlpha=1、透明阴影、零阴影模糊/偏移，以及可用时 filter=none；清除整个背板，再画背景。每条矩形命令单独 save/restore，对每层 clip 设置其世界矩阵乘 pixelRatio、beginPath/rect/clip，再设置图元矩阵、fillStyle 和 globalAlpha 填充；命令结束后清空当前路径。可见重叠保持提交顺序，不保留外部状态、路径和像素。直接 host.close 在校验中触发时，修改画布前拒绝；绘制中触发时，在安全边界停止后续命令。异常及 close 重入通过 finally 归还忙屏障。

## 验证与来源边界

CPU对照使用明示坐标与顺序，不复制生产矩阵函数作为期望。例：父节点(x=10,y=20,scaleX=2,scaleY=1)，子节点(x=3,y=4,rotation=90)，子世界矩阵约为(0,1,-2,0,16,24)；矩形(1,2,3,4)的角点约为(12,25)、(12,28)、(4,28)、(4,25)。浮点比较容差1e-10。

浏览器实际像素检查：透明叠放、祖先alpha、变换、旋转clip、兄弟clip隔离、DPR、clear、异常前校验及关闭后拒绝。黑色不透明背景上依次画半透明红、半透明蓝，重叠内部点预期约(64,0,128,255)，逐通道容差2，避开抗锯齿边缘。自动化应确实读取像素并操作样例；no-op后端必须不能通过。监听pageerror及非预期console/network失败，提供favicon避免忽略404。记录浏览器与自动化版本，不从渲染器字符串推断硬件覆盖。

新代码按本规格独立编写，成熟二维数学与Web平台API属于实现依据。规范参考：[Canvas状态](https://html.spec.whatwg.org/multipage/canvas.html#the-canvas-state)、[Canvas变换](https://html.spec.whatwg.org/multipage/canvas.html#transformations)、[WebGPU scissor](https://gpuweb.github.io/gpuweb/#dom-gpurenderpassencoder-setscissorrect)。第三方研究执行链保持独立，不作为自主实现源码输入。实际实现、依赖与代码hash随后按来源规范登记。
