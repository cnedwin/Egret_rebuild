# Galaxy Z Fold7 上的 Android 脚本宿主

[English](../../en/docs/runtime-sdk-v8-fold7.md) | 简体中文

Android 示例支持用系统 WebView 或内置的 V8 运行随包发布的白鹭场景，也可以直接回放场景产生的命令。四条测量路径共用同一套 Rust GLES3 渲染器。本次比较的范围为一台 Galaxy Z Fold7 和一个 arm64 调试应用。

## Fold7 实测结果

同机、同负载，Android 17，系统 WebView 157.0.8103.50。时钟和设备状态详见逐轮记录。包体以 MiB 表示，启动与帧间隔以 ms 表示。启动与帧间隔汇总四轮测量，括号列出冷启动的四轮范围。每条路径另开一轮内存测量，PSS 取该轮三次驻留采样的中位数。包体取签名后文件的实际大小。

| 路径 | APK | 冷启动（范围） | 帧间隔 p50 / p95 / p99 | 场景驻留 PSS（MiB） |
| --- | ---: | ---: | ---: | ---: |
| 系统 WebView | 0.75 | 165.7 (145.4–194.9) | 8.300 / 8.302 / 8.303 | 160.4 |
| V8 标准版 | 22.04 | 103.7 (100.8–106.5) | 8.300 / 8.302 / 8.303 | 145.7 |
| V8 裁剪版 | 16.49 | 90.0 (88.5–92.3) | 8.300 / 8.302 / 8.303 | 136.9 |
| 原生命令回放 | 0.75 | 59.2 (54.8–64.2) | 8.300 / 8.302 / 8.303 | 62.5 |

| V8 裁剪版 | 0.808 | 0.014 | 1.282 | 0.058 | 0.093 |

逐轮记录包含签名 APK 身份、固定场景摘要、前后台状态、资源计数及可复算的逐帧纳秒数据。每个 timing 轮的 relativeFrames.data 是经 raw DEFLATE 压缩、再以 Base64 编码的 JSON 数组；按 fields 顺序解释每行，用 SHA-256 校验解压后的字节。[实测记录](https://github.com/cnedwin/Egret_rebuild/blob/main/runtime-sdk/measurements/fold7-v8.json)

裁剪版 APK 比标准版小 5.55 MiB（25.2%），四组对照中进程冷启动都更快。标准版在四组中的“请求至命令可用”中位数都更短。四条路径的帧间隔 p95 都约为 8.30 ms。对于已经依赖国际化的游戏，这个场景没有表现出为了帧率而裁去 `Intl` 的收益。

标准版正确性轮次首次解包 10,824,432 字节 ICU 数据，进程启动至首绘回调为 127.4 ms，含诊断开销。正式启动四轮均复用本地已校验的数据。每个诊断轮次在上下文恢复后重新上传图集，记录一次旧上下文失效，最终释放当前 GPU 纹理页。每条实时路径均释放一份引擎租约。标准版从桌面图标启动后能从后台恢复，按返回键释放租约。另一次故意转后台的定长测量按预期记为中断。

前两组完整计时沿用原始记录。第三组期间出现 Android 安装等待，另一次在替换 APK 后系统拒绝启动活动。中断区组和零帧启动保存在数据中。待系统包管理器就绪，第三、第四组按冻结顺序完整测量。安装和应用进程复位均早于计时起点。

## 如何选包

| 构建 | 脚本由谁运行 | 适用场景 |
| --- | --- | --- |
| 系统 WebView | Android 提供脚本引擎。 | 默认选项，适合重视下载体积或依赖现有 WebView 环境的游戏。 |
| 带国际化的 V8 | APK 自带 V8 和国际化支持。 | 游戏随包发布，依赖已经验证的脚本宿主和本地化服务。 |
| 裁去国际化的 V8 | APK 自带同一版本裁去国际化支持的 V8。 | 游戏及其依赖能在缺少 `Intl` 的环境运行。 |
| 原生命令回放 | 基础 APK 读取先前捕获的一轮命令。 | 单独观察渲染、调度和命令回放的开销。实际游戏脚本由前三条路径执行。 |

应用开发者在打包时选择宿主，需核对游戏依赖的时钟、本地化和平台 API。内置 V8 的应用需要随应用发行安全更新。本阶段宿主加载随包脚本，提供样板场景使用的服务。两种 arm64 V8 的上游 GN 配置均关闭了 V8 sandbox。在应用进程内运行的 isolate 不适合作为第三方插件或下载脚本的安全隔离边界。系统 WebView 的更新由平台独立提供。[Javet](https://github.com/caoccao/Javet) · [V8 嵌入说明](https://v8.dev/docs/embed)

两种构建均使用 Javet 6.0.3 和 V8 15.7.112.19。上游 arm64 构建配置的差别在于 `v8_enable_i18n_support`。标准包附带与 V8 匹配的 ICU 数据，第一次使用时校验数据，将其解包至以摘要命名的应用私有文件。这笔一次性开销与后续的进程冷启动单列。基础包最低支持 Android API 26，内置 V8 的包按上游原生库的编译目标将最低版本设为 API 29。[上游 Javet 源码](https://github.com/caoccao/Javet/tree/5d51b4eb)

## 四条路径共用的负载

固定场景包含两个纯色矩形、40 个动画图集四边形和一张 32 × 8 RGBA 纹理页，绘制到 320 × 192 的画面。每 60 帧循环一次，每帧产生一份 2,040 字节的命令。三条实时路径均使用引擎的场景、资源作用域和编码器生成命令，回放路径读取已捕获的命令。GPU 资源统一交给 Rust 管理。正确性检查逐帧比对整个循环的命令，读回末帧像素，保留图集并重建 GLES 上下文，最后核对有效纹理和场景租约的释放。[原有场景与测量](runtime-sdk-fold7.md)

## 如何读数

每轮开始前结束应用进程，保留文件系统缓存。冷启动从 Android 创建进程量到 UI 线程收到首次 GLES 绘制已提交的回调。每轮预热 60 次，正式记录 300 次帧回调，得到 299 个相邻间隔。四条路径分四组轮换出场顺序。各轮结果用于判断波动。解码和桥接计时包含 CPU 工作和调度，显示回调间隔还受系统节拍影响。GPU 实际执行与屏幕呈现需要另外的测量手段。

内存另开一轮，在场景资源仍驻留时采样。Android 能识别归属时，WebView 一栏同时计入应用专用的渲染进程。共享系统服务可能同时服务其他应用。包体取签名后 arm64 调试 APK 的文件字节，系统提供的 WebView 不占用 APK 的下载体积。商店实际下载量和功耗需要单独测量。

WebView 用 `performance.now()` 量命令生成，然后做 Base64 编码、传回、解码与复制。它的直接传输计时只含 Android 收到回调后的解析、解码与复制。内置 V8 使用暴露给脚本的单调时钟，直接传输计时只含从借用的 ArrayBuffer 复制到 Android 自有内存。两条实时路径都用“发出请求至数据可用”覆盖完整线程调度。两种直接传输计时的边界和脚本时钟精度不同。国际化裁剪效果以两份 V8 之间的对照衡量。
