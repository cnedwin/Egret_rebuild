# M4 — 混合场景与核心验收

[English](../../en/docs/m4-core-acceptance-plan.md) | 简体中文

设计提案 · 2026-10-23 · 父任务：[M4 #58](https://github.com/cnedwin/Egret_rebuild/issues/58)

## 1. 目标与范围

M4 通过一个可编辑的游戏示例，证明已声明的 2D 渲染、复杂 UI、动画和资源能力能够共同工作，完成整个生命周期，并达到选定发布配置的要求。M2、M3 通过 M1 既有的渲染和资源契约集成。

M4 保留既定范围：复杂 UI、选定版本完整 Spine、序列帧动画、资源替换，以及现有有限 3D 背景组合。不增加导入或动画化的 3D 角色、通用材质/特效系统、世界编辑器、原生 Runtime 或新平台 SDK。这些仍是产品目标，由后续工程和验收计划承接。

交付物是具备明确能力矩阵、可编辑示例、测量结果和迁移说明的合格核心预览。完成 M4 不代表一体化创作平台或完整一键旧工程迁移已经可用。

M4.3 必须将交付范围表述为复杂 2D UI／动画／资源核心预览，包含有界 3D 背景合成。它不验证通用 3D 场景资源、材质、动画角色或特效，也不验证原生 SDK 或一体化编辑器。这些产品能力继续作为明确后续路线工作，完成 M4 不能关闭它们。

## 4. 三个完整工作包

### M4.1 — 可编辑混合参考游戏

**结果：**一个可复现工程，包含选定完整交互循环、源素材、可编辑代码/数据、预期状态变化及中英文指南。

**启动条件：**M2 内容/实例与 M3 布局/输入接口完成评审。场景设计、来源清单和社区反馈可以提前开展。当前实现工作依赖这些接口。

**范围：**选定有限的装扮/角色管理场景，组合复杂 UI、独立 Spine 轨道/皮肤、序列帧效果、资源替换和现有不透明 3D 背景。约定 U/A 场景的子集，不把各自最大负载暗中相加。

**集成位置：**`examples/resource-scene/`、`examples/prepared-resource-groups/`、`examples/scene3d/`，以及评审后的实际 M2/M3 公开入口。示例放在 `examples/` 下，不另建一个引擎包。

**验收：**

- 按文档构建/预览后，修改代码/数据能改变预期 UI 或动画；源素材保持可编辑并保留出处。
- 在采集前，场景声明固定内容、版本、数量、事件顺序、裁剪/遮罩/混合预期、输入动作和比较范围。
- 共享资源支持独立实例；改变装扮、轨道或选择不会改变另一个实例或重复触发游戏事件。
- 每个选定可执行后端的视觉顺序、拾取、焦点、文字输入和异步替换符合声明行为。
- 不支持的特性明确失败，或使用单独说明并验证的缩减配置；Canvas 不被表述为与完整混合场景等价。
- 新能力有独立参考验证；旧版能力较少的示例不是性能等价基线。

**评审职责：**渲染集成人与 M2、M3 维护者共同负责。素材格式与再分发要求明确后，素材作者可以独立参与。

### M4.2 — 集成生命周期与预算验收

**结果：**一份绑定场景的验收报告，覆盖混合行为、资源/Host 恢复、持续运行、内存、启动和性能，列明每个不可执行或失败的行。

**启动条件：**使用 M4.1 已评审可运行场景和选定 M2/M3 能力实现。实现完成前可准备矩阵及必需设备清单；各项采集前固定实际输入和目标。

**范围：**保留架构计划的 L 负载：100 次场景进入/退出/取消/替换循环，每个可执行恢复后端十次实际图形丢失/重建，前后台和网络故障，以及 30 分钟持续运行。新混合内容执行需要自己的证据；历史 M1.5 时长结果保留原范围。

**验收：**

- 全部选定 M2/M3 特性行完成，包括加载/替换期间交互，以及恢复后的约定状态还原。
- 分别观察资源就绪、新代际显示就绪和交互就绪；旧异步结果不能向新场景或新代际发布。
- 清理后，活跃所有者、未结束任务和在途计数返回声明基线；保留缓存处于明确上限内。堆/引用趋势支撑持续增长结论。
- 固定 M1 D60 负载满足原正式要求；全脏 CPU 缺口和准备覆盖获得真实证据前，M1.2 保持 OPEN。
- 混合 X 负载在测量前完成内容数量及适用 CPU/GPU、帧时间、内存、启动和交互预算评审。M1 原素材/包体额度不自动成为更大 Spine/UI 示例的额度。
- 选定浏览器的实际正确性、恢复和完整窗口计时满足固定矩阵。CPU 提交时间不能替代 GPU 时间、物理显存、能耗或温度测量。
- 保留失败和中断运行；短时运行或受控端口不能代替必需的持续运行或实体设备行。

**评审职责：**渲染/性能维护者与独立结果评审者负责；平台贡献者提供明确设备身份及实际宿主观测。按适用范围复用既有采集器和场景适配，不建立新的通用验收框架。

### M4.3 — 核心预览与社区交接

**结果：**可审查的核心预览、可复现示例交付、能力矩阵、API/迁移说明，以及由 M4.1/M4.2 结果支持的简洁贡献入口。

**启动条件：**能力文档、打包设计和迁移兼容说明现在可以准备。最终发布验收依赖 M4.1/M4.2 及 M1–M3 的必需验收行。

**范围：**在干净消费者环境验证选定包/归档，保留可选入口隔离，将每项能力连接到实际证据，并说明支持版本/宿主及限制。修改 `private` 或包版本不等于消费验证。若选择公开示例网站，还需独立的实际部署检查。

**验收：**

- 新贡献者按固定环境指引运行可编辑示例，无需私有仓库路径或未说明的本机产物。
- 选定分发物可解析声明的公开入口，保留依赖/许可声明；可选 Spine/3D/工具链不能悄然进入最小 2D 路径。
- 包体和首次交互测量明确实际产物、内容及网络配置。M1 原目标仍可独立追溯。
- 能力页区分已设计、已实现、受控验证、实际浏览器验证和合格设备范围；不能通过文档或 CI 将 M1.2/D60 标为关闭。
- 迁移说明映射保留的显示/事件/资源语义、有意差异和不支持的旧版结构，不宣称自动整项目转换。
- 实际发布候选完成独立评审、来源核对、关键英文注释、完整中英文文档和正常受保护合并检查。

**评审职责：**发布集成人与文档/打包贡献者负责。新贡献者演练记录是否由真人完成；自动演练不能关闭真人观察行。

| --- | --- |

| 更新状态 | 静态冻结动画和 UI；稀疏每个准入帧恰好改变 6,000 个创作 UI 节点中的 60 个，同时推进八个 Spine 和 80 个序列实例；全脏改变全部 6,000 个并推进相同动画。预先声明变更属性和输入序列。X 状态独立于原有不变的 M1 U 负载。 |

| 逻辑内存 | 保留解码/源数据 ≤ 128 MiB；就绪图像驻留 ≤ 32 MiB、256 项，包含适用字形图像及已提交/分阶段替换；复用缓冲/目标 ≤ 32 MiB；在途上传 ≤ 64 MiB；临时 CPU 上传 ≤ 32 MiB。这是分别计量的类别，不代表物理 RAM/显存总和。既有更严格 API 限额保持不变。 |
| 下载与首次交互 | X 必需的全部 JavaScript（包含 Spine 和文字 provider 胶水）≤ 1.5 MiB gzip；必需文字 provider WASM 与 Unicode 数据压缩传输 ≤ 4.5 MiB；其它首次交互素材（含字体）传输 ≤ 6 MiB。必需首次交互总传输 ≤ 12 MiB。冷缓存、10 Mbit/s、80 ms RTT 下首次交互 ≤ 15 s；该带宽传输 12 MiB 本身约需 10.1 s。X 声明的多语言 UI 使用 M3 ICU/HarfBuzz/FreeType 段落 provider，其必需模块/数据/字体初始化必须在标记前完成。可选加载使基础应用可不含该 provider，不能从 X 测量中排除必需字节或工作。这些是预算提案，不是实测 provider 体积。 |
| 恢复与响应 | 从观测丢失到正确的新代际帧：保留 CPU 来源时 ≤ 2 s，同网络条件重新加载时 ≤ 15 s。固定 100 动作输入回放中，从事件派发到对应帧完成/读回的 p95 ≤ 100 ms。这是软件观测响应，不是物理触控到光子或 IME 易用性证据。 |

验收批次前固定源码/构建/内容和两种后端配置。每个静态/稀疏/全脏状态沿用 30 秒预热、五次 60 秒测量，报告每次 p95 的中位数并保留全部运行。比较基线使用相同输入，不与缺少 Spine/UI 能力的旧构建比较。M1 相对回归检查仍绑定原等价负载。

记录下载字节、缓存状态和实际网络整形；首次交互标记要求全部声明内容就绪、匹配帧完成、预期输入启用。内存采集包含替换和恢复期间新旧代际重叠。通过 L 运行验证清理及驻留上限，记录堆/引用趋势，不把重叠逻辑账相加当成物理内存。按适用范围复用现有采样、响应和生命周期接口。

X-D60/1 的明确内存上限部分沿用 M1，作为保守初始目标。场景和素材组成不同，M1 的内存或启动证据不能用于认证 X。缺少预算证据时保持 OPEN，不能用样例构造或功能通过代替。

### 测量责任与准确计时范围

M4.1 负责场景声明，M4.2 负责测量定义及独立结果评审。原 M1 负载、采集区间和失败结果保持不变。X 使用独立的完整引擎 CPU 指标：包括引擎输入路由、动画推进、引擎事件队列工作、样式／测量／布局、变换／裁剪、捕获、准备／打包及同步上传／编码／提交。期间发生的场景回调工作计入，不扣除猜测成本。仅预先声明的外部用例／应用修改生成器位于此指标之外，并单独报告其耗时。引擎工作跨任务或 worker 延后执行时，将全部活动 CPU 区间归属到对应逻辑更新，避免嵌套重复计数，并分别报告 worker CPU 与经过的就绪时间。网络／GPU 等待不属于 CPU 工作，其可观察影响仍由帧间隔、就绪及响应记录覆盖。必需阶段未插桩时，完整引擎验收保持 OPEN。

从每次更新的完整引擎样本计算 p95，各阶段分布用于归因，不能相加各阶段 p95。保留 X 的 8 ms 目标与准备 4 ms 目标，并在采集前记录准确边界。冻结静态／稀疏／全脏的修改属性、值、顺序、动画时钟及输入序列。静态状态冻结动画，热态动画性能由已声明的推进状态体现，不能从静态缓存推断。固定列表视口／最小行高／overscan，使 32 行参考视口及任何保留焦点行均处于总计 48 个容器内；UI 子节点计入 600 可见节点额度。

正确性、性能及生命周期运行可以使用不同插桩和调度，但最终验收使用相同的经验证源码／产物身份及完整选定场景语义。缩减开发用例明确标注，不能替代 X 或必需 L 项。在首个可执行混合子集中发现成本及正确性风险，全部必需能力完成后仍保留最终组合验收。不同功能覆盖的构建不能组成优化对照。

可移植的自有分配／缓存计数、替换峰值及清理趋势，与可选的浏览器／进程堆或物理 GPU 观察分别记录。保留的新旧代次及 provider 暂存／存储在声明类别中各计一次，不能把重叠的 JS／Wasm／资源账本相加成虚构物理总量。无法取得的物理测量保持未测。X 拟议上限在组合负载实际证明前仍是目标。

## 6. 性能与外部边界

原 M1 D60 负载保留 Engine p95 ≤ 8 ms、准备 p95 ≤ 4 ms、帧间隔 p95/p99 ≤ 16.7/33.4 ms 及固定相对回归规则。Engine 跨度包含捕获和同步 Host 工作，不含负载更新。GPU p95 ≤ 8 ms 单独成立；没有实际 GPU 证据时仍未测量。

Schema 6 的 Host 跨度包括准备、打包、编码和提交。五次运行 Host p95 的中位数 ≤ 4 ms，能够建立准备耗时的充分上界。Host 更大表示上界尚未建立，不代表已证明纯准备超过 4 ms。任何直接测量方案都必须覆盖原要求的准备工作，并在采集前完成评审。

M1 启动/恢复目标保持：应用 JavaScript ≤ 1 MiB gzip，不含可选 Spine/素材；固定场景素材 ≤ 4 MiB；10 Mbit/s、80 ms RTT 条件下首次交互 ≤ 5 s；保留源数据恢复 ≤ 2 s，同网络条件重新加载恢复 ≤ 5 s。这些绑定原样例，不能认证任意 M4 应用。

## 7. 与一体化创作平台的衔接

长期平台整合 Coding、调试、主画布、UI/动画编辑、3D 场景/特效、世界/角色和目标平台发布。可视化、代码和自然语言编辑共享工程身份、版本化修改、诊断、预览和撤销。工作流评估后，可以有机合并适合的编辑界面。

M4 为后续平台提供可编辑集成项目及明确的所有权/诊断边界。复用现有项目事务内核；模型客户端、MCP 服务、Skill、凭据和 Token 计费不进入 Runtime/图形层。外部 Agent harness 后续可调用相同项目服务并取得有界任务结果，不掌握项目权威状态。

用户指定模型 API、Skill/MCP 接入、插件商店、直观 Token 用量和可配置消费上限仍属创作平台需求。M4 记录其接口需求与示例，不选择厂商、不实现计费、不构建编辑器外壳，也不宣称自然语言游戏创作已经完成。

同样，`packages/project/src/legacy-res-plan.ts` 等规划器仍是有限迁移前提。完整旧工程迁移仍需原版本基线、确定性转换、有界 Agent 修复、行为/视觉比较、持续编辑和发布，遵循[迁移要求](旧工程迁移.md)。
