## 环境与验证

工作区声明 hoisted 安装，因为当前源码采集工具要求第三方包的物理归属。Setup 自动建立渲染依赖的精确包内别名并核对归属；Windows 同时检查原生编译器别名。贡献者无需手工建立别名。已有不兼容安装可能被拒绝，不会静默覆盖；切换布局时用干净克隆复现。

修改根开发脚本会使嵌入的配置指纹失效。本次更新并重新验证活跃配置引用及其关联策略身份；引擎源码指纹、历史源码快照和原始回执保持不变。这是有限的迁移，不代表完整依赖闭包解耦。当前 B1 验证器准入与产物宿主测试配置已改用 Node 26.7.0；命令行拒绝测试及全部 13 个产物宿主用例通过。Node 26 下真实 B1 浏览器复验仍为 OPEN。其他固定旧 Node 的浏览器采集工具保留原配置，等待迁移。VM 宿主拒绝辅助程序现在根据访问记录拒绝，即使 VM 代理吞掉 getter 异常也不会误通过；负向控制仍为必需。

本地验证与远程 CI 分别记录。Windows 执行完整既有 prepush 门禁及上手测试。Linux/macOS 只运行构建、matrix4、display-tree 和无界面检查；编译器归属、发布及真实浏览器门禁明确未包含。最终 `M0 / merge-ready` 拒绝必需 job 的失败、取消或跳过；它不证明图形或移动性能。

## GitHub 执行与验收

| 顺序 | 执行 | 验收 |
| --- | --- | --- |
| G1 | 记录基线、权限与角色 | 保留既有设置，明确实际维护人 |
| G2 | 交付环境、指南与模板 | 干净克隆可运行文档中的可视示例 |
| G3 | 在 PR 运行公开 CI | 所有声明的 job 对最终候选报告结果 |
| G4 | CI 验证后启用主干规则 | 必须 PR/检查、解决讨论，禁止强推/删除；回读实际规则 |
| G5 | 启用社区入口 | Discussions、M0–M4 里程碑可发现，看板状态明确 |
| G6 | 人类新人运行/修改/PR/评审 | 未参与搭建的人完成流程，否则 OPEN |
| G7 | 明确网站/预览包发布衔接 | 没有验证就不宣称 Pages 或可安装包发布 |

当前仓库登录缺少 Project 权限。Discussions、Topics 和里程碑不受此限制；Project 看板等待所需权限。未分配个人任务。当前单一 CODEOWNER 只负责评审路由，不代表第二位人类批准。独立 AI 技术评审如实记录，不冒充 GitHub 人工审批。

## 验证记录

首次公开 Windows CI 暴露了临时目录夹具问题：普通同步 realpath 保留 Windows 8.3 短路径，而异步门禁将其展开。已在本机用真实短路径观察到同步/原生解析的写法差异，但原夹具测试在本机仍通过，公开 runner 是决定性的复现环境。夹具改为通过原生 realpath 获取完整物理 owner 和仓库根目录，CI 同时在检查前选定规范 TEMP/TMP。没有增加字节归一化、逻辑键大小写折叠或别名放行。失败的 CI 保留在 PR #51 中。

独立 AI 评审发现并修复四项问题：文件白名单别名、外部依赖归属、冲突的安装步骤及缺少 pnpm 诊断。回归测试覆盖对应失败。

上手测试先复现工具缺失，再通过诊断及 HTTP 访问检查。干净安装发现 pnpm 包装器固定旧 Node 和隐含依赖布局，现通过明确运行时和公开 setup 处理原因。已在应用内浏览器实际打开 Canvas 示例，观察资源/画面/交互就绪、蓝色换装和 0.125 秒动画单步。这是上手冒烟检查，不是固定浏览器图形验收矩阵。合并前必须通过完整本地门禁、独立评审和远程 CI，具体候选结果由 PR 检查承载。

[整体架构与工程计划](architecture-and-engineering-plan.md)保留完整 M0–M4 范围与验收标准，本次只实现上述基础子集。
