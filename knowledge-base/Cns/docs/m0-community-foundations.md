## 环境与验证

工作区声明 hoisted 安装，因为当前源码采集工具要求第三方包的物理归属。Setup 自动建立渲染依赖的精确包内别名并核对归属；Windows 同时检查原生编译器别名。贡献者无需手工建立别名。已有不兼容安装可能被拒绝，不会静默覆盖；切换布局时用干净克隆复现。

修改根开发脚本会使嵌入的配置指纹失效。本次更新并重新验证活跃配置引用及其关联策略身份；引擎源码指纹、历史源码快照和原始回执保持不变。这是有限的迁移，不代表完整依赖闭包解耦。当前 B1 验证器准入与产物宿主测试配置已改用 Node 26.7.0；命令行拒绝测试及全部 13 个产物宿主用例通过。Node 26 下真实 B1 浏览器复验仍为 OPEN。其他固定旧 Node 的浏览器采集工具保留原配置，等待迁移。VM 宿主拒绝辅助程序现在根据访问记录拒绝，即使 VM 代理吞掉 getter 异常也不会误通过；负向控制仍为必需。

本地验证与远程 CI 分别记录。Windows 执行完整既有 prepush 门禁及上手测试。Linux/macOS 只运行构建、matrix4、display-tree 和无界面检查；编译器归属、发布及真实浏览器门禁明确未包含。最终 `M0 / merge-ready` 拒绝必需 job 的失败、取消或跳过；它不证明图形或移动性能。

## 验证记录

首次公开 Windows CI 暴露了临时目录夹具问题：普通同步 realpath 保留 Windows 8.3 短路径，而异步门禁将其展开。已在本机用真实短路径观察到同步/原生解析的写法差异，但原夹具测试在本机仍通过，公开 runner 是决定性的复现环境。夹具改为通过原生 realpath 获取完整物理 owner 和仓库根目录，CI 同时在检查前选定规范 TEMP/TMP。没有增加字节归一化、逻辑键大小写折叠或别名放行。失败的 CI 保留在 PR #51 中。

独立 AI 评审发现并修复四项问题：文件白名单别名、外部依赖归属、冲突的安装步骤及缺少 pnpm 诊断。回归测试覆盖对应失败。

上手测试先复现工具缺失，再通过诊断及 HTTP 访问检查。干净安装发现 pnpm 包装器固定旧 Node 和隐含依赖布局，现通过明确运行时和公开 setup 处理原因。已在应用内浏览器实际打开 Canvas 示例，观察资源/画面/交互就绪、蓝色换装和 0.125 秒动画单步。这是上手冒烟检查，不是固定浏览器图形验收矩阵。合并前必须通过完整本地门禁、独立评审和远程 CI，具体候选结果由 PR 检查承载。

M0 的架构/场景/预算冻结、人类新人演练、完整元数据解耦及剩余宿主/工具迁移保持未完成。参见[上手指南](getting-started.md)和[公开里程碑](https://github.com/cnedwin/Egret_rebuild/milestones)。

[整体架构与工程计划](architecture-and-engineering-plan.md)保留完整 M0–M4 范围与验收标准，本次只实现上述基础子集。

### 新人流程技术复演

基线：主干 `26136df66a493eb721e0780148de4bdc8ed4fb87`。Windows x64，Node 26.7.0、pnpm 11.25.0、TypeScript 7.0.2、PowerShell 7.6.5、Git 2.53.0.windows.3。两个公开新克隆均使用包含中文及空格的目录名。工具前提已安装，另行安装固定版本 pnpm，未修改全局工具。没有复制旧 node_modules 或构建产物。

| 观察项 | 实际结果与边界 |
| --- | --- |
| 首次克隆及热缓存安装 | 克隆 5.19 秒、安装 3.36 秒、快速检查 4.34 秒；日志复用四项依赖，因此不是冷缓存 |
| 独立冷缓存克隆 | 用 pnpm 11 的 `pnpm_config_store_dir` 指定新缓存；复用 0/下载 4；安装 4.08 秒、快速检查 4.04 秒；安装后受跟踪文件未变 |
| 本地标题修改后重复准备 | 安装 2.26 秒，修改文件 SHA 未变，快速检查通过，无手工别名 |
| 浏览器可视结果 | 应用内浏览器 Canvas 显示两个角色、固定文字及资源/画面/交互就绪；C 服装完成并呈现；0.125 秒单步；刷新看到修改后的双语标题 |
| 完整门禁发现 | 快速检查通过，完整类型门禁拒绝编译器转义的中文仓库路径；针对性回归控制复现问题，识别已知完整 owner 的写法后修复；实际中文路径类型门禁单独重跑，当前账本集成仍是另一项工程义务 |
| 参与人与宿主边界 | 实现代理执行，不是未参与搭建的人类；没有外部 fork 批准、手机、小游戏、温度/功耗或通用中文字体性能结果 |

以上单机观察不含初始 Node/Git/PowerShell 安装、包管理器安装及人类学习/评审时间。安装时间包含依赖下载，下载未单独计时。首次缓存隔离尝试使用过时的 `npm_config_store_dir` 前缀，仍复用默认缓存；实际包日志暴露了这一点，第二个克隆使用正确 pnpm 前缀确认冷缓存结果。不得把数字推广为慢网或新人速度。公开指南为后续演练设定暂定阈值，不追溯宣称这些观察已达成预设验收。

PR #51 的四个声明 [CI 作业](https://github.com/cnedwin/Egret_rebuild/actions/runs/38999228653)全部通过后合并，Git 树完全一致。[Main 规则](https://github.com/cnedwin/Egret_rebuild/rules/25288511)要求 PR、讨论解决及 GitHub Actions 的 `M0 / merge-ready`，禁止强推/删除，未配置绕过者。必需 GitHub 审批数为零反映单维护者现状，不代表独立人工批准。启用主干规则前，同等临时分支规则实际拒绝直接更新、强推和删除。本轮最终候选检查及合并回执由本轮 PR 承载，不将历史结果升级为新候选证据。

### G7 展示与发布衔接

M0 定义衔接条件，不宣称网站或可安装预览包已发布。后续文档站变更必须从经评审提交构建双语内容，保留相对链接、来源和当前能力边界，并在实际部署基础 URL 验证导航及素材加载。在线示例使用经评审构建、显示后端限制，验证真实输入/资源及不支持后端的处理。从可信已评审分支部署，仅使用部署所需凭据；不可信 PR job 不获得发布凭据。保留上一版已验收部署供回退，并记录产物/提交及实际 URL。

预览包发布需要明确范围、独立消费者的导出/类型/导入检查、源码/许可与素材审计、可复现产物和归档内容、安装运行验证及双语版本兼容/限制说明。当前 private 0.0.0 工作区包不是已发布 SDK。发布/站点工作随能力成熟并获得发布授权后推进，CPU 门禁通过本身不够。

完整 M0 继续开放。本轮交付社区基础设施、可复现证据及发布衔接条件，不增加引擎功能，也不证明产品性能。

诊断修复仅限验证工具。TypeScript 在引用的导入类型中把非 ASCII UTF-16 单元写成 Unicode 转义。转换器只从完整已知仓库 owner 推导可接受写法，并要求后随路径分隔符；sdk-other 之类的相邻 owner 不能匹配 sdk。原诊断后缀、逻辑文件键、文件原始字节和冻结的预期诊断元组均不变。针对转义 owner、相邻前缀及大小写敏感外部路径的控制先失败，修复后全部九项上手测试通过。这不授权任意诊断解码或为指纹做路径归一化。

第二处修复针对 BitmapBindingTicket 诊断：先认证选定声明，再替换该精确引用命名空间的原样或编译器转义写法。实际中文/空格目录随后通过完整类型门禁，包括 NS1 和 BitmapBindingTicket，而非仅提取函数测试。独立 AI 评审未发现可操作代码问题，并独立通过四项新增诊断测试；其整文件执行受沙箱本地监听/符号链接权限限制，因此与作者执行的九项通过分别记录。人类新人/fork 验收仍开放。

随后在中文与空格目录运行的提交快照推送门禁通过主测试，但暴露了 F2 Spine 实验验证器中的第三处转义 owner 转换遗漏。推送被拒绝并保留失败记录。新增针对性控制在修复前失败；修复后全部十项上手控制通过，实际中文检出中的完整 F2 source/profile 消费者类型检查也通过，原冻结元组保持不变。已检查其余诊断转换入口；该检出中的普通完整类型阶段此前已经通过。最终完整候选门禁与远端集成结果记录在 PR 中；本次修复没有新增 Spine 运行时功能。
