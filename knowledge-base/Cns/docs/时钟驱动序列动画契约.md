## 用途与公开 API

`Engine.createSequencePlayback` 将既有 `SequenceClip`、`Bitmap` 与引擎的显式游戏时钟连接起来。选帧、裁剪准入和精确资源绑定复用 `SequencePlayer`。调用方继续负责加载资源、提交源时间和渲染帧。

`@egret/engine` 根入口只增加三个类型名和一个 Engine 实例方法，不增加独立工厂、运行时类、包入口或依赖。

```ts
type SequencePlaybackState = 'idle' | 'running' | 'paused'
  | 'completed' | 'stopped' | 'failed';
interface SequencePlaybackOptions {
  readonly mode?: SequencePlaybackMode;
}
interface SequencePlayback extends Disposable {
  readonly state: SequencePlaybackState;
  readonly isDisposed: boolean;
  readonly elapsedSeconds: number;
  readonly lastSample: SequenceSample | undefined;
  start(): void;
  pause(): void;
  resume(): void;
  stop(): void;
  dispose(): void;
}
// Engine 实例成员；实际声明还包含私有名义类型标记。
createSequencePlayback(scope: Scope, bitmap: Bitmap, clip: SequenceClip,
  options?: SequencePlaybackOptions): SequencePlayback;
```

必须使用同一引擎创建的真实 Scope，以及持有资源管理器签发租约的 Bitmap；Texture 必须覆盖完整图像，clip 图集尺寸必须与图像一致。创建返回冻结的 idle 句柄，时间为零、尚无采样；不修改裁剪、不订阅、不获取资源、不渲染。默认模式为 `once`，`loop` 保留既有采样器的 binary64 取余行为。

Options 可以省略或显式传入 undefined，均使用默认模式；其他值必须为非 null、非数组对象。Mode 只读取一次，允许继承字段，忽略无关字段；不保留调用方对象。Bitmap、租约、Texture、mode、clip 和图集错误仍按既有播放器的顺序判定。

## 状态与时间

| 操作 | 行为 |
| --- | --- |
| `start()` | 仅用于 idle。先取得真实时钟订阅，再应用时间零。容量拒绝保持 idle，裁剪不变；应用成功后进入 running。 |
| `pause()` | Running 转为 paused，释放活动时钟订阅。时间与采样保持在最后一次成功应用的位置；重复暂停无变化，idle 拒绝。 |
| `resume()` | Paused 取得新订阅并重新应用保留的时间，重新检查精确资源绑定。成功后以当前游戏时间为新段锚点；容量拒绝保持 paused。Running 重复恢复无变化，idle 拒绝。 |
| 时钟 tick | 按当前播放时间最多应用一次，不补播跨过的帧。既有播放器成功提交裁剪后，才提交句柄时间与采样。 |
| Once 完成 | 应用精确 clip 时长，保留最后一帧；进入 completed，释放订阅并清理内部借用。 |
| `stop()` / `dispose()` | 同步、幂等、终止性操作。保留裁剪与最后一个自有采样；completed、failed 身份不改变。 |

终态的 `isDisposed` 为 true。关闭后仍可读取观察值，start/pause/resume 不能使终态复活；重播需要创建新句柄。显式跳转和倒退采样继续使用独立的 `SequencePlayer.applyAt`。

运行段使用固定的保留时间基点，加上从该段锚点开始的游戏时间间隔，不会反复把完整间隔累加到上次结果。局部暂停排除暂停间隙，其他时钟消费者可以继续运行。整个时钟暂停与恢复保持原有的源时间基线规则。默认时钟间隔上限仍为 0.25 秒，可配置的最大值仍为 1 秒；播放器不钳制或拆分源时间差。

时钟继续使用既有候选快照和注册顺序。Tick 中启动或恢复的句柄等待后续 tick。较早的回调可以在较晚的动画候选执行前暂停它；恢复不会补播这次遗漏更新。相同源时间不派发 tick；捕获、渲染和重播保存帧均不推进动画。

## 归属、容量与清理

Scope 拥有控制句柄和一个内部真实播放器。调用方按租约 → Bitmap → playback 的顺序注册资源，使反向清理先停止动画。Playback 只借用既有精确租约，不获取或释放租约、不销毁 Bitmap 或 Texture、不使资源管理器失效，也不恢复先前裁剪。

每个 Engine 最多允许 256 个活动 idle/running/paused 句柄，同一 Bitmap 最多一个活动 playback。这是明确的工程限制，不是实测内存或 UI 规模结论。Idle、paused 保留目标占用；running 还占用游戏时钟共享的 256 个活动订阅槽位。停止、完成和失败释放目标占用与所属记录槽位；旧 Scope 的历史清理不能删除新句柄的占用。

引擎关闭会在既有时钟与清理屏障完成前，同步终止全部活动 playback。Scope 取消后，尚未执行的动画回调不能再提交裁剪。终态记录清除内部播放器、目标、clip、订阅与活动归属借用；最后的不可变采样仅包含区域和标量。Scope 历史记录与生命周期验证依据可能继续存在，不据此承诺物理 GC、历史记录数量上限或立即完成 GPU 退役。

内部播放器在被 Scope 接管之前安装封存的自有清理操作。随后修改公开 `SequencePlayer` 原型方法，不能替换内部播放器的应用或历史清理路径。公开播放器实例、原 Scope 与播放器算法保持不变；导入前替换语言内建操作和任意进程隔离不在该保证范围内。

## 失败规则

句柄观察与方法先认证 receiver。Start/pause/resume 随后检查 Engine 生命周期、真实 Scope 状态、操作重入、终态和允许的状态。Stop/dispose 在关闭或活动操作期间仍可使用，终止结果优先于稍后的返回或失败。

新增拒绝包括 `SEQ_PLAYBACK_INVALID`、`SEQ_PLAYBACK_SCOPE_INVALID`、`SEQ_PLAYBACK_OPTIONS_INVALID`、`SEQ_PLAYBACK_CREATION_REENTRANT`、`SEQ_PLAYBACK_REENTRANT`、`SEQ_PLAYBACK_LIMIT`、`SEQ_PLAYBACK_TARGET_BUSY`、`SEQ_PLAYBACK_NOT_STARTED`、`SEQ_PLAYBACK_ALREADY_STARTED`、`SEQ_PLAYBACK_TERMINAL` 与 `SEQ_PLAYBACK_TIME_RANGE`。既有 Scope、Engine、时钟、播放器和资源错误保留原 code 与 cause。

成功读取 options 后重新检查生命周期；getter 抛出的原 cause，包括 undefined，先于它产生的关闭副作用，按 options 错误包装并保留。同一 owner 的递归创建在读取递归载荷前拒绝。Bitmap 租约被替换或清空时，即使新租约指向同一 Texture，也会拒绝。

Start/resume 的应用失败先终止句柄，再抛出原播放器 cause。Tick 应用失败同样先清理，由既有时钟提供唯一的 `CLOCK_CALLBACK_FAILED` 诊断和包装。已经提交的游戏时间不回滚，相同源时间不重放失败更新。次级清理错误不替代已经存在的主拒绝。本工作包不增加应用回调或 Promise 返回契约。

## 验证与范围

独立 oracle 使用原创 6×2 图集：红色 2×2、绿色 1×2、蓝色 3×1 区域，时长为 0.125、0.25、0.125 秒。字面量边界、暂停间隙、真实容量、资源身份、派发顺序、原型捕获与清理分别验证。缺失别名、模块或宿主初始化失败，不能被认定为具名能力缺失测试。

实际数量与环境身份将在执行后进入成对核验记录。既有显式播放器的浏览器证据保留其历史范围，不能为新控制器授予验收。新浏览器观察必须通过公开 Canvas/WebGPU 入口验证真实时钟驱动的 once/loop、暂停恢复和保存帧重播。

标签、帧事件、播放速率、有限循环次数、跳转与重置、trim 或旋转图集、完整 UI、骨骼整合、完整 Spine 支持及完整旧 MovieClip 迁移继续分别制定契约与验收。本工作包不产生性能、手机、Native SDK 或第三方许可结论。

本工作包是采用 AI 辅助、依据项目既有 clip、播放器、资源、时钟和生命周期契约独立编写的白鹭代码与文档，适用 Apache-2.0。不引入第三方动画实现；已有依赖声明、鸣谢和研究来源继续适用。
