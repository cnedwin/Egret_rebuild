# 历史资产与研究边界

[English](../../en/docs/historical-assets-and-research-boundaries.md) | 简体中文

历史产品经验、公开仓库和获准研究的工程资料共同帮助恢复白鹭的设计意图。它们的版本、可公开范围及验证程度分别登记，为新设计、兼容规则和回归样本提供依据。

## 历史经验

S002 记录创始人的历史说明：AS3 风格 API 降低 Flash 团队进入 H5 的成本；精简 Web/移动 Native 运行时改善加载、渲染、功耗和发热；复杂 UI 对传奇、装扮、放置等品类有价值；Runtime 内嵌合作与自研整合工具链是重要能力。

公开 Egret 仓库也说明 TypeScript API 与 AS3 的相近关系，支持这项设计意图；它不证明全部私有产品或当时的性能对照。[官方仓库](https://github.com/egret-labs/egret-core#typescript)。历史合作不等于目前仍有 SDK 部署权限。

## 可借鉴机制与复用规则

EUI 的分阶段失效与组件复用适合进入复杂 UI 原型；原生批量命令适合研究跨语言固定成本；资源预下载与缓存适合研究首个可玩体验。相邻合批、缓存和原生化的收益受绘制顺序、失效率、上传、内存与桥接影响，需端到端测量。

源码包压缩大小和预编译依赖大小不等于发布底包。目录存在不等于平台完成，README版本名称不等于全部子模块版本，历史协议范围相近不等于已互通。对每个候选复用模块先明确来源、版本、构建、许可、缺陷与测试，随后决定复用、重写或替换。

## 公开与内部记录

知识库公开经过整理的机制摘要与出处，设计记录说明它们与新白鹭的关系。原始工程包、受权限限制的源码、接收记录及私有配置按各自权限保存，发行清单列明公开范围。历史模块与第三方依赖使用其实际适用声明，项目许可证覆盖范围单独明确。

支持矩阵、性能结论和迁移成功率只能来自[交付验收](交付计划.md)。社区可以用自有或明确授权的最小样本协助验证，无需提交完整商业工程或取得私有源码。
