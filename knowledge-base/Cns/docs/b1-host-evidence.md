## 保留历史

此前FOCUSED_6使用 `--test-isolation=none` 通过十三项，绑定84,270字节测试／`b4e02cdc48bf59c2cd706a8e7fedb2290736f98d50a9215a1b228b0d4180d2bb`，此历史专项结果仍有效。随后一次默认整仓尝试得到 **900/901通过、1项失败**：默认Node24.19 worker参数guard在十三个directdriver启动前失败。这是harness/setup故障，不是十三个driver用例失败。parent guard修正后，FOCUSED_8与上述full901/901后继通过；旧isolation-none结果不能替代这些默认路线结果。

| 用例 | 实际观察范围 |
| --- | --- |
| S01 | Node `SourceTextModule` 构造，不链接、不求值，以及有限的首方导入扫描，包含九个准确除法表达式见证。 |
| N01–N05 | Core、Canvas 加载，以及普通 WebGPU 的导入、启动、渲染、回读、关闭，未加载 B1 场景模块。 |

| R01 | 人工注入的加载拒绝与启动错误传递。 |
| C01–C04 | 加载成功或拒绝期间的停止、关闭；取消启动后不再开始 GPU 工作。 |

H01–H18 是正例内的具名断言，覆盖真实身份准入、几何身份共享、上传与回读合计预算、两通道顺序、可重入属性读取、尝试写入后的栅栏、隔离和账本计费。它们不是额外十八套用例序列。指定故障用例预期会出现不安全清理拒绝；测试通过不表示每个模拟主机都安全关闭。

这一版本还检验了两项技术回归：共用的 CPU 图片投影不应归入 GPU 专用依赖；B1 在停止、关闭后重复调用 `start()`，应保留待结算启动 Promise，直到启动工作结束。
