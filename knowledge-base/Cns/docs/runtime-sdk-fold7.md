# 首个 Android 2D 宿主的 Galaxy Z Fold7 实测

[English](../../en/docs/runtime-sdk-fold7.md) | 简体中文

在同一台 Fold7 上，三条路径画出的最后一帧逐像素一致。实时路径每帧生成并从 Android System WebView 取回 2,040 字节的命令包，各轮中位耗时为 1.50–1.57 ms，GL 线程提交 Rust 绘制的中位耗时为 0.088–0.110 ms。在这个负载下，脚本生成与跨进程传输占用的时间更长。[架构与分期](runtime-sdk.md) · [逐轮数据](../../../runtime-sdk/measurements/fold7.json)

## 场景与设备

三路使用相同的 320 × 192 渲染缓冲、两个纯色矩形、40 个使用图集的动画四边形和一张 32 × 8 RGBA8 纹理。实时 APK 在独立的 WebView 中运行白鹭场景，由 Rust GLES3 绘制原生表面。回放直接循环读取捕获的 60 帧命令，沿用同一 Rust 执行器。Chrome 使用白鹭现有的 SharedFrame2D WebGL2 执行器。APK 为 arm64 调试包，基于引擎提交 `859bd0ee` 构建。[构建与运行](../../../runtime-sdk/android/README.zh-CN.md)

实测设备搭载 Android 17、Chrome/157.0.8103.78 和 Adreno 830，测试期间通过 USB 供电并保持亮屏解锁。三路画面均按比例适配。绘制缓冲分辨率固定，Chrome 工具栏可独立改变 CSS 视口。九轮短测起止时的电池温度为 30.0–30.2 °C，系统热状态为 0。

## 复跑 H5 采集

通过 HTTP 提供生成的场景目录，在手机前台的 Chrome 中打开 index.html。页面标题变为 egret-ready 后，在控制台执行以下调用可复跑一轮计时，再完成独立的像素核对和释放检查。每个启动样本使用一次新导航。

```js
const bench = globalThis.EgretRuntimeBenchmark;
const startup = await bench.ready;
const timing = await bench.run(60, 300);
const image = await bench.pixels(59);
const cleanup = await bench.close();
```

## 帧间隔与启动

下表按执行顺序列出每一轮。预热 60 帧后，H5 记录 300 个相邻 requestAnimationFrame 间隔；Android 保留 300 个 Choreographer 回调时间戳，可得到 299 个相邻间隔。分位数采用最近秩法。CPU 提交列是提交线程在调用内经过的实际时间。首帧列的起止点见表后说明。

| 轮次 | 路径 | 帧间隔 p50 / p95 / p99（ms） | CPU 提交 p50（ms） | 首帧（ms） |
| ---: | --- | --- | ---: | ---: |
| 1 | H5 | 16.600 / 16.700 / 16.700 | 3.800 | 540.9 |
| 2 | 原生实时 | 8.289 / 8.290 / 8.290 | 0.110 | 158.1 |
| 3 | 原生回放 | 8.288 / 8.291 / 8.292 | 0.121 | 53.0 |
| 4 | 原生实时 | 8.288 / 8.290 / 8.291 | 0.088 | 168.5 |
| 5 | 原生回放 | 8.288 / 8.291 / 8.291 | 0.110 | 59.8 |
| 6 | H5 | 16.600 / 16.700 / 16.700 | 3.800 | 567.1 |
| 7 | 原生回放 | 8.288 / 8.290 / 8.294 | 0.123 | 63.8 |
| 8 | H5 | 16.600 / 16.700 / 16.700 | 3.800 | 534.6 |
| 9 | 原生实时 | 8.288 / 8.291 / 8.291 | 0.107 | 169.4 |

H5 从已运行 Chrome 中发起新导航计时，经过 USB 回环连接加载，首个 renderSharedFrame 调用返回时结束。从场景初始化到同一终点为 32.0–33.4 ms，从导航到首帧 GPU 工作回收为 536.0–569.0 ms。Android 从系统创建应用进程起算，到 UI 线程收到首次 GL 绘制回执为止。若从 Activity 创建起算，实时路径为 143.1–157.5 ms，回放为 42.0–51.5 ms。文件系统缓存保留。屏幕实际呈现和首次输入延迟超出本次仪器的观测范围。

H5 等待宿主回收上一帧的 GPU 工作后才申请下一次回调。Android 每次只允许一个命令包在途，GL 提交回到 UI 线程后即可申请下一次回调。观察到的帧间隔包含这两种调度方式的影响。要计算可比较的加速倍数，还需要统一节奏、背压和呈现终点。

## 桥接与内存

实时路径的 JS 局部计时包括游戏捕获、命令编码和 Base64，各轮中位数为 0.60–0.70 ms。对每一帧，用从请求到字节就绪的耗时减去该帧 JS 局部耗时，所得差值的中位数为 0.99–1.05 ms，包含 VM 调度和返回、JSON 解析、Base64 解码及 Java 缓冲区复制。回放选择已存命令包的中位耗时为 0.001 ms。这些量都是包含等待的时段，JS 计时还受本地时钟精度影响。

H5 在计时前后采样 Chrome 浏览器主进程 PSS，随后回读像素并释放资源；结束样本为 269.4–270.3 MiB。APK 在末帧回读并释放 GL 纹理页后、关闭 JS 租约前，采样应用宿主进程；实时为 107.0–107.5 MiB，回放为 60.7–61.0 MiB。这些终点快照未包含隔离渲染或 GPU 服务，Chrome 主进程还可能包含其他已有的浏览器状态。峰值游戏内存与整机能耗需分别采集。

### 运行期间的进程采样

在单独一轮运行中保留场景，每条路径采样三次 PSS。H5 在完成 60 次计时回调后维持页面和资源；两条 APK 路径各自从新应用进程启动，在持续绘制期间采样。下表为三次观察的范围，单位 MiB。

| 路径 | 宿主或浏览器主进程 | 归属已核实的渲染进程 | 已观测小计 |
| --- | ---: | ---: | ---: |
| H5 | 271.7–275.2 | 52.7 | 324.4–327.9 |
| 原生实时 | 100.4–103.3 | 45.4–50.5 | 148.6–150.9 |
| 原生回放 | 59.0–59.4 | 未发现可归属进程 | 59.0–59.4 |

Android 侧通过应用的服务绑定识别 WebView 渲染进程。Chrome 侧由样板标签页写入 performance.mark，跟踪中定位到唯一 OS PID；再由 CDP 核对渲染进程类型、Android 核对 Chrome 沙箱进程身份，并通过 dumpsys meminfo --local 取得 PSS。小计按每次采样加总已确认的进程。Chrome 主进程可能含其他浏览器状态，各组小计均未覆盖共享 GPU 服务和系统合成器。

从桌面启动已安装的 APK，经退到后台、返回和关闭，共完成 973 帧，进入前台 2 次，图集上传 2 次，GL 纹理释放 2 次，引擎租约释放一次。

## 像素、恢复与释放

九轮计时结束时，H5、实时与回放在动画槽位 59 的完整自上而下 RGBA 摘要均相同。单独的原生诊断将 60 帧实时命令与回放逐字节比对，校验资源摘要，并强制重建一次 EGL 上下文。两种 APK 模式均报告两次设备创建、两次图集上传、一个旧上下文废弃和一次最终 GL 纹理页释放。实时路径释放了一个引擎资产租约。H5 释放一个租约，关闭时待处理帧、上传字节和回读字节均为零。早期 APK 曾因 Windows 生成混合分隔符导致嵌套资源缺失；修正后的打包器核对最终签名 ZIP 的成员名。APK、帧循环、图集和画面摘要见[逐轮数据](../../../runtime-sdk/measurements/fold7.json)。
