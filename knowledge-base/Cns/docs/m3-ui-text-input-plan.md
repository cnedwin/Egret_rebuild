[English](../../en/docs/m3-ui-text-input-plan.md) | 中文

架构与交付计划，2026-10-23。父任务：#57。保留四个工作包。已实现的输入与 UI 基础分别记录契约和证据；本计划不代表整个工作包、性能、IME 或辅助技术验收通过。

M3 在既有 Engine、显示树、Scope 和资源所有者之上交付可用 UI 系统，包括自动布局、变高虚拟列表、带样式段落文字、指针/键盘输入、焦点、基础原生文字编辑及浏览器无障碍。它不代表完整 EUI/EXML 迁移、所有平台接入或 M4 生产验收完成。

sequence-6 正式计时得出有效失败后，M1.2/D60 继续 OPEN。现有渲染/资源结果是前置基础和回归参考，不是 M3 验收。M3 的独立工作可以推进，但不能因此将性能缺口标为关闭。

## 2. 一份 UI 状态，四个协作模块

保持现有四包分层。无 DOM 的布局、段落/编辑状态和语义描述归 runtime 侧模块；公开编排归 Engine 可选入口；浏览器 API 仅放在 Engine web 入口。下文新增路径是拟议落点，不是已有导出。

| 目标概念——并非已有 API | 职责与边界 |
| --- | --- |
| UI 根 / 已提交布局 | 管理组件状态、脏队列、测量/排列及一个公开布局版本，在 capture 前写入既有显示树。 |
| 段落计划 / 文字提供器 | 管理源码范围映射、行布局和经提供器验收的整形几何；栅格结果仍是普通受管图像/纹理资源。 |
| 输入/焦点/编辑桥接 | 将宿主输入转换为同步类型化动作及带版本编辑事务；管理原生监听器和可编辑元素。 |
| 语义投影 | 将同一控件状态映射成浏览器角色、名称、状态和焦点目标，不另建应用状态模型。 |

更新边界为：应用同步动作 → 处理待测量项 → 排列 → 发布布局/交互/语义版本 → capture/render。Host 提交不得启动布局或字体任务。准备期间的重入修改排入后续 UI 版本；失败或过期准备不得部分发布新布局。

这一事务属于新 UI 所有者，不会追溯性地让既有任意显示对象 setter 具有事务能力。UI 所有的几何只能由其所有者写入；外部覆盖需要明确的退出自动管理/失效规则。

拾取、派生命中区域、裁剪、原生光标位置及语义边界使用同一已提交版本和 viewport 变换。既有手动 `hitArea` 继续可用。不得从栅格像素或 GPU 读回推断交互几何。

Scope、AssetManager/租约及 Host/device generation 保持权威。M3 不另建 GPU 管理器或销毁层级。UI 与 M2 共用纹理视图、裁剪、时间及恢复契约；M3 不必等待全部动画功能完成。

### 最小目标接口约定

以下是目标数据/生命周期约定，不是已实现导出或最终 TypeScript 命名。M3.1–M3.4 共用这些约定，不各造一套身份。

| 目标接口面 | 最少字段与生命周期 |
| --- | --- |
| UI 根 / 布局提交 | `engine`、`scope`、逻辑 `viewport`、`density`、组件 `id`、`revision`；min/max/显式尺寸约束；结果 box、clip、父级/顺序及依赖版本。`invalidate → prepare → commit`，或保留旧提交；`dispose` 取消待处理工作。 |
| 虚拟数据源 | 稳定 `key`、记录数、估计/实测高度和数据版本；`bind(key, scope)` / `unbind`；锚点 `{key, offset}`；可见、overscan 和保留计数。绑定代次拒绝迟到完成。 |
| 段落请求 / 计划 | 精确文本与 UTF-16 属性范围、字体集身份/代次、size/features/variations、语言/方向、宽度/断行策略、paint/density 及请求版本；结果行/源码范围、glyph ID/advance/offset/cluster、逻辑/ink 边界及受管栅格租约。`prepare` 可取消，只有当前完整结果才能提交。 |
| 字体/provider 所有者 | 字节身份、face index、fallback 顺序、profile/build/Unicode 版本及有界工作/驻留；`acquire/release`、代次失效、idle 收敛和终止销毁。Provider 内存及字体字节计入 CPU，Host 管 GPU 物化。 |
| 输入 / 焦点 / 编辑 | 控件 ID、已提交布局版本、pointer ID/type/逻辑点或键盘动作；焦点目标与原因；编辑基版本、替换范围/文本、选区 `{anchor, focus, affinity}` 和 composition session ID。同步派发，明确捕获/释放及组合 begin/update/commit/cancel。 |
| 主题 / 语义快照 | 主题代次及不可变 token/skin 引用；控件 ID、role/name/value/state、关系、边界及布局版本。共同暂存/发布；订阅和原生节点由 Scope 管理，销毁时移除。 |

未知字段、不支持能力及过期版本在所属契约中明确拒绝或按过期结果忽略，不得静默换用其他字体、编辑器、布局或渲染器。公开工厂仍是可选 Engine 入口；资源所有者真实性和普通自定义适配器回退仍是明确实现要求。

### 主题、层级、遮罩与效果

主题采用不可变带版本记录，包含颜色、间距、字体及状态到皮肤的引用。切换时区分度量变化和仅绘制变化，暂存所需字体/图片租约，再发布一致版本。不引入可执行 CSS 层叠或隐式资源加载器。

最低皮肤集包含 default、hover、pressed、disabled 和焦点提示；需要的控件另有 checked/selected/expanded 变体。皮肤图像复用既有图集/九宫格能力；主题替换仅释放被替换需求，保留共享资源的其他使用者。

UI 根明确管理内容层、弹出层和模态层，它们都处于同一显示/渲染顺序。锚定弹窗跟随所有者已提交几何并限制于 viewport；锚点消失后明确关闭或转移所有权。模态背景管理输入拦截及焦点约束，视觉深度本身不授予输入优先级。

`DisplayObject.clipRect` 和 `renderBoundary` 已存在；isolate 边界不等于已实现离屏缓存/滤镜。滚动容器使用已提交裁剪。弹窗只有显式迁移到根弹出层才能脱离祖先滚动裁剪，不能静默忽略裁剪。

目标层级验收切片包含嵌套矩形裁剪、一个作者提供的 alpha 遮罩组合、一个有界离屏模糊组，并与普通 UI/内容交错。Alpha 遮罩和离屏执行属于需与其所有者共同交付/验收的共享渲染能力，不能从当前 clip API 推定；未具备前对应整合项保持 blocked。

UI 管理效果参数和失效；渲染器管理 render target、设备代次句柄、像素面积/scratch/in-flight 预算及物理退役。声明的有界 kernel 和固定参考定义模糊夹具。Canvas 或其他不支持 backend 不得静默去掉效果；启动/加载时拒绝缺失的必需能力。

命中使用控件明确的已提交几何及裁剪。Alpha 图像遮罩不会自动启用逐像素命中；示例若要求遮罩形状命中，须提供对应已准入几何命中区域。模糊像素不得隐式放大命中面积。

使用固定层级/像素/交互参考验收嵌套弹窗/模态顺序、滚动条拖拽、裁剪与命中、主题/字体变化、效果失效和恢复。任意 shader/filter graph、通用矢量遮罩编辑、无限制 CSS、主题编辑器、停靠/树表格控件及旧 EUI 皮肤属于后续范围，不藏入首批控件集的完成声明。

### 异步更新一致性与共享效果

M3.1 负责已提交 UI 更新域：必须共同变化的最小子树，以及依赖它的祖先、弹层锚点、焦点／编辑器和语义投影。异步字体／皮肤结果暂存全部受影响布局、绘制绑定和交互几何，不能单独发布其中一项。等待或失败期间，该域保持原有已提交呈现与几何，其他域继续交互。尺寸变化影响父级／兄弟布局时，先扩大更新域再提交。初始域没有旧版本时，发布命中／语义行为一致的明确占位内容。全局动画时钟不等待 GPU 恢复。

M3.2 提供就绪、取消及版本身份，M3.3 仅消费已提交几何。M3.1 通过 UI 所有者在已说明的帧边界提交，部分写入之间不调用用户回调，重入修改排入下一版本。UI 所有者之外的显示树直接 setter，对受管几何必须拒绝或进入明确失效路径，不能暗中绕过事务。测试迟到字体改变获得焦点的虚拟行高度，同时新皮肤到达，以及取消／销毁和未受影响兄弟节点；联合断言滚动锚点、命中目标、编辑器位置与语义版本。保留的焦点／组合输入行计入场景声明的活动容器总上限。

M3.4 包含明确的共享渲染交付，由渲染维护者在 UI 集成前评审。说明效果输入／输出、pass 顺序、目标尺寸／格式、alpha／颜色约定、父级裁剪与嵌套效果准入。渲染器拥有目标池、重叠代次及暂存预算、基于完成的退役和丢失／恢复。M2.3 负责 Spine 颜色转换并评审共同颜色边界，不接管 UI 效果实现。在 WebGPU 与 WebGL2 验证选定遮罩和模糊核，包括嵌套裁剪、预算拒绝及设备丢失。复用既有执行路径，通用渲染图和新的 shared-frame 版本都不是前置条件。表示不兼容时，先完成具体扩展评审，再合并消费者。

## 3. M3.1——自动布局与变高虚拟化

**结果：**可调整尺寸、可滚动且变高回收稳定的数据面板，而非互不连通的布局辅助函数。难度：高。启动：可开始有界实现；最终文字接入与 M3.2 汇合。

1. 定义显式/min/max 尺寸、内容测量、padding/gap、横纵排列和对齐。约束通过确定性的先测量后排列解决；无法满足的依赖环明确拒绝，不反复迭代得到与耗时有关的结果。
2. 区分测量、位置、绘制、交互和语义失效。仅绘制变化不触发测量；局部宽度/文字变化只使必要的祖先/后代依赖失效。未变化 UI 不新增测量或栅格工作。
3. 按版本发布不可变布局结果。显示写入前暂存组件修改；完整提案及所有准入数值校验通过后才发布。失败时保留前一已提交版本。
4. 实现滚动与 50,000 条记录的变高列表，使用稳定项目键、前缀高度索引及对数复杂度的偏移查找/更新。数据记录不等于显示节点；仅实例化可见行及固定配置的 overscan 区域。
5. 行绑定管理自己的监听器、文字/图片需求和异步代次。复用前先取消旧绑定；迟到结果不得填入另一个项目。脱离父节点不得释放其他所有者的资源。
6. 高度或数据变化时，用稳定项目键及行内偏移保留滚动锚点。锚点删除后按明确的后继存活项/前驱规则选择，再按新范围钳制一次。索引不能代替身份。
7. 键盘焦点/组合输入所在行必须有界地显式保留，或先完成明确焦点转移再回收。保留行与 overscan 分开记账，不得形成无上限的隐藏行缓存。
8. viewport/density/字体变化后的重排是单次带版本事务；滚动与拾取不得混用旧裁剪和新行几何。

拟议路径：既有 `packages/engine/src/layout*.ts` 兼容面；新增可选 `packages/engine/src/ui/`、`packages/runtime/src/ui/`；遵循现有风格的聚焦测试及 `examples/` 示例。不要求新增包。

交付端到端数据面板示例、组件/布局契约、有界内存记账、确定性小型参考夹具和大型压力夹具。依赖既有显示/Scope/输入基础；段落测量与焦点通过上述契约接入。

验收可执行：小布局与虚拟范围对照独立简单参考；测试冲突约束/环、正负零及非有限数准入、插入/删除/重排、视口上方高度变化、空数据和极端滚动位置。覆盖回收中的取消、重入、销毁及迟到结果。

用计数证明静止 UI 不重复测量/栅格，局部失效不会无理由扩大到整树，保留行/资源处于配置上限内。大型夹具的数量与耗时分别记录；本文不声称已达到任何固定耗时。

## 4. M3.2——段落文字、字体身份及可恢复文字缓存

**结果：**带样式、换行、对齐和截断的段落，并具备可复核字体输入、源码映射及资源恢复。难度：文字/渲染专家。启动：可开始；布局与编辑消费其已声明计划契约。

1. 新增段落 profile，包含不可变属性化文本、明确语言/基方向、换行约束、对齐、截断及 density。公开/原生边界保留 UTF-16 源码偏移，另存簇边界及视觉顺序/亲和性映射。
2. 区分分段、双向解析、断行机会与字形整形。引擎自有算法固定 Unicode 数据版本；不得声称字素边界本身能产生字形、光标几何或行宽适配。[UAX #29](https://www.unicode.org/reports/tr29/)、[UAX #9](https://www.unicode.org/reports/tr9/)、[UAX #14](https://www.unicode.org/reports/tr14/)。
3. 保留 WC1 既有原生整行测量/栅格路径。新段落 profile 的首个推荐实现是可选 CPU/Wasm provider：ICU 提供分段/双向服务，HarfBuzz 整形，FreeType 从相同受管字体字节栅格化字形。具体 build/数据/许可在实现验收时固定；本计划不添加依赖。[ICU 分段](https://unicode-org.github.io/icu/userguide/boundaryanalysis/)、[ICU 双向](https://unicode-org.github.io/icu/userguide/transforms/bidi/)。
4. 按脚本、bidi level、语言及整形样式/字体分 run；仅绘制属性变化不切断整形。向 HarfBuzz 传完整段落上下文和 item 范围，保留 UTF-16 cluster 映射及 glyph advance/offset；从准入机会选择断点后重整最终行，再应用行级双向顺序。Fallback 替换缺失簇/上下文 run，不任意拆 UTF-16 码元。[HarfBuzz 上下文](https://harfbuzz.github.io/adding-text-to-the-buffer.html)、[cluster](https://harfbuzz.github.io/clusters.html)。
5. FreeType 按相同 face/variation/size/load 策略栅格化这些精确 glyph ID/位置；边界来自该计划，不来自 Canvas 前缀宽度。首批字体格式包含经验证的轮廓字体和内嵌彩色/COLRv0 字体；SVG/COLRv1 需要后续渲染扩展，明确拒绝而非静默转单色。明确预乘 BGRA 到既有图像策略的转换。字形图集仍可选，整 run/整行图像为基线。[FreeType 字形加载](https://freetype.org/freetype2/docs/reference/ft2-glyph_retrieval.html)。
6. 字体 manifest 标识精确字节、face/variation 设置、许可/来源、有序 fallback 和代次。应用自管/系统字体需明确命名环境 profile；`FontFaceSet` 就绪不能单独证明实际字形来源。[CSS Font Loading](https://www.w3.org/TR/css-font-loading-3/)。
7. 分离 font/shape/layout/raster 键，包含精确文本与属性 run、字体/fallback 身份与代次、provider/profile 版本、语言/方向/features/variation、约束/断行策略以及栅格 density/绘制属性。只复用输入未变化的阶段。
8. 分别限制源长度、run、行、元数据、队列任务、调用方租约、图像和 scratch 字节。T1 原限制不变；新上限属于新 profile，在分配前声明，并有边界测试。
9. 仅为最新已接受版本共同发布布局、边界和栅格。替换成功前保留旧文字；字体取消、fallback 失败或迟到完成不得部分修改段落显示或命中几何。
10. 使用现有资源租约和设备恢复。字体代次变化使相关 CPU 计划/栅格失效；GPU 代次变化只重建设备物化，不制造新的文字、选区或字体身份。保留 CPU 数据或明确重载配方。

拟议路径：在 `packages/runtime/src/text/`、`packages/engine/src/text*.ts`、`packages/engine/web/CanvasTextRasterProvider.ts` 旁扩展；保持现有 T1/TF1/WC1 入口行为及测试。段落 provider 通过可选入口接入，不把 DOM 导入 runtime。

### 移动端与多触点输入契约——M3.3

触摸和多个独立接触点是 M3 必交付能力，不是后续平台增强。现有 MI1 桥接仅支持鼠标；监听 Pointer Events 不代表已经支持触摸。保留 MI1 公开行为和显式命中区域准入。新的输入编排通过可选 Engine 入口同时服务游戏场景与 UI；基础游戏交互不得依赖段落整形、UI 根节点或原生文字编辑。触点／路由状态属于不依赖 DOM 的 runtime 输入模块，浏览器转换留在可选 Engine web 适配器。这些是目标边界，不是已实现导出。

| 容量与所有权 | 声明有界触点容量，初始核心配置至少同时接纳五个触摸接触点。超限时可观察地拒绝新增触点，不替换活动触点。手机必需场景为双指游戏操作；五触点路由还需受控测试，硬件限制另记。历史、监听器、识别器状态均有界，Scope 销毁释放其所有会话与监听器。 |
| 路由与捕获 | 初始路由由已提交几何和裁剪确定。捕获按触点独立管理，与键盘焦点分开；后续事件按声明路由策略交给仍存活的捕获目标或当前命中对象。回调后重查所有权。up/cancel 只终止一次；活动会话丢失捕获则取消。up 后迟到的捕获丢失通知不能再次终止。目标移除、禁用或被模态层排除时取消对应所有权；仅换父遵循既有路由语义。 |
| 坐标与版本 | 通过已验收视口／表面变换，将宿主坐标一次转换为逻辑场景坐标。UI 命中使用已提交布局版本；基础场景输入保留作者指定的 hitArea。旋转或键盘缩放等视口映射变化，须先取消活动触点再发布新映射，此后要求新的 down。仅布局变化使用下一已提交几何，不混用版本。不支持的 CSS 变换明确拒绝，不猜测。 |
| 顺序与游戏动作 | 保留同步类型化事件派发、首错误和清理语义。游戏可每次更新采样连续状态，但 down/up/cancel 和动作边沿必须有序，不能合并丢失。保留的公开事件不得引用复用暂存。为示例提供小型显式动作绑定：键盘或触摸移动、指针或键盘激活共用游戏命令；不要求可配置动作编辑器或控制器框架。 |
| 中断 | 进入后台、宿主／桥接停止、窗口失焦或系统接管时，结束受影响触点并清除持续游戏动作。恢复时不伪造 down、不重放激活；普通 UI 焦点变化不等于窗口失焦。设备丢失采取明确交互策略：受影响表面不可交互时取消活动游戏触点，保留应用状态，interactive-ready 后才接纳新触点。 |
| 宿主策略 | 浏览器适配优先采用 Pointer Events；另行支持的兼容路径必须消除兼容鼠标事件造成的重复激活。在手势开始前声明画布局部 touch-action／默认滚动行为，保留游戏表面以外的页面行为。真实浏览器捕获与引擎逻辑捕获分别管理。小游戏／原生适配器将各自事件转换到核心契约，分别验收；浏览器通过不代表这些平台通过。 |

M3.3 输入／宿主维护者负责此契约和浏览器桥接；M3.1 提供已提交 UI 命中几何，M3.4 使用共同路由权威实现手势／控件，M2 接收游戏命令而不安装输入监听器。在现有 #89 实施 PR 中确定具体事件载荷、容量、坐标配置和错误／取消结果，再合并依赖消费者。首个完整交付为基础场景多触点输入及最小双区域路由夹具（不包含可复用摇杆或手势识别器）；可复用双手控件归 M3.4；焦点／IME 工作在同包后续完成，仍是关闭该包的必需条件。不新增工作包或全局审批阶段。

[Pointer Events 规范](https://www.w3.org/TR/pointerevents3/)为浏览器适配提供依据，不直接成为无宿主核心 API。键盘状态与原生文字编辑仍是独立输入通道。受控测试覆盖 ID 复用、超限拒绝、多触点路由、回调失败／重入／销毁、兼容事件重复和完整清理。真实移动验收遵循 M4 的 X-MTouch/1 矩阵；合成事件不能证明真实触摸、系统手势或手机键盘行为。

## 6. M3.4——无障碍控件、皮肤与完整 UI 场景

**结果：**完整可复用控件集及可检查的复杂 UI 示例。难度：高，需无障碍评审。启动：整合等待 M3.1–M3.3 契约及可执行切片；夹具/设计贡献可提前开始。

最低控件集明确为：布局面板、静态图像、段落标签、按钮、checkbox/toggle、互斥 radio 组、单选 listbox、带可拖滚动条的滚动视口、变高虚拟列表、锚定弹窗、模态对话框、单行 input、多行 textarea。适用的选择状态、键盘行为、皮肤状态和语义角色都是控件组成部分。菜单、tabs、slider 及文档编辑器属于后续增加项，除非另行明确范围。

1. 交付容器、文字/图像、按钮、切换/选择控件、滚动容器、虚拟列表、弹窗/对话框和基础文字输入。共享控件状态提供 default/hover/pressed/disabled/focus 皮肤；指针、键盘、语义动作共用一个激活路径。
2. 保留 `BitmapButton` 兼容行为。新控件可复用其受管纹理与激活原则，但不能把现有仅鼠标状态机说成已提供键盘或无障碍语义。
3. 名称、角色、值、selected/expanded/checked/disabled 状态及关系来自与视觉控件相同的状态。适合时优先使用原生 HTML 控件；ARIA 描述语义，不会补上缺失的键盘行为。[WAI-ARIA 1.2](https://www.w3.org/TR/wai-aria-1.2/)。
4. 虚拟语义区域仅保留已准入的可见/overscan/显式保留项。位置和集合大小必须真实；active-descendant 目标必须存在。移除前先实体化目标或转移焦点，不为虚拟行发布大量不可达焦点目标。
5. 活动原生编辑器就是该编辑器的语义节点，不通过第二代理重复播报。模态不可交互范围、名称、label、错误提示与焦点恢复必须和真实交互模型一致。
6. 每个控件提供键盘规则及焦点指示。[ARIA Authoring Practices 模式](https://www.w3.org/WAI/ARIA/apg/patterns/) 用于指导实现；DOM 断言通过不能证明读屏可用或普遍符合 WCAG。
7. 提供一个可编辑整合示例，组合变高列表、本地化样式文字、表单、选择控件、滚动、弹窗和共享图片/动画内容。可用时使用既有 M2 接口；最终 M4 验收不能用占位物掩盖动画功能缺失。
8. 在控件保持焦点时执行字体/density/viewport 变化、列表替换、释放/重载、backend 丢失/恢复及后台返回。保留值、选区、锚点与所有权；错误可见且完整尝试清理。
9. 交付第 2 节的主题/层级/遮罩/效果切片，包括原子主题切换、根弹出层所有权、几何命中策略及共享渲染资源记账。不能因为无滤镜控件可用，就把缺失的必需效果/backend 项称为完成。

拟议路径：可选 UI 组件/皮肤模块、浏览器语义桥接、`examples/`、聚焦测试及双语知识库。不另建 UI 资源加载器、调度器或通用插件/权限框架。

验收包含控件交互参考、布局/像素和语义树检查、仅键盘导航，以及声明 browser/OS 组合上的真实辅助技术会话。明确记录失败/不可用组合。Native SDK/手机无障碍不能继承桌面浏览器结果。

### 手势与控件责任——M3.4

在 M3.3 触点流上交付点击、拖动／平移、长按和双指缩放／旋转识别器，不另装相互竞争的宿主监听器。采集前以逻辑单位声明移动／时间阈值，以及嵌套滚动、轴选择和边界交接策略。每个触点只有一个胜出的手势所有者；双指识别器必须原子取得两个触点，否则拒绝，不能抢占已由摇杆／控件捕获的触点。地图所有者仅在第二触点空闲时，可将自己持有的单指平移提升为双指缩放：原子结束平移、取得两触点并重设位置基准，再输出缩放增量，不能隐式转移其他控件的触点。拖动／滚动胜出时取消候选点击，此后不补发点击。双指手势结束后，剩余手指需重新 down 才能开始另一手势，避免跳变或误点击。不同触点可同时操作独立控件。

提供可复用的虚拟移动控制示例及独立动作按钮，键盘通过相同游戏命令操作。包含地图平移／双指缩放／旋转，并提供明确的缩放按钮替代操作，不新增通用相机／导航框架。模态拦截、控件禁用、虚拟行回收、系统取消以及资源／表面中断必须取消受影响所有权，不能将同一动作传给下层场景。浏览器默认动作策略仍归 M3.3；布局、滚动及语义激活保留既有责任归属。

M3.4 负责识别、仲裁和控件行为；输入维护者评审其对 M3.3 路由的使用，UI 维护者评审已提交几何及无障碍替代操作。验收覆盖同时移动／动作、嵌套滚动与激活冲突、按下期间打开模态层、缩放中移除／替换手指、触摸和鼠标共存且不重复激活，以及取消／销毁后持续动作归零。复用完整示例及 M4 手机矩阵，不另建手势调度器或任务族。

## 7. 共用夹具、门禁与交接

既有 architecture 的 U 压力设计指定 **10,000 逻辑节点、1,000 可见节点、八层嵌套裁剪、50,000 条变高列表记录**，覆盖中文/英文/RTL/emoji，以及静态、1% 变化和全脏更新。这些是计划夹具输入，不是实测容量或已达性能。

比较实现前固定作者数据、字体、viewport、density、脚本、修改节拍、计数及独立参考。逻辑数据、存活显示行、语义节点、待处理任务、驻留字节和设备资源分别计数。

布局/虚拟化使用小型确定性参考；已验收宿主文字/图像使用固定独立参考。覆盖默认/自定义适配器、修改/重入、首错误、取消及清理，不添加仅复刻实现循环的测试。

继续使用现有仓库入口：`pnpm run build`、`pnpm run test`、`pnpm run check:types`、`pnpm run check:boundaries`、`pnpm run check:quick`、`pnpm run check:merge`。新案例加入适用的既有测试集；本设计不虚构未来 CLI 或新增资格命令。

本地聚焦反馈不是合并资格。候选合并仍要求现有完整门禁与保护 CI。浏览器/IME/无障碍证据是额外的限定结果，不能替代这些门禁。

性能工作保留 architecture 既有预算和完整测量披露。在固定负载下记录 CPU 分段/完整窗口、cadence、原始样本及资源记账；字形缓存命中数或 helper 微基准不是 D60 验收。M1.2 与 M3 性能项在各自要求的实际证据通过前保持 OPEN。

向 M4 交付已验收能力矩阵、精确字体/provider/host 输入、夹具参考、已知限制、恢复结果和实际性能记录。M3 完成要求四个包所声明行为全部具备；不得静默删除缺失的必需 IME、脚本或无障碍项。

## 9. 方案取舍与非目标

将显式行/鼠标/纯布局规划 API 原地扩成完整 UI，会抹掉其限定兼容契约；另建 DOM 应用则会分裂应用状态、裁剪和混合渲染。建议在既有场景/资源体系之上增加分层可选 UI 所有者，在浏览器边界提供原生编辑及语义适配器。

本计划不增加另一套框架，不承诺任意 CSS，不在缺少来源的情况下重写整个浏览器文字引擎，不实现完整富文本编辑器，也不宣称完整 EUI/EXML 兼容。设计、源码检查或所引标准均不能单独证明原生验收。
