# 独立实现与第三方依赖规范

[English](../../en/docs/independent-implementation-and-dependency-policy.md) | 简体中文

版本：1.1 · 所属知识库：0.9.0 · 更新：2026年10月8日。

新白鹭从开发第一天按公开协作组织工程。源代码、设计、文档、知识库、测试和可公开的验证记录共同进入开源库，使贡献者能够理解设计、复现结果并参与改进。指定公开仓库为cnedwin/Egret_rebuild，沿用既有Apache-2.0配置；维护职责逐步明确；公开开发策略已经确认，发布状态以实际仓库与发行记录为准。

白鹭依据自己的需求、合同和验收条件设计核心，以成熟开源项目、公开标准和维护经验作为研究基础。通用库通过明确的第三方依赖接入。每个模块都说明设计依据、实现范围、依赖身份和验证状态，让技术贡献与第三方归属同样清楚。

本规范与成熟实现优先的研究原则共同执行。参见[研究与验证分工](开源实现优先与验证分工.md)、[参考采用方案](开源参考实现与采用方案.md)、[贡献指南](../CONTRIBUTING.md)和[项目鸣谢](../ACKNOWLEDGEMENTS.md)。

## 实现角色与归属

| 角色 | 工作方式 | 必须记录的归属 |
| --- | --- | --- |
| 白鹭自主核心 | 研究问题、机制、约束和反例，形成白鹭规格，再设计数据组织、接口和实现 | 自有规格、作者与变更、研究依据、实际实现范围和验证 |
| 显式第三方依赖 | 通过库的公开接口集成；保留包或目录身份，固定版本，管理升级与补丁 | 上游仓库、版本或commit、适用许可与声明、修改、集成责任 |
| 研究运行依赖 | 用成熟实现建立对照链、验证资产与接口交接 | 第三方执行模块、白鹭适配模块、实验条件和结果范围 |
| 机制研究 | 阅读源码、文档、测试和维护记录，产出机制摘要与设计依据 | 已读文件、固定版本、来源事实、白鹭设计推断及未覆盖范围 |
| 标准或工具生成 | 依据公开标准实现，或使用已登记工具生成代码和数据 | 标准版本、生成器版本、输入与配置、生成范围及适用声明 |
| 历史授权资料 | 在已有授权范围内核对命名、行为、格式与迁移需求 | 来源种类、授权范围、公开摘要与可分发样本；发布权单独核实 |

自主核心包括白鹭定义的场景与UI语义、帧调度与合成、资源生命周期、动画事件与采样组织、工程事务和旧工程迁移规则。GPU API实现、脚本VM、字体塑形或纹理转码等通用设施可以采用公共库；模块说明应清楚区分白鹭实现的层与依赖提供的层。

Three.js、Babylon.js、PlayCanvas、PixiJS等项目可同时承担不同角色，按实际模块分别登记。完整renderer或GUI作为依赖时，其内部能力保留第三方归属；白鹭的接口封装、适配或测试单独记录。研究状态、集成状态与生产选择分别维护。

## 从研究形成独立设计

1. **记录研究依据。** 绑定仓库、版本、文件和已读范围，归纳机制、不变量、错误路径与维护经验；来源事实与白鹭推断分开写。
2. **写出白鹭规格。** 明确问题、输入输出、生命周期、失败行为、预算、兼容要求与替代方案，说明设计取舍及预期改进。
3. **按规格实现。** 自主核心以规格、公开标准、显式依赖接口和自有或授权样本为输入，独立组织代码。竞品源码的复制、翻译或机械改写应按真实第三方来源处理，不能登记为自主核心。
4. **随变更维护来源。** 提交[实现来源记录](../templates/实现来源记录.md)，列出自主代码、依赖、研究对照、生成内容及实际接触的资料。
5. **复核来源与合同。** 评审接口、数据结构、依赖声明和需进一步确认的相似片段；留下复核依据与解决记录。来源声明和相似度检查提供审阅线索，其结论限于实际检查范围。
6. **验证设计改进。** 在可比较的功能、画质、资产和设备条件下检验正确性、成本和维护性，保留失败与未覆盖项。设计新颖程度本身不构成性能结论。

当前实现来源记录是有限范围的工程证据，并非全量原创性证明。一般源码研究与独立实现按实际过程描述；严格隔离的开发流程只有在确实执行并有记录时才作该项声明。

## 依赖、许可证与发行记录

依赖记录至少包含用途、上游URL、完整版本或commit、实际取得文件与hash、适用许可及版权声明、本地修改、接口边界、升级责任和已运行验证。第三方补丁保留原有归属，与白鹭适配代码分别维护。

源码、文档、字体、示例资产、shader、转码器和生成内容按各自适用许可登记。第一方源码与文档沿用指定仓库既有Apache-2.0许可，第三方已有许可与声明持续随文件保留。顶层项目许可证只覆盖其明确声明的内容。发行前整理实际分发清单、第三方声明和所需归属信息，权利复核状态随版本更新。

历史私有资料在公开库中保留必要的来源种类、研究范围和技术结论。私有原包、凭据、个人信息及未获公开授权的合作资料不进入贡献内容；涉及它们的公开摘要只保留完成技术复核所需的信息。

## AI参与与作者责任

AI可以辅助检索、解释机制、拟定规格、编写代码与审查。作者记录工具参与范围、实际提供的资料或提示摘要、生成范围和复核结果，并对提交内容、来源及样本使用权限负责。核心实现任务应明确规格与依赖边界，输出按同样的代码和来源流程评审。

发现来源尚待确认或明显相似的片段时，结合规格、输入资料、实现和上游版本复核，完成记录后再进入自主核心。AI参与声明只描述实际工作过程，不作模型训练资料或全部输出来源的保证。

## 已有实现与研究链

已有核心原型包含`@egret/contracts`、`@egret/runtime`、`@egret/engine`三个headless包。实现范围、工具来源和记录见[核心框架实现记录](核心框架实现记录.md)及[原型来源记录](../../evidence/core-framework-implementation.json)。现有44/44行为检查和11项负类型断言限于CPU与模拟host切片；GPU、Native、真实宿主和CI仍待验收。

Three r186研究链实际执行了第三方WebGLRenderer、GLTFLoader、AnimationMixer和SkeletonUtils，并使用Canvas原生文字。其vendor文件、适配代码、固定来源和许可声明分别保留，角色为研究对照。已有17项检查仍限于原实验条件；该链的渲染与动画执行能力归属于Three.js，不计作白鹭自主渲染内核。详见[第三方声明](../experiments/asset-reference-probe/THIRD_PARTY_NOTICES.md)和[第三轮集成记录](第三轮集成记录.md)。

后续自主模块可沿用研究得到的测试问题与白鹭规格，再与参考链对照。生产依赖选择另行记录模块角色、成本、支持矩阵及验证结果。历史研究证据按原版本保留，当前设计和实现以对应的来源记录为依据。

## 白鹭改进的验证方向

优先检验复杂UI与3D协作、稀疏更新、资源恢复、小包体、首交互、编译调试反馈、Agent持续修改和完整旧工程迁移。代码评审同时检查接口清晰度、错误处理、可诊断性和维护负担。

先完成当前环境能够证明的规格与正确性；帧时、内存、功耗、发热和目标宿主表现留给对应环境实测。优势结论附可复现条件、结果与限制，并随实现版本更新。
