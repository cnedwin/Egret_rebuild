# 产品需求说明书

[English](../../en/docs/product-requirements.md) | 简体中文

Egret 是面向复杂二维游戏与轻量三维体验的开源游戏引擎项目。产品方向将可靠的渲染与运行时核心、可编辑工程、资源工具、AI 辅助创作及完整旧工程迁移连接起来。可玩结果在持续修改中应保持可理解、可编辑、可恢复和可发布。

本文规定产品义务与验收场景。[当前核心预览](core-progress.md)提供可运行前提；完整创作工具、宿主覆盖、性能、市场验证和迁移仍待完成。

## 目标、人群与确认边界

主要服务对象是使用 AI 制作游戏的新创作者，也重视进入 AI 辅助制作流程的手游开发者。R001–R017 规定原有产品与工程范围：复杂二维 UI、轻量三维场景/角色/特效、骨骼与序列帧动画、渲染与运行时基础、开放工程接口、旧 Egret 迁移以及持续维护的社区知识库。

新创作者需要表达玩法、选择对象、理解改动、诊断失败并完成发布；有经验的开发者需要在同一工程中进行代码编辑、调试、资源复用与批量操作。验收应分别观察各类人群；专家代办不能证明新手独立完成。

R011 规定研究验证与审计，R012 规定审慎评估成熟技术机制，R015 规定核心独立实现及准确的依赖归属，R016 规定现代工程与熟悉的 Egret API。R017下的建设按可验证增量及明确缺口核查推进，每项增量始终保留完整产品义务。D 类方案须达到各自验收条件才能转为已接受决定。

规模、画质、最低设备、首批宿主顺序、人员、预算、日期、商业模式和数字性能门槛须单独决策。本文不规定浏览器、微信、抖音或其他宿主的首发顺序。

## 底层复用对产品的要求

渲染、文字、资源和动画机制按 Egret 接口、正确性、许可与维护需求评估。创作者通过统一工程流程工作，无需选择字形图集策略、管理 GPU 状态或协调库版本。依赖和适配层按[实现与依赖规范](独立实现与第三方依赖规范.md)保留真实归属；[研究与参考记录](开源参考实现与采用方案.md)说明技术比较及组件边界。

生产包需要明确的二维/三维能力配置，避免二维工程携带无关三维负载。初始化失败、加载取消、离开和重复启动应回到可恢复状态，图形恢复后须复验交互。

## 工程与创作者控制

工程包含可编辑场景/UI、稳定对象身份、资源原件与依赖、业务代码、玩法规则、目标配置和版本记录。试玩状态和发布构建属于工程产物，工程导出应保留源码与继续制作能力。

改名、移动和资源路径调整应保持引用与诊断位置。复制形成新身份并明确引用关系，删除展示受影响的玩法和资源。创作者按名称、画面和用途选择对象，内部身份持续稳定。

自然语言、可视化和代码编辑作用于同一工程，源码可检查和导出。AI 生成的改动绑定工程版本与明确范围；后续手动修改产生冲突，不能被覆盖。每项操作展示目标、局部差异、受影响对象与验收结果，试玩临时状态写回由创作者明确选择。

修改应保留无关玩法、事件、资源、存档与宿主能力。行为或画质降级必须在应用前说明影响，并由创作者明确选择。取消、重试、失败和撤销均保留可恢复版本。

工作台围绕工程、编辑、资源、试玩、任务记录和发布组织，反馈说明当前操作、已有成果、阻塞与可用下一步。

| 能力 | 必须具备的行为 | 失败与恢复 |
| --- | --- | --- |
| 首次创作 — R001、R006；V003、V005 | 可编辑角色/换装工程达到首次可玩，能够切换装扮并保持选择；测量耗时与人工帮助。 | 展示未解决意图、可用部分与重试路径。 |
| 混合表现 — R002–R005；V002、V004 | 三维角色、特效、复杂 UI、骨骼与序列帧在连续操作和恢复后保持遮挡、文本、输入、顺序及动画事件。 | 按对象和复现步骤定位缺失行为、点击错位与预算问题，说明画质取舍。 |
| 布局与点击一致 — R002、R004；V002、V005 | 文案增长、插入/删除、隐藏/恢复及面板重挂载同步更新相关祖先、兄弟和命中区域；可见输入选中正确业务对象，裁剪外对象不接收该输入。 | 拒绝或冲突保留原布局/命中状态并定位依赖；真实字体、IME 和虚拟列表复用单独验收。 |
| 连续局部修改 — R001、R006；V003、V005 | 布局、角色、手动价格逻辑及 AI 特效改动保持兼容；应用前展示局部预览/差异，应用后回放既有流程，撤销恢复可编辑版本。 | 明确歧义目标、过期结果、手动冲突及回归来源；保留手改并提供恢复或修复。 |
| 资源导入与换装 — R004、R007；V004 | 模型、贴图、字体、骨骼/序列帧与音频具有预览、依赖和使用位置。替换前准备好可显示素材，保持交互/选择，拒绝迟到过期结果，并保护共享素材。 | 定位素材、阶段与原因，保留原件及可用旧内容，提供补齐、替换或取消；内存限制须有明确恢复路径。 |
| 试玩诊断 — R003、R005、R006；V002、V003、V005 | 复现输入或动画失败并定位对象、规则和资源；性能建议依据真实测量。 | 说明复现条件差异、证据不足及最后可靠状态。 |
| 中断与恢复 — R003–R005、R007；V002、V004、V005 | 区分素材准备、显示资源恢复及可交互状态；保持玩法、选择与布局，已完成音效/奖励不重放，未完成操作可定位。 | 分别识别准备、上传或交互失败；外部服务、进程重启和未确认操作保留待核对状态，提供重试、退出或接管。 |
| 修复与撤销 — R006；V003、V005 | 在可见时间/费用限制内修复引用，复验原玩法，撤销恢复工程、资源与玩法后继续编辑。 | 取消、达到限制或语义不确定时停止，报告已改/未改及剩余问题；失败重试计入成本。 |
| 发布与更新 — R007；V004、V005 | 检查声明支持的目标，在真实设备构建和试玩；发布更新后验证启动、前后台、资源更新和存档保持。 | 打包前说明不支持项，定位构建/服务/渠道失败并保留上一可用版本；生成构建、渠道批准与成功发行分别记录。 |

## 旧项目旅程与正式交付

R008/V006 在公布的版本、特性和宿主矩阵内追求最少人工干预及迁移后等价执行。旧 Egret3D、自定义分支和第三方 SDK 需要明确覆盖，矩阵外、部分通过和未验证结果分别显示。

| 阶段 | 验收与交付证据 |
| --- | --- |
| 导入与盘点 | 保留只读原工程，识别引擎版本、UI、资源、动画、业务代码、扩展及宿主依赖；取得可运行旧基线与范围报告。未知版本、缺少依赖和不可运行工程保持阻塞状态。 |
| 转换与修复 | 创建独立新工程，提供对象对应、差异、转换进度及有限 AI 修复记录；不支持语义或次数/时间/费用耗尽时允许接管、回滚和重跑，保留原有行为。 |
| 旧新对照 | 同输入比较玩法、事件顺序/次数、计时/暂停/恢复、动画事件、布局命中、资源切换/释放、存档、宿主和性能；加入图形中断、素材失败与迟到完成。重复奖励/音效、漏事件和计时跳变均不通过，外部服务替身不能代替真实宿主检查。 |
| 继续编辑与发布 | 修改角色/UI/业务代码，试玩、撤销、目标构建并更新；交付源码、资源、构建、日志、差异、未解决项及报告，保持原工程可恢复，并将通过样本纳入升级回归。 |

## 非功能验收与测量口径

V001 先建立有授权、同功能同画质、固定宿主/设备/网络的样本基线，再确定数值门槛。以下产品级指标尚无已接受基线；须报告分布、失败任务和样本范围，创作任务耗时与玩家首次交互分别统计。

| 指标 | 测量合同 |
| --- | --- |
| firstInteractive | 冷请求到约定输入得到有效响应，区分加载/初始化/等待并固定缓存/网络，覆盖热启动与恢复。 |
| tailFrame | 在明确窗口、场景和输入下记录持续帧时间尾部、卡顿及输入响应。 |
| memory | 在明确设备下记录峰值、稳定态及反复进出/替换的增长，包括失败/恢复残留。 |
| AI 总成本 | 完整任务的模型调用/费用、缓存、失败修复/重试、工具时间与等待，以及每个成功任务的成本。 |
| manualIntervention | 接管次数/原因/角色、有效工作和等待；账号/测试配置另记并披露专家代修。 |
| 体验与可靠性 | 首次可玩、需求满足、无关行为保持、撤销、发布/更新成功、包体/加载及持续功耗/发热。 |
| 恢复与语义保持 | 分别记录素材就绪、当前显示上传就绪及可交互时点，保留状态、事件次数和未完成操作；画面出现本身不证明完整恢复。 |

迁移漏斗覆盖每个范围内工程的导入、转换、构建、运行、完整对照和继续编辑，报告拒绝率及原因。零人工成功要求完整通过验收，且无人修改代码、配置或资源，也无专家代修。

## 首轮标杆与待验证问题

候选主标杆包含三维角色/换装、多层 UI、滚动列表、文字、骨骼与序列帧特效，检验对象选择、资源替换、事件、连续编辑和预算。小型三维动作场景补充移动、输入、角色动画与特效，其规则和规模尚未确定。迁移使用有授权、可运行的旧工程，不能由新示例代替。

研究须明确：人群/玩法需求与独立完成任务能力；目标宿主、设备及真实服务要求；固定 UI、资源、画质与三维范围；可理解的稳定对象选择；保持、冲突与撤销行为；清晰恢复和可见专家劳动；开发者代码/资源流程；有代表性的旧版本、扩展、SDK 和等价语义；完整任务成本与设备表现；可复现的社区参与及资源权利。

R009 要求可复现问题提交及接收、补证据或结论反馈；R010 以等价任务、成本和记录条件开展技术比较。需求变化持续写入[登记册](../registry/需求.json)。

## 编译调试与原生扩展

R013 覆盖短编辑反馈周期、独立预览/类型/发布状态、映射回源码/场景/Agent 事务的诊断，以及避免无关重建。历史 30 秒以内数据不构成新数字门槛。R014 保留原生 App/SDK 与跨平台扩展空间，Steam/PC 和 GPU AI 仍非首发承诺。浏览器二维无需原生 VM，原生二维需要选定或已验收宿主 VM；具体选择由[后端与运行时设计](图形后端编译与原生Runtime选型.md)规定。

## 社区开源与实现归属

公开项目、知识库及可维护工程记录支持可复现社区协作。自主核心、依赖、研究参考与适配层分别说明真实来源。工程来源记录披露 AI 辅助，并遵守同样的评审和许可标准。cnedwin/Egret_rebuild 的第一方代码与文档使用 Apache-2.0，公开资源须有相应权利。这些实践服务 R015 及完整迁移、编辑和发布义务。
