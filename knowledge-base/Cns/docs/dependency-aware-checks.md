# 依赖感知的本地检查

[English](../../en/docs/dependency-aware-checks.md) | 中文

修改现有包时，可以先获取与改动相关的本地反馈。推送钩子检查干净已提交快照与公开结构，受保护的合并 CI 继续执行完整门禁，不缓存或复用旧 PASS；本地成功不构成合并授权，也不代表浏览器或设备验收。

## 运行与解释

~~~text
node tools/check-incremental.mjs --base origin/main --explain
node tools/check-incremental.mjs --base origin/main
~~~

先获取目标分支；fork 贡献者可以使用 upstream/main。基线必须是 HEAD 的祖先。已提交、暂存和工作区改动分别参与选择，方向相反的修改不会相互抵消；未跟踪文件也参与。解释结果列出配置、原因、变更包、受影响包和选中/共享/省略的测试文件。缺失或无关基线直接失败，不猜测；工作区无改动时执行全部行为测试，不假定此前已通过。

| 改动 | 本地反馈 |
| --- | --- |
| 仅修改现有阅读版 Markdown | 环境、文本规范、发布/双语派生及知识库只读检查 |
| 四个包 src 或 engine 的 web/rendering 下现有 TypeScript 源码 | 将影响传播到依赖该包的包，再选择已评审归属的测试及全部共享测试 |
| contracts 或影响全部测试的改动 | 全部行为测试 |
| 新增/删除/重命名、测试及辅助模块、元数据/策略、工具/CI、包/锁定/配置、未知路径 | 全部行为测试 |
| 清单过期、包归属变化、不支持的依赖图、测试成员缺失、隐藏/稀疏 Git 索引标记 | 全部行为测试并说明原因 |

开发配置执行环境及文本规范、完整构建、通用包依赖边界、选中或全部顶层行为测试以及无头示例，不重复专用源码/类型与公开工具测试。这些检查继续保留在完整合并门禁中；渲染修改仍需相应真实浏览器证据。

## 包与测试归属

声明的依赖关系为 contracts → runtime → engine，engine 和 project 还直接使用 contracts。影响向使用方传播，而不是向前置依赖传播：runtime 修改影响 runtime 和 engine，project 修改不表示 engine 源码受影响。开发构建与通用边界检查覆盖包连接，严格消费者类型用例继续保留在完整合并门禁中。

经评审的 tools/incremental-test-catalog.json 绑定精确包清单、完整门禁调度、全部 190 个顶层行为测试及辅助模块的原始字节。其中 110 个测试为共享范围。涉及源码检查、子进程、特权钩子或依赖范围不明确的测试始终保留。明确包归属依据已评审的导入及辅助模块依赖，不依据测试文件名，也不声称自动证明覆盖完整性。原测试代码和断言没有变化。

当前清单中，单独修改 project 选择 114 个文件、省略 76 个；engine 选择 184 个、省略六个；runtime 选择 187 个、省略三个。这些是调度数量，不是速度或覆盖率测量。共享源码检查可能占据主要耗时，因此小改动仍可能需要数分钟；不承诺通用加速倍数。

既有 SpriteSheet 边界冻结了全部四个包的源码及编译产物身份。即使只修改源码注释，最终 PASS 也可能需要另行评审新的源码基线。依赖反馈先执行完整构建和通用依赖边界，再运行选中的行为测试；专用源码及类型检查保留在完整合并门禁中。这样可以更早获得诊断，但不授权新的源码身份，也不保证普通源码修改自动通过；共享的源码绑定行为测试同样可能拒绝变化的身份。

端到端正向对照采用隔离历史：祖先提交包含有意设置的错误，当前快照则精确恢复已获认可的源码。这验证健康快照的执行流程，以及根据真实已提交源码差异进行选择，不代表未经评审的新源码修改获准通过。另设当前源码的行为回归和禁止依赖反例，必须实际失败，并保留精确诊断及恢复记录。先前仅添加注释的尝试在不可变源码准入处失败，作为限制保留，不计作正向通过。

## 清单维护

贡献者新增或修改测试时，不必同步编辑共享清单：过期或新增输入直接执行全部顶层行为测试。维护者在独立评审包归属、辅助模块导入、精确成员和原始字节后，可以恢复较小反馈范围。仅更新已评审的当前测试/辅助模块及包身份，不修改历史证据；检查选择结果并重跑代表性正向和反例。清单自身的修改在集成前也执行全部行为测试。

运行器在依赖检查前后绑定 HEAD、索引条目、已跟踪文件原始身份及未跟踪成员。持续存在的输入变化会拒绝最终本地 PASS。这是单次运行的一致性检查，不是可复用凭据、恶意进程隔离保证，也不是执行较早的暂存文件：检查针对当前工作区，已提交推送门禁另行验证真正提交的快照。

## 验收与限制

回归反例覆盖反向依赖、共享测试、原始清单漂移、成员缺失、未知/配置/新增文件、各 Git 层和隐藏索引标记。交付还需包含真实选中检查的正向运行，以及分别观察到的行为回归和禁止依赖失败，随后恢复现场。记录精确命令、环境、范围和失败；最终交付证据归入 PR。

真实已提交推送钩子和受保护的 M0 / merge-ready 始终保留；合并候选执行完整集成检查，本地开发反馈不必在每次编辑后重复该流程。选择器不修改 CI 权限和分支保护。独立 AI 评审不是人工批准；独立新人/外部 fork 验证（#52）、目标设备/宿主、完整 Spine 及场景/性能预算（#54）仍未完成，本轮工具改造不代表全部 M0 完成。

维护者可以通过[检查维护流程](check-maintenance.md)生成基线原始差异和保守的清单候选。提案始终待评审，不替代当前源码准入或完整门禁。
