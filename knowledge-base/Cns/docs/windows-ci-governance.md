# Windows CI 失败治理

[English](../../en/docs/windows-ci-governance.md)

Windows 作业失败后，在重试或准入前形成一份证据记录及预防决定。目标是缩短重复排查，同时保留有效的源码、行为与保护合并检查。可复用的[白鹭 Windows CI Skill](https://github.com/cnedwin/Egret_rebuild/tree/main/skills/egret-windows-ci)包含离线记录摘要工具。

## 失败记录与责任

记录 PR／head／base、工作流／运行／尝试次数／作业、实际观察到的检出提交、首个停止步骤及未改写的原始记录。比较实际源码、产物、夹具或环境证据后再填写根因与所有者。记录有界修复、聚焦结果、复用的成功证据、剩余候选检查及预防决定。分类工具输出是记录起点，不是已确认根因或合并批准。

变更作者负责实现与复现，相关模块维护者评审契约；维护者负责当前共享源码记录准入及最终元数据。基础设施问题保留准确的外部边界。独立评审覆盖源码、结果及公开双语版本；增量合并不关闭未执行的设备、IME 或性能验收。

## 可复用根因类别

| 根因类别 | 证据与经验 | 预防措施 |
| --- | --- | --- |
| 当前源码所有者记录过期 | 新模块或指针代码变化可能在任何操作系统触发 `SS1_BOUNDARY_SOURCE_OWNER`，仅此签名不能证明 Windows 换行问题。 | 比较准确的自有原始身份；正确代码稳定后，为完整工作包建立一次有界、经评审的当前接续，保留原源码／图／诊断记录。 |
| 夹具依赖过期 | 复制的冒烟夹具可能漏掉新增依赖，或错误归属文件。 | 复制真实准入闭包，在昂贵检查前执行受影响的健康／拒绝控制；不能放宽预期拒绝来掩盖无效前置条件。 |
| 路径与作者字节不符 | 仓库逻辑名称和 Windows 物理路径采用不同的比较规则。 | 使用共享身份工具与规范作者入口，保留原始哈希。参见[仓库身份规范](repository-identity-and-line-endings.md)。 |
| 误读预期负向输出 | 编译器和变异控制会先输出指定失败，再恢复健康控制。 | 读取实际停止的命令／聚合结果及附近诊断，不能看到第一个 error 就宣布根因。 |
| 执行机／服务中断 | 排队、取消或日志尚未发布时，产品可能尚未执行。 | 保留未完成状态；确认服务故障后才有限重试失败作业，原成功作业继续绑定原候选。 |

当前源码记录的案例见 [PR #127](https://github.com/cnedwin/Egret_rebuild/pull/127)；夹具前置条件及提前共享检查的修复见 [PR #125](https://github.com/cnedwin/Egret_rebuild/pull/125)。这些链接支撑所述有界案例，不表示普遍的 Windows 性能或可靠性结论。

## 收口与后续更新

开发阶段使用聚焦检查，发布阶段使用必需候选检查，里程碑／浏览器／设备验收单独处理。复用输入未变的证据，明确标出变化的 head／base／tree。不能通过归一化源码字节满足指纹，也不能把历史记录替换为当前字节；应先完成行为评审，再准入源码身份。

每次失败增加必要的聚焦回归、改善所有者／准入信息，或说明既有机制为何足以防止复发。仅在新经验会改变后续决定时更新本根因类别和 Skill。保留完整工作包，不为每次失败运行新开任务、采集器或继承链；正常钩子、独立评审和保护分支检查继续作为交付路径。

原日志和执行记录保存在公开源码之外，只发布经评审的诊断、修复及相关证据链接。离线摘要工具不会执行测试、访问服务、改变凭据、更新源码钉子，也不会授权重试或合并。
