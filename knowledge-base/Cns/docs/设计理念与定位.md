# 设计理念与定位

[English](../../en/docs/design-philosophy-and-positioning.md) | 简体中文

白鹭希望让游戏从初次可玩到持续修改、发布和更新始终可理解、可维护。自然语言、可视化工具与代码操作同一工程。新创作者需要清晰的可运行路径，有经验的手游开发者也需要熟悉的API、资源实践与诊断；两类学习路径分别评价。

过去的AS3风格对象、显示列表和事件帮助Flash团队进入H5。这段历史说明熟悉领域模型的价值，不预先决定今天的实现、平台或性能。

## 已确认的方向

R001定义人群，R002/R004覆盖复杂二维UI与轻量三维，R003将渲染和Runtime作为基础，R008要求完整旧工程迁移，R009建立公开知识与社区参与。[需求登记](../registry/需求.json)保存正式范围。

轻量三维需要明确玩法、内容、画质、宿主、设备和资源预算，名称本身不固定模型数量、材质规格或物理范围。广泛PC兼容和大型原生三维的优先级分别决策。

## 候选产品定位

产品方向结合游戏引擎与创作工具，让成果始终可编辑、可验证。复杂UI和轻量三维共享工程身份、资源及交付流程，各自采用适合的执行策略。

三项潜在收益需要证据：混合渲染的持续效率、AI对现有作品修改的可靠性、旧白鹭资产迁移的低干预能力。市场价值、创作者完成率和比较性能仍为[假设](../registry/假设.json)，不能由小包交付直接推导。

## 设计原则

- **创作者控制：** 自然语言、可视化和代码修改均可定位、预览、撤销，成果能够长期维护。
- **玩家体验：** 在等价内容和画质下共同评价首交互、持续帧时、延迟、内存及功耗。
- **能力聚焦：** 共享基础，按负载组织执行，裁剪可选模块、后端、诊断和兼容层。
- **接口持久：** 工程格式、资源、协议和API分别管理版本，提供迁移规则与回归证据。
- **证据驱动工程：** 解释取舍和参考机制，保留归属，核对适用版本及维护成本。
- **交付连续：** 连接资源、构建、宿主适配、测试与更新，平台能力由实际宿主验收确认。
- **开放建设：** 公开文档、理由、来源、失败与未解决边界供社区审阅，并遵守资产权利。

## 本阶段的判断标准

以同一创作任务比较首次可玩、连续修改后的保持、人工接管、修改成本和实际设备发布，结合新手学习观察有经验开发者的API、资源与调试需要。[验证方法](核心优势与验证.md)和[技术架构](技术架构.md)将这些结果连接到工程选择。
