## 发现与处置

| 问题 | 为什么原证据不足 | 修正与复验 |
| --- | --- | --- |
| 完成栅栏缺失设备代次 | 默认当前epoch可能把旧回调当成新设备的完成通知 | 捕获注册时epoch且必须显式传入，缺失拒绝且无状态变更；[24过1失败](../../evidence/async-resource-probe-audit-red-results.json)→[25过](../../evidence/async-resource-probe-results.json) |
| 稀疏glyph数组 | Array.some跳过空位，使NaN进入布局 | 检查每个own index；[UI审计失败](../../evidence/nested-ui-probe-audit-red-results.json)→[18过](../../evidence/nested-ui-probe-results.json) |
| 有限输入累加溢出 | 单值有限不能保证依赖计算与累加有限 | 加明确研究输入预算，超预算原子拒绝；与稀疏数组一并先16过2失败再18过，不承诺任意有限输入 |
| 稀疏color数组 | Array.every同样跳过空位，错误输入绕过批次校验 | 四个own index逐项检查；[7过1失败](../../evidence/batch-state-probe-audit-red-results.json)→[8过](../../evidence/batch-state-probe-results.json) |
| GPU参考共用分批器 | 被测builder和参考共享漏分界错误，7过也不足以证明独立正确性 | 参考改为原命令逐pixel合成；[共用参考版](../../evidence/mixed-scene-probe-shared-builder-results.json)保留，[独立参考新版](../../evidence/mixed-scene-probe-results.json)重新实际运行7过 |
| 空画面恢复可过 | 空renderer前后相同也满足弱恢复比较 | 作者加非空守卫；[1过6失败](../../evidence/mixed-scene-probe-empty-results.json)→[0过7失败](../../evidence/mixed-scene-probe-strict-empty-results.json)，实现后才通过 |

独立审阅者在内存内复演四CPU程序64项，检查结果名/状态和当时源码摘要一致；对事件、资源、UI及批次各失败链也复演出原先的通过/失败数量。另对UI尝试1,000步编辑，852次接受、148次拒绝，143次全量参考比较和2,860次命中对照一致。这是补充审阅覆盖，没有计入主程序18项，也不是产品性能测试。

独立审阅者核查最新浏览器报告7项与6份源码摘要、历史空renderer与严格守卫版本映射，并只读审阅截图和图形代码，没有将报告核查写成新增浏览器复跑。将新CPU参考单独执行时，与正确批次消费者0通道超容差；故意旧纹理分批器130,304/196,608通道超容差。这验证参考能揭示旧分批错误，不表示真实GPU性能收益。

作者随后只修改当前事件runner的本地位置输出并保存旧版，实际重新运行13项；其余三CPU当前版也重新运行，合计64项通过。图形参考改动后的实际7项报告及共享批次源码未再变动。最终证据摘要与全库文件核对由集成检查单独进行，不能把审阅时旧runner的摘要冒充修改后的摘要。

## 保留的限制

事件只验证单实例同步effects与水位；同一Node进程内创建第二个内存实例确实可重复副作用，没有执行操作系统进程重启或崩溃。资源回调手动调度，驱动释放与真实fence未测。UI使用glyph宽度夹具，文本塑形与输入法未测；全树复制/校验/坐标遍历仍在。GPU只覆盖程序生成的固定网格、刚性骨节、图集与英文纹理，不证明完整角色/骨骼、任意遮罩或文字质量。

没有实际IPC/C++/WASM、WebGPU场景恢复、真实小游戏或原生宿主、手机、持续负载、GPU时间、功耗、冷加载和迁移对照。71项包含负对照与边界检查，数量不能充当完整性或质量评分。独立AI审阅仍可能遗漏问题，正式产品验收另行建立样本与条件。
