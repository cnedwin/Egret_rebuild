# AI 创作与工程接口

[English](../../en/docs/ai-creation-and-engineering-interfaces.md) | 简体中文

AI创作的价值在于理解现有游戏、完成有界修改，并在不破坏无关工作的前提下验证结果。白鹭因此让工程操作、构建任务和运行诊断共用可视化及代码工具的语义。R006包括Agent、Skills与MCP接入，可靠的端到端创作仍是待实现和验收的目标。

## 共同工程语义

稳定对象和资源ID在重命名、移动及场景重排后保持身份。工程schema、资源格式、引擎版本和目标宿主配置分别锁定。全部编辑客户端共用引用校验、命令、构建和诊断，使同一修改不因入口不同而改变含义。

可编辑工程拥有持久创作数据，运行实例拥有临时玩法状态，GPU及原生投影可重建。试玩变更只有显式应用后才进入工程。生成的业务代码遵循普通编译、运行及玩法验证；结构化编辑提供约束，本身不能证明行为正确。

## 修改闭环

一次修改先确定目标对象、引用、版本、能力、预算和完成条件，再生成有限差异，说明资源与交互影响，并在版本前提下应用。冲突要求重新读取，修改前快照保留用于恢复。

导入和构建任务返回指向原对象、资产、代码与阶段的诊断。试玩回放关键输入，检查预期行为、原有玩法、视觉及适用性能预算。修复受轮数与成本限制，结果包含剩余问题及可执行的撤销或重试入口。

任务响应携带task ID、输入/输出工程版本、状态、差异、诊断、产物和实际验收结果。长任务支持查询、取消、超时与恢复，重试声明幂等性；迟到结果不能覆盖较新工程。结构化定位反馈与解释配合使用。

## 候选能力分组

| 能力 | 典型用途 | 验证重点 |
| --- | --- | --- |
| 工程查询与定位 | 找到某个角色、按钮、玩法规则及资源引用 | 多次重命名、移动后仍定位正确 |
| 结构与代码修改 | 改 UI 布局、角色属性、事件和业务逻辑 | 局部范围、类型/引用、玩法保持 |
| 资源导入与构建 | 导入骨骼、模型、音频，生成目标资源 | 源资产保留、授权、异步完成与错误 |
| 试玩与诊断 | 输入回放、对象状态、截图、帧时间分析 | 可重复结果、对象来源、测量口径 |
| 版本与恢复 | 撤销、比较、继续修复、更新旧工程 | 冲突、取消、失败恢复与数据一致 |

Skills提供任务知识和操作流程，MCP提供工具发现与调用，工程服务负责编辑语义和正确性。不同模型和客户端可使用相同边界；模型、费用与托管选择尚未确定。协议参考为[MCP工具规范](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)。

## 验收方式

在同一作品上执行连续修改，检查需求满足、无关行为保持、撤销成功及失败后人工接管，并记录等待、修复轮数和费用。新创作者与有手游经验者分别测试。优化建议需要行为、视觉和实测复验。

H005及V003见[假设](../registry/假设.json)与[交付](../registry/交付.json)。[旧工程迁移](旧工程迁移.md)将转换后的工程带入同样可编辑、可验证的闭环。当前核心进展提供前提，不代表这些接口已经完成。
