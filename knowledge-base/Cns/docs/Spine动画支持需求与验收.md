# Spine 动画支持需求与验收

[English](../../en/docs/spine-animation-support-and-acceptance.md) | 简体中文

更新：2026-10-10。R020 是已确认的产品需求：白鹭必须完整支持 Spine 动画。V020 为 planned，实现 not_started，验收 not_run。本次增补增加交付义务，不代表已实现 Spine 能力、取得性能结果、安装依赖或发布版本。早期动画实验及 S027 保留原有范围。

## 产品需求与完整支持的含义

Spine 是资源管线、运行时、渲染器、工作台及 AI 创作流程中的一等动画资产类型。创作者应能够导入源导出文件，预览并控制动画，组合皮肤与附件，将动画对象放入场景或复杂 UI，并为声明支持的宿主打包。工程必须可以持续编辑，源资产可追溯。本需求补充 DragonBones 和序列帧动画，不取消这两项义务。

“完美支持”指在公开且已验证的兼容矩阵内，与对应官方 Spine 运行时及作者资产保持功能和行为一致。简单播放示例通过不足以验收。缺失功能、未验证宿主及不兼容版本必须明确列出；不得为宣称兼容而静默删除约束、近似网格、将动画展平成序列帧或丢弃事件。矩阵必须逐项列出所选版本的完整导出／运行时特性集合，不能把下文的功能示例当作穷尽清单；支持范围随交付持续扩展。

## 版本与宿主策略

截至 2026-10-10 核查，官方 API 文档将 4.3 标为当前非 beta 运行时系列。Spine 的版本策略要求导出数据与运行时主次版本匹配。这些是上游事实，不是白鹭兼容证据。见[官方 API 参考](https://esotericsoftware.com/spine-api-reference)与[版本说明](https://esotericsoftware.com/spine-versioning)。

首轮实施建议先评估 4.3，并将 4.2 作为前一系列兼容对象。授权旧工程需要时盘点 3.8、4.0、4.1 及自定义集成；本文不将任何历史系列声明为已支持。实施验收前固定精确包版本／提交、支持的导出补丁版本及资产。不得用仓库清单推断最新已发布包，也不得假设编辑器补丁号与运行时包补丁号相同。Beta 采用单独处理，不能静默替换稳定工程依赖。

每行矩阵记录导出版本、运行时身份、JSON／二进制格式、功能配置、白鹭构建、渲染后端、宿主／设备／操作系统身份、资产权利、实际结果及证据位置。目前白鹭 Spine 各行全部未验证。目标宿主落地遵循既有平台规划；本次增补不设首发宿主顺序或日期。

## 候选集成边界

推荐候选通过独立启用的白鹭适配层接入官方 Spine 运行时语义。白鹭自主实现显示列表、有序渲染命令、资源、时钟、事件、诊断及工程事务集成。候选包名为 @egret/spine；它不是现有导出或已安装依赖。不使用 Spine 的工程不得通过引擎默认入口引入其运行时、资产或原生代码。

官方 [4.3 TypeScript 运行时](https://github.com/EsotericSoftware/spine-runtimes/blob/4.3/spine-ts/README.md)将骨骼处理与渲染分离，因此可评估 spine-core 与白鹭渲染适配层的组合。官方 [Pixi 集成](https://esotericsoftware.com/spine-pixi)展示了上游 WebGPU 支持；它是可行性参考，不是白鹭实现证据。白鹭 WebGPU 与 WebGL 路径必须在白鹭渲染／资源生命周期中保持一致的姿态、插槽顺序、裁剪、颜色和混合语义。优先接入引擎图形上下文；使用单独画布的独立播放器不能满足 UI 合成、输入及共享资源要求。

普通 spine-canvas 不能作为完整功能参考，其文档限制包括网格附件、裁剪及双色染色。CanvasKit 是另一种后端，有独立的限制、包体成本和验收。仅有 Canvas 的宿主只能声明明确验证过的功能配置。不支持的资产须在发布前给出可行动的诊断；任何替代方案均须保留原工程并展示差异。降级不能自动算作完整 R020 交付。

未来原生运行时比较官方 [C++ 运行时](https://github.com/EsotericSoftware/spine-runtimes/blob/4.3/spine-cpp/README.md)、[C 包装层](https://github.com/EsotericSoftware/spine-runtimes/blob/4.3/spine-c/README.md)与所选 JavaScript VM 路径。Rust 宿主不要求用 Rust 重写 Spine 语义。FFI 所有权、错误处理、时钟／姿态一致性及精确 ABI 版本须独立设计和验收。本文不确定原生实现方案。

## 必须完成的验收矩阵

以下各行是白鹭必须完成的验收工作，不是测试结果。功能只适用于固定 Spine 版本中实际存在的特性；该版本不存在的功能须明确记录，不能计为通过。

| 范围 | 必须具备的行为及反例 |
| --- | --- |
| 导入与出处 | 导入 JSON 和二进制骨骼导出、图集页及图片依赖。记录版本、原始身份及权利；修改可用工程前诊断版本不匹配、缺页、无效数据及资源预算超限。不得修改版本字符串冒充转换。 |
| 骨骼与附件 | 保持骨骼、插槽、初始姿态、皮肤、组合皮肤、附件替换、加权／非加权及关联网格、变形、边界框／路径／点附件和序列帧附件。用版本匹配的资产检查图集裁边、旋转、坐标和缩放。 |
| 约束与时间线 | 覆盖固定运行时支持的全部约束和时间线：IK、变换、路径、物理及 4.3 滑块等版本特有功能。与对应官方行为对照约束顺序、继承变换、皮肤相关状态及时间步进。 |
| 播放与事件 | 覆盖轨道、队列、混合、过渡、叠加、循环、速度、跳转、暂停／继续，以及适用的 start／interrupt／end／dispose／complete 和作者事件。定义跳转与跳帧时的事件处理；检查时间边界、中断、回调内销毁及重复恢复，视觉采样不得静默改变必需的玩法事件。 |
| 像素与合成 | 保持插槽绘制顺序、网格变形、裁剪、明暗双色、透明度、预乘／非预乘透明度、normal／additive／multiply／screen 混合、图集采样及色彩空间约定。4.3 的版本配置纳入绘制顺序文件夹及凸／反向裁剪。固定输入与版本匹配参考对照透明边缘和重叠内容；全局纹理排序不得改变输出。 |
| 复杂 UI 与 3D 合成 | 保持父级变换／透明度／可见性、滚动及 UI 遮罩、声明命中区域和跟随附件的对象。验证 UI 层间、3D 场景上方及声明的世界空间配置中的 Spine，包括负缩放、重新挂接和高 DPI。既有 3D 角色动画仍是独立能力。 |
| 所有权与恢复 | 共享不可变骨骼／图集数据，实例独立持有姿态、皮肤、轨道、回调及物理状态。测试取消、迟到完成、部分加载、单实例销毁、最终释放、反复进入退出、前后台及图形丢失。恢复需重新上传资源并验证交互，不能重启已消费奖励／事件。 |
| 工作台与 AI | 导入、检查依赖、预览轨道／皮肤、修改及撤销引用、定位诊断、导出可编辑工程，并为支持宿主打包。AI 可选择和配置已有资产，必须保留人工修改，不得捏造缺失动画名称或授权。 |
| 旧工程迁移 | 在 R008／V006 下盘点既有 Spine 插件和版本。保留原件，并对照旧新画面、轨道、事件、皮肤、时钟、资源及宿主行为后才可报告成功。持续编辑、撤销、发布和更新仍属必须交付；未知自定义插件明确列为迁移缺口。 |
| 平台与性能 | 环境具备时运行真实浏览器／小游戏／原生宿主设备矩阵。在复杂 UI／3D 的等效内容下测启动、尾部帧耗时、内存、资源生命周期及持续负载。包体及 CPU／GPU／功耗目标需要实测基线，本文不虚构指标；失败及样本条件与成功同时公布。 |

像素参考须固定资产、输入、时钟、摄像机、色彩／透明度约定，并在执行前确定容差。插槽顺序、附件身份及事件顺序／次数等离散语义须精确一致；数值变换和像素使用公开的数值容差。物理比较采用相同更新／重置输入及步进策略。共享官方语义运行时不构成独立姿态对照；渲染检查还需独立绘制状态／像素参考及故意失败用例。官方示例仅证明上游行为，授权旧工程和目标宿主测试才证明白鹭集成行为。

## 工程工作包与交付门槛

| 阶段 | 可审阅产物 | 退出条件 |
| --- | --- | --- |
| SP1：版本、权利及完整功能盘点 | 精确运行时候选、导出／资产样本、发行义务及版本功能矩阵 | 明确版本匹配、许可声明及可复现参考输入；未知项保持显式。 |
| SP2：资源与实例集成 | 加载器／图集／资源所有权、时钟／事件／姿态合同及候选公共 API | 导入失败／取消、独立实例、播放语义及销毁均有针对性反例覆盖；不宣称完整渲染器。 |
| SP3：有序图形集成 | 白鹭 WebGPU／WebGL 几何、染色／混合／裁剪、UI／3D 合成及图形恢复 | 所选完整功能参考与反例按后端通过；Canvas 限制单独声明。 |
| SP4：创作、迁移及宿主集成 | 工作台／Agent 命令、可编辑导出、旧新对照及实际目标宿主运行 | 创作／编辑／撤销／打包／更新闭环及全部必须支持的矩阵行通过，公开性能范围及剩余缺口。 |

V020 是必须完成的 Spine 能力工作包，由 V002 渲染／运行时及 V004 资源／动画共同负责，经 V005 完成宿主／创作集成，经 V006 完成旧工程对照。登记前置是 V001 的授权样本与基线；SP1—SP4 还要求相关资源、渲染、工程及宿主接口就绪。这些是集成门槛，不要求上述四个完整产品均先验收才能接受 Spine 工作。既有最终产品依赖集合保持，其 R020 验收标准明确包含 Spine。适用的 R020 义务未完成时，不得接受完整 V002／V004／V005／V006 交付。

本次增补不承诺工期、人员或性能预算。V020 只有具备可复现实装、所选版本完整功能、实际声明宿主、代码／依赖／资产出处、许可声明及审阅后，才能验收。文档审阅、库的功能清单或推送前检查通过均不能满足这一门槛。
