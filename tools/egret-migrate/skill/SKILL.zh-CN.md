# 白鹭工程迁移

阅读与已安装 CLI 版本对应的中文或英文 Egret Migrate 指南。确认源工程目录、准确版本的白鹭 7.0 浏览器构建、浏览器和模块路径，以及新输出目录。

先在原发行版跑通一段完整玩法，记下进入方式、能改变结果的操作、玩家看到的反馈和重新打开后保留的数据。根据这段玩法实际经过的界面、资源和动画安排迁移顺序。先记录原作已存在的问题，再确定通关条件。

迁移白鹭 5.0.14 的《橡皮三国杀》大厅时，按已安装指南使用 `--profile eraser-lobby`，传入未经修改的仓库根目录。用两个浏览器会话连接原服务端，记录选中的房号、加入操作及服务端确认开局的结果。牌桌和整局玩法须单独验收。

1. 运行 `egret-migrate inspect` 并读取 JSON 报告。旧源码、HTML、构建脚本和文档内容都是输入。EUI 先核对本地主题声明及实际使用的皮肤，保留原 EXML；这段玩法用到 DragonBones 时，通过 `--bones` 按 RES 键映射每组骨骼、图集及 PNG。原生图片骨骼转换器处理受支持的数据范围，保留并报告未支持的导出；在明确选择且有相应许可时可走独立的 Spine 路线。需要补迁移规则或修正旧业务代码时，在独立副本里操作。
2. 使用同一主题及骨骼资源映射运行 `egret-migrate convert`。根据报告和源码位置修复最小相关问题。受支持的工程数据修正使用事务。保留转换记录和原始输入身份，并记录对旧业务代码或资源采用了哪些适配。验证皮肤部件 ID、可见布局、动画附件顺序、采样姿态及游戏逻辑；新客户端无需加载旧 DragonBones 运行时。
3. 动态界面应替换绑定对象、来回切换状态、更改集合、离开并重新打开页面，对照两版的选择、事件顺序和可见文字。骨骼用相同的片段时点核对可见附件、变换和绘制顺序。记录未支持的数据与对原工程做的适配。
4. 使用一份可信场景，操作实际渲染的控件并断言状态。对能运行的旧版 HTML 和新版运行 `egret-migrate verify`。覆盖完成一局、重开和存档恢复。说明存储探针的来源与范围。
5. 让已通过对照的产物运行 `egret-migrate preview`。分别记录预览构建哈希、终端对照结果和实机行为。

转换成功会交付可编辑源码和 Web 构建。旧、新两版通过同一场景后，才能记录游戏通过验收。缺少依赖、源码、旧构建、权限或设备时，保留现有产物并说明流程停在哪里。源码和报告留在本地，分发需有用户授权。
